# 准备工作：不同系统下的 Python 环境配置 (Environment Setup)
---

## 章节概述

本章是 Python 教程的零号章节。在敲下第一行 Python 之前，你需要先拥有一份能用的 Python 解释器。C 程序员的习惯是"装编译器 → 配环境变量 → 写代码"，Python 的路数几乎一样，只是简单得多：解释器装好就能跑，不需要头文件、不需要链接库。

本章按 Windows / macOS / Linux 分别给出安装与配置步骤，然后讨论编辑器选择。特别说明：**Python 是脚本语言，在终端环境下你甚至不需要编辑器**——直接用 REPL 或 `python -c` 就能执行代码，这点和 C 必须"先编辑文件再编译"完全不同。

> **核心理念**：Python 环境 = 解释器 + pip（包管理器）。环境配置的终点是 `python --version` 能给出结果。编辑器是锦上添花，不是必需品。

---

### 第一节：Windows 环境配置
---

1.1 安装包方式（推荐新手）
--------------------------

访问 [python.org](https://www.python.org/downloads/) 下载最新稳定版安装包（.exe），双击运行。**有两个关键选项必须注意**：

| 选项 | 必须勾选 | 原因 |
|------|:-------:|------|
| "Add Python to PATH" | 是 | 否则 `python` 命令在终端中无法直接使用 |
| "Install launcher for all users" | 是 | 提供 `py` 启动器，便于多版本管理 |

安装完成后，**务必重启终端**（PATH 变更需要新进程才能生效），然后验证：

```cmd
python --version
pip --version
```

1.2 命令行方式（winget / chocolatey）
-------------------------------------

有包管理器的用户可以直接一行装好：

```cmd
winget install python
```

或用 Chocolatey：

```cmd
choco install python
```

> 注意：winget 装的是 python.org 官方包，PATH 会自动配置；但同样的，**安装完成后需要重启终端**。

1.3 py 启动器与多版本管理
--------------------------

Windows 上 `py` 是官方启动器，可以同时管理多个 Python 版本：

```cmd
py -0          # 列出已安装的所有 Python 版本
py -3.12       # 用指定版本运行
py -3.12 -m pip install numpy   # 为指定版本安装包
```

| 命令 | 含义 |
|------|------|
| `python` | 默认版本（通常是最新安装的） |
| `py -0` | 列出所有版本 |
| `py -3.11` | 指定 3.11 运行 |
| `py -m pip` | 为当前版本调用 pip |

1.4 Windows 下常见问题
-----------------------

| 问题 | 原因 | 解决 |
|------|------|------|
| `python 不是内部或外部命令` | PATH 未配置或终端未重启 | 重装时勾选 PATH，重启终端 |
| `python` 打开微软商店 | 系统应用别名拦截 | 设置 → 应用 → 高级应用设置 → 应用执行别名，关闭 python.exe 别名 |
| 中文路径报错 | 工作目录含中文 | 尽量使用英文目录，或用 `py -3.12 -X utf8` 强制 UTF-8 |
| pip 安装慢 | 默认源在国外 | 换清华源：`pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple` |

### 第二节：macOS 环境配置
---

2.1 系统自带与 Homebrew
-----------------------

macOS 自带 Python 3（从 macOS 12.3 起系统自带 `/usr/bin/python3`），但**系统版不应作为开发环境**——它被系统工具依赖，版本老且不能随便动。开发请用 Homebrew 安装：

```bash
brew install python
```

Homebrew 版会自带 pip，安装后：

```bash
python3 --version
python3 -m pip --version
```

2.2 安装包方式（.pkg）
-----------------------

不习惯 Homebrew 的用户可去 [python.org](https://www.python.org/downloads/) 下载 macOS 安装包（.pkg），双击安装即可，无需额外配置 PATH。

2.3 Xcode Command Line Tools
----------------------------

很多 Python 包在 macOS 上需要编译（如 `numpy`、`pyyaml` 的二进制轮子），编译需要 clang 编译器。建议提前装好：

```bash
xcode-select --install
```

| 方式 | 优点 | 缺点 |
|------|------|------|
| Homebrew | 版本新、升级方便、与系统隔离 | 需先装 Homebrew |
| python.org .pkg | 官方、即装即用 | 升级需手动重装 |
| 系统自带 | 零安装 | 版本老、不可乱动，只应急用 |

> 建议：日常开发用 Homebrew 版，`/usr/bin/python3` 留给系统。

### 第三节：Linux 环境配置
---

Linux 各发行版包管理器不同，命令如下：

| 发行版 | 安装命令 |
|--------|----------|
| Debian / Ubuntu | `sudo apt install python3 python3-pip python3-venv` |
| Arch / Manjaro | `sudo pacman -S python python-pip` |
| Fedora / RHEL | `sudo dnf install python3 python3-pip` |

安装后验证：

```bash
python3 --version
python3 -m pip --version
```

3.1 Linux 注意点
----------------

| 注意点 | 说明 |
|--------|------|
| 不要动系统的 python | Debian/Ubuntu 的 `python3` 被系统工具依赖，升级系统 Python 可能弄坏 `apt` |
| 用 `python3` 而非 `python` | 很多发行版没有 `python` 命令（或指向 python2），一律用 `python3` |
| 装包用 `pip3` 或 `python3 -m pip` | 与系统 python 解耦，避免依赖混乱 |
| 加装 `python3-venv` | 创建虚拟环境必需，见工程化章节 |

3.2 源码编译（不推荐但可行）
-----------------------------

从 [python.org](https://www.python.org/downloads/) 下载源码 tarball 编译安装：

```bash
wget https://www.python.org/ftp/python/3.12.x/Python-3.12.x.tgz
tar xzf Python-3.12.x.tgz && cd Python-3.12.x
./configure --enable-optimizations
make -j$(nproc)
sudo make altinstall   # altinstall 不会覆盖系统 python3
```

> 除非你需要特殊编译选项，否则直接用包管理器即可，编译耗时且无收益。

### 第四节：统一验证与版本管理
---

无论哪个系统，装完的验证标准只有一个：

```bash
python3 --version   # 或 python --version / py -0 (Windows)
python3 -c "print('hello')"   # 能跑通一行程序
```

4.1 多版本共存：uv（推荐）
--------------------------

`uv` 是目前最省心的 Python 版本与包管理器（Rust 写的，快），跨平台支持：

| 系统 | 安装 uv |
|------|---------|
| Windows | `winget install astral-sh.uv` |
| macOS | `brew install uv` |
| Linux | `curl -LsSf https://astral.sh/uv/install.sh \| sh` |

常用命令：

```bash
uv python install 3.12      # 安装指定版本
uv run --python 3.12 hello.py   # 指定版本运行
uv init                    # 初始化项目 + venv
uv add numpy               # 装包并写进 pyproject.toml
```

| 工具 | 定位 | 适用 |
|------|------|------|
| `py` (仅 Windows) | 官方多版本启动器 | Windows 用户 |
| `uv` | 版本管理 + 包管理 + venv 一体化 | 全平台推荐 |
| `conda` | 科学计算全家桶 | 量化/科学计算场景 |

4.2 虚拟环境最小认识
--------------------

不同项目依赖不同版本包，虚拟环境把它们隔开（类似 C 项目各自的 `lib/`）：

```bash
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
```

> 虚拟环境的完整玩法见 [[../5工程化/01_venv与uv：环境隔离|5工程化/01 venv 与 uv]]。

### 第五节：编辑器选择——甚至不需要编辑器
---

5.1 终端即编辑器：Python 的特殊性
---------------------------------

C 程序员写代码的常规流程是：`vim hello.c` → 编译 → 运行。**Python 把这个流程拆了——它可以直接在终端里执行，不需要任何编辑器和文件**：

**方式一：REPL 交互式解释器**

```bash
python3
>>> print("hello")
hello
>>> 1 + 2
3
>>> exit()
```

终端里敲 `python3` 回车就进入 REPL（Read-Eval-Print Loop，读取-求值-打印循环），边敲边出结果，适合试算法、算数据、查 API。

**方式二：`python -c` 一行流**

```bash
python3 -c "print(1 + 2)"
python3 -c "import math; print(math.sqrt(16))"
```

不建文件、不写 `main`，一句命令直接算，这就是 Python 作为"C 程序员工具"最爽的场景。

**方式三：heredoc 多行脚本**

```bash
python3 << 'EOF'
for i in range(5):
    print(i ** 2)
EOF
```

> 以上三种方式**都不需要编辑器**。这就是脚本语言与编译语言最大的体验差异：C 必须"文件 → 编译 → 可执行文件"，Python 从终端键盘到执行结果，零中间产物。

5.2 需要编辑器时怎么选
----------------------

当脚本超过一屏、或要调试复杂逻辑时，还是需要正经编辑器。三档选择：

| 编辑器 | 平台 | 定位 | 适合谁 |
|--------|------|------|--------|
| **VS Code + Python 插件** | 全平台 | 轻量 IDE | 推荐。C/C++ 插件可共存，一个编辑器干所有活 |
| **PyCharm Community** | 全平台 | 完整 IDE | 纯 Python 重度开发，内置调试/测试/虚拟环境 |
| **Vim / Neovim** | 全平台 | 终端编辑器 | C 程序员习惯的编辑方式，SSH 远程首选 |
| 系统记事本 / 文本编辑 | 全平台 | 兜底 | 只写几十行小脚本，够用 |

5.3 三档选择的细化建议
-----------------------

| 场景 | 推荐 | 原因 |
|------|------|------|
| 主要写 C，Python 只是工具 | VS Code | 一套配置，C/C++ 与 Python 插件共存 |
| 纯 Python 项目，工期长 | PyCharm Community | 补全/重构/调试一体化，零配置 |
| SSH 远程服务器操作 | Vim / Neovim | 终端内编辑，无需图形界面 |
| 只是偶尔跑几行 | 终端 REPL / `python -c` | 根本不需要编辑器 |
| 没装任何东西 | 任何文本编辑器 + `python3 file.py` | 编辑器无关，解释器跑一切 |

> **结论**：编辑器和语言强绑定（如 Java 配 IDEA）在 Python 这里不成立——Python 是脚本语言，`.py` 文件就是纯文本，任何能写文本的工具都能写 Python。唯一的硬需求是**解释器装好**。

## 章节小结

| 要点 | 一句话 |
|------|--------|
| 安装 | Windows 勾 PATH / macOS 用 brew / Linux 用包管理器 |
| 验证 | `python3 --version` + 能跑 `python3 -c "print('ok')"` |
| 终端跑 Python | REPL / `python -c` / heredoc，**不需要编辑器** |
| 编辑器 | VS Code 通用、PyCharm 纯 Python、Vim 远程终端 |
| 多版本 | Windows 用 `py`，跨平台推荐 `uv` |
