# 31 - 自定义系统打包与分发

> 当你需要为团队、企业或社区创建标准化的 Arch Linux 安装介质时，archiso 是官方提供的强大工具。本章将详细介绍如何使用 archiso 构建自定义 ISO、搭建私有仓库、实现 PXE 网络安装、制作 Docker/WSL 镜像，以及通过 CI/CD 实现自动化构建流水线。

---

## 31.1 为什么要打包自定义系统

### 31.1.1 典型使用场景

| 场景 | 需求 | 方案 |
|------|------|------|
| 企业桌面标准化 | 统一预装软件、配置、壁纸 | archiso 自定义 ISO |
| 运维快速部署 | 几十台服务器批量安装 | PXE + archinstall 自动化 |
| 安全审计 / 渗透测试 | 类 BlackArch 的工具集 | archiso + 自定义包列表 |
| 离线环境部署 | 无网络的数据中心 | 离线安装包 + 本地仓库 |
| 教学/培训 | 统一教学环境 | ISO + QEMU 虚拟机 |
| 嵌入式/Kiosk | 信息亭、展示终端 | 最小化定制系统 |
| 云镜像 | AWS/Azure/GCP 自定义镜像 | archiso + cloud-init |
| 容器基础镜像 | 统一开发/部署环境 | Docker 基础镜像 |
| WSL 分发 | Windows 开发环境 | WSL 导入包 |

### 31.1.2 自定义系统的优势

```
标准化部署的收益：
├── 一致性 → 所有机器配置完全相同，减少"在我机器上能跑"问题
├── 效率 → 从数小时手动安装缩短到几分钟自动部署
├── 安全性 → 预配置安全策略，避免人为遗漏
├── 可审计 → 构建过程版本化，可追踪任何变更
└── 可重复 → 相同输入始终产生相同输出
```

## 31.2 archiso 详解

### 31.2.1 安装 archiso

```bash
pacman -S archiso
```

安装完成后会提供两个核心命令和两个模板 profile：

```bash
# 核心命令
which mkarchiso
# /usr/bin/mkarchiso

# 模板 profile 位置
ls /usr/share/archiso/configs/
# baseline/    releng/
```

### 31.2.2 Profile 结构对比

| 特性 | baseline | releng |
|------|----------|--------|
| 用途 | 最小化 Live 系统 | 完整安装介质（官方 ISO 用此模板） |
| 预装软件 | 极少 | 包含安装所需的全部工具 |
| 网络支持 | 基础 | NetworkManager + iwd |
| 引导方式 | BIOS + UEFI | BIOS + UEFI + Secure Boot |
| 自动登录 | root | root |
| 复杂度 | 低 | 高 |

```bash
# 查看 releng profile 的目录结构
ls -la /usr/share/archiso/configs/releng/
```

```
releng/
├── airootfs/                  # 叠加到 Live 系统根目录的文件
│   └── etc/
│       ├── hostname
│       ├── locale.conf
│       ├── modprobe.d/
│       ├── systemd/
│       │   └── system/        # 需要启用的 systemd 服务链接
│       └── ssh/
├── efiboot/                   # EFI 引导配置
├── syslinux/                  # BIOS 引导配置
├── grub/                      # GRUB 配置
├── packages.x86_64            # 要安装的包列表
├── pacman.conf                # 构建时使用的 pacman 配置
└── profiledef.sh              # profile 定义文件
```

### 31.2.5 自定义配置文件叠加（airootfs）

`airootfs/` 目录中的文件会被直接复制到 Live 系统的根目录：

```bash
# 自定义主机名
echo "archcustom" > ~/archlive/airootfs/etc/hostname

# 自定义 locale
echo "LANG=zh_CN.UTF-8" > ~/archlive/airootfs/etc/locale.conf

# 创建 locale.gen
mkdir -p ~/archlive/airootfs/etc/
cat > ~/archlive/airootfs/etc/locale.gen << 'EOF'
en_US.UTF-8 UTF-8
zh_CN.UTF-8 UTF-8
EOF

# 自定义 vconsole（控制台键盘）
echo "KEYMAP=us" > ~/archlive/airootfs/etc/vconsole.conf

# 预置 pacman 镜像列表
mkdir -p ~/archlive/airootfs/etc/pacman.d/
cat > ~/archlive/airootfs/etc/pacman.d/mirrorlist << 'EOF'
Server = https://mirrors.tuna.tsinghua.edu.cn/archlinux/$repo/os/$arch
Server = https://mirrors.ustc.edu.cn/archlinux/$repo/os/$arch
Server = https://mirrors.aliyun.com/archlinux/$repo/os/$arch
EOF

# 自定义 root 的 .bashrc
mkdir -p ~/archlive/airootfs/root/
cat > ~/archlive/airootfs/root/.bashrc << 'EOF'
alias ll='ls -alF --color=auto'
alias la='ls -A --color=auto'
alias l='ls -CF --color=auto'
export EDITOR=vim
export PS1='\[\e[1;32m\]\u@\h\[\e[0m\]:\[\e[1;34m\]\w\[\e[0m\]\$ '
EOF

# 预置 SSH 配置
mkdir -p ~/archlive/airootfs/etc/ssh/
cat > ~/archlive/airootfs/etc/ssh/sshd_config.d/custom.conf << 'EOF'
PermitRootLogin yes
PasswordAuthentication yes
EOF
```

### 31.2.6 启用 systemd 服务

```bash
# 在 airootfs 中创建 systemd 符号链接来启用服务
mkdir -p ~/archlive/airootfs/etc/systemd/system/multi-user.target.wants/
mkdir -p ~/archlive/airootfs/etc/systemd/system/network-online.target.wants/

# 启用 NetworkManager
ln -sf /usr/lib/systemd/system/NetworkManager.service \
    ~/archlive/airootfs/etc/systemd/system/multi-user.target.wants/NetworkManager.service

ln -sf /usr/lib/systemd/system/NetworkManager-wait-online.service \
    ~/archlive/airootfs/etc/systemd/system/network-online.target.wants/NetworkManager-wait-online.service

# 启用 SSH
ln -sf /usr/lib/systemd/system/sshd.service \
    ~/archlive/airootfs/etc/systemd/system/multi-user.target.wants/sshd.service

# 启用 Docker
ln -sf /usr/lib/systemd/system/docker.service \
    ~/archlive/airootfs/etc/systemd/system/multi-user.target.wants/docker.service
```

### 31.2.7 自定义启动脚本

```bash
# 创建首次启动脚本
mkdir -p ~/archlive/airootfs/usr/local/bin/
cat > ~/archlive/airootfs/usr/local/bin/live-setup.sh << 'SCRIPT'
#!/bin/bash
echo "========================================="
echo "  欢迎使用自定义 Arch Linux Live 系统"
echo "  版本: $(date +%Y.%m.%d)"
echo "========================================="
echo ""
echo "可用工具："
echo "  archinstall  - 交互式安装向导"
echo "  nmtui        - 网络配置（TUI）"
echo "  htop         - 系统监控"
echo ""

locale-gen

if ! ip route | grep -q default; then
    echo "[提示] 未检测到网络连接，请运行 nmtui 配置网络"
fi
SCRIPT
chmod 755 ~/archlive/airootfs/usr/local/bin/live-setup.sh

# 创建自动运行服务
mkdir -p ~/archlive/airootfs/etc/systemd/system/
cat > ~/archlive/airootfs/etc/systemd/system/live-setup.service << 'EOF'
[Unit]
Description=Live System Setup
After=multi-user.target

[Service]
Type=oneshot
ExecStart=/usr/local/bin/live-setup.sh
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF

# 启用服务
ln -sf /etc/systemd/system/live-setup.service \
    ~/archlive/airootfs/etc/systemd/system/multi-user.target.wants/live-setup.service
```

### 31.2.9 构建 ISO

```bash
# 构建（需要 root 权限）
sudo mkarchiso -v -w /tmp/archiso-build -o ~/archlive/out ~/archlive/

# 参数说明：
# -v             详细输出
# -w <dir>       工作目录（构建临时文件，需要较大空间）
# -o <dir>       ISO 输出目录
# 最后一个参数    profile 目录

# 构建完成后
ls -lh ~/archlive/out/
# archlinux-custom-2024.01.15-x86_64.iso

# 清理构建目录（再次构建前需执行）
sudo rm -rf /tmp/archiso-build
```

## 31.3 自定义仓库搭建

### 31.3.1 创建本地仓库

```bash
# 创建仓库目录
mkdir -p /srv/repo/custom/x86_64

# 假设你已有一些自己构建的包
cp ~/builds/*.pkg.tar.zst /srv/repo/custom/x86_64/

# 使用 repo-add 生成仓库数据库
repo-add /srv/repo/custom/x86_64/custom.db.tar.gz \
    /srv/repo/custom/x86_64/*.pkg.tar.zst
```

### 31.3.2 构建自定义包

```bash
# 创建 PKGBUILD
mkdir -p ~/pkgbuilds/myapp && cd ~/pkgbuilds/myapp

cat > PKGBUILD << 'EOF'
pkgname=myapp
pkgver=1.0.0
pkgrel=1
pkgdesc="My Custom Application"
arch=('x86_64')
url="https://example.com/myapp"
license=('MIT')
depends=('python' 'python-requests')
source=("https://example.com/myapp-${pkgver}.tar.gz")
sha256sums=('SKIP')

build() {
    cd "$srcdir/myapp-$pkgver"
    python setup.py build
}

package() {
    cd "$srcdir/myapp-$pkgver"
    python setup.py install --root="$pkgdir/" --optimize=1
    install -Dm644 LICENSE "$pkgdir/usr/share/licenses/$pkgname/LICENSE"
}
EOF

# 构建包
makepkg -s

# 添加到仓库
cp myapp-1.0.0-1-x86_64.pkg.tar.zst /srv/repo/custom/x86_64/
repo-add /srv/repo/custom/x86_64/custom.db.tar.gz \
    /srv/repo/custom/x86_64/myapp-1.0.0-1-x86_64.pkg.tar.zst
```

### 31.3.3 HTTP 仓库服务

```bash
# 方法 1：使用 nginx
pacman -S nginx

cat > /etc/nginx/nginx.conf << 'EOF'
worker_processes auto;

events {
    worker_connections 1024;
}

http {
    include       mime.types;
    default_type  application/octet-stream;
    sendfile      on;

    server {
        listen 80;
        server_name repo.example.com;

        location /archlinux/custom/ {
            alias /srv/repo/custom/;
            autoindex on;
        }
    }
}
EOF

systemctl enable --now nginx

# 方法 2：快速测试用 Python HTTP 服务
cd /srv/repo && python -m http.server 8080

# 方法 3：使用 darkhttpd（轻量）
pacman -S darkhttpd
darkhttpd /srv/repo --port 8080
```

### 31.3.4 签名与安全

```bash
# 生成 GPG 密钥用于签名
gpg --full-generate-key
# 选择 RSA and RSA, 4096 bits

# 导出公钥
gpg --export --armor "My Repo Key" > /srv/repo/custom/repo-key.asc

# 签名单个包
gpg --detach-sign --no-armor /srv/repo/custom/x86_64/myapp-1.0.0-1-x86_64.pkg.tar.zst

# 使用 repo-add 时自动签名
repo-add --sign /srv/repo/custom/x86_64/custom.db.tar.gz \
    /srv/repo/custom/x86_64/*.pkg.tar.zst

# 客户端导入密钥
pacman-key --add repo-key.asc
pacman-key --lsign-key <KEY_ID>
```

## 31.4 pacman 自定义仓库配置

```ini
# /etc/pacman.conf 添加自定义仓库

# 本地仓库
[custom]
SigLevel = Optional TrustAll
Server = file:///srv/repo/custom/$arch

# HTTP 仓库
[custom]
SigLevel = Required DatabaseOptional
Server = https://repo.example.com/archlinux/custom/$arch

# 多个镜像
[custom]
SigLevel = Required DatabaseOptional
Server = https://repo1.example.com/archlinux/custom/$arch
Server = https://repo2.example.com/archlinux/custom/$arch
```

```bash
# 同步新仓库
pacman -Sy

# 验证仓库可用
pacman -Sl custom

# 安装自定义仓库中的包
pacman -S custom/myapp
```

### 31.5.2 配置管理工具集成

```bash
# Ansible 方式管理 Arch 集群
# inventory.yml
cat > inventory.yml << 'EOF'
all:
  children:
    arch_servers:
      hosts:
        server1:
          ansible_host: 192.168.1.101
        server2:
          ansible_host: 192.168.1.102
      vars:
        ansible_user: admin
        ansible_become: yes
EOF

# playbook: 确保所有机器软件一致
cat > site.yml << 'EOF'
---
- hosts: arch_servers
  tasks:
    - name: Full system update
      pacman:
        update_cache: yes
        upgrade: yes

    - name: Install required packages
      pacman:
        name:
          - nginx
          - docker
          - python
          - htop
          - vim
        state: present

    - name: Enable services
      systemd:
        name: "{{ item }}"
        enabled: yes
        state: started
      loop:
        - nginx
        - docker
        - sshd

    - name: Deploy custom config
      copy:
        src: files/nginx.conf
        dest: /etc/nginx/nginx.conf
      notify: restart nginx

  handlers:
    - name: restart nginx
      systemd:
        name: nginx
        state: restarted
EOF
```

## 31.6 Calamares 安装器集成

Calamares 是一个通用的 Linux 发行版安装框架，许多 Arch 衍生版（如 EndeavourOS、Garuda）使用它：

```bash
# 安装 Calamares（从 AUR）
yay -S calamares

# 或从源码构建以获得更多定制能力
pacman -S cmake extra-cmake-modules qt6-base qt6-tools \
    kpmcore yaml-cpp libpwquality icu boost

git clone https://github.com/calamares/calamares.git
cd calamares
mkdir build && cd build
cmake -DCMAKE_INSTALL_PREFIX=/usr ..
make -j$(nproc)
sudo make install
```

## 31.7 离线安装包制作

### 31.7.1 下载包及其所有依赖

```bash
# 方法 1：使用 pacman 下载但不安装
mkdir -p /srv/offline-repo

pacman -Syw --cachedir /srv/offline-repo \
    base linux linux-firmware grub efibootmgr \
    networkmanager vim openssh

# 方法 2：下载包括已安装包在内的完整依赖树
pacman -Sp --cachedir /srv/offline-repo \
    base linux linux-firmware 2>/dev/null | \
    xargs -I {} pacman -Sw --cachedir /srv/offline-repo --noconfirm {}
```

### 31.7.2 创建离线仓库

## 31.10 系统快照分发（Btrfs send/receive）

### 31.10.1 创建标准系统快照

```bash

# 假设系统根目录是 Btrfs 子卷 @

btrfs send /snapshots/golden-image-20240115 | \
```

```bash
    /snapshots/golden-image-20240201 | \
    zstd -T0 -10 > /srv/images/golden-image-20240115-to-20240201.btrfs.zst

# 增量快照通常非常小
```

## 31.13 CI/CD 自动化构建 ISO

### 31.13.1 GitHub Actions 工作流

```yaml

name: Build Custom Arch ISO

on:
  push:
    branches: [main]

      - 'archiso/**'

    - cron: '0 2 1 * *'   # 每月 1 号凌晨 2 点

  build:
    runs-on: ubuntu-latest
    container:
      image: archlinux:latest

      - name: Checkout
        uses: actions/checkout@v4

      - name: Install archiso

          name: arch-custom-iso

        uses: softprops/action-gh-release@v2
        with:
          tag_name: v${{ github.run_number }}
          name: "Arch Custom ISO Build #${{ github.run_number }}"
```

### 31.13.3 本地自动化构建脚本

```bash
#!/bin/bash
# build-iso.sh - 本地自动化构建脚本
set -euo pipefail

PROFILE_DIR="$(cd "$(dirname "$0")" && pwd)/archiso"
WORK_DIR="/tmp/archiso-build-$$"
OUT_DIR="./output"
LOG_FILE="./build-$(date +%Y%m%d-%H%M%S).log"

cleanup() {
    echo "清理工作目录..."
    sudo rm -rf "$WORK_DIR"
}
trap cleanup EXIT

echo "========================================" | tee "$LOG_FILE"
echo "  Arch Linux 自定义 ISO 构建" | tee -a "$LOG_FILE"
echo "  时间: $(date)" | tee -a "$LOG_FILE"
echo "========================================" | tee -a "$LOG_FILE"

echo "[1/4] 检查依赖..." | tee -a "$LOG_FILE"
if ! command -v mkarchiso &>/dev/null; then
    echo "错误: 请先安装 archiso (pacman -S archiso)" | tee -a "$LOG_FILE"
    exit 1
fi

echo "[2/4] 验证 profile..." | tee -a "$LOG_FILE"
if [ ! -f "$PROFILE_DIR/profiledef.sh" ]; then
    echo "错误: 未找到 profiledef.sh" | tee -a "$LOG_FILE"
    exit 1
fi

echo "[3/4] 开始构建..." | tee -a "$LOG_FILE"
mkdir -p "$OUT_DIR"
sudo mkarchiso -v -w "$WORK_DIR" -o "$OUT_DIR" "$PROFILE_DIR" 2>&1 | tee -a "$LOG_FILE"

echo "[4/4] 生成校验和..." | tee -a "$LOG_FILE"
cd "$OUT_DIR"
sha256sum *.iso > SHA256SUMS
md5sum *.iso > MD5SUMS

echo "" | tee -a "$LOG_FILE"
echo "构建完成！" | tee -a "$LOG_FILE"
ls -lh *.iso | tee -a "$LOG_FILE"
cat SHA256SUMS | tee -a "$LOG_FILE"
```

## 31.15 常见问题与排错

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 构建失败：找不到包 | 包名错误或仓库未同步 | `pacman -Sy` 并检查包名 |
| ISO 无法启动 | 引导配置错误 | 检查 syslinux/grub 配置 |
| ISO 体积过大 | 安装了过多包 | 精简 packages.x86_64 |
| 构建空间不足 | 工作目录所在分区满 | 使用更大的分区作为 `-w` 参数 |
| PXE 客户端无法获取 IP | DHCP 配置错误 | 检查 dnsmasq 日志 |
| 自定义仓库同步失败 | 数据库文件损坏 | 重新运行 `repo-add` |
| UEFI 安全启动失败 | 未签名的引导器 | 使用 `shim` + `MOK` 签名 |
| WSL 导入后无网络 | resolv.conf 配置问题 | 检查 `/etc/wsl.conf` 中 `generateResolvConf` |

> [!question]- 选择题 1：archiso 提供的两个模板 profile 分别是？

> [!question]- 选择题 2：在 archiso 的 profile 中，airootfs/ 目录的作用是什么？
> - A. 存放编译时的临时文件
> - B. 其中的文件会被直接复制到 Live 系统的根目录
> - C. 存放 ISO 的引导配置
> - D. 存放包管理器缓存
>
> > [!success]- 点击查看答案
> > **B**

> [!question]- 选择题 3：构建 archiso ISO 的核心命令是？
> - A. `pacstrap`
> - B. `mkarchiso`
> - C. `mkinitcpio`
> - D. `makepkg`
>
> > [!success]- 点击查看答案

> [!question]- 选择题 4：使用 repo-add 创建自定义仓库数据库的命令格式是？

> > 使用 `repo-add /path/to/custom.db.tar.gz /path/to/*.pkg.tar.zst` 来生成仓库数据库文件。createrepo 是 RPM 系的命令。

> [!question]- 判断题 5：archiso 构建 ISO 需要 root 权限。
> - A. ✓ 正确
> - B. ✗ 错误
>
> > [!success]- 点击查看答案
> > **A. ✓ 正确**
> > mkarchiso 构建过程需要 root 权限，因为需要创建文件系统、设置权限和挂载等操作。使用 `sudo mkarchiso` 执行。

> [!question]- 选择题 6：PXE 网络安装中，TFTP 服务主要用于提供什么？
> - A. 完整的根文件系统
> - B. 引导加载器和内核/initramfs 文件
> - C. 包仓库数据
> - D. DHCP 地址分配
>
> > [!success]- 点击查看答案
> > **B**
> > TFTP 用于提供 PXE 启动所需的引导加载器（如 pxelinux.0）和内核/initramfs 文件。rootfs 通常通过 HTTP/NFS 提供。

> [!question]- 选择题 7：将 Arch Linux 制作为 WSL 分发包时，打包格式应为？

> - B. .tar.gz

> - D. .vhdx
>
> > [!success]- 点击查看答案
> > **B**
> > WSL 使用 tar 格式的根文件系统存档。通过 `wsl --import` 命令导入 .tar.gz 文件来创建新的 WSL 分发。

> [!question]- 判断题 8：使用 Btrfs send/receive 进行系统分发时，增量快照通常比全量快照小得多。

> > **A. ✓ 正确**

> [!question]- 选择题 9：在 archiso 的 profiledef.sh 中，airootfs_image_type 通常设置为什么？

> [!question]- 选择题 10：在企业级 Arch 部署方案中，配合 Ansible 使用时，pacman 模块的系统更新写法是？
