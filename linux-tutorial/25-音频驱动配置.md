# 25 - 音频驱动配置

> Linux 音频系统经历了从 OSS 到 ALSA、PulseAudio，再到 PipeWire 的演进。Arch Linux 作为滚动发行版，积极拥抱最新的 PipeWire 音频栈。本章将全面介绍 Linux 音频体系的各个层次，帮助你正确配置音频并解决常见问题。

---

## 25.1 Linux 音频栈演进

### 25.1.1 发展历程

```
OSS (1992)  →  ALSA (2002)  →  PulseAudio (2004)  →  PipeWire (2017)
  ↓               ↓                  ↓                    ↓
最早的音频框架  取代OSS成为     用户空间混音服务器      统一音频/视频
内核层面       内核标准        桌面音频管理            替代PA和JACK
```

### 25.1.2 各层次职责

| 层次 | 组件 | 职责 |
|------|------|------|
| 内核层 | ALSA | 硬件驱动、底层音频接口 |
| 用户空间服务 | PipeWire / PulseAudio | 混音、路由、设备管理 |
| 会话管理 | WirePlumber | 设备策略、自动路由 |
| 应用接口 | PulseAudio API / JACK API | 应用程序使用的 API |

### 25.1.3 现代 Arch Linux 音频栈

```
┌────────────────────────────────────────────────┐
│                  应用程序                        │
│   (Firefox, mpv, Discord, OBS, Ardour ...)     │
├──────────┬─────────────┬───────────────────────┤
│ PA API   │  JACK API   │    原生 PipeWire API   │
├──────────┴─────────────┴───────────────────────┤
│              PipeWire 守护进程                    │
├────────────────────────────────────────────────┤
│            WirePlumber (会话管理)                 │
├────────────────────────────────────────────────┤
│              ALSA (内核驱动)                      │
├────────────────────────────────────────────────┤
│              声卡硬件                             │
└────────────────────────────────────────────────┘
```

## 25.2 ALSA 基础

ALSA（Advanced Linux Sound Architecture）是 Linux 内核的音频子系统，所有上层音频服务都建立在 ALSA 之上。

### 25.2.1 内核模块

```bash
# 查看已加载的声卡模块
lsmod | grep snd

# 常见的内核音频模块
# snd_hda_intel    - Intel HDA 声卡（最常见）
# snd_hda_codec_*  - HDA 编解码器
# snd_usb_audio    - USB 声卡/音频接口
# snd_aloop        - 虚拟回环设备
# snd_pcm          - PCM 核心
# snd_mixer_oss    - OSS 兼容层

# 查看检测到的声卡
cat /proc/asound/cards

# 输出示例：
#  0 [PCH            ]: HDA-Intel - HDA Intel PCH
#                       HDA Intel PCH at 0xf7210000 irq 32
#  1 [HDMI           ]: HDA-Intel - HDA ATI HDMI
#                       HDA ATI HDMI at 0xf7060000 irq 33

# 查看声卡详细信息
cat /proc/asound/card0/codec#0 | head -30

# 查看 PCM 设备
aplay -l

# 查看录音设备
arecord -l
```

### 25.2.2 alsamixer 和 amixer

```bash
# 安装 ALSA 工具
sudo pacman -S alsa-utils

# 交互式音量控制（TUI 界面）
alsamixer

# F4 - 录音控制
# F5 - 所有控制
# M  - 静音/取消静音
# ↑↓ - 调节音量

# 命令行音量控制
# 查看所有控制项
amixer scontrols

# 设置主音量
amixer set Master 80%
amixer set Master 5%+
amixer set Master 5%-

# 静音/取消静音
amixer set Master toggle

# 设置特定声卡的音量
amixer -c 0 set Master 80%

# 查看详细信息
amixer -c 0 contents
```

## 25.3 PulseAudio

虽然 PipeWire 已成为推荐方案，但了解 PulseAudio 仍然有价值。

### 25.3.1 架构与工作原理

```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│   应用 A     │  │   应用 B     │  │   应用 C     │
└──────┬──────┘  └──────┬──────┘  └──────┬──────┘
       │                │                │
       └────────┬───────┴────────┬───────┘
                │                │
         ┌──────┴──────────────┐│
         │  PulseAudio Daemon  ││
         │  (混音、路由、均衡)  ││
         └──────┬──────────────┘│
                │               │
         ┌──────┴──────┐ ┌─────┴──────┐
         │  Sink 0     │ │  Sink 1    │
         │ (扬声器)    │ │ (耳机)     │
         └─────────────┘ └────────────┘
```

核心概念：

| 概念 | 说明 |
|------|------|
| Sink | 音频输出设备（扬声器、耳机） |
| Source | 音频输入设备（麦克风） |
| Sink Input | 连接到 Sink 的音频流（应用输出） |
| Source Output | 连接到 Source 的音频流（应用录音） |
| Module | 可加载的功能模块 |
| Card | 物理声卡 |
| Profile | 声卡的配置模式（立体声、环绕等） |

### 25.3.2 安装与基本使用

```bash
# 安装 PulseAudio（如果不使用 PipeWire）
sudo pacman -S pulseaudio pulseaudio-alsa

# 图形化音量控制
sudo pacman -S pavucontrol

# PulseAudio 自动随用户会话启动，无需手动启动

# 检查状态
pulseaudio --check
echo $?  # 0 表示正在运行
```

### 25.3.3 pactl 命令

```bash
# 列出所有 Sink（输出设备）
pactl list sinks short

# 列出所有 Source（输入设备）
pactl list sources short

# 列出正在播放的流
pactl list sink-inputs short

# 设置默认输出
pactl set-default-sink <sink_name>

# 设置音量（百分比）
pactl set-sink-volume @DEFAULT_SINK@ 80%
pactl set-sink-volume @DEFAULT_SINK@ +5%
pactl set-sink-volume @DEFAULT_SINK@ -5%

# 静音
pactl set-sink-mute @DEFAULT_SINK@ toggle

# 设置输入（麦克风）音量
pactl set-source-volume @DEFAULT_SOURCE@ 80%

# 移动应用音频到指定输出
pactl move-sink-input <sink_input_index> <sink_index>

# 加载/卸载模块
pactl load-module module-loopback
pactl unload-module <module_index>
```

### 25.3.4 多声卡管理

```bash
# 列出所有声卡和配置文件
pactl list cards

# 设置声卡配置文件
pactl set-card-profile <card_index> <profile_name>

# 示例：切换到 HDMI 输出
pactl set-card-profile 0 output:hdmi-stereo

# 自动切换配置文件
# /etc/pulse/default.pa 中添加
# load-module module-switch-on-port-available

# 同时使用多个声卡输出
pactl load-module module-combine-sink \
    sink_name=combined \
    slaves=alsa_output.pci-0000_00_1f.3.analog-stereo,alsa_output.usb-device.analog-stereo
```

## 25.4 PipeWire（Arch 现代推荐）

PipeWire 是新一代多媒体框架，同时处理音频和视频流，在 Arch Linux 中已成为推荐的音频解决方案。

### 25.4.1 为什么选择 PipeWire

| 特性 | PulseAudio | JACK | PipeWire |
|------|-----------|------|----------|
| 桌面音频 | 优秀 | 不适合 | 优秀 |
| 专业低延迟 | 一般 | 优秀 | 优秀 |
| 视频流处理 | 不支持 | 不支持 | 支持 |
| 蓝牙音频 | 支持 | 不支持 | 支持（更好） |
| 编解码器支持 | SBC/AAC | 无 | SBC/AAC/LDAC/AptX |
| 沙箱应用支持 | 有限 | 无 | 原生支持 |
| CPU 占用 | 较高 | 低 | 低 |
| 兼容性 | PA API | JACK API | PA + JACK + 原生 |

### 25.4.2 安装与配置

```bash
# 安装 PipeWire 核心
sudo pacman -S pipewire pipewire-audio

# 安装 PulseAudio 兼容层（替代 pulseaudio）
sudo pacman -S pipewire-pulse

# 安装 JACK 兼容层（替代 jack2）
sudo pacman -S pipewire-jack

# 安装 ALSA 支持
sudo pacman -S pipewire-alsa

# 安装会话管理器
sudo pacman -S wireplumber

# 安装 GStreamer 插件（可选，用于编解码器）
sudo pacman -S gst-plugin-pipewire

# 如果之前安装了 PulseAudio，需要移除
sudo pacman -Rns pulseaudio pulseaudio-bluetooth pulseaudio-alsa

# PipeWire 通过 systemd 用户服务自动启动
# 通常不需要手动启用，桌面环境会自动处理

# 手动启用（如果需要）
systemctl --user enable pipewire.service
systemctl --user enable pipewire-pulse.service
systemctl --user enable wireplumber.service

# 启动
systemctl --user start pipewire.service
systemctl --user start pipewire-pulse.service
systemctl --user start wireplumber.service
```

### 25.4.3 验证 PipeWire 运行状态

```bash
# 检查 PipeWire 是否正在运行
systemctl --user status pipewire

# 检查 PipeWire-Pulse 是否正在运行
systemctl --user status pipewire-pulse

# 确认 PulseAudio 接口由 PipeWire 提供
pactl info | grep "Server Name"
# 输出应包含: PulseAudio (on PipeWire x.x.x)

# 检查 JACK 接口
pw-jack jack_lsp

# 查看 PipeWire 版本
pw-cli --version
```

### 25.4.6 WirePlumber 会话管理器

WirePlumber 是 PipeWire 的默认会话管理器，负责设备策略和自动路由。

```bash
# 查看 WirePlumber 状态
wpctl status

# 输出结构：
# Audio
#  ├── Sinks:
#  │       46. Built-in Audio Analog Stereo [vol: 0.80]
#  │      *47. USB Headset Analog Stereo [vol: 0.65]
#  ├── Sources:
#  │      *48. Built-in Audio Analog Stereo [vol: 1.00]
#  ├── Sink endpoints:
#  └── Source endpoints:

# 设置默认 Sink
wpctl set-default <id>

# 音量控制
wpctl set-volume <id> 0.8       # 设置为 80%
wpctl set-volume <id> 0.05+     # 增加 5%
wpctl set-volume <id> 0.05-     # 减少 5%

# 静音
wpctl set-mute <id> toggle

# 查看设备详细信息
wpctl inspect <id>
```

### 25.4.7 低延迟配置

```bash
# PipeWire 默认的缓冲区大小和采样率
# 查看当前配置
pw-metadata -n settings 0

# 修改量子（buffer size）和采样率
# ~/.config/pipewire/pipewire.conf.d/10-lowlatency.conf
```

```
context.properties = {
    default.clock.rate          = 48000
    default.clock.allowed-rates = [ 44100 48000 96000 ]
    default.clock.quantum       = 256
    default.clock.min-quantum   = 32
    default.clock.max-quantum   = 2048
}
```

```bash
# 量子与延迟的关系
# 延迟(ms) = quantum / sample_rate * 1000
# 256 / 48000 * 1000 ≈ 5.3ms
# 128 / 48000 * 1000 ≈ 2.7ms
# 64  / 48000 * 1000 ≈ 1.3ms

# 常见量子设置参考
# 量子   | 延迟     | 适用场景
# 1024   | ~21ms    | 普通桌面使用
# 256    | ~5ms     | 游戏、视频编辑
# 128    | ~2.7ms   | 实时音频监听
# 64     | ~1.3ms   | 专业低延迟录音
# 32     | ~0.7ms   | 极限低延迟（CPU要求高）

# 实时优先级配置（需要 rtkit 或直接 RT 权限）
sudo pacman -S rtkit

# 或手动配置 RT 优先级
# /etc/security/limits.d/99-realtime.conf
```

```
@audio - rtprio 95
@audio - memlock unlimited
@audio - nice -19
```

```bash
# 将用户添加到 audio 组
sudo usermod -aG audio $USER
```

## 25.5 常见问题

### 25.5.1 没有声音的排查步骤

```bash
# 第一步：检查基本状态
# 确认声卡被识别
aplay -l

# 确认 PipeWire 正在运行
systemctl --user status pipewire pipewire-pulse wireplumber

# 第二步：检查音量和静音
# 检查 PipeWire/PulseAudio 音量
wpctl status
pactl list sinks

# 检查 ALSA 音量（底层）
alsamixer
# 确保 Master 和 PCM 未被静音（MM 表示静音）

# 第三步：检查设备选择
# 确认使用了正确的输出设备
wpctl status
# 带 * 号的是当前默认设备

# 第四步：测试音频输出
speaker-test -c 2 -t wav

# 第五步：检查内核日志
dmesg | grep -iE "(snd|audio|sound|codec)"

# 第六步：重启音频服务
systemctl --user restart pipewire pipewire-pulse wireplumber

# 第七步：检查是否有进程独占设备
fuser -v /dev/snd/*
```

### 25.5.2 HDMI 音频

```bash
# HDMI 音频通常由显卡驱动提供
aplay -l | grep HDMI

# 设置默认

# 如果 HDMI 音频不可用

# 确认 enable_hda_codec 参数

# NVIDIA：确认 nvidia-drm 已加载
lsmod | grep nvidia_drm

# AMD：amdgpu 自动处理 HDMI 音频
```

> [!example] 📝 自测题目

> [!question]- 选择题 1：Linux 音频栈的演进顺序正确的是？
> - A. ALSA → OSS → PulseAudio → PipeWire
> - B. OSS → ALSA → PipeWire → PulseAudio
> - C. OSS → ALSA → PulseAudio → PipeWire
> - D. PulseAudio → OSS → ALSA → PipeWire
>
> > [!success]- 点击查看答案
> > **C**
> > Linux 音频栈的演进历程为 OSS (1992) → ALSA (2002) → PulseAudio (2004) → PipeWire (2017)。

> [!question]- 选择题 2：在现代 Arch Linux 中，推荐使用哪个工具来控制音量？
> - A. alsamixer 命令
> - B. wpctl 命令
> - C. pactl 命令
> - D. B 和 C 都可以
>
> > [!success]- 点击查看答案
> > **D**
> > 在 PipeWire 环境下，wpctl（WirePlumber 控制工具）和 pactl（通过 pipewire-pulse 兼容层）都可以用来控制音量。

> [!question]- 选择题 3：PipeWire 中，量子（quantum）为 256、采样率为 48000 Hz 时，延迟约为多少？
> - A. 约 1.3ms
> - B. 约 2.7ms
> - C. 约 5.3ms
> - D. 约 21ms
>
> > [!success]- 点击查看答案
> > **C**
> > 延迟计算公式为 quantum / sample_rate * 1000 = 256 / 48000 * 1000 ≈ 5.3ms。

> [!question]- 选择题 4：WirePlumber 的用户自定义配置目录位于？
> - A. /etc/wireplumber/
> - B. /usr/share/wireplumber/
> - C. ~/.config/wireplumber/
> - D. ~/.local/share/wireplumber/
>
> > [!success]- 点击查看答案
> > **C**
> > WirePlumber 的用户自定义配置位于 ~/.config/wireplumber/，会覆盖 /usr/share/wireplumber/ 中的全局配置。

> [!question]- 判断题 5：PipeWire 只能处理音频流，不能处理视频流。
> - A. ✓ 正确
> - B. ✗ 错误
>
> > [!success]- 点击查看答案
> > **B. ✗ 错误**
> > PipeWire 是统一的多媒体框架，同时处理音频和视频流，这是它区别于 PulseAudio 和 JACK 的重要特性之一。

> [!question]- 判断题 6：在 PipeWire 环境下，所有使用 PulseAudio API 的应用需要修改代码才能工作。
> - A. ✓ 正确
> - B. ✗ 错误
>
> > [!success]- 点击查看答案
> > **B. ✗ 错误**
> > pipewire-pulse 提供了完整的 PulseAudio 兼容接口，所有使用 PulseAudio API 的应用无需修改即可工作。

> [!question]- 选择题 7：查看 ALSA 检测到的声卡列表，应使用哪个命令？
> - A. `lsmod | grep snd`
> - B. `aplay -l`

> - D. B 和 C 都可以
>

> [!question]- 选择题 8：要在 PipeWire 中使用 RNNoise 降噪，需要通过什么机制实现？

> [!question]- 判断题 9：EasyEffects 是一个可以为 PipeWire 提供参数均衡器、压缩器、降噪等功能的工具。
> - A. ✓ 正确
> - B. ✗ 错误
>

> > **A. ✓ 正确**

> [!question]- 选择题 10：在排查"没有声音"的问题时，以下哪一步不属于标准排查流程？
