# 22 - 内核编译与定制

> Linux 内核是操作系统的核心。Arch Linux 默认使用 `linux` 包提供的通用内核，但你完全可以
> 编译自己的定制内核——裁剪不需要的驱动以缩短启动时间，启用特定硬件支持，应用性能补丁，
> 或进行安全加固。本章将详细介绍从源码获取到编译安装的完整流程，以及内核模块开发、调试与调优。

---

## 22.1 Linux 内核源码获取

### 方法一：从 kernel.org 下载

```bash
# 下载最新稳定版
curl -OL https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.12.5.tar.xz
curl -OL https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.12.5.tar.sign

# 验证签名
unxz linux-6.12.5.tar.xz
gpg --locate-keys torvalds@kernel.org
gpg --verify linux-6.12.5.tar.sign linux-6.12.5.tar

# 解压
tar xf linux-6.12.5.tar
cd linux-6.12.5
```

### 方法二：使用 Git

```bash
# 克隆 Linus 的主线仓库（体积大，约 4GB+）
git clone https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git
cd linux

# 或者只克隆特定深度
git clone --depth 1 --branch v6.12.5 \
  https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git
```

### 方法三：使用 Arch 的 PKGBUILD（推荐）

```bash
# 获取 Arch 官方内核的构建脚本
pkgctl repo clone linux
cd linux
```

## 22.2 内核配置

### 配置基础

内核配置保存在源码根目录的 `.config` 文件中。每个选项有三种状态：

| 状态 | 含义 |
|------|------|
| `y` | 编译进内核（built-in） |
| `m` | 编译为可加载模块 |
| `n` | 不编译 |

### 获取初始配置

```bash
# 使用当前运行内核的配置
zcat /proc/config.gz > .config

# 或从 Arch 内核包提取
cp /usr/src/linux/config .config

# 更新配置到新内核版本
make oldconfig         # 逐个询问新选项
make olddefconfig      # 新选项使用默认值
```

### make menuconfig

基于 ncurses 的配置界面，最常用：

```bash
pacman -S ncurses      # 确保依赖已安装
make menuconfig
```

操作方式：

| 按键 | 功能 |
|------|------|
| 方向键 | 导航 |
| Enter | 进入子菜单 |
| Y | 编译进内核 |
| M | 编译为模块 |
| N | 不编译 |
| / | 搜索选项 |
| ? | 查看选项帮助 |
| Esc Esc | 返回上级 |

### make nconfig

基于 ncurses 的增强版界面：

```bash
make nconfig
```

### 其他配置方式

```bash
make xconfig          # Qt 图形界面（需要 qt5-base）
make gconfig          # GTK 图形界面
make localmodconfig   # 仅保留当前已加载的模块
make tinyconfig       # 最小配置（用于嵌入式）
make defconfig        # 默认配置
```

> `make localmodconfig` 特别有用——它根据当前加载的模块自动精简配置，
> 可以大幅缩短编译时间。但在运行前务必先加载你可能需要的所有模块。

## 22.3 配置选项详解

### 文件系统

```
File systems --->
    <*> Ext4                    # ext4 必选
    <*> Btrfs                   # Btrfs（Arch 推荐）
    <*> XFS                     # XFS
    <*> F2FS                    # Flash-Friendly FS（SSD 优化）
    <*> FUSE                    # 用户空间文件系统
    [*] Inotify support         # 文件系统事件通知
    DOS/FAT/EXFAT --->
        <*> VFAT                # U 盘和 EFI 分区
        <*> exFAT               # 大容量 U 盘
```

### 驱动与硬件支持

```
Device Drivers --->
    Graphics support --->
        <M> AMD GPU             # AMD 显卡
        <M> Intel GVT-g         # Intel 集显虚拟化
        <*> Framebuffer         # 通用帧缓冲
    Network device support --->
        Wireless LAN --->
            <M> Intel WiFi      # Intel 无线网卡
    Sound card support --->
        <M> ALSA                # 音频
    USB support --->
        <*> xHCI HCD (USB 3.0) # USB 3.0
    NVMe support --->
        <*> NVM Express         # NVMe SSD
```

### 安全模块

```
Security options --->
    [*] Enable different security models
    [*] AppArmor support
    [*] SELinux support         # 通常与 AppArmor 二选一
    [*] Lockdown (Kernel lockdown feature)
    [*] Restrict unprivileged access to the kernel syslog
```

### 调度器

```
General setup --->
    Preemption Model --->
        (X) Voluntary Kernel Preemption  # 服务器推荐
        ( ) Preemptible Kernel           # 桌面推荐（低延迟）

        [*] Pressure stall information tracking  # PSI（systemd-oomd 需要）
```

### 虚拟化支持

```
Virtualization --->
    <M> KVM for Intel (or AMD)
    [*] KVM (Kernel-based Virtual Machine)

Device Drivers --->
    [*] Virtio drivers
```

## 22.4 编译步骤详解

### 完整编译流程

```bash
# 1. 清理之前的编译产物
make clean
make mrproper          # 彻底清理（包括 .config）

# 2. 配置
zcat /proc/config.gz > .config
make olddefconfig

# 3. 编译内核和模块（-j 指定并行数）
make -j$(nproc)

# 4. 安装模块
sudo make modules_install

# 5. 安装内核
sudo make install

# 6. 复制内核到 /boot
sudo cp arch/x86/boot/bzImage /boot/vmlinuz-linux-custom
sudo cp System.map /boot/System.map-linux-custom

# 7. 生成 initramfs
sudo mkinitcpio -k <内核版本> -g /boot/initramfs-linux-custom.img

# 8. 更新引导程序
sudo grub-mkconfig -o /boot/grub/grub.cfg
# 或者如果使用 systemd-boot：
# 手动创建 /boot/loader/entries/linux-custom.conf
```

### systemd-boot 引导条目

```ini
# /boot/loader/entries/linux-custom.conf
title   Arch Linux (Custom Kernel)
linux   /vmlinuz-linux-custom
initrd  /initramfs-linux-custom.img
options root=PARTUUID=xxxx rw
```

## 22.5 使用 makepkg 编译自定义内核（推荐方式）

在 Arch 上，推荐使用 `makepkg` 将内核打包为 pacman 包，便于管理。

### 获取官方 PKGBUILD

```bash
pkgctl repo clone linux
cd linux
```

### 目录结构

```
linux/
├── PKGBUILD
├── config          # 内核配置文件
└── *.patch         # 补丁文件（如果有）
```

### 修改 PKGBUILD

编辑 `PKGBUILD`，修改包名以避免与官方包冲突：

```bash
# 修改 pkgbase
pkgbase=linux-custom

# 修改 pkgver（如果使用不同版本）
# pkgver=6.12.5
```

### 编译

```bash
# 更新校验和（如果修改了源）
updpkgsums

# 编译（可能需要数小时）
makepkg -s

# 安装
sudo pacman -U linux-custom-*.pkg.tar.zst linux-custom-headers-*.pkg.tar.zst
```

### 加速编译

在 `/etc/makepkg.conf` 中调整：

```bash
MAKEFLAGS="-j$(nproc)"
COMPRESSZST=(zstd -c -T0 -)
BUILDDIR=/tmp/makepkg       # 使用 tmpfs 加速（需要足够内存）
```

## 22.6 修改 PKGBUILD 定制内核

### 自定义配置

在 `prepare()` 函数中添加配置修改：

```bash
prepare() {
    cd $_srcname

    # 应用所有补丁
    local src
    for src in "${source[@]}"; do
        src="${src%%::*}"
        src="${src##*/}"
        [[ $src = *.patch ]] || continue
        echo "Applying patch $src..."
        patch -Np1 < "../$src"
    done

    # 加载配置
    cp ../config .config

    # 使用脚本批量修改配置
    scripts/config --enable CONFIG_BTRFS_FS
    scripts/config --disable CONFIG_BLUETOOTH
    scripts/config --set-str CONFIG_LOCALVERSION "-custom"
    scripts/config --module CONFIG_DRM_AMDGPU

    # 设置编译优化
    scripts/config --set-val CONFIG_NR_CPUS 16

    make olddefconfig
    diff -u ../config .config || :
}
```

### 使用 scripts/config 常用操作

```bash
scripts/config --enable CONFIG_XXX     # 设为 y
scripts/config --disable CONFIG_XXX    # 设为 n
scripts/config --module CONFIG_XXX     # 设为 m
scripts/config --set-val CONFIG_XXX 64 # 设为数值
scripts/config --set-str CONFIG_XXX "value"  # 设为字符串
scripts/config --undefine CONFIG_XXX   # 删除选项
```

## 22.7 打补丁

### 补丁格式

内核补丁通常为 unified diff 格式：

```diff
--- a/kernel/sched/fair.c
+++ b/kernel/sched/fair.c
@@ -100,6 +100,7 @@
 static void update_curr(struct cfs_rq *cfs_rq)
 {
+    /* 补丁内容 */
     struct sched_entity *curr = cfs_rq->curr;
```

### 应用补丁

```bash
# 在内核源码目录中
patch -Np1 < /path/to/patch.patch

# 反转补丁
patch -Rp1 < /path/to/patch.patch

# 测试补丁（不实际应用）
patch -Np1 --dry-run < /path/to/patch.patch
```

### 在 PKGBUILD 中添加补丁

```bash
source=(
    "https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-${pkgver}.tar.xz"
    "config"
    "0001-my-custom-patch.patch"
    "0002-another-patch.patch"
)

sha256sums=(
    'xxx...'
    'xxx...'
    'xxx...'
    'xxx...'
)
```

### 常见第三方补丁集

| 补丁集 | 说明 |
|-------|------|
| `linux-zen` | 桌面优化，已有 Arch 包 |
| `linux-hardened` | 安全加固，已有 Arch 包 |
| `linux-lts` | 长期支持，已有 Arch 包 |
| `CachyOS patches` | 包含 BORE 调度器等优化 |
| `Xanmod` | 桌面/游戏优化 |
| `Clear Linux patches` | Intel 性能优化 |
| `graysky cpu optimization` | -march=native 支持 |

## 22.8 内核模块编写入门

### Hello World 模块

创建 `hello.c`：

```c
#include <linux/init.h>
#include <linux/module.h>
#include <linux/kernel.h>

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Your Name");
MODULE_DESCRIPTION("A simple hello world module");
MODULE_VERSION("1.0");

static int __init hello_init(void)
{
    pr_info("Hello, kernel!\n");
    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Goodbye, kernel!\n");
}

module_init(hello_init);
module_exit(hello_exit);
```

### Makefile

```makefile
obj-m += hello.o

KDIR := /lib/modules/$(shell uname -r)/build

all:
	make -C $(KDIR) M=$(PWD) modules

clean:
	make -C $(KDIR) M=$(PWD) clean
```

### 编译和测试

```bash
# 安装内核头文件
pacman -S linux-headers

# 编译
make

# 加载模块
sudo insmod hello.ko

# 查看内核日志
dmesg | tail

# 查看已加载模块
lsmod | grep hello

# 卸载模块
sudo rmmod hello
```

### 带参数的模块

```c
#include <linux/init.h>
#include <linux/module.h>
#include <linux/moduleparam.h>

static int count = 1;
static char *name = "world";

module_param(count, int, 0644);
MODULE_PARM_DESC(count, "Number of greetings");
module_param(name, charp, 0644);
MODULE_PARM_DESC(name, "Name to greet");

static int __init hello_init(void)
{
    int i;
    for (i = 0; i < count; i++)
        pr_info("Hello, %s!\n", name);
    return 0;
}

static void __exit hello_exit(void)
{
    pr_info("Goodbye!\n");
}

module_init(hello_init);
module_exit(hello_exit);
MODULE_LICENSE("GPL");
```

```bash
sudo insmod hello.ko count=3 name="Arch"
```

## 22.9 DKMS 动态内核模块

DKMS（Dynamic Kernel Module Support）可以在内核更新时自动重新编译外部模块。

```bash
pacman -S dkms
```

### DKMS 配置

创建 `/usr/src/hello-1.0/dkms.conf`：

```ini
PACKAGE_NAME="hello"
PACKAGE_VERSION="1.0"
BUILT_MODULE_NAME[0]="hello"
DEST_MODULE_LOCATION[0]="/kernel/drivers/misc"
AUTOINSTALL="yes"
MAKE[0]="make -C ${kernel_source_dir} M=${dkms_tree}/${PACKAGE_NAME}/${PACKAGE_VERSION}/build modules"
CLEAN="make -C ${kernel_source_dir} M=${dkms_tree}/${PACKAGE_NAME}/${PACKAGE_VERSION}/build clean"
```

将源码和 Makefile 放入 `/usr/src/hello-1.0/`。

```bash
# 添加模块到 DKMS
sudo dkms add hello/1.0

# 编译
sudo dkms build hello/1.0

# 安装
sudo dkms install hello/1.0

# 查看状态
dkms status

# 卸载
sudo dkms remove hello/1.0 --all
```

## 22.11 内核调试

### ftrace

```bash
# 挂载 tracefs（通常已自动挂载）
mount -t tracefs tracefs /sys/kernel/tracing

# 查看可用追踪器
cat /sys/kernel/tracing/available_tracers

# 启用函数追踪
echo function > /sys/kernel/tracing/current_tracer
echo 1 > /sys/kernel/tracing/tracing_on

# 过滤特定函数
echo 'schedule' > /sys/kernel/tracing/set_ftrace_filter

# 查看追踪结果
cat /sys/kernel/tracing/trace

# 停止追踪
echo 0 > /sys/kernel/tracing/tracing_on
echo nop > /sys/kernel/tracing/current_tracer
```

### 使用 trace-cmd 简化操作

```bash
pacman -S trace-cmd

# 记录
trace-cmd record -p function_graph -g do_sys_open
# 停止后查看
trace-cmd report
```

### kprobe

```bash
# 在 sys_openat 上设置探针
echo 'p:myprobe do_sys_openat2 dfd=%di filename=%si' > \
  /sys/kernel/tracing/kprobe_events

echo 1 > /sys/kernel/tracing/events/kprobes/myprobe/enable
cat /sys/kernel/tracing/trace

# 清理
echo 0 > /sys/kernel/tracing/events/kprobes/myprobe/enable
echo '-:myprobe' > /sys/kernel/tracing/kprobe_events
```

### perf

```bash
pacman -S perf

# CPU 性能分析
perf stat ls
perf record -g ./my_program
perf report

# 内核函数热点
perf top

# 追踪系统调用
perf trace ls

# 硬件计数器
perf stat -e cache-misses,cache-references,instructions,cycles ./my_program
```

### eBPF / bpftrace

```bash
pacman -S bpftrace

# 追踪 open 系统调用
bpftrace -e 'tracepoint:syscalls:sys_enter_openat { printf("%s %s\n", comm, str(args->filename)); }'

# 追踪进程创建
bpftrace -e 'tracepoint:sched:sched_process_exec { printf("exec: %s (pid=%d)\n", comm, pid); }'

# 统计系统调用
bpftrace -e 'tracepoint:raw_syscalls:sys_enter { @[comm] = count(); }'
```

## 22.12 编译优化

### -march=native

为当前 CPU 微架构优化，可获得 5-15% 的性能提升。

在 PKGBUILD 中修改：

```bash
# 方法一：使用 graysky 的 CPU 优化补丁
# 下载 kernel_compiler_patch 并应用

# 方法二：在 .config 中直接设置
scripts/config --disable CONFIG_GENERIC_CPU
scripts/config --enable CONFIG_MNATIVE_AMD    # AMD CPU
scripts/config --enable CONFIG_MNATIVE_INTEL   # Intel CPU
```

或者在 `/etc/makepkg.conf` 中全局设置：

```bash
CFLAGS="-march=native -O2 -pipe -fno-plt -fexceptions"
CXXFLAGS="$CFLAGS -Wp,-D_GLIBCXX_ASSERTIONS"
```

### LTO（Link-Time Optimization）

```bash
# 在内核配置中启用
scripts/config --enable CONFIG_LTO_CLANG_THIN  # 使用 Clang Thin LTO

# 需要 Clang 编译器
make LLVM=1 -j$(nproc)
```

LTO 模式比较：

| 模式 | 说明 |
|------|------|
| `CONFIG_LTO_NONE` | 不使用 LTO |
| `CONFIG_LTO_CLANG_FULL` | 完全 LTO，编译最慢，优化最好 |
| `CONFIG_LTO_CLANG_THIN` | Thin LTO，编译较快，优化接近 Full |

### PGO（Profile-Guided Optimization）

```bash
# 1. 用 profiling 配置编译内核
scripts/config --enable CONFIG_PGO_CLANG

# 2. 安装并启动 PGO 内核
# 3. 运行典型工作负载收集 profile 数据
# 4. 收集数据
cp /sys/kernel/debug/pgo/profraw vmlinux.profraw

# 5. 处理数据
llvm-profdata merge -o vmlinux.profdata vmlinux.profraw

# 6. 用 profile 数据重新编译
make LLVM=1 KCFLAGS=-fprofile-use=vmlinux.profdata -j$(nproc)
```

### 使用 Clang/LLVM 编译

```bash
make LLVM=1 -j$(nproc)

# 或指定 Clang 版本
make LLVM=1 CC=clang-17 LD=ld.lld-17 -j$(nproc)
```

## 22.13 内核安全加固

### Kernel Lockdown

```bash
# 启用 lockdown
scripts/config --enable CONFIG_SECURITY_LOCKDOWN_LSM
scripts/config --enable CONFIG_SECURITY_LOCKDOWN_LSM_EARLY
scripts/config --set-str CONFIG_LOCK_DOWN_KERNEL_FORCE_CONFIDENTIALITY y

# 通过内核参数启用
# lockdown=integrity     阻止修改内核
# lockdown=confidentiality  阻止读取内核信息
```

### kASLR（内核地址空间布局随机化）

```bash
scripts/config --enable CONFIG_RANDOMIZE_BASE
scripts/config --enable CONFIG_RANDOMIZE_MEMORY
```

默认已启用。可通过内核参数 `nokaslr` 禁用（调试时使用）。

### seccomp

```bash
scripts/config --enable CONFIG_SECCOMP
scripts/config --enable CONFIG_SECCOMP_FILTER
```

seccomp 允许进程限制自身可使用的系统调用，被 systemd、容器运行时等广泛使用。

### 其他安全选项

```bash
# 栈保护
scripts/config --enable CONFIG_STACKPROTECTOR
scripts/config --enable CONFIG_STACKPROTECTOR_STRONG

# 使用后释放检测
scripts/config --enable CONFIG_SLAB_FREELIST_HARDENED
scripts/config --enable CONFIG_SLAB_FREELIST_RANDOM

# 初始化栈变量
scripts/config --enable CONFIG_INIT_STACK_ALL_ZERO

# 控制流完整性（CFI）
scripts/config --enable CONFIG_CFI_CLANG

# 内核模块签名
scripts/config --enable CONFIG_MODULE_SIG
scripts/config --enable CONFIG_MODULE_SIG_FORCE
scripts/config --enable CONFIG_MODULE_SIG_SHA512

# 限制 userfaultfd
scripts/config --set-val CONFIG_USERFAULTFD_UNPRIVILEGED 0

# 禁止非特权用户使用 BPF
scripts/config --enable CONFIG_BPF_UNPRIV_DEFAULT_OFF
```

### 内核命令行安全参数

在引导加载器配置中添加：

```
init_on_alloc=1 init_on_free=1 slab_nomerge
page_alloc.shuffle=1 randomize_kstack_offset=on
vsyscall=none debugfs=off
```

## 22.14 总结：自定义内核工作流

完整的 Arch Linux 自定义内核工作流：

```bash
# 1. 克隆官方 PKGBUILD
pkgctl repo clone linux
cd linux

# 2. 修改 pkgbase
sed -i 's/pkgbase=linux/pkgbase=linux-custom/' PKGBUILD

# 3. 编辑配置
cp config config.bak
# 使用 scripts/config 或 make menuconfig 修改

# 4. 添加补丁（如需要）
cp /path/to/patches/*.patch .
# 在 PKGBUILD 的 source 数组中添加补丁文件

# 5. 更新校验和
updpkgsums

# 6. 编译
makepkg -s

# 7. 安装
sudo pacman -U linux-custom-*.pkg.tar.zst linux-custom-headers-*.pkg.tar.zst

# 8. 更新引导（自动通过 pacman hooks）
# 或手动添加引导条目

# 9. 重启测试
reboot
```

> 建议保留官方 `linux` 包作为后备，在自定义内核出问题时可以通过引导菜单切换。

> [!example] 📝 自测题目

> [!question]- 选择题 1：内核配置中，选项状态 `m` 表示什么？
> - A. 不编译该功能
> - B. 编译进内核（built-in）
> - C. 编译为可加载模块
> - D. 标记为实验性
>
> > [!success]- 点击查看答案
> > **C**
> > `m` 表示将该功能编译为可加载内核模块（.ko 文件），需要时动态加载；`y` 是编译进内核；`n` 是不编译。

> [!question]- 选择题 2：`make localmodconfig` 的作用是什么？
> - A. 使用最小配置
> - B. 仅保留当前已加载的模块配置
> - C. 恢复默认配置
> - D. 从 /proc/config.gz 导入配置
>
> > [!success]- 点击查看答案
> > **B**
> > `make localmodconfig` 根据当前系统已加载的模块自动精简配置，只保留实际使用的模块，可以大幅缩短编译时间。

> [!question]- 选择题 3：在 Arch Linux 上推荐的自定义内核编译方式是？
> - A. 直接 make install 安装到系统
> - B. 使用 makepkg 打包为 pacman 包
> - C. 使用 dpkg 打包为 deb 包
> - D. 手动复制文件到 /boot
>
> > [!success]- 点击查看答案
> > **B**
> > 在 Arch 上推荐使用 makepkg 将内核打包为 pacman 包（.pkg.tar.zst），便于通过 pacman 管理、升级和卸载。

> [!question]- 判断题 4：DKMS 的作用是在内核更新时自动重新编译外部模块
> - A. ✓ 正确
> - B. ✗ 错误
>
> > [!success]- 点击查看答案
> > **A. ✓ 正确**
> > DKMS（Dynamic Kernel Module Support）会在内核升级时自动为新内核重新编译注册的外部模块，避免手动操作。

> [!question]- 选择题 5：以下哪个不是内核安全加固选项？
> - A. CONFIG_STACKPROTECTOR_STRONG
> - B. CONFIG_RANDOMIZE_BASE（kASLR）
> - C. CONFIG_PREEMPT（抢占式内核）
> - D. CONFIG_MODULE_SIG_FORCE
>
> > [!success]- 点击查看答案
> > **C**
> > CONFIG_PREEMPT 是调度相关选项（可抢占内核，降低延迟），不是安全加固选项。其他三项分别是栈保护、地址空间随机化和强制模块签名。

> [!question]- 选择题 6：使用 Clang/LLVM 编译内核的命令参数是？
> - A. make CC=clang
> - B. make LLVM=1
> - C. make COMPILER=llvm
> - D. make USE_CLANG=yes
>
> > [!success]- 点击查看答案
> > **B**
> > `make LLVM=1` 是使用 Clang/LLVM 工具链编译内核的标准参数，它会将 CC、LD 等全部切换为 LLVM 工具。

> [!question]- 判断题 7：`make mrproper` 只清理编译产物，不会删除 .config 文件
> - A. ✓ 正确
> - B. ✗ 错误
>
> > [!success]- 点击查看答案
> > **B. ✗ 错误**
> > `make mrproper` 是彻底清理，包括 .config 文件。只清理编译产物而保留配置应使用 `make clean`。

> [!question]- 选择题 8：sysctl 配置文件应放在哪个目录以实现永久生效？
> - A. /proc/sys/
> - B. /etc/sysctl.d/
> - C. /sys/kernel/
> - D. /usr/lib/sysctl/
>
> > [!success]- 点击查看答案
> > **B**
> > 在 /etc/sysctl.d/ 下创建 .conf 文件可以持久化内核参数配置，系统启动时自动应用。

> [!question]- 选择题 9：以下哪个工具用于内核函数级别的性能分析？
> - A. htop
> - B. perf
> - C. systemd-analyze
> - D. strace
>
> > [!success]- 点击查看答案
> > **B**
> > perf 是 Linux 内核自带的性能分析工具，支持 CPU 热点分析、函数追踪、硬件计数器统计等内核级性能调优功能。

> [!question]- 判断题 10：LTO（Link-Time Optimization）可以在链接阶段进行跨编译单元的优化，但需要使用 Clang 编译器
> - A. ✓ 正确
> - B. ✗ 错误
>
> > [!success]- 点击查看答案
> > **A. ✓ 正确**
