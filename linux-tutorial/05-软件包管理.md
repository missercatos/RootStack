# 05 - 软件包管理

---

## 5.1 pacman 常用操作

```bash
# 同步并更新
sudo pacman -Syu                # 同步数据库 + 升级所有

# 安装
sudo pacman -S firefox          # 安装单个
sudo pacman -S --needed git vim base-devel    # 跳过已安装的
sudo pacman -S gnome            # 安装组

# 卸载
sudo pacman -R firefox          # 仅卸载包
sudo pacman -Rs firefox         # 卸载 + 无用的依赖
sudo pacman -Rns firefox        # 卸载 + 依赖 + 配置文件

# 搜索
pacman -Ss "web browser"        # 搜索仓库
pacman -Qs firefox              # 搜索已安装的
pacman -Qi firefox              # 包详细信息
pacman -Ql firefox              # 列出包内所有文件

# 清理
sudo pacman -Scc                # 清理所有缓存（小心）
sudo pacman -Sc                 # 保留当前版本
paccache -rk1                   # 保留最近1版（需安装 pacman-contrib）

# 查找某个文件属于哪个包
pacman -F filename
pacman -F /usr/bin/bash         # → core/bash

# 孤立包（不再被任何包依赖）
pacman -Qdt                     # 列出
sudo pacman -Rns $(pacman -Qdtq) # 清理（谨慎确认）
```

## 5.2 pacman 配置文件

```ini
# /etc/pacman.conf
[options]
ParallelDownloads = 5           # 并行下载
Color                           # 彩色输出
ILoveCandy                      # 好玩的进度条动画
VerbosePkgLists                 # 详细包列表

[core]
[extra]
[multilib]                      # 32位支持（取消注释）
Include = /etc/pacman.d/mirrorlist
```

## 5.3 镜像源管理

```bash
# 安装 reflector
sudo pacman -S reflector

# 按速度自动排序（推荐中国区）
sudo reflector --country China --age 12 --protocol https --sort rate --save /etc/pacman.d/mirrorlist

# 或手动编辑 /etc/pacman.d/mirrorlist 调整顺序
```

## 5.4 AUR（Arch User Repository）

### 安装 AUR 助手

```bash
# 推荐 paru（Rust 写，快速）
sudo pacman -S --needed git base-devel
git clone https://aur.archlinux.org/paru.git
cd paru
makepkg -si

# 或者 yay（Go 写，流行多年）
git clone https://aur.archlinux.org/yay.git
cd yay
makepkg -si
```

### 使用

```bash
# paru ≈ pacman + AUR
paru -S google-chrome
paru -Syu                       # 更新所有（含 AUR）
paru -Ss rust                   # 搜索（含 AUR）
paru -Qm                        # 列出 AUR 安装的包

# 清理不需要的 AUR 依赖
paru -c
```

## 5.5 PKGBUILD 编写

```bash
# PKGBUILD 示例 — 适用于简单的 GitHub 项目
# Maintainer: Your Name <email@example.com>
pkgname=my-custom-app
pkgver=1.0.0
pkgrel=1
pkgdesc="My custom application"
arch=('x86_64')
url="https://github.com/user/my-app"
license=('MIT')
depends=('python' 'gtk3')
makedepends=('git' 'go')
source=("git+https://github.com/user/my-app.git#tag=v${pkgver}")
sha256sums=('SKIP')                        # 或 sha512sums / b2sums

build() {
    cd "${srcdir}/${pkgname}"
    make
}

package() {
    cd "${srcdir}/${pkgname}"
    make DESTDIR="${pkgdir}" install
}
```

```bash
# 构建与安装
makepkg -si             # 构建并安装（自动处理依赖）
makepkg -s              # 仅构建（处理依赖）
makepkg --printsrcinfo > .SRCINFO    # 生成源信息（推送 AUR 需要）
```

## 5.6 pacman vs AUR 区别

| | pacman | AUR |
|------|--------|-----|
| 来源 | Arch 官方仓库 | 用户社区提交 |
| 类型 | 编译好的二进制包 | PKGBUILD 脚本 + 源码 |
| 可信度 | 官方签名验证 | 需要自行审查 |
| 安装 | `pacman -S` | `makepkg -si` / `paru -S` |
| 更新 | `pacman -Syu` | `paru -Syu` |

## 5.7 源码编译安装

```bash
# 传统三步曲（非 Arch 包管理系统下的方法）
git clone https://github.com/example/project.git
cd project

# 用 configure 的
./configure --prefix=/usr/local
make
sudo make install

# 用 CMake 的
mkdir build && cd build
cmake ..
make
sudo make install

# 用 Meson 的
meson setup build
ninja -C build
sudo ninja -C build install
```

## 5.8 常见考题

1. pacman 和 apt 的区别？ → pacman 是 Arch 的包管理器，apt 是 Debian 的；命令不同，格式也不同（`tar.zst` vs `deb`）
2. `-S` vs `-Q` 的区别？ → `-S` 操作远程仓库（sync），`-Q` 查询本地数据库（query）
3. 怎样完全卸载一个包及其配置？ → `pacman -Rns pkgname`
4. AUR 安全吗？ → 需要自行审查 PKGBUILD，它由社区维护无官方保证
5. `make -j$(nproc)` 什么用？ → 并行编译，加速构建

> [!example] 📝 自测题目

> [!question]- 选择题 1：`pacman -Syu` 中三个参数分别表示？
> - A. 搜索、更新、确认
> - B. 同步数据库、刷新、升级所有包
> - C. 安装、卸载、更新
> - D. 同步、忽略、强制
>
> > [!success]- 点击查看答案
> > **B**
> > `-S` 同步操作，`-y` 刷新包数据库，`-u` 升级所有可更新的包

> [!question]- 选择题 2：完全卸载一个包及其依赖和配置文件应使用？
> - A. `pacman -R pkgname`
> - B. `pacman -Rs pkgname`
> - C. `pacman -Rns pkgname`
> - D. `pacman -Rd pkgname`
>
> > [!success]- 点击查看答案
> > **C**
> > `-R` 卸载，`-s` 移除不再需要的依赖，`-n` 删除配置文件

> [!question]- 判断题 3：AUR 中的包经过 Arch 官方审查和签名验证
> - A. ✓ 正确
> - B. ✗ 错误
>
> > [!success]- 点击查看答案
> > **B. ✗ 错误**
> > AUR 是用户社区维护的，包不经过官方审查，使用前应自行检查 PKGBUILD

> [!question]- 选择题 4：查找 `/usr/bin/bash` 属于哪个包应使用？
> - A. `pacman -Qi bash`
> - B. `pacman -F /usr/bin/bash`
> - C. `pacman -Ss bash`
> - D. `pacman -Ql bash`
>
> > [!success]- 点击查看答案
> > **B**
> > `-F` 用于在文件数据库中查找某个文件属于哪个包

> [!question]- 判断题 5：`pacman -Qdt` 列出的是没有被任何包依赖的孤立包
> - A. ✓ 正确
> - B. ✗ 错误
>
> > [!success]- 点击查看答案
> > **A. ✓ 正确**
> > `-Q` 查询本地，`-d` 作为依赖安装的，`-t` 不再被需要的，组合起来就是孤立包

> [!question]- 选择题 6：`makepkg -si` 中 `-i` 的作用是？
> - A. 忽略错误
> - B. 构建后自动安装
> - C. 交互模式
> - D. 增量构建
>
> > [!success]- 点击查看答案
> > **B**
> > `-s` 自动安装构建依赖，`-i` 构建完成后自动安装生成的包

> [!question]- 选择题 7：在 `/etc/pacman.conf` 中启用 32 位支持应取消注释哪个仓库？
> - A. `[core]`
> - B. `[extra]`
> - C. `[multilib]`
> - D. `[community]`
>
> > [!success]- 点击查看答案
> > **C**
> > `[multilib]` 仓库提供 32 位兼容库，默认被注释，需手动启用

> [!question]- 判断题 8：`pacman -Sc` 会删除缓存中所有版本的包文件
> - A. ✓ 正确
> - B. ✗ 错误
>
> > [!success]- 点击查看答案
> > **B. ✗ 错误**
> > `-Sc` 只删除不再安装的包的缓存，`-Scc` 才会清除所有缓存

> [!question]- 选择题 9：PKGBUILD 中 `depends` 字段的用途是？
> - A. 定义构建时依赖
> - B. 定义运行时依赖
> - C. 定义可选依赖
> - D. 定义冲突的包
>
> > [!success]- 点击查看答案
> > **B**
> > `depends` 是运行时依赖，`makedepends` 是构建时依赖，`optdepends` 是可选依赖

> [!question]- 判断题 10：`reflector` 工具可以根据速度自动排序 pacman 镜像源
> - A. ✓ 正确
> - B. ✗ 错误
>
> > [!success]- 点击查看答案
> > **A. ✓ 正确**
> > reflector 可以按国家、协议、速度等条件筛选和排序镜像源并写入 mirrorlist
