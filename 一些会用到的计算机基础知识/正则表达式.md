#### 关于其定义
上面说过了，正则表达式是处理工具。但并没有一种指定的叫作正则表达式的工具，而是一种类型，我们可以说是正则工具。
比如在GNU工具链中，常见的工具比如
* 文本搜索grep
* 流编辑器sed
* 数据处理awk
* 搜索工具rg
* 包管理器，pacman ,apt ,dnf等等
在本质上，我更愿意将其定义为一类语言，是一套描述文本模式的”微型语言“
通称为正则语言。
正则语言是语法的标准模板，其用不同方言，且支持的工具不同。
#### 一些常见的方言和支持工具
| 方言                | 工具                |

在一些终端工具里，支持使用正则语法来实现更加复杂的功能

#### 一些基础的语法(大概吧)
首先来一个最最最最最基本的示例
```perl
^[0-9]+abc$
```
用人话来说，这是一个以数字开头，并且以abc结尾的字符串
为什么这样解释呢。
从定义来看
^是脱字符，代表行首，要求后面的内容必须从该位置开始，简单来说就是从这个符号之后位置开始检索，^之后的就是作为字符串的第一个字符
[ 0-9 ]是上一个说过的，数字0-9，但是鉴于单个数字字符只有0到9，所以这里就是数字开头的意思
+是一个量词，代表一次或多次，所以[0-9]+的意思就是说必须有一个或者多个数字。
abc就是普通的字面量，abc三个连在一起的字母
$代表末尾，意味着检索的字符串到这里结束

```bash
echo -e "1abc\n2abc\n23abc\nc1abc\n123abc" | perl -ne 'print if /^[0-9]+abc$/'
```
最后的输出结果
应该是
```bash
1abc
2abc
23abc
123abc
```
而没有c1abc,因为其不满足数字开头
实际上，可以用一些更加简单的匹配语法来实现简单的书写来完成复杂的事情

```bash
\d          数字字符     [0-9]
\w          字母，数字，下划线 [a-zA-Z0-9_] 
\s          空格,Tab,换行符    [ \t\n\r\f]
\D          非数字             [^0-9]
\W          非字母，数字，下划线  [^a-zA-Z0-9_]
\S          非空白字符          [^ \t\n\r\f]
.           任意字符（除换行符)
```
那么语法可以这么写东西
```perl
^\d+abc$
```

/i 忽略大小写

```bash
echo -e "error\nError\nERROR" | prel -ne 'print if /error/i'
```

/m 多行模式
比如
```bash
echo -e "Start\nMiddle\nEnd" | perl -0777 -ne 'print "$&\n"if /^End$/m'
```
最后输出只有End
如果没有"$&\n"则三行都输出，如果没有/m则没有输出
"$&"是按照行输出，\n是换行，因为perl -ne是默认的按行检索，所以待检索文本有\n会默认执行，所以要用-0777强制默认为整体字符串

/s单行模式
```bash
echo -e "Start\nMiddle\nEnd" | perl -0777 -ne 'print /Start.Middle.End/s' 
```
输出结果是
Start
Middle
End
可以让.能跨越跨行符去匹配



/g全局匹配
比如
```bash
echo "apple 123, banana 45,cherry 789" | perl -ne 'if (/(\d+)/){print "找到: $1\n";}'
```
输出结果是
找到：123
加上/g之后则会是这样的
```bash
echo "apple 123, banana 45,cherry 789" | perl -ne 'while (/(\d+)/g){print"找到:$1\n";}'
``` 
结果是
找到：123
找到：45
找到：789

在一般的匹配中，在找到一个符合条件的就会停止。而在全局匹配中，则会文本里所有符合条件的全找出来。

实际上也可以替换使用


##### 一些不算通用，但是有些语言会有的。 
/u Unicode模式
该修饰符通常用于解决的是正则引擎的转换问题。在原先的ASCII下，读取每串字符串其实是读取的字节流，而在Unicode模式下则为直接读取字符。解决了处理中文还有日文，emoji表情等时候的转换问题
然而在现代的虚拟机语音和现代操作系统下，比如java,python等，其自身便是Unicode模式，因此可以不用特意去写
在JS，PHP中需要去写。而在Perl下，则需要用-C开启而不是使用/u修饰符。
这里用JS来演示
```javascript
console.log("你好".match(/^.$/));    //中文测试
console.log("你好".match(/^.$/u)); //这里字符长度还是2,不会因为使用Unicode模式而改变，只是正则引擎能识别了
//emoji测试
console.log("🐱".match(/^.$/));     // null（🐱 在 JS 里算 2 个字节长度）
console.log("🐱".match(/^.$/u));    // ['🐱']（成功匹配）
```
因为JS默认是使用ASCII的，不是Unicode，对于中文，emoji这样单个字符占两个字节长度的单位特别不友好。因此需要特意开启Unicode模式，否则会出现无法识别的乱码，在windows7下常见的错误文件内容”锟斤拷“就是大致如此的原因之一。

在Python,java下则是默认的Unicode模式，想关闭需要自行关闭。但是一般不会推荐。在实际使用中，Unicode比ASCII更加通用。即使在引擎匹配上，查询庞大的Unicode表，速度会比ASCII慢一点点，但是在现代硬件使用上几乎无感

/x扩展模式 ，可以写注释
可以忽略模式中的空白和注释，使得表达式更易读
```bash
# 测试数据：2023-10-01
echo "2023-10-01" | perl -ne 'print "匹配成功\n" if /
    ^\d{4}   # 匹配 4 位年份
    -        # 匹配横杠
    \d{2}    # 匹配 2 位月份
    -        # 匹配横杠
    \d{2}    # 匹配 2 位日期
    $        # 结束
/x'
```
如果不加 `/x`，正则引擎会把代码里的空格和缩进当成真的空格去匹配文本，直接报错匹配不到

/y 黏性匹配。
要求匹配必须死死黏住正则引擎的起始位置，不许往后挪
这个修饰符是ES6(js)独有的。
```javascript
node -e '
let str = "a1 b2 c3";
let regexG = /\d/g;
let regexY = /\d/y;

console.log("--- 测试 /g (全局) ---");
console.log(regexG.exec(str)); // ["1"] (找到了 1)
console.log(regexG.exec(str)); // ["2"] (1后面没匹配，跳过空格找 2)
console.log(regexG.exec(str)); // ["3"]

console.log("--- 测试 /y (粘性) ---");
console.log(regexY.exec(str)); // ["1"] (第一个字符是 a，不匹配 \d，居然匹配上了？？)
```
第一次会返回 null。因为粘性匹配要求第 0 个位置必须匹配，而 `a` 不是数字。
```javascript
node -e '
let code = "const x = 10; let y = 20;";
let regex = /\s*(\w+)/y; // 匹配单词，忽略前面的空格

let match;
while ((match = regex.exec(code)) !== null) {
    console.log("解析到关键字/变量:", match[1]);
}
'
```
结果：
```txt
解析到关键字/变量: const
解析到关键字/变量: x
解析到关键字/变量: 10
```
因为在写代码解析器时，如果当前这里应该是个变量名，但遇到了个奇怪的符号，解析器应该立刻报错，而不是用 /g 越过那个奇怪符号去后面找变量。/y 保证了数据在当前位置的严格连续性
所以必须用/y

/x 如果说是为了人类的可读行，那么/y就是为了高频解析，词法分析的场景，严格卡位，绝不越位查找。
其实在更通用的语言上，编译器有更好的解决办法，人类手动用/y模式编写机器可读码显然更加麻烦。
Python的re模块，match()天然支持黏度，pattern.match更是指定坐标的黏性
在JS上/y并没有被淘汰，在一些场景下仍然不得不使用

#### 一些元字符，用于控制匹配模式
正则表达式内的元字符，指的就是具备特殊含义的字符，它们不表示字面意义，只用于控制匹配模式

##### 基本元字符
. 点号 
匹配除换行符的任意单个字符 
^脱字符
匹配字符串开始的位置 
$ 美元符号 
匹配结束的位置
\ 反斜杠 
转义字符，使后面的字符失去特殊含义 
比如\ . 就是单纯代指点好而不是任意单个字符 
##### 字符类元字符 
[] 方括号
定义字符集合，匹配其中任意一个字符 
比如[aeiou] 匹配任意一个元音字母 
[^] 否定字符类
^实在括号内部的，在外部就是开头的意思。
匹配不在方括号内的任意字符
[^0-9]匹配任意非数字字符
 “-” 连字符 
在字符类中表示范围
比如[a-z]匹配任意小写字母

##### 量词元字符 
”* “星号
匹配前面的子表达式零次或多次 
比如ab* c 可以匹配 ac abc abbc 

"+"加号
匹配前面的子表达式一次或多次
比如ab+c 可以匹配 abc abbc 而不匹配ac ,因为b+要求b必须出现至少一次

“？”问号
匹配前面的表达式零次或一次
ab?c匹配 abc ac

{n}花括号
精确匹配n次
比如a{3}匹配的就是aaa

{n,}就是至少n次，{n,m}就是匹配n到m次

##### 分组和选择元字符 
（）圆括号
定义子表达式或者捕获组
(ab)+匹配的是ab abab 把ab定义为一个整体，被+所作用
（：）捕获组，分组并记录
(?:)则是非捕获组，就是只分组不记录。
平时我们用 `()` 分组时，引擎不仅会把括号里的内容当个整体，还会 偷偷把匹配到的内容存进 `$1`、`$2` 里。如果你只是为了加个量词或者用 `|` 划范围，根本不需要提取它，这就白白浪费了内存。
零宽匹配，只检查后面有没有，不消耗字符

| 竖线
表示或的关系
比如 dog|cat 匹配的是cat或者dog

##### 特殊字符类元字符(大部分前面提到过)
\d 匹配任意数字
\D 匹配任意非数字
\w 匹配任意单词字符
\W 匹配任意非单词字符 
\s 匹配任意空白字符 
\S 匹配任意非空白字符 
##### 边界匹配元字符 
\b 匹配单词边界
比如\bcat\b匹配到的cat 但是匹配不到cateory
\B 匹配非单词边界
比如\Bcat\B匹配的到scate但是匹配不到cat
简单来说，就是\b会限制，而\B就是\b相反的情况

##### 其他元字符(在其他语言学习中刚开始就遇见了)
\n换行符 实际是对光标进行操作，移动到下一行开头。相当于回车键
\t制表符  对光标移动到下一个制表位，也就是Tab，一般是4或者8个空格，相当于Tab键
\r回车符  将光标移动到当前行的开头认为是
\f换页符  通常视为清屏，认为是Ctrl+
\v垂直制表符  光标向下移动定义行数
\cx  相当于Ctrl+x的效果，x是任意控制字符
\xn 十六进制，x代表Hex,n是十六进制数字，0-9,A-F,在不同语言下有所区别。比如PCRE下\x后面可以跟1或2位。而在Python下必须跟两位。\x20代表空格,\x0A代表换行。
\num八进制转义，用八进制数字表示一个字符。比如\012等价于\n 。不同语言下规定不同，比如PCRE下必须以0开头，如果不是0开头则认为是反向引用。而在Python中则都支持。在JS中则不允许使用八进制代表
\nm \nml 反向引用或八进制。
\nu Unicode转义 


##### 贪婪和非贪婪（组合量词组)
一般情况下，量词会尽可能多的匹配字符。比如 "* "会匹配零次和多次，如果在没有全局匹配或者放开限制的情况下，他只会匹配一个，那么他会默认匹配最多的。
比如
cat*  在[(cate),(catee)]里匹配，如果只输出一个，那么是catee而不是cate因为catee所占字符更多。
在量词后面加上?可以使其变得非贪婪，即偏好字符少的情况。
"* ?"零次或多次，但是尽可能少
"+？"一次或多次，但是尽可能少
“？？”零次或一次，但是尽可能少
{n,m}? n到m次，但是尽可能少

##### 正向和负向预查
（?=...)
正向肯定预查，匹配后面跟着特定模式的位置
比如Windows(?=95|98)匹配后面跟着98或95的Windows

(?!...)
正向否定预查，匹配后面不跟着特定模式的位置
比如Windows(?!95|98)匹配后面不跟着98或95的Windows

（?<=...)
反向肯定预查
匹配前面是特定模式的位置
比如(?<=95|98)Windows匹配前面是95或98的Windows

同理，那么(?<!..)则是反向否定预查
匹配的是前面不是的情况

#### 优先级
首先正则表达式是从左到右进行计算的，遵循优先顺序。
一般顺序从上到下排序为:
转义符，圆括号和方括号，限定符，位置和顺序符，或操作 

很好理解，首先要判断\转义符，因为转义符后面的符号就算是普通字符了，首先判断哪些元字符其实是普通字符。
然后是各种括号，就像是数学计算，先看括号内的一样，括号为一个整体。
这里不仅包括[]的设定字符集，()的捆绑组合，还预查操作，同样在这个等级
接着就是限定符，限定哪些内容，是一个还是多个，是几个到几个
最后是^确定开头，$确定结尾，\n的普通字符。

当需求不是所要求的，而是相反条件下，则是|的或操作。

一个显而易见的例子就是
^ [(^ab*c)\*] $

如果能判断出来是什么意思，那也就大致明白了

| [[:lower:]]  | 任何小写字母                   |
| [[:punct:]]  | 任何标点符号                   |
| [[:xdigit:]] | 任何16进制的数字，相当于[0-9a-fA-F] |
^[a-zA-Z0-9_]{1,}$      // 所有包含一个以上的字母、数字或下划线的字符串 
^[1-9][0-9]{0,}$        // 所有的正整数 
^\-{0,1}[0-9]{1,}$      // 所有的整数 
^[-]?[0-9]+\.?[0-9]+$   // 所有的浮点数
一些很常见的例子
^\-?[0-9]{1,}\.?[0-9]{1,}$

#### 位置匹配
位置匹配（也称为锚定或边界匹配）是指匹配字符串中的特定位置，而不是实际的字符。与普通字符匹配不同，位置匹配不消耗任何字符，它只是指定匹配必须发生的位置
上面已经说到的
^开头，$结尾，/b限定字符，/B非限定

比如下面的例子
```java
// 验证手机号码（以1开头，共11位数字）
const phonePattern = /^1\d{10}$/;
console.log(phonePattern.test("13800138000")); // true
console.log(phonePattern.test("a13800138000")); // false
```
用于验证输入格式的正确性。

```java
// 提取每行第一个单词
const text = "Apple Banana\nCherry Date";
const firstWords = text.match(/^\w+/gm);
console.log(firstWords); // ["Apple", "Cherry"]
```

```java
// 在每个段落开头添加"> "
const text = "First line\nSecond line";
const result = text.replace(/^/gm, "> ");
console.log(result);
// > First line
// > Second line
```

使用m标志，也就是多行模式，可以改变^和$的行为。
```java
const text = "Line 1\nLine 2\nLine 3";
// 普通模式
console.log(text.match(/^Line \d/g)); // ["Line 1"]
// 多行模式
console.log(text.match(/^Line \d/gm)); // ["Line 1", "Line 2", "Line 3"]
```
默认情况下`^`和`$`匹配整个字符串的开头和结尾
多行模式下它们匹配每行的开头和结尾

使用前后断言可以实现更加复杂的位置条件
```java
// 匹配后面跟着"px"的数字
const pattern = /\d+(?=px)/;
console.log(pattern.exec("12px")); // ["12"]
```

```java
// 匹配后面不跟着"px"的数字
const pattern = /\d+(?!px)/;
console.log(pattern.exec("12em")); // ["12"]
```

记住，边界匹配不消耗字符
#### 分组和引用
上面已经说过了，可以用()还有[]进行分组这里进行更加细致的用法。

捕获分组。会捕获匹配的内容并分配一个编号（从1开始）
```python
(\d{4})-(\d{2})-(\d{2})  # 匹配日期格式 YYYY-MM-DD
```
这个表达式会创建3个分组：

- 分组1：4位数字的年份
- 分组2：2位数字的月份
- 分组3：2位数字的日期

非捕获分组，只分组但不捕获
```python
(?:Mr|Ms|Mrs)\. (\w+)  # 匹配 "Mr. Smith" 但只捕获 "Smith"
```

命名分组 
```python
(?P<year>\d{4})-(?P<month>\d{2})-(?P<day>\d{2})
```

```javascript
(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})
```

分组可以在正则表达式内部或外部引用已匹配的内容

反向引用

命名反向引用


替换引用。在替换操作中引用分组内容

```python
text = "2023-05-15"

# 结果: "05/15/2023"
```

也可以用于匹配HTML标签
```python

```

可以支持基于分组的条件匹配
比如
```python
(?(1)true-pattern|false-pattern)
```
表示如果分组1已匹配，则匹配true-pattern,否则匹配false-pattern

注意不要使用过度分组，会影响性能。
比如(a)|(b)这里是想用将ab连起来，做到不是a就是b的分支效果。匹配到a把a存进捕获组1,匹配到b则把b存进捕获组2 如果实际上不需要捕获组，可以使用(?:a|b)来实现
如果拿来处理文本，捕获组的变量会乱跳。如果匹配到a，那么$1="a"而 $2是空的，如果匹配到a则相反过来。

同时注意分组编号的混淆问题。分组编号按左括号的顺序从1开始，非捕获组不参与编号。

#### 选择和分支
上一节提到了，|代表或的关系，这就是一种选择模式
选择允许你匹配多个可能的模式
而分支则是指正则表达式在匹配过程中遇到选择点时，会尝试不同的匹配路径，当一条路径失配的时候，引擎会回溯并尝试其他可能的路径。

|的逻辑是这样的：
首先正则表达式是从左向右扫描的
扫描到|的时候会看到|左右分隔的选项
对第一个选项进行匹配，如果成功则停止
如果第一个选项不匹配，则尝试第二个选项
以此类推。直到找到匹配或所有选项的尝试完毕，成功停止或者所有分支都尝试过

选择通常会和分组一起使用。
比如 (a|b)
这又类似于if 和else if 最后只会返回答道目标的结果。

比如下面的做法

JS
```javascript
// 匹配多种日期格式
const datePattern = /\b(January|February|March|April|May|June|July|August|September|October|November|December) \d{1,2}, \d{4}\b/;

console.log(datePattern.test("March 15, 2023")); // true
console.log(datePattern.test("Sept 10, 2022"));  // false (缩写不匹配)
```

Py
```python
import re

# 匹配美式或英式拼写
pattern = r"colou?r|color"
text = "The color is red and the colour is blue"

matches = re.findall(pattern, text)
print(matches)  # 输出: ['color', 'colour']
```

#### 断言
正则表达式中用于指定匹配位置的元字符，它们不匹配任何实际字符，而是匹配字符之间的位置。
这就是断言

断言是零宽度的，不占用匹配字符的位置，且只检查是否满足特定条件。仅作为匹配的约束条件，不影响匹配结果。

比如
```java
// 示例：匹配后面跟着 bar 的 foo 
const regex = /foo(?=bar)/;
console.log(regex.test("foobar"));  // true
console.log(regex.test("food"));    // false
```
正则表达式中的断言主要分为两大类四种类型：

|断言类型|正则语法|别称|检查方向|期望条件|通俗解释|
|:--|:--|:--|:--|:--|:--|
|**正向先行断言**|`(?=pattern)`|正前瞻|向右（向前）|**存在** `pattern`|我要找的位置，它的**右边必须**是...|
|**负向先行断言**|`(?!pattern)`|负前瞻|向右（向前）|**不存在** `pattern`|我要找的位置，它的**右边一定不能**是...|
|**正向后行断言**|`(?<=pattern)`|正后顾|向左（向后）|**存在** `pattern`|我要找的位置，它的**左边必须**是...|
|**负向后行断言**|`(?<!pattern)`|负后顾|向左（向后）|**不存在** `pattern`|我要找的位置，它的**左边一定不能**是...|
**正向先行断言** 用于匹配这样一个位置：在这个位置之后（右边），必须紧跟着出现指定的模式 `...`。

语法与参数

- **语法**：`(?=pattern)`
- **作用**：检查当前位置右侧是否匹配 `pattern`。如果匹配，则断言成功，引擎会回到当前位置继续后续匹配。
- **关键特性**：**零宽度**，即它只检查，不"吃掉"任何字符。`pattern` 中的内容不会成为最终匹配结果的一部分。

例子：提取价格数字
```python
import re

text = "商品A价格：299元，商品B价格：599元，运费：20元。"

# 使用正向先行断言
# 匹配一个或多个数字 (\d+)，但要求这个数字的右边必须紧跟着"元"
# 注意："元"本身不会被匹配到结果中
pattern = r'\d+(?=元)'
matches = re.findall(pattern, text)

print("匹配到的价格数字：", matches)
# 输出：匹配到的价格数字： ['299', '599', '20']
```

1. `\d+` 是主表达式，匹配一个或多个数字。
2. `(?=元)` 是断言，它检查 `\d+` 匹配到的数字串的**右侧**是否紧跟着一个"元"字。
3. 引擎首先找到 `299`，然后向右看，发现是"元"，断言成功，所以 `299` 被记录。
4. 继续找到 `599`，右边是"元"，成功，记录。
5. 找到 `20`，右边是"元"，成功，记录。最终，我们只得到了数字部分。

例子:验证复杂密码
```python
import re

def validate_password(password):
    # 使用多个正向先行断言来分别检查条件
    pattern = r'^(?=.*[A-Z])(?=.*[a-z])(?=.*\d).{8,}$'
    # ^ 代表字符串开始
    # (?=.*[A-Z]) 断言：从当前位置（开头）向右看，必须能在任意字符（.*）后找到一个大写字母
    # (?=.*[a-z]) 断言：同样从开头向右看，必须能找到一个小写字母
    # (?=.*\d)    断言：从开头向右看，必须能找到一个数字
    # .{8,}       主表达式：匹配任意字符至少8次（总长度要求）
    # $ 代表字符串结束
    if re.match(pattern, password):
        return True
    else:
        return False

# 测试数据
passwords = ["Weak", "strong123", "STRONG123", "Strong123"]
for pwd in passwords:
    print(f"密码 '{pwd}' 是否有效：{validate_password(pwd)}")

# 输出：
# 密码 'Weak' 是否有效：False      # 长度不够，且缺数字
# 密码 'strong123' 是否有效：False # 缺大写字母
# 密码 'STRONG123' 是否有效：False # 缺小写字母
# 密码 'Strong123' 是否有效：True  # 符合所有条件
```


##### 负向先行断言 `(?!...)`

**负向先行断言** 与正向先行断言相反。它匹配一个位置，在这个位置之后（右边），**不能**紧跟着出现指定的模式 `...`。
语法与参数

- **语法**：`(?!pattern)`
- **作用**：检查当前位置右侧是否**不匹配** `pattern`。如果不匹配，则断言成功。
- **关键特性**：同样是零宽度。

##### 正向后行断言 `(?<=...)`

**正向后行断言** 用于匹配一个位置，在这个位置之前（左边），必须紧挨着出现指定的模式 `...`。

_注意：不是所有编程语言的正则引擎都支持后行断言，JavaScript 在 ES2018 后才完全支持，而 Python 的 `re` 模块支持。_
语法与参数

- **语法**：`(?<=pattern)`
- **作用**：检查当前位置左侧是否匹配 `pattern`。如果匹配，则断言成功。
- **关键特性**：零宽度。`pattern` 必须有固定长度（不能是 `*` 或 `+` 等可变长度量词，在某些实现中）。

##### 负向后行断言 `(?<!...)`

**负向后行断言** 是正向后行断言的反面。它匹配一个位置，在这个位置之前（左边），**不能**紧挨着出现指定的模式 `...`。
语法与参数

- **语法**：`(?<!pattern)`
- **作用**：检查当前位置左侧是否**不匹配** `pattern`。
- **关键特性**：零宽度，通常要求 `pattern` 为固定长度。
