# 并发与异步安全

## 原理

数据竞争（data race）在 Rust 安全代码中被消除：`Send` + `Sync` trait 保证编译期检查。`Send` = 可跨线程传递所有权；`Sync` = 可跨线程共享 `&T`。

常见陷阱：
- **死锁**（deadlock）：两个 `Mutex` 互相等待。解决方案：始终以相同顺序获取锁
- **活锁**（livelock）：两个线程不断重试，无法实际进展
- **竞态条件**（race condition）：逻辑顺序依赖执行时序——Rust 无法完全防止（需业务层设计）

`tokio::spawn` 的 Future 必须为 `Send`（因为工作窃取调度器在线程间移动 task）。非 `Send` 的 Future 可用 `LocalSet` 在单线程上运行。

取消安全（cancellation safety）：`tokio::select!` 在一分支就绪时取消其他分支，需确保被取消的 Future 不丢失已处理的状态。典型模式：使用 `tokio::sync::oneshot` 或 `async fn` 返回 `Result` 表示完整性。

`Mutex<T>` 建议搭配 `Arc` 在多线程中使用；`RwLock<T>` 适合读多写少场景，但要注意 writer starvation。

## Send + Sync 深入理解

### Trait 定义

```rust
// 编译器自动实现（auto trait）
// 无需手动 impl

// Send: 可以安全地将 T 的所有权转移到另一个线程
pub unsafe auto trait Send {}

// Sync: 可以安全地将 &T 传给另一个线程
// 等价于: T 是 Send 的，当且仅当 &T 是 Send 的
pub unsafe auto trait Sync {}
```

### 常见类型的 Send/Sync 状态

| 类型 | Send | Sync | 原因 |
|------|------|------|------|
| `i32`, `String`, `Vec<T>` | ✅ | ✅ | 所有权语义 |
| `Arc<T>` | ✅ | ✅（T: Sync） | 引用计数线程安全 |
| `Mutex<T>` | ✅ | ✅ | 内部可变性安全 |
| `RwLock<T>` | ✅ | ✅ | 内部可变性安全 |
| `Cell<T>`, `RefCell<T>` | ✅ | ❌ | 非线程安全的内部可变性 |
| `Rc<T>` | ❌ | ❌ | 非原子引用计数 |
| `*const T`, `*mut T` | ❌ | ❌ | 裸指针无安全保证 |
| `dyn Future` | ❌ | ❌ | 通常非 Send |
| `tokio::task::JoinHandle<T>` | ✅ | ✅ | 异步任务句柄 |

### 自动实现与手动实现

```rust
use std::rc::Rc;
use std::sync::Arc;

struct MyStruct {
    data: Vec<i32>,           // Send + Sync ✅
    pointer: *const u8,       // ❌ 让整个 MyStruct 变为 !Send + !Sync
    cache: Rc<String>,        // ❌ 同上
}

// 编译器自动检测：如果任何字段是 !Send，整个类型就是 !Send
// MyStruct: !Send, !Sync

// 手动标记（unsafe）— 只在你确定安全时
unsafe impl Send for MyStruct {}   // 需要 unsafe
unsafe impl Sync for MyStruct {}   // 需要 unsafe

// 常见场景：包装非 Send 类型为 Send
struct SendWrapper<T>(T);
unsafe impl<T> Send for SendWrapper<T> {}
// ⚠️ 这绕过编译器检查，必须确保线程安全
```

### Send 与异步任务

```rust
use tokio::task;

#[tokio::main]
async fn main() {
    // tokio::spawn 要求 Future: Send
    let handle = task::spawn(async {
        // 这个 async block 必须是 Send 的
        let data = vec![1, 2, 3];
        task::spawn_in_place(|| {
            // 在工作线程中执行
            println!("{:?}", data);  // data 的所有权转移，必须 Send
        }).await.unwrap();
    });

    handle.await.unwrap();

    // 非 Send 的 Future：使用 LocalSet
    let local = task::LocalSet::new();
    local.run_until(async {
        let rc = std::rc::Rc::new(42);  // Rc 是 !Send
        // spawn_local 只在当前线程运行，不要求 Send
        task::spawn_local(async move {
            println!("{}", rc);
        }).await.unwrap();
    }).await;
}
```

## async 安全模式

### 取消安全（Cancellation Safety）

```rust
use tokio::sync::mpsc;
use tokio::time::{sleep, Duration};

// ❌ 不取消安全：select! 可能在写入中途取消
async fn unsafe_read(reader: &mut (impl tokio::io::AsyncRead + Unpin)) {
    use tokio::io::AsyncReadExt;
    let mut buf = [0u8; 1024];
    tokio::select! {
        result = reader.read(&mut buf) => {
            // 如果 ctrl_c 先就绪，read 被取消
            // buf 可能处于部分写入状态
            println!("read {} bytes", result.unwrap());
        }
        _ = tokio::signal::ctrl_c() => {
            println!("shutting down");
        }
    }
}

// ✅ 取消安全：使用 tokio::io::read_buf 或确保原子操作
async fn safe_read(reader: &mut (impl tokio::io::AsyncRead + Unpin)) {
    use tokio::io::AsyncReadExt;
    let mut buf = [0u8; 1024];
    tokio::select! {
        result = tokio::io::read_buf(reader, &mut &mut buf[..]) => {
            println!("read {} bytes", result.unwrap());
        }
        _ = tokio::signal::ctrl_c() => {
            println!("shutting down");
        }
    }
}

// ✅ 取消安全模式：oneshot channel 捕获结果
async fn safe_with_channel(rx: &mut tokio::sync::oneshot::Receiver<String>) {
    tokio::select! {
        result = rx => {
            match result {
                Ok(data) => println!("received: {}", data),
                Err(_) => println!("channel closed"),
            }
        }
        _ = tokio::signal::ctrl_c() => {
            println!("shutting down");
        }
    }
}
```

### tokio 常用模式

```rust
use tokio::sync::{mpsc, oneshot, broadcast, watch, Semaphore};
use tokio::time::{interval, Duration};
use std::sync::Arc;

// 模式 1: mpsc — 多生产者单消费者
async fn mpsc_example() {
    let (tx, mut rx) = mpsc::channel::<String>(32);

    // 多个生产者
    for i in 0..5 {
        let tx = tx.clone();
        tokio::spawn(async move {
            tx.send(format!("msg {}", i)).await.unwrap();
        });
    }
    drop(tx);  // 关闭发送端

    // 消费者
    while let Some(msg) = rx.recv().await {
        println!("received: {}", msg);
    }
}

// 模式 2: broadcast — 多生产者多消费者
async fn broadcast_example() {
    let (tx, _) = broadcast::channel::<String>(16);

    // 多个消费者
    for _ in 0..3 {
        let mut rx = tx.subscribe();
        tokio::spawn(async move {
            while let Ok(msg) = rx.recv().await {
                println!("consumer received: {}", msg);
            }
        });
    }

    // 生产者
    tx.send("hello".into()).unwrap();
}

// 模式 3: watch — 单生产者多消费者（只保留最新值）
async fn watch_example() {
    let (tx, mut rx) = watch::channel("initial".to_string());

    tokio::spawn(async move {
        loop {
            tokio::time::sleep(Duration::from_secs(1)).await;
            tx.send(format!("update at {:?}", std::time::Instant::now())).unwrap();
        }
    });

    // 只接收变化的值
    while rx.changed().await.is_ok() {
        println!("new value: {}", *rx.borrow());
    }
}

// 模式 4: Semaphore — 并发限制
async fn semaphore_example() {
    let semaphore = Arc::new(Semaphore::new(3));  // 最多 3 个并发
    let mut handles = vec![];

    for i in 0..10 {
        let sem = semaphore.clone();
        handles.push(tokio::spawn(async move {
            let _permit = sem.acquire().await.unwrap();
            println!("task {} running", i);
            tokio::time::sleep(Duration::from_secs(1)).await;
        }));
    }

    for h in handles {
        h.await.unwrap();
    }
}

// 模式 5: spawn_blocking — CPU 密集任务
async fn spawn_blocking_example() {
    let result = tokio::task::spawn_blocking(|| {
        // CPU 密集计算，不应阻塞异步线程
        let mut sum = 0u64;
        for i in 0..1_000_000 {
            sum += i;
        }
        sum
    }).await.unwrap();

    println!("result: {}", result);
}
```

## 死锁预防

```rust
use std::sync::{Arc, Mutex};

struct Account {
    id: u64,
    balance: u64,
}

// ❌ 死锁风险：不同线程以不同顺序获取锁
fn bad_transfer(
    from: &Mutex<Account>,
    to: &Mutex<Account>,
    amount: u64,
) {
    // 线程 1: transfer(A, B) → 先锁 A，再锁 B
    // 线程 2: transfer(B, A) → 先锁 B，再锁 A
    // → 死锁！
    let mut f = from.lock().unwrap();
    let mut t = to.lock().unwrap();
    f.balance -= amount;
    t.balance += amount;
}

// ✅ 死锁预防：全局锁顺序
fn safe_transfer(
    from: &Mutex<Account>,
    to: &Mutex<Account>,
    amount: u64,
) -> Result<(), String> {
    // 按 id 排序，确保全局一致的获取顺序
    let (first, second) = if from.lock().unwrap().id < to.lock().unwrap().id {
        (from, to)
    } else {
        (to, from)
    };

    let mut f = first.lock().unwrap();
    let mut t = second.lock().unwrap();

    if f.balance < amount {
        return Err("insufficient funds".into());
    }

    f.balance -= amount;
    t.balance += amount;
    Ok(())
}

// ✅ 更好的方案：使用 tokio::sync::Mutex 的 try_lock
async fn try_lock_transfer(
    from: &tokio::sync::Mutex<Account>,
    to: &tokio::sync::Mutex<Account>,
    amount: u64,
) -> Result<(), String> {
    // try_lock 不阻塞，获取失败立即返回
    let (first, second) = if from.lock().await.id < to.lock().await.id {
        (from, to)
    } else {
        (to, from)
    };

    let mut f = first.lock().await;
    let mut t = second.lock().await;

    if f.balance < amount {
        return Err("insufficient funds".into());
    }

    f.balance -= amount;
    t.balance += amount;
    Ok(())
}
```

## 数据竞争防止

Rust 通过类型系统在编译期防止数据竞争：

```rust
use std::sync::Arc;
use std::thread;

// ✅ 数据竞争不可能发生 — 编译器保证
fn thread_safe_example() {
    let data = Arc::new(vec![1, 2, 3, 4, 5]);
    let mut handles = vec![];

    for _ in 0..5 {
        let data = data.clone();  // Arc::clone 是线程安全的
        handles.push(thread::spawn(move || {
            // 只读访问 — 多线程可以同时读
            println!("sum: {}", data.iter().sum::<i32>());
        }));
    }

    for h in handles {
        h.join().unwrap();
    }
}

// ❌ 数据竞争在 Rust 中不可能编译通过
fn data_race_impossible() {
    let mut data = vec![1, 2, 3];
    let handle = thread::spawn(move || {
        // data 的所有权已经 move 到闭包中
        data.push(4);
    });
    // println!("{:?}", data);  // ❌ 编译错误：data 已 move
    handle.join().unwrap();
}
```

## 并发数据结构

```rust
use std::sync::atomic::{AtomicUsize, AtomicBool, Ordering};
use std::sync::Arc;
use crossbeam::queue::SegQueue;  // 无锁队列
use dashmap::DashMap;            // 分片并发 HashMap
use parking_lot::Mutex;          // 更快的 Mutex 实现

// 原子操作 — 无锁并发
struct Counter {
    count: AtomicUsize,
}

impl Counter {
    fn new() -> Self {
        Self { count: AtomicUsize::new(0) }
    }

    fn increment(&self) {
        self.count.fetch_add(1, Ordering::Relaxed);
    }

    fn get(&self) -> usize {
        self.count.load(Ordering::Relaxed)
    }
}

// DashMap — 并发 HashMap
fn dashmap_example() {
    let map = Arc::new(DashMap::new());

    let mut handles = vec![];
    for i in 0..100 {
        let map = map.clone();
        handles.push(std::thread::spawn(move || {
            map.insert(i, i * 2);
        }));
    }

    for h in handles {
        h.join().unwrap();
    }

    assert_eq!(map.len(), 100);
}

// crossbeam 无锁队列
fn crossbeam_queue_example() {
    let queue = Arc::new(SegQueue::new());
    let mut handles = vec![];

    for i in 0..100 {
        let queue = queue.clone();
        handles.push(std::thread::spawn(move || {
            queue.push(i);
        }));
    }

    for h in handles {
        h.join().unwrap();
    }

    let mut items: Vec<_> = queue.iter().collect();
    items.sort();
    assert_eq!(items, (0..100).collect::<Vec<_>>());
}
```

## async drop

Rust 的 `Drop` trait 不是 async 的——`drop()` 不能是 `async fn`。处理异步资源清理需要特殊模式：

```rust
use tokio::sync::mpsc;

// 模式 1: 显式 async close 方法
struct AsyncConnection {
    tx: mpsc::Sender<()>,
    handle: tokio::task::JoinHandle<()>,
}

impl AsyncConnection {
    async fn close(self) {
        drop(self.tx);       // 关闭 channel
        self.handle.await.ok();  // 等待任务结束
    }
}

// Drop 只做同步清理
impl Drop for AsyncConnection {
    fn drop(&mut self) {
        // 如果用户没有调用 close()，这里尝试同步清理
        // 但不能 await
        eprintln!("warning: AsyncConnection dropped without close()");
    }
}

// 模式 2: 作用域内使用
async fn process() {
    let conn = AsyncConnection::new().await;

    // 使用连接
    conn.send("hello").await;

    // 显式关闭
    conn.close().await;
}  // drop 在此触发（已关闭，无需额外清理）

// 模式 3: RAII 守卫 + background task
struct BackgroundTask {
    abort: Option<tokio::sync::oneshot::Sender<()>>,
}

impl Drop for BackgroundTask {
    fn drop(&mut self) {
        if let Some(tx) = self.abort.take() {
            let _ = tx.send(());  // 通知后台任务停止
        }
    }
}
```

## 优雅关闭

```rust
use tokio::sync::{broadcast, watch};
use std::sync::Arc;

struct App {
    shutdown_tx: watch::Sender<bool>,
    task_handles: Vec<tokio::task::JoinHandle<()>>,
}

impl App {
    async fn run(&mut self) {
        loop {
            tokio::select! {
                _ = self.shutdown_tx.changed() => {
                    if *self.shutdown_tx.borrow() {
                        break;
                    }
                }
                _ = async {
                    // 主工作循环
                    tokio::time::sleep(std::time::Duration::from_secs(1)).await;
                } => {}
            }
        }

        // 优雅关闭：等待所有任务完成
        for handle in self.task_handles.drain(..) {
            let _ = handle.await;
        }
    }

    fn shutdown(&self) {
        let _ = self.shutdown_tx.send(true);
    }
}

// 使用 tokio_util 的 Cancellation Token
use tokio_util::sync::CancellationToken;

async fn worker(token: CancellationToken) {
    loop {
        tokio::select! {
            _ = token.cancelled() => {
                println!("worker received shutdown signal");
                break;
            }
            _ = do_work() => {}
        }
    }
}

async fn run_app() {
    let token = CancellationToken::new();

    let mut handles = vec![];
    for i in 0..5 {
        let token = token.clone();
        handles.push(tokio::spawn(async move {
            println!("worker {} started", i);
            worker(token).await;
            println!("worker {} finished", i);
        }));
    }

    // 等待信号
    tokio::signal::ctrl_c().await.ok();
    token.cancel();

    for h in handles {
        let _ = h.await;
    }
    println!("all workers stopped");
}
```

## 并发模型对比

| | std::thread | tokio::task | rayon |
|--|------------|-------------|-------|
| 并发模型 | OS 线程 | 协作式协程 | work-stealing 线程池 |
| 适合场景 | CPU 密集 | IO 密集 | 数据并行 |
| 切换开销 | ~1μs | ~20ns | 按任务大小 |
| 并发数 | 数百 | 百万 | 数百（按核） |
| 内存开销 | ~2MB/线程 | ~数百字节/task | 按线程数 |
| 调度方式 | OS 调度 | 工作窃取 | 工作窃取 |
| 取消支持 | 无（需配合） | select!/cancel | 无 |
