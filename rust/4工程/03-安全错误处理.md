# 安全错误处理

## 企业场景

某SaaS平台的错误日志通过第三方日志聚合服务（如Datadog/Splunk）收集。在一次渗透测试中，白帽黑客从Datadog的日志中提取到了：
- 完整的用户密码哈希（含salt）
- 数据库连接字符串（含IP、端口、凭证）
- 内部API的错误堆栈，暴露了微服务架构拓扑
- JWT签名密钥的片段（因panic时内存dump）

更严重的是，当一个下游服务返回503时，错误信息沿着调用链层层包裹，最终返回给客户端时包含了完整的内部网络拓扑：`Error: Gateway(ConnectionError(HttpError(503, "http://payment-internal.cluster.local:8081/process")))`。

安全团队要求立即实施错误信息的纵深防御体系。

## 1. 信息泄露防止：自定义错误类型

### 1.1 分层错误设计

```rust
use thiserror::Error;
use std::fmt;

// ─── 层级1: 内部错误（包含完整上下文，仅日志使用） ───
#[derive(Error, Debug)]
pub enum InternalError {
    #[error("数据库查询失败 [query_id={query_id}]")]
    DatabaseQuery {
        query_id: String,
        #[source]
        source: sqlx::Error,  // 包含完整SQL错误信息
    },

    #[error("加密操作失败 [operation={operation}, key_id={key_id}]")]
    CryptoOperation {
        operation: String,
        key_id: String,
        #[source]
        source: ring::error::Unspecified,
    },

    #[error("下游服务调用失败 [service={service}, endpoint={endpoint}]")]
    DownstreamCall {
        service: String,
        endpoint: String,
        #[source]
        source: reqwest::Error,
    },
}

// ─── 层级2: 对客户端暴露的错误（最小信息） ───
#[derive(Error, Debug, Clone, Serialize)]
#[serde(tag = "type")]
pub enum ClientError {
    /// 通用内部错误——不透露任何细节
    #[error("处理请求时发生内部错误")]
    InternalServerError,

    /// 认证失败——不透露是用户名错还是密码错
    #[error("认证失败")]
    AuthenticationFailed,

    /// 资源不存在——不区分是404还是403
    #[error("请求的资源不可用")]
    ResourceUnavailable,

    /// 请求格式错误——可以透露一些结构化信息
    #[error("请求格式无效: {field}")]
    ValidationError { field: String },

    /// 速率限制——可以透露重试时间
    #[error("请求过于频繁，请在 {retry_after} 秒后重试")]
    RateLimited { retry_after: u64 },
}

// ─── 层级3: 安全的转换层 ───
impl From<InternalError> for ClientError {
    fn from(error: InternalError) -> Self {
        // ⚠️ 关键：记录完整错误到审计日志
        tracing::error!(
            error = %error,
            error_type = "InternalError",
            // 结构化日志包含完整上下文，但使用tracing的过滤功能
            // 确保这些字段不会进入常规日志流
        );

        // ⚠️ 关键：对外暴露的内容已被剥离
        match &error {
            InternalError::CryptoOperation { .. } => {
                // 加密失败可能指示密钥问题 → 告警但不透露
                metrics::increment_counter!("security.crypto.failure");
                ClientError::InternalServerError
            }
            InternalError::DatabaseQuery { .. } => {
                ClientError::InternalServerError
            }
            InternalError::DownstreamCall { .. } => {
                ClientError::InternalServerError
            }
        }
    }
}
```

```c
    printf("Executing query: %s\n", query);  // ⚠️ 日志中明文密码

    return AUTH_SUCCESS;
}
```

### 2.2 日志脱敏中间件

```rust
use std::collections::HashSet;
use once_cell::sync::Lazy;

/// 需要脱敏的字段名集合
static SENSITIVE_FIELDS: Lazy<HashSet<&'static str>> = Lazy::new(|| {
    let mut set = HashSet::new();
    set.insert("password");
    set.insert("secret");
    set.insert("token");
    set.insert("api_key");
    set.insert("access_key");
    set.insert("private_key");
    set.insert("credit_card");
    set.insert("ssn");
    set.insert("authorization");
    set.insert("cookie");
    set.insert("jwt");
    set.insert("bearer");
    set.insert("signature");
    set.insert("pin");
    set.insert("passcode");
    set.insert("otp_token");
    set.insert("refresh_token");
    // 数据库凭证
    set.insert("connection_string");
    set.insert("db_password");
    set.insert("redis_password");
    // AWS/GCP凭证
    set.insert("aws_secret_access_key");
    set.insert("gcp_private_key");
    set
});

/// 日志值脱敏函数
pub fn sanitize_value(key: &str, value: &str) -> String {
    let key_lower = key.to_lowercase();

    // 检查是否为敏感字段
    let is_sensitive = SENSITIVE_FIELDS.iter()
        .any(|s| key_lower.contains(s));

    if is_sensitive {
        if value.len() <= 8 {
            return "***REDACTED***".to_string();
        }
        // 保留前后各2个字符用于调试但不泄露完整值
        format!(
            "{}***{} (REDACTED)",
            &value[..2],
            &value[value.len()-2..]
        )
    } else if key_lower.contains("email") {
        // 邮箱部分脱敏
        if let Some(at_pos) = value.find('@') {
            let local = &value[..at_pos];
            let domain = &value[at_pos..];
            format!(
                "{}***{}",
                &local[..local.len().min(2)],
                domain
            )
        } else {
            "***@***".to_string()
        }
    } else {
        value.to_string()
    }
}

/// 对serde_json::Value进行递归脱敏
pub fn sanitize_json(value: &mut serde_json::Value) {
    match value {
        serde_json::Value::Object(map) => {
            let keys: Vec<String> = map.keys().cloned().collect();
            for key in keys {
                if let Some(val) = map.get_mut(&key) {
                    if let serde_json::Value::String(s) = val {
                        let sanitized = sanitize_value(&key, s);
                        *val = serde_json::Value::String(sanitized);
                    } else {
                        sanitize_json(val);
                    }
                }
            }
        }
        serde_json::Value::Array(arr) => {
            for val in arr {
                sanitize_json(val);
            }
        }
        _ => {}
    }
}

#[test]
fn test_sanitization() {
    let mut log = serde_json::json!({
        "username": "john_doe",
        "password": "super_secret_123",
        "email": "john.doe@company.com",
        "api_key": "sk-live-abc123def456",
        "nested": {
            "secret": "hidden_value"
        }
    });

    sanitize_json(&mut log);

    assert_eq!(log["password"], "su***23 (REDACTED)");
    assert_eq!(log["email"], "jo***@company.com");
    assert_ne!(log["api_key"], "sk-live-abc123def456");
    assert_ne!(log["nested"]["secret"], "hidden_value");
}
```

### 2.3 日志中绝对不能出现的敏感数据类型

| 数据类型 | 原因 | 替代做法 |
|---------|------|---------|
| 密码明文 | 直接认证凭据 | 从不记录，立即hash |
| 密码哈希（含salt） | salt泄露削弱暴力破解难度 | 不记录 |
| JWT/API密钥 | 可冒充用户 | 记录前8字符用于去重 |
| 完整的栈回溯 | 暴露内部架构和方法名 | 仅记录错误类型+请求ID |
| 数据库查询 | 可能含PII | 参数化查询的SQL模板 |
| IP地址（部分司法管辖区） | GDPR视为PII | 哈希或仅记录/24子网 |
| Session ID | 会话劫持 | 哈希后记录 |
| 信用卡号 | PCI-DSS要求 | PCI字段掩码 411111******1111 |

## 3. Unsafe代码中的错误处理

```rust
use std::alloc::{self, Layout};

/// 自定义分配器：当内存不足时，安全地abort
struct SecurityAllocator;

impl SecurityAllocator {
    /// 分配内存（安全关键路径）
    fn allocate(layout: Layout) -> *mut u8 {
        let ptr = unsafe { alloc::alloc(layout) };
        if ptr.is_null() {
            // ⚠️ 在安全关键系统中，内存分配失败不能让系统继续运行
            // 因为继续运行可能导致"部分状态"下的安全漏洞

            // 1. 最后一次审计日志（使用预先分配的静态缓冲）
            critical_failure_log("内存分配失败");

            // 2. 清理安全状态（擦除密钥等）
            zeroize_secrets();

            // 3. 立即中止
            std::process::abort();
        }
        ptr
    }

    /// 释放内存
    unsafe fn deallocate(ptr: *mut u8, layout: Layout) {
        // 在释放前清零（防止UAF后读取敏感数据）
        if layout.size() > 0 {
            std::ptr::write_bytes(ptr, 0, layout.size());
        }
        alloc::dealloc(ptr, layout);
    }
}

fn critical_failure_log(message: &str) {
    // 使用write(2)系统调用（而非依赖可能已损坏的std::io）
    use std::os::unix::io::RawFd;
    let msg = format!("[CRITICAL] {}\n", message);
    unsafe {
        libc::write(2, msg.as_ptr() as *const libc::c_void, msg.len());
    }
}

fn zeroize_secrets() {
    // 清零全局密钥存储
    // 使用zeroize crate确保编译器不会优化掉清零操作
    use zeroize::Zeroize;

    // 静态的密钥存储
    static mut MASTER_KEY: [u8; 32] = [0u8; 32];

    unsafe {
        MASTER_KEY.zeroize();
    }
}
```

### 3.1 Panic与Abort的选择

```rust
// 决策树：何时panic，何时abort，何时返回Err

pub enum FailureMode {
    /// 可恢复错误：返回Err，继续运行
    Recoverable,
    /// 不可恢复但需要清理：panic（触发drop）
    UnrecoverableNeedCleanup,
    /// 不可恢复且不安全清理：直接abort
    UnrecoverableAbortNow,
}

fn handle_operation_result(result: Result<Data, Error>) -> Data {
    match result {
        Ok(data) => data,

        Err(Error::NetworkTimeout) => {
            // 网络超时 → 可恢复，只是重试
            panic!("网络超时不可恢复") // 错误选择–应返回Err
        }

        Err(Error::MemoryCorruptionDetected) => {
            // 内存损坏检测 → 无法信任任何状态
            // 正确：立即abort，不做任何清理（清理代码本身可能被攻击）
            std::process::abort();
        }

        Err(Error::CryptoIntegrityCheckFailed) => {
            // 加密完整性检查失败 → 可能正在遭受攻击
            // 正确：panic，因为需要调用drop来清理敏感数据
            // 但确保设置了 panic = "abort" 在Cargo.toml中
            panic!("加密完整性检查失败——可能的篡改攻击");
        }
    }
}
```

## 4. 速率限制与熔断器模式

### 4.1 令牌桶速率限制

```rust
use std::sync::atomic::{AtomicU64, Ordering};
use std::time::{Duration, Instant};
use tokio::sync::Mutex;

pub struct RateLimiter {
    capacity: u64,           // 桶容量（最大突发请求数）
    refill_rate: f64,        // 每秒填充速率
    tokens: AtomicU64,       // 当前令牌数
    last_refill: Mutex<Instant>,
}

impl RateLimiter {
    pub fn new(capacity: u64, refill_rate: f64) -> Self {
        Self {
            capacity,
            refill_rate,
            tokens: AtomicU64::new(capacity),
            last_refill: Mutex::new(Instant::now()),
        }
    }

    /// 尝试获取一个令牌
    /// 返回值：true=允许，false=被限流
    pub async fn try_acquire(&self) -> bool {
        // 1. 补充令牌（基于时间流逝）
        let mut last = self.last_refill.lock().await;
        let now = Instant::now();
        let elapsed = now.duration_since(*last).as_secs_f64();
        let new_tokens = (elapsed * self.refill_rate) as u64;

        if new_tokens > 0 {
            let current = self.tokens.load(Ordering::Relaxed);
            let new_total = (current + new_tokens).min(self.capacity);
            self.tokens.store(new_total, Ordering::Relaxed);
            *last = now;
        }
        drop(last);

        // 2. 尝试消费令牌
        loop {
            let current = self.tokens.load(Ordering::Relaxed);
            if current == 0 {
                return false; // 桶空了
            }
            if self.tokens
                .compare_exchange(current, current - 1,
                    Ordering::SeqCst, Ordering::Relaxed)
                .is_ok()
            {
                return true; // 成功获取令牌
            }
            // CAS失败→重试
        }
    }

    /// 拒绝时返回安全响应（不泄露内部限流算法）
    pub fn rate_limit_response(retry_after_secs: u64) -> actix_web::HttpResponse {
        actix_web::HttpResponse::TooManyRequests()
            .insert_header(("Retry-After", retry_after_secs.to_string()))
            .insert_header(("X-RateLimit-Limit", "100"))
            .json(serde_json::json!({
                "error": "请求过于频繁",
                "retry_after": retry_after_secs
            }))
    }
}
```

### 4.2 熔断器（Circuit Breaker）

```rust
use std::sync::atomic::{AtomicU64, AtomicBool, Ordering};
use std::time::{Duration, Instant};

#[derive(Debug, Clone, Copy, PartialEq)]
pub enum CircuitState {
    Closed,        // 正常运行
    Open,          // 熔断开启，直接拒绝
    HalfOpen,      // 半开，尝试恢复
}

pub struct CircuitBreaker {
    state: AtomicU64,           // CircuitState编码
    failure_count: AtomicU64,
    success_count: AtomicU64,
    failure_threshold: u64,     // 失败阈值
    success_threshold: u64,     // 半开状态下需要连续成功数
    timeout: Duration,          // 熔断持续时间
    last_failure_time: Mutex<Option<Instant>>,
}

impl CircuitBreaker {
    pub fn new(failure_threshold: u64, timeout: Duration) -> Self {
        Self {
            state: AtomicU64::new(CircuitState::Closed as u64),
            failure_count: AtomicU64::new(0),
            success_count: AtomicU64::new(0),
            failure_threshold,
            success_threshold: 3,
            timeout,
            last_failure_time: Mutex::new(None),
        }
    }

    pub async fn call<F, T, E>(&self, f: F) -> Result<T, E>
    where
        F: std::future::Future<Output = Result<T, E>>,
        E: std::fmt::Debug,
    {
        // 检查熔断器状态
        let state = self.get_state().await;
        match state {
            CircuitState::Open => {
                return Err(/* 熔断器错误——不暴露内部状态 */);
            }
            CircuitState::HalfOpen => {
                // 仅允许有限请求通过
            }
            CircuitState::Closed => {
                // 正常执行
            }
        }

        match f.await {
            Ok(result) => {
                self.on_success().await;
                Ok(result)
            }
            Err(error) => {
                self.on_failure().await;
                Err(error)
            }
        }
    }

    async fn on_failure(&self) {
        let count = self.failure_count
            .fetch_add(1, Ordering::SeqCst) + 1;

        let mut last = self.last_failure_time.lock().await;
        *last = Some(Instant::now());

        if count >= self.failure_threshold {
            self.state.store(
                CircuitState::Open as u64,
                Ordering::SeqCst,
            );

            // 安全审计日志
            tracing::warn!(
                target: "audit",
                security_event = true,
                event_type = "circuit_breaker.opened",
                failure_count = count,
                threshold = self.failure_threshold,
                "熔断器开启——可能的下游服务故障或攻击"
            );
        }
    }

    async fn on_success(&self) {
        let state = CircuitState::from_u64(
            self.state.load(Ordering::SeqCst)
        );

        match state {
            CircuitState::HalfOpen => {
                let count = self.success_count
                    .fetch_add(1, Ordering::SeqCst) + 1;
                if count >= self.success_threshold {
                    self.state.store(
                        CircuitState::Closed as u64,
                        Ordering::SeqCst
                    );
                    self.failure_count.store(0, Ordering::SeqCst);
                }
            }
            _ => {
                self.failure_count.store(0, Ordering::SeqCst);
            }
        }
    }

    async fn get_state(&self) -> CircuitState {
        let state = CircuitState::from_u64(
            self.state.load(Ordering::SeqCst)
        );

        if state == CircuitState::Open {
            let last = self.last_failure_time.lock().await;
            if let Some(fail_time) = *last {
                if fail_time.elapsed() >= self.timeout {
                    drop(last);
                    self.state.store(
                        CircuitState::HalfOpen as u64,
                        Ordering::SeqCst
                    );
                    return CircuitState::HalfOpen;
                }
            }
        }

        state
    }
}

impl CircuitState {
    fn from_u64(val: u64) -> Self {
        match val {
            0 => CircuitState::Closed,
            1 => CircuitState::Open,
            2 => CircuitState::HalfOpen,
            _ => CircuitState::Open, // 默认熔断
        }
    }
}
```

### 4.3 Fail-Closed原则

```rust
/// 安全系统的Fail-Closed模式
/// 当任何组件不确定时，拒绝访问而非允许访问
pub enum SecurityDecision {
    Allow,
    Deny,
}

pub struct SecurityGate {
    auth_service: AuthClient,
    rate_limiter: RateLimiter,
    geo_fence: GeoFence,
    fraud_detector: FraudDetector,
}

impl SecurityGate {
    pub async fn should_allow(&self, request: &Request) -> SecurityDecision {
        // 1. 认证检查（fail-closed）
        match self.auth_service.verify(request.token()).await {
            Ok(true) => { /* 继续 */ }
            Ok(false) => return SecurityDecision::Deny,
            Err(_) => {
                // ⚠️ 认证服务不可用时 → 拒绝（fail-closed）
                // 虽然会拒绝合法请求，但不会放过恶意请求
                audit_log!(WARN, "gate.auth_unavailable",
                    "认证服务不可用，全部拒绝");
                return SecurityDecision::Deny;
            }
        }

        // 2. 速率限制（fail-closed）
        match self.rate_limiter.try_acquire().await {
            true => { /* 继续 */ }
            false => return SecurityDecision::Deny,
        }

        // 3. 地理围栏（fail-open的例外——有显式风险评估）
        // 如果GeoIP服务不可用，记录但放行（可能是合法用户出差）
        match self.geo_fence.check(request.ip()).await {
            Ok(true) => { /* 继续 */ }
            Ok(false) => return SecurityDecision::Deny,
            Err(_) => {
                tracing::warn!("GeoIP服务不可用，跳过地理检查");
                // 这是经过安全团队批准的fail-open
                // 有补偿控制（如增强的欺诈检测）
            }
        }

        // 4. 欺诈检测（fail-closed——最后防线）
        match self.fraud_detector.analyze(request).await {
            Ok(score) if score < 0.7 => SecurityDecision::Allow,
            Ok(_) => SecurityDecision::Deny,
            Err(_) => {
                // 欺诈检测不可用 → 拒绝高风险交易
                audit_log!(ERROR, "gate.fraud_unavailable",
                    "欺诈检测服务不可用，全部拒绝");
                SecurityDecision::Deny
            }
        }
    }
}
```

### 一、概念题（40分，每题8分）

1. 解释"信息泄露 through error messages"在企业系统中的具体含义，给出三个实例。
2. Fail-Closed与Fail-Open的区别是什么？为什么安全系统应默认Fail-Closed？
3. 审计日志与普通应用日志的核心区别有哪些？
4. `thiserror`和`tracing`在防止信息泄露中分别扮演什么角色？
5. 简述panic与abort在安全关键代码中的选择依据。

<details>
<summary>查看答案</summary>

**1. 错误信息泄露的三个实例：**
- 数据库连接失败时泄露服务器IP、端口、数据库类型和连接字符串
- 密码验证失败时区分"用户不存在"vs"密码错误"，帮助攻击者枚举账户
- panic堆栈回溯暴露内部函数名、文件路径和第三方依赖版本

**2. Fail-Closed vs Fail-Open：**
- Fail-Closed：当组件/检查无法正常工作时，默认拒绝访问
- Fail-Open：当组件/检查无法正常工作时，默认允许通过
- 安全系统应默认Fail-Closed：攻击者可能通过DDoS使安全组件超载/崩溃，从而绕过检查。Fail-Closed意味着系统降级但安全边界完整

**3. 审计日志 vs 应用日志：**
- 审计日志记录"谁在何时做了什么"（安全事件），不可篡改，保留期长（10年+）
- 应用日志记录调试信息、性能指标、错误详情，保留期短
- 审计日志必须包含用户身份、操作类型、结果、时间戳、来源IP
- 审计日志是合规证据（GDPR Art.30, PCI-DSS Req.10, SOC2）

**4. thiserror和tracing的角色：**
- `thiserror`：提供安全的From转换链，确保内部错误不会自动传播到客户端。通过显式实现From<InternalError> for ClientError来剥离敏感信息
- `tracing`：提供分层日志系统，审计日志层仅记录安全事件（通过filter），应用日志层记录调试信息。结构化日志便于脱敏和SIEM集成

**5. Panic vs Abort选择：**
- Panic：当需要运行drop清理敏感数据时（如密钥在内存中需要zeroize），且代码可信任
- Abort：当检测到内存损坏或完整性检查失败，可能drop代码不可信任（攻击者可能已感染清理路径）
- 在`Cargo.toml`中设置`panic = "abort"`是在所有情况选择安全侧：放弃可能被污染的清理，直接终止
</details>

### 二、判断题（20分，每题5分）

6. ( ) 将完整的错误堆栈返回给客户端有助于用户定位问题，是好的用户体验实践。
7. ( ) 严格遵循Fail-Closed原则没有任何弊端。
8. ( ) 日志脱敏可以在写入日志文件后进行，不一定要在记录前处理。
9. ( ) 熔断器（Circuit Breaker）同时具有安全和可靠性价值。

<details>
<summary>查看答案</summary>

6. **错误。** 完整的错误堆栈向客户端（包括攻击者）暴露了内部架构、依赖版本、文件路径等敏感信息。正确的做法是对客户端返回通用错误消息，同时在内部日志中记录完整上下文。

7. **错误。** Fail-Closed在某些场景下可能放大拒绝服务攻击——攻击者通过使认证服务过载，间接阻止所有合法用户的访问。需要有意识地决定哪些检查点可以Fail-Open并有补偿控制。

8. **错误。** 脱敏必须在记录前处理。日志一旦写入（尤其是被转发到第三方日志聚合服务），就可能被未授权访问。事后脱敏的数据可能已被缓存在多个中间系统中。

9. **正确。** 安全价值：阻止对故障服务的重复攻击，防止级联故障被利用为DoS。可靠性价值：防止级联故障扩散，给下游服务恢复时间。
</details>

### 三、代码分析题（15分）

10. 以下错误处理代码中有多个安全问题，请指出：

```rust

    let db = Database::connect("postgres://admin:secret@10.0.1.5:5432/prod")?;
    let query = format!("SELECT * FROM users WHERE id = '{}'", user_input);
    let result = db.execute(&query).map_err(|e| format!("DB error: {}", e))?;
```

<details>
<summary>查看答案</summary>

**安全问题分析：**

1. **硬编码数据库凭证**：`admin:secret@10.0.1.5:5432/prod` 暴露了生产数据库的IP、端口、用户名、密码。应使用环境变量或密钥管理服务。

2. **SQL注入**：`format!("SELECT * FROM users WHERE id = '{}'", user_input)` 直接将用户输入拼接到SQL中。应使用参数化查询。

3. **错误信息泄露**：`"DB error: {}".e` 将数据库错误直接返回给调用者，可能包含表名、字段名等内部信息。应对客户端返回通用错误，详细错误仅记录到日志。

4. **返回String错误**：使用`String`而非类型化错误使得安全策略无法依据错误类型做出不同响应。

**修正：**

```rust
fn handle_request(user_input: &str) -> Result<String, ClientError> {
    let db_url = std::env::var("DATABASE_URL")
        .map_err(|_| ClientError::InternalServerError)?;
    let pool = Database::connect(&db_url)
        .map_err(|e| {
            tracing::error!(error = %e, "数据库连接失败");
            ClientError::InternalServerError
        })?;

    // 参数化查询
    let result = sqlx::query_as::<_, User>("SELECT * FROM users WHERE id = $1")
        .bind(user_input)
        .fetch_one(&pool)
        .await
        .map_err(|e| {
            tracing::error!(error = %e, user_id = %user_input, "查询失败");
            match e {
                sqlx::Error::RowNotFound => ClientError::ResourceUnavailable,
                _ => ClientError::InternalServerError,
            }
        })?;

    Ok(result)
}
```

<details>
<summary>查看答案</summary>

```rust
use chrono::{DateTime, Utc};
use serde::Serialize;
use std::collections::HashMap;
use std::sync::Mutex;
use zeroize::Zeroize;

#[derive(Debug, Clone, Serialize)]
pub struct AuditEntry {
    pub who: String,          // 用户ID或服务ID
    pub what: String,         // 操作类型
    pub when: DateTime<Utc>,  // 时间戳
    pub r#where: String,      // 来源IP/源服务
    pub result: String,       // success/failure/denied
    #[serde(skip_serializing_if = "Option::is_none")]
    pub metadata: Option<HashMap<String, String>>,
}

#[derive(Clone)]
pub struct SecureLogger {
    audit_log: std::sync::Arc<Mutex<Vec<AuditEntry>>>,
    sensitive_keys: std::sync::Arc<Vec<&'static str>>,
}

impl SecureLogger {
    pub fn new() -> Self {
        Self {
            audit_log: std::sync::Arc::new(Mutex::new(Vec::new())),
            sensitive_keys: std::sync::Arc::new(vec![
                "password", "secret", "token", "key", "credential",
            ]),
        }
    }

    pub fn log_audit(&self, entry: AuditEntry) {
        let mut sanitized = entry.clone();

        // 脱敏metadata中的敏感字段
        if let Some(ref mut meta) = sanitized.metadata {
            for key in self.sensitive_keys.iter() {
                for (mk, mv) in meta.iter_mut() {
                    if mk.to_lowercase().contains(key) {
                        mv.zeroize();
                        *mv = "***REDACTED***".to_string();
                    }
                }
            }
        }

        // 同时写入结构化日志
        tracing::info!(
            target: "audit",
            security_event = true,
            who = %sanitized.who,
            what = %sanitized.what,
            when = %sanitized.when.to_rfc3339(),
            location = %sanitized.r#where,
            result = %sanitized.result,
            "审计事件"
        );

        if let Ok(mut log) = self.audit_log.lock() {
            log.push(sanitized);
        }
    }

    pub fn log_debug<M: AsRef<str>>(&self, message: M) {
        // 调试日志也需脱敏但不需要完整审计格式
        let sanitized = self.sanitize_string(message.as_ref());
        tracing::debug!("{}", sanitized);
    }

    fn sanitize_string(&self, input: &str) -> String {
        let mut result = input.to_string();
        for key in self.sensitive_keys.iter() {
            // 匹配 key=value 模式
            let pattern = format!("{}=", key);
            if let Some(pos) = result.to_lowercase().find(&pattern) {
                let start = pos + pattern.len();
                if let Some(end) = result[start..].find(&[',', ' ', '\n', ';', '&']) {
                    result.replace_range(start..start+end, "***REDACTED***");
                } else {
                    result.replace_range(start.., "***REDACTED***");
                }
            }
        }
        result
    }

    pub fn flush_audit_log(&self) -> Vec<AuditEntry> {
        let mut log = self.audit_log.lock().unwrap();
        std::mem::take(&mut *log)
    }
}
```

## 本章小结

安全错误处理是信息安全的"最后一公里"防线。即使所有安全机制都正确工作，如果错误消息中泄露了内部信息，攻击者也能获得宝贵的侦察情报。

本章建立了三层防御体系：第一层通过类型系统（`thiserror`）确保内部错误不会自动传播给客户端；第二层通过日志脱敏中间件确保审计日志和调试日志都不会泄露敏感数据；第三层通过速率限制和熔断器确保系统在遭受攻击时能安全降级。

Fail-Closed是安全系统的首要原则——当无法确定某事是否安全时，默认拒绝。但这需要权衡可用性：严格Fail-Closed可能导致合法用户被拒绝，因此需要在关键检查点设置合理的补偿控制。

记住：对于攻击者而言，错误信息往往是比正常响应更有价值的情报来源。只有确保你的系统在出错时和正常运行时一样安全，才能真正建立起纵深防御。
