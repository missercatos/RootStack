# 安全错误处理

## 原理

企业级错误处理的三大安全维度：

**错误信息泄漏**：外部错误消息不得暴露内部实现细节（栈追踪、文件路径、数据库结构、内部 IP）。区分 internal error（日志）和 public error（客户端返回）。

**错误处理完整性**：所有 IO 操作、网络请求、解析、转换必须处理 `Result`。库代码不应 `unwrap()` 或 `expect()`（除在已证明的不变量处）。应用层可 panic 但应有全局 `set_hook`。

**错误类型体系**：使用 `thiserror` 构建结构化错误类型，使用 `anyhow` 简化应用层错误传播。库层提供枚举错误类型供调用者匹配，应用层可使用 `Box<dyn Error>` 或 `anyhow::Error`。

**安全失败的默认策略**：权限检查失败 → 拒绝访问（而非默许）。加密失败 → 中止（而非降级明文）。验证失败 → 回滚事务。

## 错误处理哲学：没有异常

Rust 不存在异常机制。所有可恢复错误通过 `Result<T, E>` 传播，不可恢复错误通过 `panic!` 终止程序。

**与 Java/Python/Go 的对比**：

| 语言 | 错误机制 | 强制处理 | 零成本 |
|------|---------|---------|-------|
| Java | try-catch 异常 | 否（可忽略 checked） | 异常对象分配 |
| Python | try-except 异常 | 否 | 异常栈展开 |
| Go | 多返回值 `if err != nil` | 否（可忽略） | 无 |
| Rust | `Result<T, E>` + `?` | 是（编译器强制） | 零成本（类型擦除前） |

**Rust 的设计哲学**：

```rust
// 这是错误的 — 编译器强制你处理错误
let file = File::open("config.toml");  // 返回 Result<File, Error>

// 你必须选择：
// 1. ? 传播错误
fn read_config() -> Result<Config, Box<dyn Error>> {
    let file = File::open("config.toml")?;  // 传播
    // ...
    Ok(config)
}

// 2. unwrap/expect — 仅用于不可恢复场景
let file = File::open("config.toml").expect("config file must exist");

// 3. match 处理
let file = match File::open("config.toml") {
    Ok(f) => f,
    Err(e) => {
        eprintln!("failed to open config: {}", e);
        return Err(e.into());
    }
};

// 4. 组合器链式调用
let file = File::open("config.toml")
    .map_err(|e| format!("open failed: {}", e))?
    .metadata()?
    .len();
```

## thiserror — 库层结构化错误

`thiserror` 是派生宏，自动为枚举实现 `std::error::Error` trait：

```rust
use thiserror::Error;

#[derive(Error, Debug)]
pub enum ServiceError {
    // 简单错误 — 带格式化消息
    #[error("authentication failed for user: {username}")]
    AuthFailed {
        username: String,
        reason: String,
    },

    // 自动从底层错误转换（#[from]）
    #[error("database error: {0}")]
    Database(#[from] sqlx::Error),

    // 自动转换并附加上下文
    #[error("configuration error: {0}")]
    Config(#[from] config::ConfigError),

    // 手动转换（不自动 #[from]）
    #[error("validation failed: {field} - {message}")]
    Validation {
        field: String,
        message: String,
    },

    // 业务逻辑错误
    #[error("resource not found: {resource} with id {id}")]
    NotFound {
        resource: String,
        id: String,
    },

    // 内部错误 — 不暴露给外部
    #[error("internal error (ref: {ref_id})")]
    Internal {
        ref_id: String,
        #[source]  // 标记内部原因（不显示给用户）
        source: anyhow::Error,
    },

    // 超时错误
    #[error("operation timed out after {seconds}s")]
    Timeout { seconds: u64 },

    // 权限错误
    #[error("permission denied: requires {required_permission}")]
    PermissionDenied {
        required_permission: String,
    },
}

// 从任意类型转换
impl From<&str> for ServiceError {
    fn from(s: &str) -> Self {
        ServiceError::Validation {
            field: "unknown".into(),
            message: s.into(),
        }
    }
}
```

**`thiserror` 派生宏的属性**：

| 属性 | 作用 | 示例 |
|------|------|------|
| `#[error("msg")]` | Display 实现 | `#[error("failed to read {path}")]` |
| `#[from]` | 自动实现 `From<E>` | `#[from] sqlx::Error` |
| `#[source]` | 标记内部错误源 | `#[source] anyhow::Error` |
| `#[transparent]` | 透传 Display/Source | 委托给内部类型 |

**错误类型设计原则**：

```rust
// ✅ 库层错误：每个变体是一个独立错误类型
#[derive(Error, Debug)]
pub enum ParseError {
    #[error("unexpected token: expected {expected}, got {got}")]
    UnexpectedToken { expected: String, got: String },

    #[error("unexpected end of input")]
    UnexpectedEof,

    #[error("invalid number: {0}")]
    InvalidNumber(String),
}

// ✅ 通过 std::error::Error::source() 链接内部错误
#[derive(Error, Debug)]
pub enum StorageError {
    #[error("IO error while {operation}")]
    Io {
        operation: String,
        #[source] source: std::io::Error,
    },

    #[error("serialization failed")]
    Serialization(#[from] serde_json::Error),
}

// ❌ 错误：暴露内部实现细节给外部
#[derive(Error, Debug)]
pub enum BadError {
    #[error("column 'users.email' violates unique constraint at line 42")]
    DbInternal { sql_state: String, line: u32 },  // 暴露 DB 结构
}
```

## anyhow — 应用层简化

`anyhow` 是应用层错误处理库，提供动态类型的错误包装：

```rust
use anyhow::{anyhow, bail, ensure, Context, Result};

// anyhow::Result = Result<T, anyhow::Error>

fn read_config(path: &str) -> Result<Config> {
    // Context trait — 为 Result 附加上下文
    let content = std::fs::read_to_string(path)
        .context(format!("failed to read config from {}", path))?;

    // anyhow! — 创建自定义错误
    let config: Config = toml::from_str(&content)
        .map_err(|e| anyhow!("failed to parse config: {}", e))?;

    // bail! — 提前返回错误
    if config.name.is_empty() {
        bail!("config name cannot be empty");
    }

    // ensure! — 断言式错误检查
    ensure!(
        config.port > 0 && config.port < 65535,
        "invalid port: {}",
        config.port
    );

    Ok(config)
}

// 错误链式传播
fn process_data(input: &str) -> Result<String> {
    let parsed = parse_input(input)
        .context("failed to parse input")?;

    let validated = validate(parsed)
        .context("validation failed")?;

    let transformed = transform(validated)
        .context("transformation failed")?;

    Ok(transformed)
}

// anyhow 支持任意类型的错误
fn multi_error() -> Result<()> {
    let io_err = std::io::Error::new(std::io::ErrorKind::NotFound, "file missing");
    let parse_err = "not a number".parse::<i32>().unwrap_err();

    // 可以返回任何实现了 std::error::Error 的类型
    Err(io_err.into())
}
```

**`anyhow` 的核心 API**：

| API | 作用 | 使用场景 |
|-----|------|---------|
| `.context(msg)` | 为 Result 附加上下文 | 传播时添加信息 |
| `anyhow!(msg)` | 创建自定义错误 | 动态错误消息 |
| `bail!(msg)` | 等价于 `return Err(anyhow!(msg))` | 提前返回错误 |
| `ensure!(cond, msg)` | 条件不满足时返回错误 | 断言式检查 |
| `anyhow::Error::downcast_ref::<T>()` | 尝试向下转型 | 匹配特定错误类型 |

## 错误转换链

错误在不同层之间传播时，每一层都可以添加上下文：

```rust
// 底层：IO 错误
fn read_file(path: &str) -> Result<String, std::io::Error> {
    std::fs::read_to_string(path)
}

// 中间层：解析错误
fn parse_config(path: &str) -> Result<Config, anyhow::Error> {
    let content = read_file(path)
        .context(format!("reading config file: {}", path))?;
    // 错误链: "reading config file: config.toml: No such file or directory"

    let config: Config = toml::from_str(&content)
        .context("parsing config")?;
    // 错误链: "reading config file: ... -> parsing config: invalid TOML"

    Ok(config)
}

// 应用层：业务错误
fn init_app() -> Result<(), anyhow::Error> {
    let config = parse_config("config.toml")
        .context("application initialization")?;
    // 错误链完整展示所有上下文
    Ok(())
}
```

**错误链的访问**：

```rust
use anyhow::Result;

fn example() -> Result<()> {
    let outer = read_file("missing.txt")
        .context("outer context")?;

    Ok(())
}

// 错误链输出:
// outer context: No such file or directory (os error 2)

// 访问错误链
fn inspect_error_chain(err: &anyhow::Error) {
    // 当前错误
    println!("Error: {}", err);

    // 源错误
    if let Some(source) = err.source() {
        println!("Caused by: {}", source);
    }

    // 完整链
    for cause in err.chain() {
        println!("  -> {}", cause);
    }
}
```

## panic vs Result

### 何时使用 panic

`panic!` 用于不可恢复的错误——程序无法安全继续执行：

```rust
// 1. 不变量被破坏（逻辑错误）
fn get_element(index: usize, data: &[i32]) -> i32 {
    assert!(index < data.len(), "index out of bounds: {} >= {}", index, data.len());
    data[index]
}

// 2. 初始化时配置错误（启动失败）
fn init_database() -> Database {
    let url = std::env::var("DATABASE_URL")
        .expect("DATABASE_URL environment variable must be set");
    Database::connect(&url).expect("failed to connect to database")
}

// 3. 数组越界
let arr = [1, 2, 3];
// let x = arr[10];  // panic: index out of bounds

// 4. unwrap() 在已证明不会失败的场景
fn read_u32(s: &str) -> u32 {
    // 已验证 s 只包含数字
    s.parse::<u32>().unwrap()  // 如果这里 panic，说明验证逻辑有 bug
}

// 5. 全局 panic hook — 捕获所有 panic
use std::panic;
panic::set_hook(Box::new(|info| {
    let location = info.location()
        .map(|l| format!("{}:{}:{}", l.file(), l.line(), l.column()))
        .unwrap_or_else(|| "unknown".to_string());
    let payload = info.payload().downcast_ref::<String>()
        .map(|s| s.as_str())
        .or_else(|| info.payload().downcast_ref::<&str>())
        .unwrap_or("no message");
    tracing::error!(
        panic_location = %location,
        panic_message = %payload,
        "application panic"
    );
    // 可选：发送到监控系统
    std::process::abort();
}));
```

### 何时使用 Result

`Result` 用于可恢复的错误——程序可以优雅地处理或传播：

```rust
// 1. IO 操作（文件可能不存在、权限不足等）
fn read_user(id: u64) -> Result<User, io::Error> {
    let path = format!("users/{}.json", id);
    let content = std::fs::read_to_string(&path)?;
    let user = serde_json::from_str(&content)?;
    Ok(user)
}

// 2. 网络请求（可能超时、连接失败等）
async fn fetch_data(url: &str) -> Result<Response, reqwest::Error> {
    reqwest::get(url).await?.json().await
}

// 3. 解析/验证（用户输入可能无效）
fn parse_port(s: &str) -> Result<u16, ParseError> {
    let port: u16 = s.parse().map_err(|_| ParseError::InvalidPort(s.to_string()))?;
    if port == 0 {
        return Err(ParseError::InvalidPort("port cannot be 0".into()));
    }
    Ok(port)
}

// 4. 库代码 — 永远不 panic，返回 Result 让调用者决定
pub fn process(input: &str) -> Result<Output, Error> {
    let parsed = parse(input)?;
    let validated = validate(parsed)?;
    Ok(Output::from(validated))
}
```

## 错误处理模式

### 模式 1: 错误恢复

```rust
fn fetch_with_fallback(url: &str) -> Result<String> {
    // 尝试主 URL
    match reqwest::blocking::get(url) {
        Ok(resp) if resp.status().is_success() => {
            return Ok(resp.text()?);
        }
        Ok(resp) => {
            tracing::warn!("primary returned status {}", resp.status());
        }
        Err(e) => {
            tracing::warn!("primary failed: {}", e);
        }
    }

    // 回退到备用 URL
    let fallback_url = url.replace("primary", "fallback");
    let resp = reqwest::blocking::get(&fallback_url)
        .context("both primary and fallback failed")?;
    Ok(resp.text()?)
}
```

### 模式 2: 错误累积

```rust
fn validate_user(user: &User) -> Result<(), Vec<ValidationError>> {
    let mut errors = Vec::new();

    if user.name.is_empty() {
        errors.push(ValidationError::EmptyName);
    }
    if !user.email.contains('@') {
        errors.push(ValidationError::InvalidEmail);
    }
    if user.age < 0 || user.age > 150 {
        errors.push(ValidationError::InvalidAge);
    }

    if errors.is_empty() {
        Ok(())
    } else {
        Err(errors)
    }
}

// 使用
match validate_user(&user) {
    Ok(()) => println!("valid"),
    Err(errors) => {
        for err in errors {
            eprintln!("validation error: {}", err);
        }
    }
}
```

### 模式 3: 错误类型擦除与向下转型

```rust
use anyhow::anyhow;

fn handle_error(err: anyhow::Error) {
    // 尝试向下转型为特定错误类型
    if let Some(io_err) = err.downcast_ref::<std::io::Error>() {
        match io_err.kind() {
            std::io::ErrorKind::NotFound => {
                println!("file not found, creating default");
            }
            std::io::ErrorKind::PermissionDenied => {
                println!("permission denied, check file permissions");
            }
            _ => {
                println!("other IO error: {}", io_err);
            }
        }
    } else if let Some(db_err) = err.downcast_ref::<sqlx::Error>() {
        // 处理数据库错误
    } else {
        println!("unknown error: {}", err);
    }
}
```

### 模式 4: 错误隔离（Error Boundary）

```rust
// 库层提供具体错误类型
#[derive(Error, Debug)]
pub enum ApiError {
    #[error("not found")]
    NotFound,
    #[error("unauthorized")]
    Unauthorized,
    #[error("internal error")]
    Internal(#[from] anyhow::Error),
}

// 应用层将具体错误转为 HTTP 响应
fn error_to_response(err: &ApiError) -> HttpResponse {
    match err {
        ApiError::NotFound => HttpResponse::NotFound().json("not found"),
        ApiError::Unauthorized => HttpResponse::Unauthorized().json("unauthorized"),
        ApiError::Internal(_) => {
            // 不暴露内部错误详情给客户端
            HttpResponse::InternalServerError().json("internal server error")
        }
    }
}

// 内部日志记录完整错误
fn handle_request() -> Result<Response, ApiError> {
    let result = process_request().map_err(|e| {
        tracing::error!("request failed: {:?}", e);  // 完整错误
        ApiError::Internal(e)  // 不暴露给外部
    })?;
    Ok(result)
}
```

### 模式 5: 重试与幂等

```rust
use std::time::Duration;

fn retry_with_backoff<F, T, E>(max_retries: u32, mut f: F) -> Result<T, E>
where
    F: FnMut() -> Result<T, E>,
    E: std::fmt::Display,
{
    let mut last_err = None;

    for attempt in 0..=max_retries {
        match f() {
            Ok(val) => return Ok(val),
            Err(e) => {
                tracing::warn!("attempt {} failed: {}", attempt + 1, e);
                last_err = Some(e);
                if attempt < max_retries {
                    let delay = Duration::from_millis(100 * 2u64.pow(attempt));
                    std::thread::sleep(delay);
                }
            }
        }
    }

    Err(last_err.unwrap())
}

// 使用
let result = retry_with_backoff(3, || {
    reqwest::blocking::get("https://api.example.com/data")?
        .error_for_status()?
        .json()
});
```

## CWE-209 防范：错误信息泄漏

```rust
// ❌ 危险：暴露内部细节
fn bad_handler(id: u64) -> Result<User, String> {
    let user = db.query(&format!(
        "SELECT * FROM users WHERE id = {}",  // 暴露 SQL
    )).map_err(|e| format!(
        "Database error at line 42: {} from table 'users'",  // 暴露表名
    ))?;
    Ok(user)
}

// ✅ 安全：区分内部和外部错误
fn safe_handler(id: u64) -> Result<User, ServiceError> {
    let user = db.find_user(id)
        .map_err(|e| {
            // 内部日志：完整错误信息
            tracing::error!(user_id = id, error = %e, "database query failed");
            // 外部：通用错误消息
            ServiceError::Internal {
                ref_id: uuid::Uuid::new_v4().to_string(),
                source: e.into(),
            }
        })?;
    Ok(user)
}

// ✅ 安全：验证错误不暴露业务逻辑
fn validate_password(password: &str) -> Result<(), String> {
    if password.len() < 8 {
        // 不说具体要求（"must be at least 8 characters" 可以）
        // 但不说 "must contain uppercase, lowercase, digit, and symbol"
        return Err("password too short".into());
    }
    Ok(())
}
```
