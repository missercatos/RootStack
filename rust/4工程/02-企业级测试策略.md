# 企业级测试策略

## 原理

Rust 测试体系分为三层：

**单元测试**：`#[cfg(test)] mod tests { #[test] fn ... }`，通常与源码放在同一文件。`cargo test` 运行所有单元测试。

**集成测试**：放在 `tests/` 目录下，每个文件编译为独立 crate。用于测试公开 API 和黑盒行为。`cargo test --test integration_test` 运行指定集成测试。

**文档测试**：`//! ```rust` 代码块在 `cargo test` 时编译运行，确保 doc 中的示例代码始终有效。

**基准测试**：`#[bench]` 在 nightly channel 可用，或使用 `criterion` crate（稳定渠道）。

### 测试分层策略

| 层级 | 目标 | 速度 | 覆盖率要求 |
|------|------|------|-----------|
| 单元测试 | 函数/模块 | 毫秒级 | >80% |
| 集成测试 | 模块间交互 | 秒级 | 关键路径 100% |
| E2E 测试 | 完整业务流程 | 分钟级 | 核心场景 |
| 基准测试 | 性能回归 | 秒-分钟 | 关键热路径 |

Mock 和依赖注入通过 `mockall` crate 实现自动化 mock 生成。

## cfg(test) 模块深入

### 为什么用 `#[cfg(test)]`

`#[cfg(test)]` 是编译期条件编译：只在 `cargo test` 时编译该模块。这意味着：

1. **零生产开销**：测试代码不进入生产二进制
2. **访问私有函数**：测试模块在同文件内，可访问 `pub(crate)` 和私有函数
3. **测试辅助函数**：可在模块内定义仅测试使用的辅助函数

```rust
// src/lib.rs
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

// 私有函数 — 单元测试可以访问
fn validate_input(n: i32) -> bool {
    n >= 0 && n <= 1000
}

pub fn validated_add(a: i32, b: i32) -> Result<i32, String> {
    if validate_input(a) && validate_input(b) {
        Ok(a + b)
    } else {
        Err("input out of range".into())
    }
}

#[cfg(test)]
mod tests {
    use super::*;  // 导入父模块所有公开和私有项

    #[test]
    fn test_add_basic() {
        assert_eq!(add(2, 3), 5);
    }

    // 测试私有函数 — 单元测试特权
    #[test]
    fn test_validate_input() {
        assert!(validate_input(0));
        assert!(validate_input(500));
        assert!(validate_input(1000));
        assert!(!validate_input(-1));
        assert!(!validate_input(1001));
    }

    // 测试边界条件
    #[test]
    fn test_validated_add_boundary() {
        assert_eq!(validated_add(0, 0), Ok(0));
        assert_eq!(validated_add(1000, 0), Ok(1000));
        assert!(validated_add(1001, 0).is_err());
    }

    // 测试预期 panic
    #[test]
    #[should_panic(expected = "overflow")]
    fn test_overflow_panic() {
        // 自定义 panic 消息
        panic!("overflow: result exceeds maximum");
    }

    // 测试返回 Result 的函数（? 操作符可用）
    #[test]
    fn test_with_result() -> Result<(), String> {
        let result = validated_add(10, 20)?;
        assert_eq!(result, 30);
        Ok(())
    }

    // 测试被忽略（临时跳过）
    #[test]
    #[ignore]
    fn expensive_test() {
        // 耗时测试，cargo test -- --ignored 才运行
        std::thread::sleep(std::time::Duration::from_secs(60));
    }
}
```

### 测试辅助模式

```rust
#[cfg(test)]
mod tests {
    use super::*;

    // 测试固定器（Fixture）— 复用测试数据
    fn create_test_db() -> Database {
        Database::new(":memory:").expect("failed to create test db")
    }

    // 初始化日志 — 仅测试时启用
    fn init_test_logging() {
        let _ = tracing_subscriber::fmt()
            .with_test_mode(true)  // 启用 test output
            .try_init();
    }

    // 并行安全的临时目录
    fn temp_dir() -> tempfile::TempDir {
        tempfile::tempdir().expect("failed to create temp dir")
    }

    #[test]
    fn test_database_operations() {
        init_test_logging();
        let db = create_test_db();

        // 测试插入
        db.insert("key", "value").unwrap();
        assert_eq!(db.get("key").unwrap(), Some("value".to_string()));

        // 测试删除
        db.delete("key").unwrap();
        assert_eq!(db.get("key").unwrap(), None);
    }

    // 带自定义错误消息的断言
    #[test]
    fn test_with_message() {
        let data = vec![1, 2, 3];
        assert!(
            data.contains(&2),
            "expected data to contain 2, got: {:?}",
            data
        );
    }

    // 测试浮点数近似相等
    #[test]
    fn test_float_approx() {
        let result = 0.1 + 0.2;
        assert!(
            (result - 0.3).abs() < f64::EPSILON,
            "floating point mismatch: {} != 0.3",
            result
        );
    }
}
```

## 单元测试 vs 集成测试

### 单元测试特点

- 位于 `src/` 内的 `#[cfg(test)] mod tests`
- 可访问私有函数和内部状态
- 测试粒度：单个函数或小模块
- 速度：毫秒级
- 依赖：直接 `use super::*`

### 集成测试特点

- 位于 `tests/` 目录
- 每个文件是独立 crate
- 只能访问 `pub` API
- 测试粒度：模块间交互
- 速度：秒级（需编译）
- 依赖：通过 `use my_crate::*` 导入

```
my_project/
├── src/
│   └── lib.rs              # 单元测试在 lib.rs 内
├── tests/
│   ├── api_test.rs          # 集成测试 1（独立 crate）
│   ├── database_test.rs     # 集成测试 2（独立 crate）
│   └── common/
│       └── mod.rs           # 集成测试的共享辅助模块
└── Cargo.toml
```

```rust
// tests/api_test.rs — 集成测试（独立 crate）
use my_project::api::Client;  // 只能访问 pub API

#[tokio::test]
async fn test_api_client() {
    let client = Client::new("http://localhost:8080");
    let response = client.get("/health").await.unwrap();
    assert_eq!(response.status(), 200);
}
```

```rust
// tests/common/mod.rs — 集成测试共享辅助
pub fn setup() {
    // 初始化测试环境
    tracing_subscriber::fmt()
        .with_test_mode(true)
        .try_init()
        .ok();
}

pub fn test_db_url() -> String {
    std::env::var("TEST_DATABASE_URL")
        .unwrap_or_else(|_| "sqlite::memory:".to_string())
}
```

### cargo test 的筛选

```bash
# 运行所有测试
cargo test

# 运行名称包含 "add" 的测试
cargo test add

# 运行指定集成测试文件
cargo test --test api_test

# 运行指定模块的测试
cargo test tests::test_add

# 运行被忽略的测试
cargo test -- --ignored

# 运行所有测试包括被忽略的
cargo test -- --include-ignored

# 单线程运行（测试有共享状态时）
cargo test -- --test-threads=1

# 显示测试输出（默认被成功测试抑制）
cargo test -- --nocapture

# 列出所有测试（不运行）
cargo test -- --list
```

## 文档测试

文档测试是 Rust 独特的测试机制：doc comment 中的代码块在 `cargo test` 时编译运行。

```rust
/// 计算两个数的和。
///
/// # Examples
///
/// ```
/// use my_crate::add;
/// assert_eq!(add(2, 3), 5);
/// ```
///
/// # Panics
///
/// 当输入为负数时 panic：
///
/// ```should_panic
/// use my_crate::add;
/// add(-1, 0);
/// ```
///
/// 返回 Result 的函数：
///
/// ```
/// # fn main() -> Result<(), String> {
/// use my_crate::validated_add;
/// let result = validated_add(10, 20)?;
/// assert_eq!(result, 30);
/// # Ok(())
/// # }
/// ```
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

// 隐藏文档测试的辅助代码
/// 使用示例：
///
/// ```
/// # // 以 # 开头的行在文档中不显示，但会编译
/// # fn main() {
/// let mut map = std::collections::HashMap::new();
/// map.insert("key", "value");
/// assert_eq!(map.get("key"), Some(&"value"));
/// # }
/// ```
pub fn example() {}
```

## mockall — Mock 测试

```rust
use mockall::automock;
use mockall::predicate::*;

// 定义 trait
#[automock]  // 自动生成 MockTraitName
trait UserRepository {
    fn find_by_id(&self, id: u64) -> Result<User, Error>;
    fn save(&self, user: &User) -> Result<(), Error>;
    fn count(&self) -> Result<usize, Error>;
}

// 服务依赖 trait
struct UserService {
    repo: Box<dyn UserRepository>,
}

impl UserService {
    fn new(repo: Box<dyn UserRepository>) -> Self {
        Self { repo }
    }

    fn get_user(&self, id: u64) -> Result<User, Error> {
        self.repo.find_by_id(id)
    }

    fn create_user(&self, name: &str) -> Result<User, Error> {
        let user = User { id: 0, name: name.to_string() };
        self.repo.save(&user)?;
        Ok(user)
    }
}

#[cfg(test)]
mod tests {
    use super::*;
    use mockall::predicate;

    #[test]
    fn test_get_user() {
        let mut mock_repo = MockUserRepository::new();

        // 设置期望
        mock_repo
            .expect_find_by_id()
            .with(predicate::eq(42))           // 参数精确匹配
            .times(1)                           // 只调用一次
            .returning(|id| {
                Ok(User { id, name: "Alice".into() })
            });

        let service = UserService::new(Box::new(mock_repo));
        let user = service.get_user(42).unwrap();
        assert_eq!(user.name, "Alice");
    }

    #[test]
    fn test_create_user() {
        let mut mock_repo = MockUserRepository::new();

        mock_repo
            .expect_save()
            .times(1)
            .returning(|_| Ok(()));

        let service = UserService::new(Box::new(mock_repo));
        let user = service.create_user("Bob").unwrap();
        assert_eq!(user.name, "Bob");
    }

    #[test]
    fn test_user_not_found() {
        let mut mock_repo = MockUserRepository::new();

        mock_repo
            .expect_find_by_id()
            .returning(|_| Err(Error::NotFound));

        let service = UserService::new(Box::new(mock_repo));
        assert!(service.get_user(999).is_err());
    }
}
```

## proptest — 属性测试

属性测试不手动构造测试用例，而是声明属性（不变量），由框架自动生成随机输入并验证：

```rust
#[cfg(test)]
mod tests {
    use proptest::prelude::*;

    // 为自定义类型实现 Arbitrary
    #[derive(Debug, Clone)]
    struct Point {
        x: f64,
        y: f64,
    }

    impl Point {
        fn distance_to_origin(&self) -> f64 {
            (self.x * self.x + self.y * self.y).sqrt()
        }
    }

    // 自定义 Arbitrary 实现
    impl Arbitrary for Point {
        type Parameters = ();
        type Strategy = BoxedStrategy<Self>;

        fn arbitrary_with(_args: Self::Parameters) -> Self::Strategy {
            (-1000.0f64..1000.0)
                .prop_flat_map(|x| {
                    (-1000.0f64..1000.0).prop_map(move |y| Point { x, y })
                })
                .boxed()
        }
    }

    proptest! {
        // 属性 1: 加法交换律
        #[test]
        fn test_add_commutative(a: i32, b: i32) {
            prop_assert_eq!(add(a, b), add(b, a));
        }

        // 属性 2: 加法结合律
        #[test]
        fn test_add_associative(a: i32, b: i32, c: i32) {
            prop_assert_eq!(add(add(a, b), c), add(a, add(b, c)));
        }

        // 属性 3: 零元素
        #[test]
        fn test_add_identity(a: i32) {
            prop_assert_eq!(add(a, 0), a);
        }

        // 属性 4: 排序后有序
        #[test]
        fn test_sort_ordered(mut v: Vec<i32>) {
            v.sort();
            for w in v.windows(2) {
                prop_assert!(w[0] <= w[1]);
            }
        }

        // 属性 5: 距离非负
        #[test]
        fn test_distance_non_negative(point in any::<Point>()) {
            prop_assert!(point.distance_to_origin() >= 0.0);
        }

        // 属性 6: 编码解码往返
        #[test]
        fn test_encode_decode_roundtrip(s in ".*") {
            let encoded = encode(&s);
            let decoded = decode(&encoded).unwrap();
            prop_assert_eq!(s, decoded);
        }
    }
}
```

**proptest 的 Shrinking 机制**：

当测试失败时，proptest 会尝试 "缩小" 输入到最小的失败用例。例如：

```rust
proptest! {
    #[test]
    fn test_no_negative(v: Vec<i32>) {
        // 如果 v 包含负数就失败
        for &x in &v {
            prop_assert!(x >= 0, "found negative: {}", x);
        }
    }
}
// proptest 会输出:
// FAILED: Shrinking found: [-1]  ← 最小的失败输入
// 而不是原始的随机大 Vec
```

## criterion — 基准测试

```rust
// benches/my_benchmark.rs
use criterion::{black_box, criterion_group, criterion_main, Criterion};

fn fibonacci(n: u64) -> u64 {
    match n {
        0 => 0,
        1 => 1,
        _ => fibonacci(n - 1) + fibonacci(n - 2),
    }
}

fn criterion_benchmark(c: &mut Criterion) {
    // 基本基准测试
    c.bench_function("fib 20", |b| {
        b.iter(|| fibonacci(black_box(20)))
    });

    // 分组测试 — 对比不同实现
    let mut group = c.benchmark_group("fibonacci");
    for i in [10, 20, 30] {
        group.bench_with_input(format!("fib_{}", i), &i, |b, &i| {
            b.iter(|| fibonacci(black_box(i)));
        });
    }
    group.finish();

    // 测量吞吐量
    c.bench_function("vector allocation", |b| {
        b.iter(|| {
            let v: Vec<i32> = (0..1000).collect();
            black_box(v);
        })
    });
}

criterion_group!(benches, criterion_benchmark);
criterion_main!(benches);
```

```bash
# 运行基准测试
cargo bench

# 与上次结果对比
cargo bench -- --save-baseline before
cargo bench -- --baseline before

# 生成 HTML 报告
# (在 Cargo.toml 中配置 criterion features = ["html_reports"])
```

## 代码覆盖率

```bash
# 安装工具
cargo install cargo-tarpaulin

# 生成覆盖率报告
cargo tarpaulin --all-features

# 仅测试特定包
cargo tarpaulin -p my-crate

# 排除某些模块
cargo tarpaulin --exclude my_crate::tests --exclude my_crate::benches

# 输出格式
cargo tarpaulin --out Html      # HTML 报告
cargo tarpaulin --out Xml       # Cobertura XML（CI 集成）
cargo tarpaulin --out Json       # JSON 格式

# 设置覆盖率阈值（CI 中失败如果低于阈值）
cargo tarpaulin --fail-under 80
```

**覆盖率指标解释**：

| 指标 | 含义 | 目标 |
|------|------|------|
| 行覆盖率 | 被执行的代码行占比 | >80% |
| 函数覆盖率 | 被调用的函数占比 | >90% |
| 分支覆盖率 | 被执行的分支占比 | >70% |
| 区域覆盖率 | 被执行的区域占比 | >80% |

## CI/CD 集成

```yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

env:
  CARGO_TERM_COLOR: always
  RUSTFLAGS: -Dwarnings

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install Rust toolchain
        uses: dtolnay/rust-toolchain@stable
        with:
          components: rustfmt, clippy

      - name: Cache cargo registry
        uses: actions/cache@v4
        with:
          path: |
            ~/.cargo/registry
            ~/.cargo/git
            target
          key: ${{ runner.os }}-cargo-${{ hashFiles('**/Cargo.lock') }}

      - name: Check formatting
        run: cargo fmt --all -- --check

      - name: Run clippy
        run: cargo clippy --all-targets --all-features

      - name: Run tests
        run: cargo test --all-features

      - name: Security audit
        run: cargo install cargo-audit && cargo audit

      - name: Code coverage
        run: |
          cargo install cargo-tarpaulin
          cargo tarpaulin --all-features --fail-under 80 --out Xml

      - name: Upload coverage
        uses: codecov/codecov-action@v3
        with:
          file: cobertura.xml
```

**CI 优化技巧**：

1. **缓存依赖**：`~/.cargo/registry` 和 `target/` 目录
2. **并行任务**：clippy、fmt、test 可并行运行
3. **增量测试**：使用 `cargo nextest` 替代 `cargo test`（更快的测试运行器）
4. **依赖审计**：每次 PR 自动检查新引入的漏洞
