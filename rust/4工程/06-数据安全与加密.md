# 数据安全与加密

## 企业场景

某医疗SaaS平台存储着200万患者的电子健康记录（EHR）。在一次安全审计中发现：
1. 数据库中存储的用户密码使用SHA256（无盐）哈希——80%可在Rainbow Table中查到
2. 备份文件以明文存储在S3中，访问控制配置了一个过于宽松的IAM策略
3. API响应中包含完整的社会安全号码（SSN）和信用卡号，仅有客户端做掩码显示
4. 密钥硬编码在环境变量中，被CI日志意外记录

GDPR合规审计给予90天整改期，否则面临全球营收4%的罚款（约€2,400,000）。

## 1. 密码哈希：Argon2 — 为啥不用SHA256/bcrypt？

### 1.1 哈希算法对比

```rust
// ❌ 错误方式1：SHA256（无盐）
use sha2::{Sha256, Digest};
fn bad_hash(password: &str) -> String {
    let mut hasher = Sha256::new();
    hasher.update(password.as_bytes());
    format!("{:x}", hasher.finalize())
    // 问题：
    // 1. 无盐→Rainbow Table可破解
    // 2. 太快→GPU每秒可算数十亿次→暴力破解可行
    // 3. 相同密码产生相同哈希
}

// ❌ 错误方式2：单轮MD5
// 比SHA256更糟——已被证明碰撞

// ⚠️ 过时方式：bcrypt
// bcrypt曾是行业标准，但：
// - 最大密码长度限制为72字节（长密码被截断）
// - 内存硬化为0，对FPGA/ASIC攻击无防护

// ✅ 正确方式：Argon2id
use argon2::{
    password_hash::{
        rand_core::OsRng,
        PasswordHash, PasswordHasher, PasswordVerifier, SaltString,
    },
    Argon2, Params, Version,
};

pub struct PasswordManager {
    argon2: Argon2<'static>,
}

impl PasswordManager {
    /// 创建密码管理器（使用推荐参数）
    pub fn new() -> Self {
        // Argon2id: 混合Argon2d（抗GPU）和Argon2i（抗侧信道）
        let params = Params::new(
            19_456,    // m_cost: 19MB内存（使ASIC攻击成本高昂）
            2,         // t_cost: 2次迭代
            1,         // p_cost: 并行度1（Web服务不应并行hash）
            None,      // 输出长度（默认32字节）
        ).expect("Argon2参数构建失败");

        Self {
            argon2: Argon2::new(
                argon2::Algorithm::Argon2id,  // ✅ 混合模式
                Version::V0x13,               // 最新版本
                params,
            ),
        }
    }

    /// 哈希密码
    pub fn hash_password(&self, password: &[u8]) -> Result<String, HashError> {
        // 密码在传入前已验证长度和复杂度
        if password.is_empty() || password.len() > 128 {
            return Err(HashError::InvalidPasswordLength);
        }

        let salt = SaltString::generate(&mut OsRng);

        let password_hash = self.argon2
            .hash_password(password, &salt)
            .map_err(|e| HashError::HashingFailed(e.to_string()))?;

        // Argon2的PHC字符串格式自动包含算法、版本、参数、盐和哈希
        // 示例: $argon2id$v=19$m=19456,t=2,p=1$SALT$HASH
        Ok(password_hash.to_string())
    }

    /// 验证密码
    pub fn verify_password(
        &self,
        stored_hash: &str,
        attempted_password: &[u8],
    ) -> Result<bool, HashError> {
        let parsed_hash = PasswordHash::new(stored_hash)
            .map_err(|e| HashError::InvalidHashFormat(e.to_string()))?;

        // ⚠️ 使用verify_password而非重新哈希后比较
        // 这提供常量时间验证（防止时序攻击）
        Ok(self.argon2
            .verify_password(attempted_password, &parsed_hash)
            .is_ok())
    }
}

#[derive(Debug, thiserror::Error)]
pub enum HashError {
    #[error("密码长度无效")]
    InvalidPasswordLength,
    #[error("哈希失败: {0}")]
    HashingFailed(String),
    #[error("存储的哈希格式无效: {0}")]
    InvalidHashFormat(String),
}
```

## 2. 加密：AES-256-GCM（认证加密）

### 2.1 静态数据加密

```rust
use aes_gcm::{
    aead::{Aead, KeyInit, OsRng},
    Aes256Gcm, Nonce,
};
use zeroize::Zeroize;

pub struct DataEncryptor {
    cipher: Aes256Gcm,
}

impl DataEncryptor {
    /// 从密钥创建加密器
    pub fn new(key: &[u8; 32]) -> Self {
        let cipher = Aes256Gcm::new_from_slice(key)
            .expect("AES-256-GCM密钥创建失败");
        Self { cipher }
    }

    /// 生成新的256位随机密钥
    pub fn generate_key() -> [u8; 32] {
        use aes_gcm::aead::OsRng;
        let mut key = [0u8; 32];
        // ⚠️ 使用OsRng（操作系统级随机源）而非thread_rng
        use rand::RngCore;
        OsRng.fill_bytes(&mut key);
        key
    }

    /// 加密数据
    /// 返回: nonce (12 bytes) + ciphertext + tag (16 bytes)
    pub fn encrypt(&self, plaintext: &[u8]) -> Result<Vec<u8>, CryptoError> {
        use rand::RngCore;

        // 1. 生成随机的nonce（Number used ONCE）
        let mut nonce_bytes = [0u8; 12];
        OsRng.fill_bytes(&mut nonce_bytes);
        let nonce = Nonce::from_slice(&nonce_bytes);

        // 2. 加密（AES-256-GCM自动添加认证标签）
        let ciphertext = self.cipher
            .encrypt(nonce, plaintext)
            .map_err(|e| CryptoError::EncryptionFailed(e.to_string()))?;

        // 3. 前置nonce以便解密
        let mut output = Vec::with_capacity(12 + ciphertext.len());
        output.extend_from_slice(&nonce_bytes);
        output.extend_from_slice(&ciphertext);

        Ok(output)
    }

    /// 解密数据
    pub fn decrypt(&self, encrypted_data: &[u8]) -> Result<Vec<u8>, CryptoError> {
        if encrypted_data.len() < 28 {
            // 12 (nonce) + 16 (tag) = 28 bytes minimum
            return Err(CryptoError::InvalidCiphertext);
        }

        // 1. 分离nonce
        let (nonce_bytes, ciphertext) = encrypted_data.split_at(12);
        let nonce = Nonce::from_slice(nonce_bytes);

        // 2. 解密（自动验证认证标签）
        let plaintext = self.cipher
            .decrypt(nonce, ciphertext)
            .map_err(|e| CryptoError::IntegrityCheckFailed)?;

        Ok(plaintext)
    }

    /// 加密并有选择地包含关联数据（AAD）
    pub fn encrypt_with_aad(
        &self,
        plaintext: &[u8],
        associated_data: &[u8],  // 不加密但参与认证的额外数据
    ) -> Result<Vec<u8>, CryptoError> {
        use aes_gcm::aead::Aead;
        use rand::RngCore;

        let mut nonce_bytes = [0u8; 12];
        OsRng.fill_bytes(&mut nonce_bytes);
        let nonce = Nonce::from_slice(&nonce_bytes);

        let ciphertext = self.cipher
            .encrypt(nonce, aes_gcm::aead::Payload {
                msg: plaintext,
                aad: associated_data,
            })
            .map_err(|e| CryptoError::EncryptionFailed(e.to_string()))?;

        let mut output = Vec::with_capacity(12 + ciphertext.len());
        output.extend_from_slice(&nonce_bytes);
        output.extend_from_slice(&ciphertext);

        Ok(output)
    }
}

#[derive(Debug, thiserror::Error)]
pub enum CryptoError {
    #[error("加密失败: {0}")]
    EncryptionFailed(String),
    #[error("完整性检查失败——可能的数据篡改")]
    IntegrityCheckFailed,
    #[error("无效的密文格式")]
    InvalidCiphertext,
}
```

## 3. 密钥管理

### 3.1 密钥层级

```rust
/// 密钥管理层级结构
///
/// 主密钥 (Master Key) — 存储在HSM/KMS，永不离开安全硬件
///   ├── 数据加密密钥 (DEK) — 用主密钥加密存储
///   ├── 传输密钥 (TEK) — 用于TLS
///   └── 签名密钥 (Signing Key) — 用于JWT/代码签名

pub struct KeyHierarchy {
    /// 密钥加密密钥（KEK）— 从不直接用于数据加密
    /// 仅用于加密/解密DEK
    kek: [u8; 32],
}

impl KeyHierarchy {
    /// 生成新的数据加密密钥（DEK）
    pub fn generate_dek(&self) -> Result<EncryptedDeK, CryptoError> {
        let mut dek = [0u8; 32];
        OsRng.fill_bytes(&mut dek);

        // 生成DEK ID（用于密钥轮转）
        let dek_id = uuid::Uuid::new_v4().to_string();

        // 用KEK加密DEK生成EncryptedDeK
        let encryptor = DataEncryptor::new(&self.kek);
        let encrypted_dek = encryptor.encrypt(&dek)?;

        // ⚠️ 立即清零明文DEK
        dek.zeroize();

        Ok(EncryptedDeK {
            id: dek_id,
            encrypted_key: encrypted_dek,
            created_at: chrono::Utc::now(),
            algorithm: EncryptionAlgorithm::Aes256Gcm,
        })
    }

    /// 解封DEK（仅在需要加密/解密数据时临时解封）
    pub fn unwrap_dek(&self, encrypted_dek: &EncryptedDeK) -> Result<DataEncryptor, CryptoError> {
        let encryptor = DataEncryptor::new(&self.kek);
        let mut dek_bytes = encryptor.decrypt(&encrypted_dek.encrypted_key)?;

        let mut key = [0u8; 32];
        key.copy_from_slice(&dek_bytes[..32]);
        // ⚠️ 立即清零明文DEK字节
        dek_bytes.zeroize();

        Ok(DataEncryptor::new(&key))
    }
}

pub struct EncryptedDeK {
    pub id: String,
    pub encrypted_key: Vec<u8>,
    pub created_at: chrono::DateTime<chrono::Utc>,
    pub algorithm: EncryptionAlgorithm,
}

pub enum EncryptionAlgorithm {
    Aes256Gcm,
    ChaCha20Poly1305,
}

impl Drop for KeyHierarchy {
    fn drop(&mut self) {
        // 清理密钥材料
        self.kek.zeroize();
        // 注意：zeroize确保编译器不会"优化掉"清零操作
    }
}
```

### 3.2 使用AWS KMS / HashiCorp Vault

```rust
use aws_sdk_kms::Client as KmsClient;

pub struct KmsKeyManager {
    kms: KmsClient,
    key_id: String,
}

impl KmsKeyManager {
    pub fn new(kms: KmsClient, key_id: &str) -> Self {
        Self {
            kms,
            key_id: key_id.to_string(),
        }
    }

    /// 通过KMS加密数据（数据不超过4KB可直接KMS加密）
    pub async fn encrypt_with_kms(
        &self,
        plaintext: &[u8],
    ) -> Result<Vec<u8>, CryptoError> {
        let response = self.kms
            .encrypt()
            .key_id(&self.key_id)
            .plaintext(aws_sdk_kms::primitives::Blob::new(plaintext.to_vec()))
            .send()
            .await
            .map_err(|e| CryptoError::EncryptionFailed(e.to_string()))?;

        Ok(response.ciphertext_blob
            .ok_or(CryptoError::EncryptionFailed("空密文".to_string()))?
            .into_inner())
    }

    /// 信封加密模式（Envelope Encryption）
    /// 用于大数据量：用DEK加密数据，用KMS加密DEK
    pub async fn envelope_encrypt(
        &self,
        data: &[u8],
    ) -> Result<EnvelopeEncrypted, CryptoError> {
        // 1. 生成DEK
        let mut dek = [0u8; 32];
        OsRng.fill_bytes(&mut dek);

        // 2. 用DEK加密数据
        let data_encryptor = DataEncryptor::new(&dek);
        let encrypted_data = data_encryptor.encrypt(data)?;

        // 3. 用KMS加密DEK
        let encrypted_dek = self.encrypt_with_kms(&dek).await?;

        // 4. 清零明文DEK
        dek.zeroize();

        Ok(EnvelopeEncrypted {
            encrypted_data,
            encrypted_dek,
            key_id: self.key_id.clone(),
        })
    }
}

pub struct EnvelopeEncrypted {
    pub encrypted_data: Vec<u8>,
    pub encrypted_dek: Vec<u8>,
    pub key_id: String,
}
```

## 4. 常量时间比较：防止时序攻击

```rust
use subtle::ConstantTimeEq;

/// 密码验证中的时序攻击防护
///
/// 攻击者通过测量服务器响应时间来推测密码前缀：
/// 比较在第一个不同字符处短路→正确前缀需要更多时间=更长响应
/// 逐字符破解密码，时间复杂度从O(256^n)降为O(256*n)

// ❌ 易受时序攻击的比较
fn vulnerable_verify(expected: &[u8], actual: &[u8]) -> bool {
    if expected.len() != actual.len() {
        return false;  // ⚠️ 长度检查立即返回→泄露长度信息
    }
    for (a, b) in expected.iter().zip(actual.iter()) {
        if a != b {
            return false;  // ⚠️ 第一个不同字符立即返回→泄露前缀
        }
    }
    true
}

// ✅ 常量时间比较
use subtle::ConstantTimeEq;

fn constant_time_verify(expected: &[u8], actual: &[u8]) -> bool {
    // 1. 常量时间长度检查
    let len_eq = expected.len().ct_eq(&actual.len());

    // 2. 常量时间逐字节比较（使用subtle crate）
    let content_eq = expected.ct_eq(actual);

    // 3. 仅在两个条件都满足时返回true
    // 使用bitwise操作避免短路
    len_eq.into() && content_eq.into()
}

// MAC（消息认证码）验证必须常量时间
pub fn verify_hmac(expected: &[u8], actual: &[u8]) -> Result<(), HmacError> {
    if expected.ct_eq(actual).into() {
        Ok(())
    } else {
        Err(HmacError::InvalidMac)
    }
}

// API密钥验证（经常被忽略的时序攻击入口）
pub fn verify_api_key(stored_hash: &str, provided_key: &str) -> bool {
    // ⚠️ 不要直接比较存储的哈希（即使存储的是哈希）
    // 应使用常量时间比较
    let stored = hex::decode(stored_hash).unwrap_or_default();
    let mut hasher = hmac_sha256::Hash::hash(provided_key.as_bytes());
    stored.ct_eq(&hasher).into()
}
```

## 5. 敏感数据清零：zeroize

### 5.1 为什么需要zeroize？

```rust
// 编译器优化可能"优化掉"显式的清零操作
fn bad_clear_secret() {
    let mut secret_key = [0u8; 32];
    get_random_bytes(&mut secret_key);

    // 使用密钥...
    encrypt_with_key(&secret_key);

    // ⚠️ 显式清零——但编译器看到secret_key之后不再使用
    // 可能会优化掉这行代码！
    for byte in secret_key.iter_mut() {
        *byte = 0;
    }
    // secret_key仍可能留在栈上或寄存器中
}

// ✅ 使用zeroize crate——保证不被优化
use zeroize::Zeroize;

fn good_clear_secret() {
    let mut secret_key = [0u8; 32];
    get_random_bytes(&mut secret_key);

    encrypt_with_key(&secret_key);

    // zeroize使用volatile写入和内联汇编防止编译器优化
    secret_key.zeroize();
    // 确保密钥已从内存中清除
}

// zeroize还可以和derive一起使用
```

### 5.2 安全序列化（防止反序列化攻击）

```rust
use serde::{Deserialize, Serialize};
use serde_json;

/// 不受信任的反序列化→可能的攻击向量
///
/// 攻击者可以构造恶意JSON导致：
/// 1. 栈溢出（深层嵌套） → Rust安全代码中panic而非UB
/// 2. 拒绝服务（极大JSON） → 需要限制大小
/// 3. 类型混淆 → Rust的类型系统防止

pub fn safe_deserialize<'a, T: Deserialize<'a>>(
    data: &'a [u8],
    max_depth: usize,
) -> Result<T, DeserializeError> {
    // 1. 限制输入大小（防止内存耗尽）
    const MAX_SIZE: usize = 10 * 1024 * 1024; // 10MB
    if data.len() > MAX_SIZE {
        return Err(DeserializeError::InputTooLarge);
    }

    // 2. 限制嵌套深度（防止栈溢出）
    // serde_json默认递归深度为128，通常足够
    // 使用自定义深度限制：
    let mut deserializer = serde_json::Deserializer::from_slice(data);
    deserializer.disable_recursion_limit();

    let value = T::deserialize(&mut deserializer)
        .map_err(|e| DeserializeError::ParseError(e.to_string()))?;

    // 3. 验证嵌套深度
    if let Ok(json_value) = serde_json::from_slice::<serde_json::Value>(data) {
        let depth = calculate_depth(&json_value);
        if depth > max_depth {
            return Err(DeserializeError::DepthExceeded(depth));
        }
    }

    Ok(value)
}

fn calculate_depth(value: &serde_json::Value) -> usize {
    match value {
        serde_json::Value::Array(arr) => {
            1 + arr.iter().map(calculate_depth).max().unwrap_or(0)
        }
        serde_json::Value::Object(map) => {
            1 + map.values().map(calculate_depth).max().unwrap_or(0)
        }
        _ => 0,
    }
}

#[derive(Debug, thiserror::Error)]
pub enum DeserializeError {
    #[error("输入过大")]
    InputTooLarge,
    #[error("嵌套深度 {0} 超过限制")]
    DepthExceeded(usize),
    #[error("解析错误: {0}")]
    ParseError(String),
}
```

## 6. 安全随机数生成

```rust
use rand::RngCore;

/// ⚠️ 随机数来源的安全性对比
///
/// thread_rng():   CSPRNG（加密安全）— Web服务中推荐
/// OsRng:          操作系统熵源（/dev/urandom）— 密钥生成推荐
/// SmallRng:       XORShift算法— ⚠️ 不可用于安全目的
/// StdRng:         ChaCha12— 可用于安全，但thread_rng更方便
/// Pcg64:          预测性伪随机— ⚠️ 不可用于安全

pub struct SecureRandom;

impl SecureRandom {
    /// 生成加密安全的随机密钥
    pub fn generate_key(size: usize) -> Vec<u8> {
        let mut key = vec![0u8; size];
        OsRng.fill_bytes(&mut key);
        key
    }

    /// 生成加密安全的随机令牌
    pub fn generate_token(length: usize) -> String {
        let mut bytes = vec![0u8; length];
        OsRng.fill_bytes(&mut bytes);
        // 使用URL安全的base64（无+、/字符）
        base64::Engine::encode(
            &base64::engine::general_purpose::URL_SAFE_NO_PAD,
            &bytes,
        )
    }

    /// 生成密码重置令牌
    pub fn generate_reset_token() -> String {
        // 128位熵 = 足够安全
        Self::generate_token(16) // 128 bits
    }

    /// 生成API密钥
    pub fn generate_api_key() -> String {
        // 256位熵
        let prefix = "sk_live_";
        let random_part = Self::generate_token(32);
        format!("{}{}", prefix, random_part)
    }
}

/// ⚠️ 错误示例：使用非加密安全的随机数
fn bad_token_generation() {
    // ❌ 不可预测但非加密安全
    let token: u64 = rand::random();
    // 仅2^64可能的token——对于现代GPU暴力破解耗时<1小时

    // ❌ 使用时间戳作为种子
    use std::time::{SystemTime, UNIX_EPOCH};
    let seed = SystemTime::now()
        .duration_since(UNIX_EPOCH)
        .unwrap()
        .as_secs();
    // 攻击者可以枚举过去/未来的时间戳

    // ✅ 正确：使用OsRng
    let mut token = [0u8; 32];
    OsRng.fill_bytes(&mut token);
```

```rust
    fn mask_email(email: &str) -> String {
        if let Some(at_pos) = email.find('@') {
            let local = &email[..at_pos];
            let domain = &email[at_pos..];
            match local.len() {
                0..=2 => format!("*{}", domain),
                3..=5 => format!("{}***{}", &local[..1], domain),
                _ => format!("{}***{}{}", &local[..2], &local[local.len()-1..], domain),
            }
        } else {
            "***".to_string()
        }
    }

        if phone.len() >= 4 {
            format!("*******{}", &phone[phone.len()-4..])
        } else {
            "*******".to_string()
        }
    }

    /// 加密存储PII

        self.encryptor.encrypt(pii)
```

## 章节考查（100分）

### 一、概念题（40分，每题8分）

1. 为什么Argon2id取代了bcrypt和SHA256作为密码哈希的标准？
2. AES-GCM相比AES-CBC有哪些安全优势？
3. 什么是信封加密（Envelope Encryption）？它解决了什么问题？
4. 解释时序攻击的原理以及常量时间比较如何防御它。
5. zeroize crate的必要性是什么？Rust编译器为什么可能"优化掉"清零操作？

<details>
<summary>查看答案</summary>

**1. Argon2id的优势：**
- vs SHA256：有盐（防Rainbow Table）、内存硬化（抗GPU/ASIC）、可配置迭代次数
- vs bcrypt：无72字节密码长度限制、内存硬化（bcrypt不含内存硬化）、抗FPGA攻击
- Argon2id混合Argon2d（抗GPU）和Argon2i（抗侧信道），是PWHA（密码哈希竞赛）获胜者

**2. AES-GCM vs AES-CBC：**
- GCM是认证加密（AEAD）——提供机密性和完整性，CBC仅提供机密性
- GCM自动验证认证标签（MAC），篡改密文会被检测到
- CBC需要额外的HMAC来防止密文篡改，容易配置错误
- GCM允许关联数据（AAD）在不加密的情况下参与认证

**3. 信封加密：**
- 用DEK（数据加密密钥）加密实际数据，用KEK（密钥加密密钥）加密DEK
- 解决的问题：
  - KMS/H SM通常有4KB的数据限制（信封加密可加密任意大小）
  - 密钥轮转：只需重新加密DEK，不需要重新加密所有数据
  - 最小权限：DEK仅在被需要时解封

**4. 时序攻击原理与防御：**
- 原理：正常比较在第一个不同字节立即返回→不同前缀的执行时间不同→通过时间差异逐字节破解
- 防御：常量时间比较（subtle crate的ct_eq）遍历所有字节，不提前返回
- 关键实现：使用bitwise AND而非&&（避免短路）、循环不因匹配结果改变执行路径

**5. zeroize的必要性：**
- Rust编译器进行死存储消除（Dead Store Elimination）优化
- 如果编译器发现变量在清零后不再被读取，会认为清零是"无用操作"并优化掉
- zeroize使用volatile写和内联汇编阻止编译器优化，确保敏感数据从内存中清除
- 对攻击者来说，内存dump获取已清零的密钥是不可能的
</details>

### 二、判断题（20分，每题5分）

6. ( ) 使用thread_rng()生成API密钥和加密密钥是安全的选择。
7. ( ) AES-256-GCM的nonce可以重用，只要密钥不同。
8. ( ) 密码哈希后的PHC字符串包含算法标识、参数、盐和哈希值，可以安全地存储在数据库中。
9. ( ) 直接比较两个HMAC标签使用`==`运算符是安全的。

<details>
<summary>查看答案</summary>

6. **错误。** thread_rng()对于API密钥等非加密场景足够安全（它是CSPRNG），但对于加密密钥应使用OsRng直接访问操作系统熵源。两者都是加密安全的，但OsRng直接来自内核熵池，有更强的保证。

7. **错误。** AES-GCM的nonce必须对每个密钥是唯一的。nonce重用会完全破坏GCM的安全性——攻击者可以恢复认证子密钥，进而伪造任意密文和恢复明文。这是GCM最严重的使用错误之一。

8. **正确。** PHC（Password Hashing Competition）格式字符串包含算法（如$argon2id）、版本（v=19）、参数（m=,t=,p=）、盐（base64）和哈希（base64）。其中不包含原始密码——攻击者无法从哈希反推密码。

9. **错误。** 使用`==`比较HMAC标签会引入时序攻击。`==`在Rust字符串中也是短路比较：遇到第一个不同字符就返回false。HMAC验证必须使用常量时间比较（`subtle::ConstantTimeEq`）。
</details>

### 四、编程题（15分）

11. 实现一个`SecureStore`，支持：
    - 使用信封加密存储任意字节数据
    - 使用Argon2id派生的密钥进行本地加密
    - 自动key rotation
    - 数据删除时使用加密擦除（crypto-shredding）

<details>
<summary>查看答案</summary>

```rust
use std::collections::HashMap;
use std::sync::RwLock;

pub struct SecureStore {
    master_encryptor: DataEncryptor,
    entries: RwLock<HashMap<String, EncryptedEntry>>,
    current_dek_id: RwLock<String>,
}

struct EncryptedEntry {
    dek_id: String,
    encrypted_data: Vec<u8>,
}

impl SecureStore {
    pub fn new(master_key: &[u8; 32]) -> Self {
        Self {
            master_encryptor: DataEncryptor::new(master_key),
            entries: RwLock::new(HashMap::new()),
            current_dek_id: RwLock::new(uuid::Uuid::new_v4().to_string()),
        }
    }

    /// 安全存储数据
    pub fn store(&self, key: &str, plaintext: &[u8]) -> Result<(), StoreError> {
        let dek_id = self.current_dek_id.read().unwrap().clone();
        let encrypted = self.master_encryptor.encrypt(plaintext)?;

        let mut entries = self.entries.write().unwrap();
        entries.insert(key.to_string(), EncryptedEntry {
            dek_id,
            encrypted_data: encrypted,
        });

        Ok(())
    }

    /// 安全读取数据
    pub fn retrieve(&self, key: &str) -> Result<Vec<u8>, StoreError> {
        let entries = self.entries.read().unwrap();
        let entry = entries.get(key)
            .ok_or(StoreError::NotFound)?;

        self.master_encryptor.decrypt(&entry.encrypted_data)
            .map_err(|e| StoreError::DecryptionFailed(e.to_string()))
    }

    /// 密钥轮转
    pub fn rotate_keys(&self) -> Result<(), StoreError> {
        let new_dek_id = uuid::Uuid::new_v4().to_string();
        let mut new_key = [0u8; 32];
        OsRng.fill_bytes(&mut new_key);
        let new_encryptor = DataEncryptor::new(&new_key);

        let mut entries = self.entries.write().unwrap();
        for entry in entries.values_mut() {
            // 解密旧数据
            let plaintext = self.master_encryptor.decrypt(&entry.encrypted_data)?;
            // 用新密钥重新加密
            entry.encrypted_data = new_encryptor.encrypt(&plaintext)?;
            entry.dek_id = new_dek_id.clone();
        }

        *self.current_dek_id.write().unwrap() = new_dek_id;
        new_key.zeroize();

        Ok(())
    }

    /// 加密擦除（crypto-shredding）删除数据
    /// 不实际删除数据，而是销毁加密密钥使数据不可恢复
    pub fn crypto_shred(&self, key: &str) -> Result<(), StoreError> {
        let mut entries = self.entries.write().unwrap();
        let entry = entries.get_mut(key)
            .ok_or(StoreError::NotFound)?;

        // 用随机数据覆盖加密数据
        let mut random_data = vec![0u8; entry.encrypted_data.len()];
        OsRng.fill_bytes(&mut random_data);
        entry.encrypted_data.copy_from_slice(&random_data);
        entry.encrypted_data.zeroize();

        entries.remove(key);
        Ok(())
    }
}

#[derive(Debug, thiserror::Error)]
pub enum StoreError {
    #[error("条目未找到")]
    NotFound,
    #[error("加密/解密失败: {0}")]
    CryptoError(#[from] CryptoError),
    #[error("解密失败: {0}")]
    DecryptionFailed(String),
}
```
</details>

## 本章小结

数据安全是信息安全的最底层——当所有网络防御和访问控制被绕过时，数据本身的保护是最后一道防线。本章涵盖了从密码存储（Argon2id替代SHA256/bcrypt）、静态加密（AES-256-GCM认证加密）、传输加密（TLS配置）、密钥管理（信封加密+HSM）到数据生命周期管理的完整链条。

Argon2id的内存硬化特性使GPU/ASIC攻击成本呈指数增长，而Argon2id的混合模式同时抵御侧信道攻击。AES-GCM的认证加密提供了机密性和完整性的双重保证——密文被篡改会被自动检测。常量时间比较看似微小，但在HMAC验证和密码比较中是防止时序攻击的关键。

zeroize解决了Rust编译器优化可能带来的安全隐患——类型系统不能阻止编译器"过度优化"。安全随机数生成从正确的熵源开始——`OsRng`直接访问内核熵池，`thread_rng`是CSPRNG但多一层抽象。

记住：加密不是魔法，它取决于正确使用API。AES-GCM的nonce重用、SHA256的无盐哈希、`==`的短路比较——每一个微小的错误都可能导致整个安全体系崩溃。使用经过审计的Rust加密库（`aes-gcm`、`argon2`、`ring`、`subtle`）可以将这些正确性保证编码到类型系统中。
