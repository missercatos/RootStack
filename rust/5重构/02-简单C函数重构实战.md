# 简单C函数重构实战

## 学习目标

1. 掌握将简单C函数重构为安全Rust函数的方法
2. 理解每个重构中的安全性改进
3. 能够进行C和Rust的并排对比分析
4. 掌握从裸指针到引用、从错误码到Result的转换技巧
5. 建立重构信心，为更大规模项目做准备

## 一、重构原则

在开始重构每个函数之前，先确立原则：

```
原则1: 先理解，后改写 —— 不理解C原意绝不写Rust
原则2: 保持语义等价 —— Rust版本必须产生相同结果
原则3: 利用类型系统 —— 将运行时约束转化为编译期约束
原则4: 测试驱动 —— 先写测试，C和Rust共享同一套测试用例
原则5: 逐步安全化 —— 如果无法一次安全，用unsafe封装再渐进重构
```

## 二、函数1: strlen —— 字符串长度

### 2.1 C原始实现

```c
#include <stddef.h>

/**
 * 计算以空字符结尾的字符串长度
 * @param s 指向C字符串的指针
 * @return 字符串长度（不包括终止空字符）
 */
size_t strlen(const char* s) {
    const char* p = s;
    while (*p != '\0') {
        p++;
    }
    return (size_t)(p - s);
}
```

### 2.2 代码分析

```
算法：线性扫描直到遇到'\0'
复杂度：O(n)，n为字符串长度
边界情况：
  - s == NULL: 未定义行为（段错误）
  - 字符串无终止符: 无限循环，越界访问
  - 空字符串"": 返回0，正确
内存：只读，无内存分配
线程安全：是（只读操作）
```

### 2.3 不安全因素

| 序号 | 因素 | 严重性 | 影响 |
|------|------|--------|------|
| 1 | s可为NULL | 致命 | 段错误，程序崩溃 |
| 2 | 字符串可能无终止符 | 致命 | 内存越界访问，信息泄露 |
| 3 | p-s可能溢出size_t | 极低 | 理论可能，实际上极少发生 |
| 4 | 指针运算无边界 | 致命 | 与#2相关 |

### 2.4 Rust重构

```rust
/// 计算字符串切片的长度（字节数）
/// 
/// 注意：Rust标准库已提供 str::len()，此处仅为教学演示
fn strlen(s: &str) -> usize {
    let bytes = s.as_bytes();
    let mut count = 0;
    while count < bytes.len() && bytes[count] != b'\0' {
        count += 1;
    }
    count
}

/// 更惯用的Rust版本：统计非空字节数
fn strlen_idiomatic(s: &str) -> usize {
    s.bytes().take_while(|&b| b != b'\0').count()
}
```

### 2.5 并排对比

| 方面 | C strlen | Rust strlen |
|------|----------|-------------|
| 参数类型 | `const char*`（可能为NULL） | `&str`（编译期保证非空） |
| 边界检查 | 无，依赖`\0` | `bytes.len()`提供上界 |
| 无终止符处理 | 未定义行为 | 最多读到切片末尾 |
| 返回值 | `size_t`（可能超大） | `usize`（受切片长度约束） |
| 空字符串 | 返回0 | 返回0 |
| 所有权 | 无影响（只读借用） | 无影响（共享引用） |

### 2.6 测试

```rust
#[cfg(test)]

    use super::*;

    #[test]
    fn test_empty_string() {
        assert_eq!(strlen(""), 0);
    }

    #[test]

        // 即使在unsafe下，Rust也只在切片范围内搜索
    }
}
```

## 三、函数2: strdup —— 字符串复制

### 3.1 C原始实现

```c
#include <stdlib.h>
#include <string.h>

/**
 * 复制字符串到新分配的内存
 * @param s 源字符串
 * @return 新分配的字符串副本，调用者负责释放
 */
char* strdup(const char* s) {
    if (s == NULL) {
        return NULL;
    }
    size_t len = strlen(s);
    char* dup = (char*)malloc(len + 1);
    if (dup == NULL) {
        return NULL;
    }
    memcpy(dup, s, len + 1);  /* +1 复制终止空字符 */
    return dup;
}
```

### 3.2 内存管理分析

```
分配点: malloc(len + 1) 在 strdup 内部
释放点: 调用者必须调用 free()
所有权: 转移给调用者

问题场景:
  场景A: 调用者忘记 free() → 内存泄漏
  场景B: 调用者 free() 后继续使用 → use-after-free (UB)
  场景C: 调用者 free() 两次 → double-free (UB)
  场景D: malloc 失败 → 返回 NULL，调用者可能忘记检查
  场景E: s 非空但无 '\0' 终止 → strlen 越界
```

### 3.3 Rust重构

```rust
/// 复制字符串（事实上就是标准库的 to_string / to_owned）
///
/// 在Rust中不需要手动实现此函数，此处仅为教学演示
fn strdup(s: &str) -> String {
    s.to_string()
}

/// 手动实现版本（展示底层操作）
fn strdup_manual(s: &str) -> String {
    let bytes = s.as_bytes();
    let mut result = String::with_capacity(bytes.len());
    for &b in bytes {
        if b == b'\0' {
            break;  // C字符串语义：遇到\0停止
        }
        result.push(b as char);
    }
    result
}

/// 处理C风格字符串（可能包含内嵌\0）
fn strdup_c_style(s: &str) -> String {
    // 截断到第一个\0之前
    let c_len = s.bytes().position(|&b| b == b'\0').unwrap_or(s.len());
    s[..c_len].to_string()
}
```

### 3.4 所有权对比

```
C版本:
  char* s1 = strdup("hello");   // s1拥有内存
  char* s2 = s1;                // s2也指向同一内存（两个指针，一个所有权）
  free(s1);                     // 释放内存
  // s2现在是悬垂指针！
  printf("%s\n", s2);           // 未定义行为

Rust版本:
  let s1 = strdup("hello");     // s1: String 拥有内存
  let s2 = s1;                  // s1被移动，s2现在是所有者
  // println!("{}", s1);        // 编译错误！s1已被移动
  println!("{}", s2);           // OK
  // 不需要手动释放，s2离开作用域时自动释放
```

### 3.5 安全性改进总结

| 改进点 | C版本风险 | Rust版本保障 |
|--------|----------|-------------|
| 忘记释放 | 内存泄漏 | 编译期无此可能 |
| 重复释放 | 未定义行为 | 编译期无此可能 |
| 释放后使用 | 未定义行为 | 编译期阻止 |
| NULL返回 | 可能崩溃 | Result/Option或直接panic |
| 越界访问 | 可能发生 | 切片边界保证 |

## 四、函数3: create_array —— 创建数组

### 4.1 C原始实现

```c
#include <stdlib.h>
#include <stdio.h>

/**
 * 创建包含n个元素的整数数组，初始化为0
 * @param n 数组大小
 * @return 新分配的数组，调用者负责释放；NULL表示失败
 */
int* create_array(int n) {
    if (n <= 0) {
        return NULL;
    }
    int* arr = (int*)malloc((size_t)n * sizeof(int));
    if (arr == NULL) {
        return NULL;
    }
    for (int i = 0; i < n; i++) {
        arr[i] = 0;
    }
    return arr;
}

/**
 * 创建并初始化数组
 * @param n 数组大小
 * @param initial_value 初始值
 * @return 新分配的数组
 */
int* create_array_with_value(int n, int initial_value) {
    if (n <= 0) {
        return NULL;
    }
    int* arr = (int*)malloc((size_t)n * sizeof(int));
    if (arr == NULL) {
        return NULL;
    }
    for (int i = 0; i < n; i++) {
        arr[i] = initial_value;
    }
    return arr;
}

/* 使用示例 */
void example_usage(void) {
    int* arr = create_array(10);
    if (arr != NULL) {
        arr[5] = 42;
        printf("arr[5] = %d\n", arr[5]);
        free(arr);
    }
}
```

### 4.2 不安全因素标注

```c
int* create_array(int n) {
    if (n <= 0) {                    // ① n可能为负数 → 返回NULL
        return NULL;
    }
    int* arr = (int*)malloc(         // ② malloc可能失败 → NULL
        (size_t)n * sizeof(int));    // ③ n*sizeof(int)可能溢出
    if (arr == NULL) {
        return NULL;                 // ④ 返回NULL，调用者可能不检查
    }
    for (int i = 0; i < n; i++) {    // ⑤ 如果n很大，循环可能极慢
        arr[i] = 0;                  // ⑥ 手动初始化，可能写错范围
    }
    return arr;                      // ⑦ 所有权转移，无编译器跟踪
}
```

### 4.3 Rust重构

```rust
/// 创建包含n个元素的向量，初始化为0
fn create_array(n: usize) -> Vec<i32> {
    vec![0i32; n]
}

/// 创建并初始化数组
fn create_array_with_value(n: usize, initial_value: i32) -> Vec<i32> {
    vec![initial_value; n]
}

/// 如果需要更精细的控制（例如零大小数组）：
fn create_array_safe(n: usize) -> Vec<i32> {
    if n == 0 {
        return Vec::new();
    }
    let mut v = Vec::with_capacity(n);
    v.resize(n, 0);
    v
}

/// 演示：实际上标准库已经提供了所有这些功能
fn demonstrate_std() {
    let v1 = vec![0; 10];            // 10个0
    let v2 = vec![42; 5];            // 5个42
    let v3: Vec<i32> = (0..10).collect();  // 0到9
    let v4 = Vec::<i32>::with_capacity(100); // 预分配容量
}
```

### 4.4 功能和安全性对比

| 特性 | C版本 | Rust版本 |
|------|-------|---------|
| 创建 | malloc + 手动循环 | vec![] 宏，一行搞定 |
| 释放 | 手动free，容易出错 | 自动Drop |
| 大小跟踪 | 无内置机制，需额外变量 | .len() 方法 |
| 容量管理 | realloc，手动策略 | 自动扩容，优化策略 |
| 边界检查 | 无 | .get()返回Option，[]带有panic |
| 切片操作 | 指针+长度手动传递 | &[i32] 自带长度和边界 |
| 零大小 | 返回NULL（语义不清） | Vec::new() 返回空Vec |
| 大内存分配 | malloc可能失败 → NULL | 当前Rust默认panic（可配置allocator） |

### 4.5 性能安全性权衡

```
操作                       C耗时     Rust耗时    说明
─────────────────────────────────────────────────────────
初始化 vec![0; 1000]     ~1μs       ~1μs       两者都使用memset等效
索引访问 arr[500]         ~1ns       ~2ns       Rust有边界检查（debug）
索引访问 arr[500]         ~1ns       ~1ns       Rust release优化掉边界检查
获取长度                  手动变量    ~0.5ns     Rust内联.len()
释放内存                  free()     Drop       O(n)析构（i32无析构所以O(1)）
传递子数组                指针+长度   切片引用     Rust保证生命周期安全
```

## 五、函数4: sort_array —— 数组排序

### 5.1 C原始实现（冒泡排序）

```c
#include <stddef.h>

/**
 * 冒泡排序（升序）
 * @param arr 待排序数组
 * @param n   数组长度
 */
void sort_array(int* arr, int n) {
    if (arr == NULL || n <= 1) return;

    for (int i = 0; i < n - 1; i++) {
        int swapped = 0;
        for (int j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
                swapped = 1;
            }
        }
        if (!swapped) break;
    }
}

/* 使用示例 */
void example_sort(void) {
    int arr[] = {5, 2, 8, 1, 9};
    sort_array(arr, 5);
    /* 但调用者怎么知道数组长度是5？ */
}
```

### 5.2 C版本的问题分析

```c
void sort_array(int* arr, int n) {
    // ① arr和n的关联无法验证 —— arr可能指向3个元素但n=100
    // ② arr可能为NULL（已检查，但不强制）
    // ③ n的类型是int，可以为负数
    // ④ 无法表达"排序后"的语义 —— 调用者不知道原地修改
    // ⑤ 对于大型数组，冒泡排序O(n²)不可接受
    // ⑥ 无类型参数：int数组可以，但double数组需要另一个函数
}
```

### 5.3 Rust重构

```rust
/// 对可变切片进行原地排序（升序）
/// 
/// 注意：标准库已提供 [T]::sort()，此处为教学演示
fn sort_array(arr: &mut [i32]) {
    let n = arr.len();
    if n <= 1 {
        return;
    }
    for i in 0..n - 1 {
        let mut swapped = false;
        for j in 0..n - 1 - i {
            if arr[j] > arr[j + 1] {
                arr.swap(j, j + 1);
                swapped = true;
            }
        }
        if !swapped {
            break;
        }
    }
}

/// 泛型版本：适用于任何可比较的类型
fn sort_array_generic<T: Ord>(arr: &mut [T]) {
    let n = arr.len();
    if n <= 1 {
        return;
    }
    for i in 0..n - 1 {
        let mut swapped = false;
        for j in 0..n - 1 - i {
            if arr[j] > arr[j + 1] {
                arr.swap(j, j + 1);
                swapped = true;
            }
        }
        if !swapped {
            break;
        }
    }
}

/// Rust标准库版本（生产代码请使用此版本）
fn sort_array_std(arr: &mut [i32]) {
    arr.sort();
}

/// 泛型标准库版本
fn sort_array_std_generic<T: Ord>(arr: &mut [T]) {
    arr.sort(); // 使用timsort，O(n log n)，稳定排序
}
```

### 5.5 编译期保障对照

| C版本的运行时风险 | Rust的编译期保障 |
|-----------------|----------------|
| arr为NULL或n<=0时行为未定义 | `&mut [i32]` 保证非空且有已知长度 |

## 六、函数5: read_file —— 读取文件

### 6.1 C原始实现

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/**
 * 读取整个文件内容到字符串
 * @param path 文件路径
 * @return 文件内容字符串，调用者负责free；失败返回NULL
 */
char* read_file(const char* path) {
    if (path == NULL) {
        return NULL;
    }

    FILE* file = fopen(path, "rb");
    if (file == NULL) {
        return NULL;
    }

    /* 获取文件大小 */
    if (fseek(file, 0, SEEK_END) != 0) {
        fclose(file);
        return NULL;
    }
    long file_size = ftell(file);
    if (file_size < 0) {
        fclose(file);
        return NULL;
    }
    rewind(file);

    /* 分配缓冲区 */
    char* buffer = (char*)malloc((size_t)file_size + 1);
    if (buffer == NULL) {
        fclose(file);
        return NULL;
    }

    /* 读取文件 */
    size_t bytes_read = fread(buffer, 1, (size_t)file_size, file);
    if (ferror(file)) {
        free(buffer);
        fclose(file);
        return NULL;
    }

    buffer[bytes_read] = '\0';
    fclose(file);
    return buffer;
}
```

### 6.2 错误处理分析

C版本的错误处理覆盖了多种情况，但依然存在问题：

```
成功路径 (Happy Path):
  fopen → fseek → ftell → rewind → malloc → fread → fclose → return buffer
  共7步，每步都可能失败

失败路径:
  1. path == NULL     → return NULL (错误信息丢失)
  2. fopen 失败       → return NULL (不知道是权限问题还是不存在)
  3. fseek 失败       → fclose + return NULL
  4. ftell 失败       → fclose + return NULL
  5. malloc 失败      → fclose + return NULL (buffer已分配的先free，此处未分配)
  6. fread 失败       → free + fclose + return NULL
  7. fclose 失败      → return buffer (实际上这个错误被忽略了！)

潜在问题:
  - ftell 对某些文件（如管道、stdin）返回不可靠的值
  - file_size long→size_t 在32位系统上可能溢出
  - 文件在 fseek 和 fread 之间可能被修改（TOCTOU）
  - 文本文件在Windows上\r\n被转换为\n，ftell不准确
```

### 6.3 Rust重构

```rust
use std::fs;
use std::io::{self, Read};
use std::path::Path;

/// 读取整个文件内容到字符串
///
/// 注意：标准库已提供 std::fs::read_to_string()，此处为教学演示
fn read_file(path: &str) -> Result<String, io::Error> {
    fs::read_to_string(path)
}

/// 手动实现版本（展示底层操作）
fn read_file_manual(path: &str) -> Result<String, io::Error> {
    let path = Path::new(path);
    let mut file = fs::File::open(path)?;

    let metadata = file.metadata()?;
    let mut buffer = String::with_capacity(metadata.len() as usize);

    file.read_to_string(&mut buffer)?;
    Ok(buffer)
}

/// 读取二进制文件
fn read_file_bytes(path: &str) -> Result<Vec<u8>, io::Error> {
    fs::read(path)
}

/// 流式读取大文件（不一次性加载到内存）
fn read_file_streaming(path: &str) -> Result<String, io::Error> {
    use std::io::BufReader;
    use std::io::BufRead;

    let file = fs::File::open(path)?;
    let reader = BufReader::new(file);
    let mut result = String::new();
    for line in reader.lines() {
        result.push_str(&line?);
        result.push('\n');
    }
    Ok(result)
}
```

### 6.4 错误类型对比

```
C版本错误信息:
  所有错误 → NULL（丢失了错误原因）

Rust版本错误信息:
  fs::read_to_string 返回 io::Error，包含:
    - ErrorKind::NotFound     → 文件不存在
    - ErrorKind::PermissionDenied → 权限不足
    - ErrorKind::InvalidInput → 路径无效
    - ErrorKind::InvalidData  → 非UTF-8数据
    - 操作系统错误码           → 精确错误原因
```

重构每个C函数到Rust时，使用以下检查清单：

```
□ 1. 参数是否可为NULL？              → 用 Option<T> 或直接禁止

□ 9. 是否有多线程共享数据？           → 用 Arc/Mutex 或消息传递
□ 10. 函数文档是否描述了所有不变量？   → 用类型系统编码不变量
```

### 一、概念题（40分，每题8分）

1. 重构C函数到Rust时，处理C中可能导致段错误的NULL指针参数的最佳方法是什么？请给出至少两种策略。
2. 解释为什么Rust的`&str`类型比C的`const char*`更安全（至少两个原因）。
3. C语言的`malloc`/`free`模式在Rust中被什么机制替代？这种替代带来了什么好处？
4. 解释C语言中"输出参数"模式（如`int parse(const char*, int* out)`）在Rust中应该如何表达。
5. 什么是TOCTOU问题？Rust如何帮助防止这类问题？

<details>
<summary>参考答案</summary>

1. 两种策略：
   - 策略A：使用`Option<&T>`明确表示参数可为空，调用者必须显式处理None情况
   - 策略B：使用`&T`直接禁止NULL，如果C代码允许NULL，在FFI边界检查并转换为Option
   两种策略都将运行时错误转化为编译期检查。

2. `&str`比`const char*`更安全：
   - `&str`自带长度信息，不需要依赖`\0`终止符来确定边界
   - `&str`由Rust的生命周期系统保证不会成为悬垂引用
   - `&str`的UTF-8保证由类型系统部分强制执行

3. `malloc`/`free`被所有权系统+Drop trait替代：
   - Box<T>分配堆内存，离开作用域时自动调用Drop释放
   - Vec<T>管理动态数组，自动扩容和释放
   - 好处：消除忘记释放、重复释放、释放后使用等内存错误

4. 输出参数模式在Rust中应使用：
   - `Result<T, E>`作为返回值，T是成功时的输出
   - 或者用元组：`fn parse(s: &str) -> Result<(i32, usize), ParseError>`
   - 避免使用`&mut`输出参数，除非有多个输出值

5. TOCTOU（Time-of-check Time-of-use）：
   - 指在检查和实际操作之间存在时间窗口，文件状态可能被修改
   - Rust不能完全消除TOCTOU（这是OS级别的问题），但Rust的类型系统可以使文件状态更明确
   - 做法：打开文件后持有File句柄，通过句柄操作而非重新通过路径打开

</details>

### 二、判断题（20分，每题4分）

1. Rust的`Vec<i32>`在功能上等价于C的`int*`加上一个`size_t`变量。（ ）
2. 使用c2rust转译的代码可以直接在生产环境使用。（ ）
3. `fn strlen(s: &str) -> usize` 比 `size_t strlen(const char* s)` 更安全，因为前者不需要依赖`\0`终止符。（ ）
4. Rust中`String::with_capacity(n)`等价于C中`malloc(n+1)`加手动填充。（ ）
5. 每次C到Rust的重构都应该追求零性能损失。（ ）

<details>
<summary>参考答案</summary>

1. × — Vec<i32>自带长度、容量、所有权管理、边界检查、自动释放，而int*+size_t只是两个无关联的值。
2. × — c2rust生成的代码充满unsafe和裸指针，必须经过大量人工重构才能达到生产质量。
3. √ — &str自带长度，在切片边界内保证安全，不依赖\0终止符。
4. × — String::with_capacity(n)只分配内存不初始化内容，而malloc(n+1)有类似效果但String还需要管理UTF-8有效性和长度。
5. × — 在某些情况下牺牲微小性能换取安全性是值得的，且Rust的零成本抽象通常在release模式下消除额外开销。

</details>

### 三、代码分析题（15分）

分析以下C代码，指出所有潜在问题，并给出对应的安全Rust实现：

```c
#include <stdlib.h>
#include <string.h>

char** split_string(const char* str, char delimiter, int* count) {
    if (str == NULL || count == NULL) return NULL;

    /* 统计分隔符数量 */
    int delim_count = 0;
    for (const char* p = str; *p; p++) {
        if (*p == delimiter) delim_count++;
    }

    /* 分配结果数组（多一个用于NULL终止） */
    char** result = (char**)malloc((delim_count + 2) * sizeof(char*));
    if (result == NULL) return NULL;

    int idx = 0;
    const char* start = str;
    for (const char* p = str; ; p++) {
        if (*p == delimiter || *p == '\0') {
            size_t len = (size_t)(p - start);
            result[idx] = (char*)malloc(len + 1);
            if (result[idx] == NULL) {
                /* 清理已分配的内存 */
                for (int i = 0; i < idx; i++) free(result[i]);
                free(result);
                return NULL;
            }
            memcpy(result[idx], start, len);
            result[idx][len] = '\0';
            idx++;
            if (*p == '\0') break;
            start = p + 1;
        }
    }
    result[idx] = NULL; /* NULL终止数组 */
    *count = idx;
    return result;
}
```

<details>
<summary>参考答案</summary>

**潜在问题分析：**

1. `delim_count`溢出：如果分隔符极多，int可能溢出
2. `(delim_count + 2)`溢出：如果delim_count接近INT_MAX
3. `result[idx]` malloc失败时的清理逻辑中，`idx`此时指向刚分配失败的索引，之前的已正确清理
4. `memcpy`用于可能重叠的内存：实际上start和result[idx]一定不重叠，但使用memcpy而非memmove表明作者意识到了这一点
5. 调用者必须同时释放result数组和每个子字符串，极易出错
6. 如果str为空字符串""，返回一个包含空字符串的数组和一个NULL终止符
7. `*count = idx` 如果没有到达过赋值就在错误路径上，但代码结构保证了只有成功才走到这里

**Rust安全实现：**

```rust
fn split_string(s: &str, delimiter: char) -> Vec<String> {
    s.split(delimiter)
        .map(|part| part.to_string())
        .collect()
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_basic_split() {
        let result = split_string("a,b,c", ',');
        assert_eq!(result, vec!["a", "b", "c"]);
    }

    #[test]
    fn test_no_delimiter() {
        let result = split_string("hello", ',');
        assert_eq!(result, vec!["hello"]);
    }

    #[test]
    fn test_empty() {
        let result = split_string("", ',');
        assert_eq!(result, vec![""]);
    }

    #[test]
    fn test_consecutive_delimiters() {
        let result = split_string("a,,b", ',');
        assert_eq!(result, vec!["a", "", "b"]);
    }
}
```

Rust版本3行代码完成C版本40行代码的工作，且完全内存安全。
</details>

### 四、编程题（15分）

请将以下C函数重构为安全Rust：

```c
#include <stdlib.h>
#include <string.h>

/**
 * 过滤数组中的正数，返回新数组
 * @param arr 输入数组
 * @param len 数组长度
 * @param out_len 输出数组长度
 * @return 正数数组，调用者负责释放
 */
int* filter_positive(const int* arr, int len, int* out_len) {
    if (arr == NULL || out_len == NULL || len <= 0) {
        if (out_len) *out_len = 0;
        return NULL;
    }

    /* 第一遍：统计正数个数 */
    int count = 0;
    for (int i = 0; i < len; i++) {
        if (arr[i] > 0) count++;
    }

    /* 分配结果数组 */
    int* result = (int*)malloc(count * sizeof(int));
    if (result == NULL) {
        *out_len = 0;
        return NULL;
    }

    /* 第二遍：复制正数 */
    int idx = 0;
    for (int i = 0; i < len; i++) {
        if (arr[i] > 0) {
            result[idx++] = arr[i];
        }
    }

    *out_len = count;
    return result;
}
```

要求：Rust实现不能使用unsafe代码，使用迭代器简化实现。

<details>
<summary>参考答案</summary>

```rust
/// 过滤数组中的正数，返回包含所有正数的Vec
fn filter_positive(arr: &[i32]) -> Vec<i32> {
    arr.iter()
        .copied()
        .filter(|&x| x > 0)
        .collect()
}

// 或者更明确的版本：
fn filter_positive_explicit(arr: &[i32]) -> Vec<i32> {
    let mut result = Vec::new();
    for &val in arr {
        if val > 0 {
            result.push(val);
        }
    }
    result
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_empty() {
        assert_eq!(filter_positive(&[]), vec![]);
    }

    #[test]
    fn test_all_negative() {
        assert_eq!(filter_positive(&[-1, -2, -3]), vec![]);
    }

    #[test]
    fn test_mixed() {
        assert_eq!(
            filter_positive(&[-5, 3, 0, 7, -1]),
            vec![3, 7]
        );
    }

    #[test]
    fn test_all_positive() {
        assert_eq!(
            filter_positive(&[1, 2, 3]),
            vec![1, 2, 3]
        );
    }
}
```

安全改进：
- 无需检查arr是否为NULL（&[i32]编译期保证）
- 无需out_len输出参数（Vec自带.len()）
- 无需手动malloc/free（Vec自动管理）
- 无需两遍遍历（Rust的迭代器惰性求值在collect时一次完成过滤和收集）
- 如果没有正数，返回空Vec而非NULL（语义更清晰）
