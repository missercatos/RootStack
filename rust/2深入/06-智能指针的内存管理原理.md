# 智能指针的内存管理原理

## 原理

### Box\<T\>：堆分配的单所有权指针

`Box<T>` 是堆分配的单所有权指针，等同于 C++ 的 `unique_ptr`。内存布局：栈上 8B 指针指向堆上 T。`Box` 的 drop 触发时先调用 `T::drop`，再释放堆内存（通过 `__rust_dealloc`）。

**名词解释**：

- **RAII（Resource Acquisition Is Initialization）**：资源获取即初始化，C++ 和 Rust 使用的核心模式——在构造函数中获取资源，在析构函数中释放资源。
- **堆分配器（Heap Allocator）**：操作系统或运行时提供的内存分配服务，如 glibc 的 `malloc`/`free` 或 Rust 的 `__rust_alloc`/`__rust_dealloc`。
- **引用计数（Reference Counting）**：跟踪指向同一数据的引用数量，当计数归零时释放数据。
- **原子操作（Atomic Operation）**：不可被中断的 CPU 操作，在多线程环境下保证原子性。
- **Copy-on-Write（COW，写时复制）**：多个读者共享同一数据，仅在写入时才复制一份。

```text
Box<T> 的内存布局:

栈上 (8 字节):                堆上:
┌─────────────────┐          ┌──────────────────┐
│ ptr (8 bytes)   │─────────→│ T 的数据          │
└─────────────────┘          │ (size of T)       │
                             └──────────────────┘

Box::new(42) 的详细过程:
  1. 调用 __rust_alloc(size_of::<i32>(), align_of::<i32>())
     → 分配 4 字节堆内存，4 字节对齐
  2. 将 42 写入分配的内存
  3. 返回指向该内存的指针

Box::drop 的详细过程:
  1. 调用 <i32 as Drop>::drop(ptr)  // T 的析构函数
  2. 调用 __rust_dealloc(ptr, size_of::<i32>(), align_of::<i32>())
     → 释放 4 字节堆内存

汇编层面:
  ; Box::new(42)
  mov     edi, 4             ; size = 4
  mov     esi, 4             ; align = 4
  call    __rust_alloc       ; 分配堆内存
  mov     dword [rax], 42   ; 写入值
  mov     [rbp-8], rax      ; 存储指针到栈

  ; Box::drop
  mov     rdi, [rbp-8]       ; 获取指针
  call    <i32 as Drop>::drop ; 调用析构 (对 i32 是空操作)
  mov     rdi, [rbp-8]       ; 获取指针
  mov     esi, 4             ; size
  mov     edx, 4             ; align
  call    __rust_dealloc     ; 释放堆内存
```

### Rc\<T\>：引用计数智能指针

`Rc<T>` 使用非原子引用计数（`Cell<usize>` 计数器），堆上分配时保存 {T, strong_count, weak_count}。`clone` 增加计数，`drop` 减少计数，计数归零时释放 T。`Rc` 不能跨线程（`!Send + !Sync`）。

```text
Rc<T> 的内存布局:

栈上:                        堆上:
┌─────────────────┐         ┌──────────────────────┐
│ ptr (8 bytes)   │────────→│ RcBox {              │
└─────────────────┘         │   strong: usize (8B) │
                            │   weak:   usize (8B) │
                            │   data:   T          │
                            │ }                    │
                            └──────────────────────┘

引用计数操作:

Rc::clone(&rc):
  ; 非原子操作 (因为 Rc 是 !Send + !Sync)
  mov     rax, [rc_ptr]           ; rax = &RcBox
  mov     rcx, [rax]              ; rcx = strong_count
  add     rcx, 1                  ; strong_count += 1
  mov     [rax], rcx              ; 写回
  ; 无 LOCK 前缀，无内存屏障
  ; 这就是为什么 Rc 不能跨线程

Rc::drop(&rc):
  mov     rax, [rc_ptr]
  mov     rcx, [rax]
  sub     rcx, 1                  ; strong_count -= 1
  mov     [rax], rcx
  cmp     rcx, 0
  jne     .skip_free              ; 如果不为 0，跳过释放
  call    <T as Drop>::drop       ; 释放 T
  call    __rust_dealloc          ; 释放 RcBox
.skip_free:

Weak 的处理:
  weak_count 用于跟踪弱引用
  当 strong_count 归零时:
    - 释放 T 的数据
    - 但不释放 RcBox (因为 weak 可能仍存在)
  当 weak_count 也归零时:
    - 释放整个 RcBox
```

### Arc\<T\>：原子引用计数

`Arc<T>` 使用原子引用计数（`AtomicUsize`），安全的跨线程共享。额外开销是 `fetch_add` / `fetch_sub` 的 `LOCK` 前缀（x86）和内存屏障。

```text
Arc<T> 的内存布局:

与 Rc<T> 相同，但 strong/weak 使用 AtomicUsize:

堆上:
┌──────────────────────────┐
│ ArcBox {                 │
│   strong: AtomicUsize    │  ← 原子操作
│   weak:   AtomicUsize    │  ← 原子操作
│   data:   T              │
│ }                        │
└──────────────────────────┘

原子操作的汇编 (x86_64):

Arc::clone:
  lock inc qword [rax]     ; LOCK 前缀 + 原子递增
  ; 或等价于:
  ; lock xadd [rax], rcx   ; 原子加法

Arc::drop:
  lock dec qword [rax]     ; LOCK 前缀 + 原子递减
  jnz .skip_free           ; 如果不为 0，跳过
  ; 需要完整的内存屏障 (acquire + release)

性能开销:
  非原子 (Rc): ~1-2 CPU 周期
  原子 (Arc):  ~10-30 CPU 周期 (取决于竞争)
  LOCK 前缀:   阻止其他 CPU 访问同一缓存行
  内存屏障:    确保操作顺序 (acquire/release semantics)
```

### RefCell\<T\>：运行时借用检查

`RefCell<T>` 在运行时检查借用规则：通过 `Cell<isize>` 跟踪 borrow count。`borrow()` 读时计数+1，`borrow_mut()` 写时计数设为 -1。违反规则时触发 `panic!` 而非编译错误。

```text
RefCell<T> 的内部状态:

栈上:
┌─────────────────┐
│ ptr (8 bytes)   │──────→ 堆上:
└─────────────────┘         ┌──────────────────┐
                            │ RefCellBox {      │
                            │   borrow: Cell    │
                            │     <isize>       │
                            │   value: T        │
                            │ }                 │
                            └──────────────────┘

borrow 状态机:
  borrow 值的含义:
    -1        → 已被可变借用 (borrow_mut)
    0         → 未被借用
    1, 2, ... → 被不可变借用 N 次

borrow() 操作:
  let r = cell.borrow();
  ; 1. 读取 borrow 值
  ; 2. 检查: borrow != -1 (没有可变借用)
  ; 3. borrow += 1
  ; 4. 返回 Ref<T> (RAII 守卫)
  ; 如果 borrow == -1 → panic!("already borrowed")

borrow_mut() 操作:
  let mut r = cell.borrow_mut();
  ; 1. 读取 borrow 值
  ; 2. 检查: borrow == 0 (没有其他借用)
  ; 3. borrow = -1
  ; 4. 返回 RefMut<T> (RAII 守卫)
  ; 如果 borrow != 0 → panic!("already borrowed")

Ref<T> 和 RefMut<T> 的 drop:
  当守卫被 drop 时:
    Ref::drop → borrow -= 1 (恢复到借用前状态)
    RefMut::drop → borrow = 0 (恢复到未借用状态)

运行时开销:
  每次借用: 读取 + 检查 + 修改 (约 2-5 CPU 周期)
  对比编译期借用检查: 零运行时开销
```

### Cow\<T\>：写时复制

`Cow<'a, T>`：写时复制。持有 `&T` 引用或 `T` 的所有权。仅在需要修改时才分配新数据。

```text
Cow<'a, T> 的内部表示:

enum Cow<'a, T: ToOwned> {
    Borrowed(&'a T),    // 持有引用，不拥有数据
    Owned(T::Owned),    // 持有所有权，拥有数据
}

内存布局:
  Borrowed 变体:
    ┌──────────────────────┐
    │ 标签: Borrowed (0)   │
    │ 指针 (8B) → 外部数据 │
    └──────────────────────┘

  Owned 变体:
    ┌──────────────────────┐
    │ 标签: Owned (1)      │
    │ 数据: T::Owned       │  ← 内联存储
    └──────────────────────┘

使用场景:
  let s: Cow<str> = Cow::Borrowed("hello");
  // 不分配堆内存，直接引用静态字符串

  let mut s = s.into_owned();
  // 首次修改时分配堆内存并复制
  s.push_str(" world");

  性能优势:
    - 读取路径: 零分配
    - 写入路径: 按需分配 (仅第一次)
```

### Pin\<T\>：固定指针

`Pin<T>` 保证指向的数据不会在内存中移动，用于自引用结构体（如异步生成器）。

```text
自引用结构体的问题:

struct SelfRef {
    data: String,
    ptr: *const String,  // 指向 data
}

impl SelfRef {
    fn new(s: String) -> Self {
        let mut sr = SelfRef { data: s, ptr: std::ptr::null() };
        sr.ptr = &sr.data as *const String;
        sr
    }
}

问题:
  let sr = SelfRef::new("hello".to_string());
  let sr2 = sr;  // 移动! sr2.data 是新地址
  // sr2.ptr 仍然指向旧地址 → 悬垂指针!

Pin 的解决方案:
  let sr = Box::pin(SelfRef::new("hello".to_string()));
  // Pin<Box<SelfRef>> 保证 SelfRef 不会被移动
  // 编译器阻止任何可能导致移动的操作

  // 以下操作被禁止:
  // - std::mem::replace
  // - std::mem::swap
  // - 解构 (destructuring)
  // - 将 Pin<&mut T> 转换为 &mut T (除非 Unpin)
```

### Send 与 Sync traits

```text
Send 和 Sync 的定义:

unsafe trait Send { }
// 如果 T: Send，则 T 可以安全地在线程间转移所有权

unsafe trait Sync { }
// 如果 T: Sync，则 &T 可以安全地在线程间共享

自动实现:
  大多数类型自动实现 Send 和 Sync
  以下类型不实现:
    - *const T, *mut T (裸指针)
    - Rc<T> (非原子引用计数)
    - Cell<T>, RefCell<T> (内部可变性)

线程安全的智能指针:
  Box<T>:   Send (如果 T: Send)
            Sync (如果 T: Sync)
  Rc<T>:    !Send, !Sync
  Arc<T>:   Send (如果 T: Send + Sync)
            Sync (如果 T: Send + Sync)
  RefCell<T>: Send (如果 T: Send)
              !Sync (内部可变性不安全)
  Mutex<T>: Send + Sync (如果 T: Send)
  RwLock<T>: Send + Sync (如果 T: Send + Sync)

示例:
  // Rc<T> 不能跨线程
  use std::rc::Rc;
  let rc = Rc::new(42);
  std::thread::spawn(move || {
      println!("{}", rc);  // ❌ 编译错误: Rc<i32> 不能跨线程
  });

  // Arc<T> 可以跨线程
  use std::sync::Arc;
  let arc = Arc::new(42);
  let arc2 = Arc::clone(&arc);
  std::thread::spawn(move || {
      println!("{}", arc2);  // ✅ OK: Arc<i32> 可以跨线程
  });
```

## 语法

```rust
// Box — 堆分配单所有权
let b = Box::new(42);
let raw = Box::into_raw(b); // 消费 Box，返回裸指针
unsafe { Box::from_raw(raw); } // 从裸指针重建 Box

// Rc — 单线程引用计数
use std::rc::Rc;
let r = Rc::new(String::from("hi"));
let r2 = Rc::clone(&r); // 计数+1（浅克隆）
assert_eq!(Rc::strong_count(&r), 2);

// Arc — 原子引用计数（线程安全）
use std::sync::Arc;
let a = Arc::new(42);
let a2 = Arc::clone(&a);

// RefCell — 运行时借用检查
use std::cell::RefCell;
let c = RefCell::new(42);
*c.borrow_mut() = 100; // 可变借用
let v = *c.borrow(); // 不可变借用
// c.borrow_mut(); // panic! 已有不可变借用

// Cow — 写时复制
use std::borrow::Cow;
let mut cow = Cow::Borrowed("hello");
cow.to_mut().push_str(" world"); // 首次修改时分配
```

### 智能指针对比

| | Box\<T\> | Rc\<T\> | Arc\<T\> | RefCell\<T\> |
|--|--------|-------|--------|------------|
| 所有权 | 单 | 单线程共享 | 跨线程共享 | 单+运行时借用 |
| 引用计数 | 否 | 是(非原子) | 是(原子) | 否 |
| 线程安全 | `Send+Sync` | `!Send+!Sync` | `Send+Sync` | `Send+!Sync` |
| 内部可变性 | 否 | 否(需RefCell) | 否(需Mutex) | 是(runtime) |

### 智能指针的组合使用

```rust
use std::cell::RefCell;
use std::rc::Rc;

// Rc<RefCell<T>>: 单线程共享 + 内部可变性
let shared = Rc::new(RefCell::new(vec![1, 2, 3]));
let shared2 = Rc::clone(&shared);

shared.borrow_mut().push(4);
println!("{:?}", shared2.borrow()); // [1, 2, 3, 4]

use std::sync::{Arc, Mutex};

// Arc<Mutex<T>>: 跨线程共享 + 内部可变性
let shared = Arc::new(Mutex::new(vec![1, 2, 3]));
let shared2 = Arc::clone(&shared);

std::thread::spawn(move || {
    shared2.lock().unwrap().push(4);
});
```

## 深入理解

### 智能指针的 drop 顺序

```text
智能指针的 drop 顺序:

规则: 变量按声明的逆序 drop

let a = Box::new(1);
let b = Rc::new(2);
let c = Arc::new(3);
// drop 顺序: c, b, a (逆序)

对于嵌套结构:
let x = Rc::new(RefCell::new(Box::new(String::from("hello"))));
// drop 顺序:
// 1. Rc::drop → strong_count -= 1
// 2. 如果 strong_count == 0:
//    a. RefCell::drop (无操作)
//    b. Box::drop → 释放堆内存
//    c. String::drop → 释放字符串缓冲区
//    d. 释放 RcBox
```

### 智能指针的内存对齐

```text
智能指针的对齐要求:

Box<T>:
  指针对齐: 8 字节 (x86_64)
  数据对齐: align_of::<T>()

Rc<T> / Arc<T>:
  指针对齐: 8 字节
  RcBox 对齐: max(align_of::<usize>(), align_of::<T>())
  // 引用计数需要 usize 对齐

RefCell<T>:
  指针对齐: 8 字节
  RefCellBox 对齐: max(align_of::<isize>(), align_of::<T>())
  // borrow 计数需要 isize 对齐

内存布局示例 (Rc<i32>):
  栈:                    堆:
  ┌──────────┐          ┌─────────────────────┐
  │ ptr (8B) │────────→ │ strong: 1 (8B)      │
  └──────────┘          │ weak: 0 (8B)        │
                        │ data: 42 (4B)       │
                        │ padding: 4B         │  ← 对齐填充
                        └─────────────────────┘
  堆分配大小: 24 字节 (8 + 8 + 4 + 4)
```

### 智能指针的性能对比

```text
性能基准测试 (估算):

操作            │ Box     │ Rc      │ Arc     │ RefCell
────────────────┼─────────┼─────────┼─────────┼─────────
创建            │ ~100ns  │ ~100ns  │ ~100ns  │ ~10ns
克隆            │ N/A     │ ~2ns    │ ~10ns   │ N/A
借用 (不可变)   │ ~0ns    │ ~0ns    │ ~0ns    │ ~2ns
借用 (可变)     │ ~0ns    │ N/A     │ N/A     │ ~2ns
Drop            │ ~2ns    │ ~2ns    │ ~10ns   │ ~0ns

注: 以上为估算值，实际性能取决于硬件和竞争情况

关键洞察:
  - Box: 最快的堆分配方式 (单次 malloc)
  - Rc: 非原子操作，单线程最快
  - Arc: 原子操作有开销，但跨线程安全
  - RefCell: 运行时检查有开销，但提供内部可变性
```
