# 宏系统的编译原理

## 原理

Rust 宏系统分为两类：

**声明宏**（`macro_rules!`）：语法层面的模式匹配 + 替换。在 token 流级别工作（AST 之前），不进行类型检查。匹配到的 token 子树被替换为新的 token 流。这是编译器前端的第一个扩展 pass。

**过程宏**（Proc Macro）：Rust 程序生成 Rust 程序的元编程。在编译时为每个 `#[derive]` 或 `#[attr]` 调用编译一个动态库（`.so`），编译器调用其导出的函数，输入为 TokenStream，输出为生成代码的 TokenStream。

声明宏的内部工作方式：macro arm 从左到右尝试匹配 token 树。`$pat:pat` 等是一种分类的捕获（fragment specifier）。递归宏（`$(...)*`）和 token 拼合通过 `macro_rules!` 实现。

过程宏的类型：
- `#[derive(Trait)]` — 自动生成 trait 实现
- `#[attr]` — 属性宏，修改被标记的项
- `fn-like` — 类似函数调用的宏

声明宏在编译时间开销小（纯 token 操作），过程宏需要额外编译 proc-macro crate，增加首次编译时间。

## 声明宏（macro_rules!）深度解析

### Token 树（Token Tree）

```text
Rust 编译器将源码解析为 token 树:

Token 树的递归定义:
  - 单个 token (identifier, keyword, literal, punctuation)
  - 由括号匹配的 token 树序列:
    - ( ... ) — 圆括号组
    - [ ... ] — 方括号组
    - { ... } — 花括号组

示例:
  vec![1, 2, 3]

  Token 树:
    [Ident(vec)] [!] [LParen] [  [IntLit(1)] [,] [IntLit(2)] [,] [IntLit(3)]  ] [RParen]

  vec 宏看到的 token 流:
    [IntLit(1)] [,] [IntLit(2)] [,] [IntLit(3)]
```

### Fragment Specifier（片段说明符）

```text
$捕获名:片段类型

片段类型定义了捕获的 token 范围:

┌──────────┬────────────────────────────────────────┐
│ 片段类型   │ 匹配范围                               │
├──────────┼────────────────────────────────────────┤
│ expr     │ 表达式 (1 + 2, "hello", x, if ... {})   │
│ ty       │ 类型 (i32, String, Vec<T>)              │
│ pat      │ 模式 (x, (a, b), Some(_), 1..=5)        │
│ stmt     │ 语句 (let x = 1;, x.push(1);)           │
│ item     │ 项 (fn, struct, impl, mod, ...)          │
│ block    │ 块 ({ ... })                             │
│ ident    │ 标识符 (变量名、函数名、类型名)            │
│ literal  │ 字面量 (1, "hello", true)                │
│ tt       │ 单个 token 树 (最灵活的匹配)              │
│ lifetime │ 生命周期 ('a, 'static)                   │
│ meta     │ 属性内容 (derive(Debug), allow(unused))  │
│ vis      │ 可见性修饰符 (pub, pub(crate), ...)      │
│ path     │ 路径 (std::vec::Vec, crate::foo)         │
└──────────┴────────────────────────────────────────┘

重要:
  - expr 不能匹配完整的语句（如 if 表达式在某些位置需要 tt）
  - tt 可以匹配任何单个 token 树，包括括号组
  - 使用 $crate 可以引用定义宏的 crate
```

### 重复模式（Repetition）

```text
$(...)*  — 零次或多次
$(...)+  — 一次或多次
$(...)?  — 零次或一次

分隔符:
  $( $x:expr ),*     — 逗号分隔，零次或多次
  $( $x:expr );+     — 分号分隔，一次或多次
  $( $x:expr ),+ ,   — 逗号分隔，最后一次后跟逗号

嵌套重复:
  $( $( $x:expr ),* ),*
  匹配: 1, 2; 3, 4, 5; 6

捕获变量在重复中的使用:
  $( v.push($x); )*  — 对每个匹配的 $x 执行一次
  $crate::$func($($arg),*)  — 传递给其他宏或函数
```

### 递归宏

```rust
// 递归宏用于处理任意深度的嵌套结构
macro_rules! count {
    () => (0usize);
    ($head:tt $($tail:tt)*) => (1usize + count!($($tail)*));
}

assert_eq!(count!(), 0);
assert_eq!(count!(a), 1);
assert_eq!(count!(a b c), 3);
```

### 宏卫生性（Hygiene）

```text
Rust 声明宏的部分卫生性:

卫生的方面:
  - 宏内部引入的局部变量不会与外部同名变量冲突
  - 通过 hygienic expansion，每个标识符有唯一的 "context"

  macro_rules! make_func {
      ($name:ident) => {
          fn $name() {
              let x = 1;  // 这个 x 是 macro 上下文的
              println!("{}", x);
          }
      }
  }

  let x = 42;
  make_func!(my_func);
  my_func();  // 打印 1，不是 42
  // 宏内的 x 和外部的 x 是不同的

不卫生的方面:
  - 宏内的 $crate 可以引用调用处的上下文
  - 某些场景下仍可能产生意外的名称冲突
  - 过程宏可以生成任意代码（完全不卫生）
```

### macro_rules! 的编译过程

```text
macro_rules! 定义的宏在编译中的位置:

源码 (.rs)
    │
    ▼
Lexer → Token 流
    │
    ▼
macro_rules! 定义展开 ← 第一个 pass
    │                    (宏在解析前展开)
    ▼
AST 生成
    │
    ▼
... (后续编译)

关键: macro_rules! 在 AST 之前工作
      这意味着宏可以改变语法结构
      例如: vec![...] 展开为 { let mut v = Vec::new(); ... }
```

## 过程宏（Proc Macro）深度解析

### 过程宏的类型

```text
三种过程宏:

1. Derive 宏 — #[derive(MyTrait)]
   - 为结构体/枚举自动生成 trait 实现
   - 输入: 结构体/枚举定义
   - 输出: impl MyTrait for ... { ... }

2. 属性宏 — #[my_attribute]
   - 修改被标记的项
   - 可以完全替换原始项
   - 输入: 属性参数 + 原始项
   - 输出: 修改后的项

3. 函数式宏 — my_macro!(...)
   - 类似声明宏，但使用 Rust 代码处理
   - 输入: TokenStream
   - 输出: TokenStream
```

### 过程宏的编译流程

```text
过程宏的编译流程:

1. 编译 proc-macro crate
   - 生成动态库 (.so / .dylib / .dll)
   - 包含导出函数: fn(TokenStream) -> TokenStream

2. 编译宿主 crate
   - 加载 proc-macro 动态库
   - 遇到 #[derive(X)] 时:
     a. 解析 X 对应的 proc-macro 函数
     b. 将被标记项的 TokenStream 传入
     c. 接收返回的 TokenStream
     d. 将返回的代码插入到编译流程中

3. 过程宏可以:
   - 读取输入的结构/枚举定义
   - 分析字段名和类型
   - 生成新的代码
   - 返回编译错误（通过 syn::Error）
```

### quote! 和 parse

```rust
// quote! 宏 — 生成 Rust 代码
// 使用 #variable 语法插入变量

use quote::quote;
use syn;

let name = syn::Ident::new("MyStruct", proc_macro2::Span::call_site());
let fields = vec![
    syn::Ident::new("field1", proc_macro2::Span::call_site()),
    syn::Ident::new("field2", proc_macro2::Span::call_site()),
];

let expanded = quote! {
    impl MyTrait for #name {
        fn method(&self) -> i32 {
            #(#fields)*  // 展开字段名
            0
        }
    }
};
// expanded 现在是 TokenStream
```

```rust
// syn — 解析 TokenStream 为 Rust 语法结构

use syn::{parse_macro_input, DeriveInput};

#[proc_macro_derive(MyTrait)]
pub fn my_trait_derive(input: proc_macro::TokenStream) -> proc_macro::TokenStream {
    // 解析输入
    let input = parse_macro_input!(input as DeriveInput);

    // 获取结构体名称
    let name = &input.ident;

    // 获取字段
    let fields = match &input.data {
        syn::Data::Struct(data) => &data.fields,
        _ => panic!("MyTrait can only be derived for structs"),
    };

    // 生成代码
    let expanded = quote! {
        impl MyTrait for #name {
            fn method(&self) -> i32 {
                0
            }
        }
    };

    expanded.into()
}
```

### 过程宏的错误处理

```rust
use syn::{parse_macro_input, DeriveInput};

#[proc_macro_derive(MyTrait)]
pub fn my_trait_derive(input: proc_macro::TokenStream) -> proc_macro::TokenStream {
    let input = parse_macro_input!(input as DeriveInput);

    // 检查是否为结构体
    match &input.data {
        syn::Data::Struct(_) => {},
        _ => {
            // 返回编译错误
            return syn::Error::new(
                input.ident.span(),
                "MyTrait can only be derived for structs"
            ).to_compile_error().into();
        }
    };

    // ... 生成代码
}
```

## cfg(test) 宏详解

### 条件编译

```rust
// cfg 属性用于条件编译
#[cfg(target_os = "linux")]
fn linux_only() {}

#[cfg(target_os = "windows")]
fn windows_only() {}

#[cfg(test)]
mod tests {
    #[test]
    fn it_works() {
        assert_eq!(2 + 2, 4);
    }
}

// cfg! 宏用于运行时检查
if cfg!(target_os = "linux") {
    println!("Running on Linux");
}

// 自定义 cfg 标志
// RUSTFLAGS='--cfg my_feature' cargo build
#[cfg(my_feature)]
fn feature_flagged() {}
```

### cfg 表达式

```rust
// 复杂的 cfg 表达式
#[cfg(all(target_os = "linux", target_arch = "x86_64"))]
fn linux_x86_64_only() {}

#[cfg(any(target_os = "linux", target_os = "macos"))]
fn unix_only() {}

#[cfg(not(target_os = "windows"))]
fn not_windows() {}

#[cfg(all(feature = "serde", not(feature = "no-serde")))]
fn with_serde() {}
```

## 与 C 预处理器宏的对比

### C 宏的局限

```c
// C 预处理器宏 — 文本替换，无类型安全
#define MAX(a, b) ((a) > (b) ? (a) : (b))

// 问题 1: 副作用
int x = 5, y = 3;
MAX(x++, y);  // 展开为 ((x++) > (y) ? (x++) : (y))
               // x 被递增两次！

// 问题 2: 类型不安全
MAX(1, 2.5);  // 混合类型，结果可能意外

// 问题 3: 语法歧义
#define SQUARE(x) x * x
SQUARE(1 + 2);  // 展开为 1 + 2 * 1 + 2 = 5 (不是 9)
```

### Rust 宏的优势

```rust
// Rust 声明宏 — token 级别的模式匹配
macro_rules! max {
    ($a:expr, $b:expr) => {
        if $a > $b { $a } else { $b }
    };
}

// 优势 1: 表达式捕获（$a:expr 保证是完整表达式）
max!(x + 1, y);  // 安全

// 优势 2: 重复模式
macro_rules! vec_of {
    ($($x:expr),* $(,)?) => {
        {
            let mut v = Vec::new();
            $( v.push($x); )*
            v
        }
    };
}

// 优势 3: 递归处理
macro_rules! nested {
    ($head:expr, $($tail:expr),*) => {
        // 处理 $head，递归处理 $tail
    };
    ($single:expr) => {
        // 处理单个元素
    };
}
```

### 对比表

```text
┌──────────────────┬──────────────────┬──────────────────┐
│       特性        │    C 宏          │   Rust 宏        │
├──────────────────┼──────────────────┼──────────────────┤
│ 处理级别          │ 文本替换          │ Token 树匹配     │
│ 类型安全          │ 无               │ 部分（片段类型）   │
│ 语法检查          │ 无               │ 有               │
│ 递归              │ 受限（栈溢出）    │ 支持             │
│ 调试              │ 困难（预处理后）  │ 可用 cargo expand │
│ 卫生性            │ 无               │ 部分             │
│ 作用域            │ 全局              │ 定义处           │
│ 错误信息          │ 差               │ 好               │
│ 编译时间          │ 快               │ 快（声明宏）      │
│                  │                  │ 慢（过程宏）      │
└──────────────────┴──────────────────┴──────────────────┘
```

## 声明宏的高级技巧

### 内部规则（Internal Rules）

```rust
// 使用内部规则模式分离匹配逻辑和代码生成
macro_rules! my_vec {
    // 公共入口 — 调用内部规则
    ($($x:expr),* $(,)?) => {
        my_vec!(@internal $($x),*)
    };

    // 内部规则 — 实际实现
    (@internal) => {
        Vec::new()
    };
    (@internal $head:expr $(, $tail:expr)*) => {
        {
            let mut v = Vec::new();
            v.push($head);
            $( v.push($tail); )*
            v
        }
    };
}
```

### TT Muncher 模式

```rust
// TT Muncher: 逐个消费 token 树
macro_rules! print_list {
    // 空列表
    () => {};

    // 处理第一个元素，递归处理剩余
    ($head:tt $($tail:tt)*) => {
        println!("{}", $head);
        print_list!($($tail)*);
    };
}

print_list!(1 2 3 4);
// 打印: 1 2 3 4 (每行一个)
```

### Push-down Accumulation 模式

```rust
// Push-down Accumulation: 累积结果
macro_rules! accumulate {
    // 累积器为空，开始新累积
    ($($visited:tt)*) => {};

    // 累积第一个元素
    ($head:tt $($tail:tt)*) => {
        accumulate!(@ accum ($head) $($tail)*);
    };

    // 累积后续元素
    (@ accum ($($accum:tt)*) $head:tt $($tail:tt)*) => {
        accumulate!(@ accum ($($accum)* $head) $($tail)*);
    };

    // 完成累积
    (@ accum ($($result:tt)*)) => {
        println!("Result: {:?}", stringify!($($result)*));
    };
}
```

## 宏导出（macro_export）

```rust
// macro_export 使宏在 crate 外部可用
#[macro_export]
macro_rules! public_macro {
    () => {};
}

// 使用 $crate 引用定义宏的 crate
#[macro_export]
macro_rules! my_vec {
    ($($x:expr),* $(,)?) => {
        {
            let mut v = $crate::Vec::new();
            $( v.push($x); )*
            v
        }
    };
}

// macro_export 的特点:
// - 宏被提升到 crate 根
// - 通过 use 导入
// - $crate 始终指向定义宏的 crate
// - 避免路径问题
```
