# 类型系统的力量

## 原理

### Hindley-Milner 类型推导

Rust 类型系统基石为 Hindley-Milner（HM）扩展版本，增加子类型（lifetime subtyping）、trait 约束、关联类型。类型推导通过合一（unification）将类型变量与具体类型统一：`Vec::<_>` 遇到 `push(42i32)` 后合一 `?0 = i32`。

**名词解释**：

- **Hindley-Milner（HM）类型系统**：一种简单的多态类型系统，由 Roger Hindley (1969) 和 Robin Milner (1978) 独立提出。核心特征是"类型推导"——不需要显式标注类型，编译器可以自动推断。
- **合一（Unification）**：类型推导的核心算法，将两个类型"统一"为同一类型。例如合一 `?T` 和 `i32` 得到 `?T = i32`。
- **类型变量（Type Variable）**：表示未知类型的占位符，如 `?T`，在推导过程中被具体类型替换。
- **单态化（Monomorphization）**：将泛型代码为每个具体类型生成独立副本，消除运行时多态开销。

```text
HM 类型推导算法 (Algorithm W):

输入: 表达式 e
输出: 类型替换 S 和类型 T

W(Γ, x) = (id, lookup(Γ, x))           // 变量
W(Γ, λx.e) = (S, S(τ) → T)            // lambda
             其中 (S1, T1) = W(Γ ∪ {x: ?α}, e)
W(Γ, e1 e2) = (S2 ∘ S1, S2(T1))       // 函数应用
             其中 (S1, T1) = W(Γ, e1)
                   (S2, T2) = W(S1(Γ), e2)
                   S3 = unify(T1, T2 → ?β)

合一算法:
unify(τ1, τ2) = {
    if τ1 == τ2: return id                    // 相同类型
    if τ1 is type var: return bind(τ1, τ2)    // 绑定变量
    if τ2 is type var: return bind(τ2, τ1)
    if τ1 = T1→T2, τ2 = T3→T4:
        S1 = unify(T1, T3)
        S2 = unify(S1(T2), S1(T4))
        return S2 ∘ S1
}

Rust 的扩展:
  - 增加 trait 约束: T: Display
  - 增加生命周期: &'a T
  - 增加子类型: &'a T <: &'b T (如果 'a: 'b)
```

### Curry-Howard 同构

Curry-Howard 同构表明：类型 = 命题，程序 = 证明。

| 逻辑 | 类型 | Rust 示例 |
|------|------|-----------|
| $(A \land B)$ | 积类型 `(A, B)` | `(i32, String)` |
| $(A \lor B)$ | 和类型 | `Result<T, E>` |
| $(A \to B)$ | 函数 `fn(A) -> B` | `fn f(x: i32) -> bool` |
| $\forall x. P(x)$ | 多态 `for<T>` | `fn foo<T>(x: T)` |
| $\exists x. P(x)$ | 存在类型 | `dyn Trait` |
| $\perp$ (假) | Never 类型 | `!` |
| $\top$ (真) | Unit 类型 | `()` |

```text
Curry-Howard 同构详解:

积类型 (Product Type):
  逻辑: A ∧ B (A 且 B)
  类型: (A, B) 或 struct { a: A, b: B }
  证明: 同时提供 A 的证明和 B 的证明
  Rust: let pair: (i32, bool) = (42, true);

和类型 (Sum Type):
  逻辑: A ∨ B (A 或 B)
  类型: enum { Left(A), Right(B) }
  证明: 提供 A 的证明或 B 的证明
  Rust: let result: Result<i32, String> = Ok(42);

函数类型:
  逻辑: A → B (如果 A 则 B)
  类型: fn(A) -> B
  证明: 将 A 的证明转换为 B 的证明
  Rust: fn add_one(x: i32) -> i32 { x + 1 }

全称量化 (Universal Quantification):
  逻辑: ∀x. P(x) (对所有 x，P(x) 成立)
  类型: for<T> fn(T) -> P<T>
  证明: 对任意类型 T，提供 P<T> 的证明
  Rust: fn identity<T>(x: T) -> T { x }

存在量化 (Existential Quantification):
  逻辑: ∃x. P(x) (存在 x 使得 P(x) 成立)
  类型: dyn Trait (隐藏具体类型)
  证明: 提供具体的值和其类型
  Rust: let d: &dyn Display = &42; // 存在某个 T: Display

永假类型 (Bottom Type):
  逻辑: ⊥ (假命题，无证明)
  类型: ! (Never 类型)
  特性: 可以转换为任何类型 (ex falso quodlibet)
  Rust: let x: i32 = panic!(); // panic! 返回 !

永真类型 (Top Type):
  逻辑: ⊤ (真命题，平凡证明)
  类型: () (Unit 类型)
  特性: 唯一的值是 ()，没有信息量
  Rust: let u: () = ();
```

### 单态化 (Monomorphization)

泛型代码在编译时为每个具体类型生成独立副本，无虚函数调用开销。这是零成本抽象的核心——与 C++ 模板的 monomorphization 同构，但 Rust 先完成类型检查再展开，错误信息更清晰。

```text
单态化过程:

Rust 源码:
fn add<T: std::ops::Add<Output=T>>(a: T, b: T) -> T {
    a + b
}

let x = add(1i32, 2i32);
let y = add(1.0f64, 2.0f64);

编译器展开:
fn add_i32(a: i32, b: i32) -> i32 { a + b }
fn add_f64(a: f64, b: f64) -> f64 { a + b }

let x = add_i32(1, 2);
let y = add_f64(1.0, 2.0);

二进制中的表示:
  .text:
  add_i32:
      lea eax, [rdi + rsi]   ; 整数加法直接内联
      ret
  add_f64:
      addsd xmm0, xmm1      ; 浮点加法
      ret

性能:
  静态分发 (泛型): 直接调用，可内联 → 零额外开销
  动态分发 (trait object): 间接调用 → 有 vtable 查找开销
```

### Trait 约束作为约束求解

```text
Trait 约束的编译器处理:

源码:
fn print_all<T: Display + Debug>(items: &[T]) {
    for item in items {
        println!("{:?} {}", item, item);
    }
}

编译器的约束求解:
  1. 收集所有 T 的约束: [Display, Debug]
  2. 为每个约束生成代码:
     - Display → 调用 fmt 方法
     - Debug → 调用 fmt 方法
  3. 生成具体的函数代码 (单态化)

LLVM IR (简化):
  define void @print_all_i32(i32* %items, i64 %len) {
      ; T = i32 时的具体实现
      ; i32 实现了 Display 和 Debug
      ; 编译器直接内联 fmt 实现
  }

  define void @print_all_string({ ptr, i64, i64 }* %items, i64 %len) {
      ; T = String 时的具体实现
      ; String 实现了 Display 和 Debug
  }
```

### 关联类型与泛型参数

```rust
// 关联类型: 每种迭代器只有一种 Item 类型
trait Iterator {
    type Item;  // 关联类型
    fn next(&mut self) -> Option<Self::Item>;
}

// 泛型参数: 一个类型可以实现多次
trait Convertible<T> {
    fn convert(&self) -> T;
}

// i32 可以同时转换为 f64 和 String
impl Convertible<f64> for i32 {
    fn convert(&self) -> f64 { *self as f64 }
}
impl Convertible<String> for i32 {
    fn convert(&self) -> String { self.to_string() }
}

// 关联类型 vs 泛型参数的选择:
// - 关联类型: 每个类型只有一个"自然"的实现 → Iterator
// - 泛型参数: 一个类型可以有多个实现 → Convertible
```

### Newtype 模式

```rust
// Newtype: 用元组结构体包装现有类型，创建新类型
struct Meters(f64);
struct Seconds(f64);

fn speed(distance: Meters, time: Seconds) -> f64 {
    distance.0 / time.0
}

// speed(Meters(100.0), Seconds(9.58)) // OK
// speed(Seconds(9.58), Meters(100.0)) // 编译错误: 类型不匹配

// Newtype 的优势:
// 1. 类型安全: 防止混淆不同含义的数值
// 2. 零成本: 运行时与原始类型完全相同
// 3. 可以为 newtype 实现额外的方法和 trait
// 4. 可以绕过孤儿规则 (orphan rule)
```

### Phantom Types (幻影类型)

```rust
use std::marker::PhantomData;

// 幻影类型: 在类型中标记一个不使用的类型参数
struct QrCode<Data> {
    data: Vec<u8>,
    _marker: PhantomData<Data>,  // 不占空间
}

struct RawData;
struct ValidatedData;

impl QrCode<RawData> {
    fn new(data: Vec<u8>) -> Self {
        QrCode { data, _marker: PhantomData }
    }
}

impl QrCode<RawData> {
    fn validate(self) -> Result<QrCode<ValidatedData>, String> {
        if self.data.is_empty() {
            Err("empty data".to_string())
        } else {
            Ok(QrCode { data: self.data, _marker: PhantomData })
        }
    }
}

impl QrCode<ValidatedData> {
    fn render(&self) -> String {
        // 只有验证后的 QR 码才能渲染
        "QR code rendered".to_string()
    }
}

// 编译时保证: 只有验证后的 QR 码才能渲染
// let qr = QrCode::new(vec![1, 2, 3]);
// qr.render();  // 编译错误: QrCode<RawData> 没有 render 方法
// let qr = qr.validate().unwrap();
// qr.render();  // OK: QrCode<ValidatedData> 有 render 方法
```

### Typestate Pattern (类型状态模式)

```rust
use std::marker::PhantomData;

// 类型状态: 用类型系统编码状态机
struct Door<State> {
    _marker: PhantomData<State>,
}

struct Closed;
struct Open;

impl Door<Closed> {
    fn new() -> Self {
        println!("门已关闭");
        Door { _marker: PhantomData }
    }

    fn open(self) -> Door<Open> {
        println!("门已打开");
        Door { _marker: PhantomData }
    }
}

impl Door<Open> {
    fn close(self) -> Door<Closed> {
        println!("门已关闭");
        Door { _marker: PhantomData }
    }
}

// 状态机:
//   Closed → open() → Open
//   Open → close() → Closed
//
// 编译时保证: 不能关闭已关闭的门，不能打开已打开的门
// let door = Door::<Closed>::new();
// door.close();  // 编译错误: Closed 没有 close 方法
// let door = door.open();
// door.open();   // 编译错误: Open 没有 open 方法
// let door = door.close();
```

### 零大小类型 (ZST)

```rust
use std::mem;

// 零大小类型: 大小为 0 的类型
struct Marker;  // 单元结构体
enum Void {}    // 空枚举 (never type 的变体)

assert_eq!(mem::size_of::<Marker>(), 0);
assert_eq!(mem::size_of::<()>(), 0);  // Unit 类型
assert_eq!(mem::size_of::<[i32; 0]>(), 0);  // 空数组

// ZST 的用途:
// 1. 编译时状态标记 (PhantomData 的替代)
// 2. 零成本抽象: 作为泛型参数不增加运行时开销
// 3. 标记 trait: Send, Sync, Sized 等都是 ZST

// Vec<ZST> 的特殊优化:
// Vec<()> 不分配内存，因为每个元素大小为 0
let v: Vec<()> = vec![(), (), ()];
println!("len: {}", v.len());  // 3
println!("capacity: {}", v.capacity());  // 可能 > 3
// 但实际堆分配为 0 字节!
```

## 深入理解

### 类型推导的算法细节

```text
Rust 类型推导的完整流程:

1. 收集约束:
   let x = 5;                    // ?T = i32 (整数字面量默认 i32)
   let v: Vec<i32> = vec![];    // Vec<?U> = Vec<i32> → ?U = i32
   v.push(x);                    // Vec<i32>::push(i32) → 一致

2. 合一 (Unification):
   将类型变量与具体类型统一
   ?T = i32
   ?U = i32

3. 解决歧义:
   let x = "42".parse().unwrap();
   // parse::<?T>() → ?T
   // 目标类型需要显式标注或从上下文推断

4. 检查约束:
   fn foo<T: Display>(x: T) { ... }
   foo(42);  // i32: Display → 满足约束

推导失败的例子:
   let x = vec![];
   // vec![] 的类型是 Vec<?T>
   // 没有足够的信息推断 ?T
   // 错误: "type annotations needed"
```

### 单态化与代码膨胀

```text
单态化的代码膨胀问题:

源码:
fn process<T: Display>(items: &[T]) { ... }

调用:
process(&[1i32, 2, 3]);      // 生成 process_i32
process(&[1.0f64, 2.0, 3.0]); // 生成 process_f64
process(&["a", "b", "c"]);    // 生成 process_str

二进制膨胀:
  每个具体类型生成一份完整的函数代码
  如果函数体很大，膨胀会很严重

Rust 的优化:
  1. 小函数: 直接内联，消除函数调用开销
  2. 大函数: 提取公共部分为非泛型函数
  3. LTO (Link-Time Optimization): 跨 crate 去重

对比:
  C++ 模板: 更激进的展开，可能导致严重膨胀
  Rust 泛型: 更保守的展开，错误信息更清晰
```
