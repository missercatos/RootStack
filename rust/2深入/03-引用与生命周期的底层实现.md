# 引用与生命周期的底层实现

## 原理

### 引用的运行时表示

Rust 引用在运行时与 C 指针完全等效——都是 8B 虚拟地址。区别在编译期：borrow checker 为 `&T` 附加 noalias 属性传给 LLVM，为 `&mut T` 附加 unique + noalias 属性。

**名词解释**：

- **noalias 属性**：LLVM IR 中的函数参数属性，告知优化器：通过该指针访问的内存没有其他指针同时访问（除了通过该指针本身）。
- **alias（别名）**：两个或多个指针指向同一内存位置的情况。C/C++ 中指针别名是优化的主要障碍之一。
- **strict aliasing 规则**：C/C++ 中规定不同类型的指针不能指向同一内存（有例外），Rust 通过借用检查器在编译期保证更强的别名约束。
- **NLL（Non-Lexical Lifetimes）**：生命周期基于使用点（use-site）而非词法作用域（scope）确定，允许更精确的借用分析。

```text
引用在编译期 vs 运行时的区别:

编译期 (类型信息):
  &T:     编译器附加 noalias 属性
  &mut T: 编译器附加 unique + noalias 属性
  借用检查器验证所有借用规则

运行时 (机器码):
  &T:     8 字节指针 (x86_64)
  &mut T: 8 字节指针 (x86_64)
  完全等价于 C 指针，零额外开销

LLVM IR 表示:
  define void @foo(i32* noalias %a, i32* noalias %b) { ... }
  ; noalias 告知优化器: a 和 b 不指向同一内存

  define void @bar(i32* noalias %a, i32* %b) { ... }
  ; 只有 a 有 noalias，b 可能与 a 重叠
```

### LLVM noalias 属性的影响

`noalias` 属性告知优化器：通过该指针访问的内存没有其他指针同时访问。这使得：

- Load/store 可以重排
- 值可以缓存到寄存器不重新加载
- 向量化时可以忽略别名冲突

```text
noalias 优化效果示例:

原始代码:
fn add(a: &mut i32, b: &i32) {
    *a += *b;
    *a += *b;  // 两次读取 *b
}

LLVM 优化 (a 有 noalias):
fn add(a: *mut i32 noalias, b: *const i32 noalias) {
    let r1 = *b;     // 第一次读取
    let r2 = *a;     // 读取 a
    let r3 = r1 + r2; // r1 + r2
    *a = r3;         // 写入 a (可能改变 b 指向的值)
    let r4 = *b;     // 但 b 有 noalias，所以 b 指向的值未变!
    *a = r3 + r4;    // 可以直接用 r1 替代 r4
}

优化后:
fn add(a: *mut i32 noalias, b: *const i32 noalias) {
    let r1 = *b;     // 只读取一次
    let r2 = *a;
    let r3 = r1 + r2;
    *a = r3 + r1;    // 用 r1 替代第二次 *b
}

性能差异:
  无 noalias: 2 次内存读取 (load b, load b)
  有 noalias: 1 次内存读取 (load b)
  在紧密循环中差异显著
```

### 借用检查器 (Borrow Checker)

借用规则的检查在 MIR 层执行（NLL borrowck），通过求解变量（variable）在每条语句上的存活性约束来工作。每条 `&` 生成 borrow，每条 `&mut` 生成 unique borrow，borrows 与所有权之间的关系用 disjoint intervals 表示。

```text
NLL 借用检查的工作流程:

1. 将源代码转换为 MIR (控制流图)
   每个基本块 (basic block) 包含一系列语句

2. 为每个借用生成约束:
   &x       → 生成 region 'a，约束: x 必须在 'a 期间有效
   &mut x   → 生成 region 'a，约束: x 必须在 'a 期间有效且无其他借用

3. 构建约束图:
   节点 = 区域 (region)
   边 = 区域包含关系

4. 求解约束图:
   使用数据流分析确定每个区域的最小范围

5. 检查冲突:
   如果两个互斥的借用区域重叠 → 编译错误

示例:
let mut s = String::from("hello");
let r1 = &s;           // borrow(s, 'a) 从这里开始
println!("{}", r1);     // 'a 在这里结束 (NLL: 最后使用点)
let r2 = &mut s;       // borrow_mut(s, 'b) 从这里开始
// r1 已经结束，'a 和 'b 不重叠 → OK
println!("{}", r2);
```

### NLL 区域推断

```text
NLL 区域推断示例:

代码:
let mut s = String::from("hello");
let r1 = &s;
let x = 5;              // 不相关操作
println!("{} {}", r1, x);
let r2 = &mut s;        // NLL: r1 已结束，可以借用
println!("{}", r2);

词法生命周期 (旧):
  'a = 从 r1 创建到作用域结束
  'b = 从 r2 创建到作用域结束
  'a 和 'b 重叠 → 编译错误 (旧编译器)

NLL 生命周期:
  'a = 从 r1 创建到 r1 最后使用 (println! 之前)
  'b = 从 r2 创建到 r2 最后使用
  'a 和 'b 不重叠 → OK

控制流图:
  bb0: {
      s = String::new();
      r1 = &s;              // 'a 开始
      x = 5;
  }
  bb1: {
      println!("{}", r1);   // 'a 结束 (最后一次使用 r1)
      r2 = &mut s;          // 'b 开始
  }
  bb2: {
      println!("{}", r2);   // 'b 结束
  }
```

### Polonius（新一代借用检查器）

Polonius 是 Rust 正在开发的新借用检查器，目标是支持更复杂的借用模式。与 NLL 不同，Polonius 跟踪**每个路径上的引用状态**，而非仅跟踪区域重叠。

```text
NLL vs Polonius 对比:

NLL:
  - 跟踪区域 (region) 的重叠
  - 区域是控制流路径上的连续范围
  - 不能处理"条件借用"

Polonius:
  - 跟踪每个路径上的引用状态
  - 更精确地分析引用何时"出生"和"死亡"
  - 支持更复杂的借用模式

示例 (Polonius 支持但 NLL 不支持):
fn example(cond: bool) {
    let mut s = String::from("hello");
    let r1 = &s;
    if cond {
        println!("{}", r1);  // r1 在这里使用
    }
    // NLL: r1 的区域延伸到这里 (分支汇聚点)
    // Polonius: r1 只在 cond=true 的路径上存活
    let r2 = &mut s;  // NLL: 错误! Polonius: OK
    println!("{}", r2);
}

Polonius 算法概述:
  1. 为每个引用维护 "origin" (来源)
  2. 追踪 origin 的 "loan" (借用) 和 "liveness" (存活性)
  3. 在每个路径上检查: 如果 loan 活跃且 origin 被使用 → 冲突
  4. 使用 "dataflow" 分析确定每个路径上的活跃引用
```

### 宽指针 (Fat Pointers)

`&str` 和 `&[T]` 是 fat pointer（16B），包含数据指针和长度。`&dyn Trait` 包含数据指针和 vtable 指针。这些在调用时通过寄存器对传递。

```text
Fat pointer 内存布局:

&[i32] (slice 引用):
  ┌──────────────────┐
  │ ptr  (8 bytes)   │ ──→ [1, 2, 3, 4, 5]
  │ len  (8 bytes)   │ = 5
  └──────────────────┘
  总大小: 16 字节

&str (字符串切片):
  ┌──────────────────┐
  │ ptr  (8 bytes)   │ ──→ "hello" (UTF-8)
  │ len  (8 bytes)   │ = 5
  └──────────────────┘
  总大小: 16 字节

&dyn Trait (trait object):
  ┌──────────────────┐    ┌─────────────────────┐
  │ data_ptr (8B)    │──→ │ T 的数据             │
  │ vtable_ptr (8B)  │──→ │ [drop, size, align, │
  └──────────────────┘    │  method1, method2,  │
                          │  ...]               │
                          └─────────────────────┘
  总大小: 16 字节

与 C 的对比:
  C 的 char* 必须配合 strlen() 获取长度 → O(n) 时间
  Rust 的 &str 编码长度在指针中 → O(1) 时间
  C 的 void* 无类型信息 → 不安全
  Rust 的 &dyn Trait 包含 vtable → 安全的动态分发
```

### 与 C/C++ 别名规则的对比

```text
C/C++ 别名规则 vs Rust 借用规则:

C/C++:
  - strict aliasing 规则: 不同类型的指针不能指向同一内存 (有例外)
  - 指针可以自由转换 (void* 是万能指针)
  - 别名违规 → 未定义行为 (UB)
  - 编译器基于 strict aliasing 做优化

  示例 (C, 未定义行为):
  int x = 1;
  float* fp = (float*)&x;  // strict aliasing 违规
  *fp = 2.0f;              // UB!

Rust:
  - 借用检查器在编译期保证: &T 和 &mut T 不能同时存在
  - 更强的约束: 没有类型转换，没有 void*
  - 借用违规 → 编译错误 (不是 UB)
  - 无 unsafe 代码时，不可能有别名违规

  示例 (Rust, 编译错误):
  let mut x = 1i32;
  let r1 = &x;
  let r2 = &mut x;  // 编译错误: 不能同时有 &x 和 &mut x

性能对比:
  C/C++: 别名规则是优化的"最佳努力"，可能有隐藏的别名
  Rust:  借用规则是强制的，优化器可以完全信任 noalias
```

## 语法

### 引用与指针

```rust
let x = 5;
let r: &i32 = &x; // 编译后等价于 *const i32
let v = *r; // 解引用

// 裸指针（unsafe）
let p: *const i32 = &x as *const i32;
unsafe { println!("{}", *p); }
```

### 借用检查的核心规则

| 规则 | 示例 |
|------|------|
| 共享借用可复制 | `let r1 = &s; let r2 = &s;` |
| 独占借用唯一 | `let r = &mut s;` |
| 二者不能共存 | `&s` 和 `&mut s` 不可同时有效 |
| 被借时不可 move | 有 `&s` 时不能 `let t = s` |

### noalias 优化效果

```rust
fn add(a: &mut i32, b: &i32) { *a += *b; }

// 编译器可为 a 生成 noalias load/store
// 因为 &mut 保证无其他引用指向同一位置
```

### fat pointer 布局

| 类型 | 栈大小 | 组成部分 |
|------|--------|----------|
| `&T` | 8B | 数据指针 |
| `&[T]` | 16B | ptr + len |
| `&str` | 16B | ptr + len |
| `&dyn Trait` | 16B | data ptr + vtable ptr |
| `&mut T` | 8B | 数据指针 |

### 引用的高级用法

```rust
// 引用的生命周期标注
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}

// 引用与解引用
let x = 5;
let r = &x;
assert_eq!(5, *r);  // 解引用获取值
assert_eq!(&5, r);  // 引用自动解引用

// 可变引用的独占性
let mut v = vec![1, 2, 3];
let first = &mut v[0];
*first = 10;  // 通过可变引用修改
// v.push(4); // 错误: first 仍然活跃，不能借用 v
```

### 悬垂引用的防止

```rust
// 编译器阻止悬垂引用
fn dangle() -> &String { // 错误: 缺少生命周期标注
    let s = String::from("hello");
    &s // s 在函数结束时被 drop，引用指向已释放内存
}

// 正确: 返回所有权
fn no_dangle() -> String {
    let s = String::from("hello");
    s // 所有权转移给调用者，不会被 drop
}

// 编译器在汇编层面的保证:
// 所有引用在使用时，被引用数据必须在作用域内
// 这通过借用检查器的区域推断实现
```

## 深入理解

### 借用检查器的约束生成算法

```text
约束生成示例:

fn example() {
    let mut s = String::from("hello");
    let r1 = &s;           // 生成: borrow(s, region 'a)
    println!("{}", r1);     // 使用 r1: region 'a 包含此点
    let r2 = &mut s;       // 生成: borrow_mut(s, region 'b)
    println!("{}", r2);     // 使用 r2: region 'b 包含此点
}

约束:
  1. borrow(s, 'a)      → s 在 'a 期间必须有效
  2. borrow_mut(s, 'b)  → s 在 'b 期间必须有效
  3. 'a 和 'b 不能重叠  → 'a 必须在 'b 开始前结束

求解:
  'a = [创建 r1, 最后使用 r1] = [line 2, line 3]
  'b = [创建 r2, 最后使用 r2] = [line 4, line 5]
  'a 和 'b 不重叠 → 通过

冲突检测:
  如果 'a 和 'b 重叠 → 编译错误
  错误信息: "cannot borrow `s` as mutable because it is also borrowed as immutable"
```

### 生命周期在编译后的表示

```text
生命周期在编译后的实际表示:

Rust 源码:
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}

编译后的 MIR:
fn longest(x: &str, y: &str) -> &str {
    // 生命周期 'a 在 MIR 中消失
    // 借用检查器已经验证了生命周期约束
    // 编译后只留下纯指针操作
}

LLVM IR:
define i8* @longest(i8* noalias %x, i64 %x_len,
                     i8* noalias %y, i64 %y_len) {
    ; 没有任何生命周期信息
    ; 只有 noalias 属性 (来自借用规则)
    ; 生命周期约束已经被编译器验证并消除
}

机器码:
  mov rax, rdi    ; x 指针
  mov rdx, rsi    ; x 长度
  cmp rdx, rcx    ; 比较长度
  cmovle rax, r8  ; 如果 x 更短，返回 y
  ret

结论: 生命周期信息完全在编译期使用，运行时零开销
```

### 引用与原始指针的关系

```rust
use std::ptr;

// Rust 引用 vs 原始指针
let x = 42;
let r: &i32 = &x;           // 安全引用
let p: *const i32 = &x as *const i32;  // 原始指针

// 引用保证: 对齐、非空、有效
// 原始指针: 可能为空、未对齐、悬垂

// unsafe 块中可以绕过借用规则
let mut x = 42;
let r1: &mut i32 = &mut x;
let r2: &mut i32 = unsafe { &mut *(&mut x as *mut i32) };
// r1 和 r2 都是 &mut i32，但指向同一内存
// 这是未定义行为! Rust 的安全保证只在 safe 代码中成立
```

## 实践

### 力扣问题

力扣: 力扣DFS — 引用传递

```rust
fn dfs(graph: &Vec<Vec<usize>>, node: usize, visited: &mut Vec<bool>) {
    visited[node] = true;
    for &next in &graph[node] {
        if !visited[next] {
            dfs(graph, next, visited);
        }
    }
}
// graph: 共享借用，多次读取
// visited: 独占借用，每次修改一个元素
// 借用检查器验证: graph 和 visited 不冲突
```
