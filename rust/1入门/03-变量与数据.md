# 变量与数据

## 原理

Rust 类型系统分为两类存储：栈（stack）和堆（heap）。

栈上数据大小在编译期确定，分配/释放是单指令栈指针移动（`sub rsp, N` / `add rsp, N`）。所有标量类型（`i32`, `f64`, `bool`, `char`）和其组合均存于栈，实现 `Copy` trait 后赋值行为是 `memcpy`。

堆上数据大小在运行时可变（`String`, `Vec<T>`），由分配器（默认 jemalloc 或系统 malloc）管理。非 `Copy` 类型赋值触发所有权转移（move），即仅拷贝栈上的"胖指针"（ptr + len + cap），不深拷贝堆数据。

`const` 与 `let` 的区别：常量在编译期求值，直接内联到使用点（类似 C 的 `#define`），不占运行时内存地址。数组 `[T; N]` 的大小 N 也必须在编译期确定。

## 深入理解：内存布局与类型系统

### 栈与堆的内存布局

理解栈和堆的区别是理解 Rust 所有权的基础：

```text
程序内存布局（简化）
┌─────────────────────── 高地址
│        栈 (Stack)      │ ← 向低地址增长
│  ┌─────────────────┐  │
│  │ 参数、返回地址    │  │
│  │ 局部变量         │  │
│  │ ...              │  │
│  └─────────────────┘  │
│           ↓            │
│                        │
│           ↑            │
│  ┌─────────────────┐  │
│  │  堆 (Heap)       │ ← 向高地址增长
│  │  动态分配的数据   │  │
│  └─────────────────┘  │
│        静态/全局数据    │
│        代码段          │
└─────────────────────── 低地址
```

**栈上的 `i32`：**
```text
内存地址    值
0x7fff...  │ 42 │  ← i32 占 4 字节
```

**栈上的 `String`（24字节）：**
```text
栈（24字节）                堆
┌──────────────────┐      ┌─────────────────┐
│ ptr ─────────────────→  │ h │ e │ l │ l │ o │
│ len: 5           │      └─────────────────┘
│ cap: 5           │
└──────────────────┘
  8B    8B    8B
```

**`&str` 切片引用（16字节）：**
```text
栈（16字节）                堆/静态存储
┌──────────────────┐      ┌─────────────────┐
│ ptr ─────────────────→  │ h │ e │ l │ l │ o │
│ len: 5           │      └─────────────────┘
└──────────────────┘
  8B    8B
  没有 cap，因为 &str 不拥有数据
```

### 变量遮蔽（Shadowing）深度解析

```rust
let x = 5;        // x1: i32, 值 5
let x = x + 1;    // x2: i32, 值 6，x1 被遮蔽（shadowed）
let x = "hello";  // x3: &str, 值 "hello"，x2 被遮蔽
```

```text
编译器视角的变量表：

作用域开始
├─ x1 (i32 = 5)        ← 活跃
├─ x2 (i32 = 6)        ← x1 被遮蔽，不可访问
└─ x3 (&str = "hello") ← x2 被遮蔽，不可访问

NLL 分析：x1 和 x2 在被遮蔽后不再使用，可以提前 drop
```

**Shadowing vs `mut` 的内存影响：**

```rust
// Shadowing：编译器可能复用内存
let x = String::from("hello");
let x = x.len();  // String 被 drop，x 现在是 usize
                   // 编译器可以复用之前 String 占用的栈空间

// mut：变量始终存在
let mut x = String::from("hello");
x = String::from("world");  // 旧 String 被 drop，新 String 被创建
                             // x 的栈空间（24字节）始终被占用
```

### mut 与 immutable 的深层含义

Rust 默认不可变的设计哲学来自 **一致性**——不可变是安全的基线，可变是需要证明的例外：

```rust
// 不可变绑定：编译器可以自由优化
let x = 5;
let y = x + 1;  // 编译器知道 x 始终是 5，可以常量折叠为 y = 6

// 可变绑定：编译器必须保守处理
let mut x = 5;
let mut v = vec![x];
x = 10;  // v 仍然包含 5（Vec 存储的是 x 的值，不是引用）
```

**在并发场景中，不可变性更加关键：**

```rust
use std::thread;

let data = vec![1, 2, 3];

// ✅ 多个线程可以共享不可变引用
let handles: Vec<_> = (0..3).map(|i| {
    let d = &data;  // 不可变借用
    thread::spawn(move || {
        println!("thread {}: {:?}", i, d);
    })
}).collect();

// ❌ 不能在共享不可变的同时修改
// let mut data = vec![1, 2, 3];
// let handle = thread::spawn(|| {
//     data.push(4);  // 编译错误：closure may outlive current function
// });
```

### 类型推断（Type Inference）深入

Rust 的类型推断是 **局部的**（local inference），不是全局的。编译器从使用点反向推断类型：

```rust
let mut v = Vec::new();  // 此时类型不确定
v.push(5);               // 从 push(5) 推断出 T = i32
v.push(6);               // 类型已确定，不能 push 字符串
// v.push("hello");      // ❌ 编译错误：expected `i32`, found `&str`

// 对比：C++ 的 auto 是从初始化表达式推断
// auto x = 5;  // 类型从右侧推断
// Rust 是从使用点推断，更灵活
```

```rust
// 函数返回类型帮助推断
fn parse(s: &str) -> i32 {
    s.parse().unwrap()  // 返回类型 i32 帮助推断 parse() 返回 i32
}

// 类型标注消除歧义
let x = "42".parse::<i32>().unwrap();  // turbofish 语法
let x: i32 = "42".parse().unwrap();    // 类型标注
```

### 整数溢出行为

```text
编译模式    溢出行为           底层实现
────────  ─────────────────  ──────────────────────
debug     panic（运行时崩溃）  插入溢出检查指令
release   二进制补码回绕       直接使用 CPU 指令（无检查）
```

```rust
// debug 模式
let x: u8 = 255;
// let y = x + 1;  // panic: attempt to add with overflow

// release 模式
// let y = x + 1;  // y = 0（静默回绕，与 C 行为相同）

// 安全的溢出处理
let x: u8 = 255;
let y = x.checked_add(1);     // Some(0) 或 None
let y = x.wrapping_add(1);    // 0（始终回绕）
let y = x.saturating_add(1);  // 255（饱和在最大值）
let y = x.overflowing_add(1); // (0, true)  // (值, 是否溢出)
```

### 标量类型与复合类型

```text
标量类型（Scalar）              复合类型（Compound）
─────────────────             ──────────────────
一个值                         多个值的组合

整数: i8~i128, u8~u128        元组: (T1, T2, ...)
浮点: f32, f64                 数组: [T; N]
布尔: bool                     切片: &[T]
字符: char
```

**元组的内存布局：**
```rust
let t: (i32, bool, f64) = (42, true, 3.14);
```
```text
栈上布局（紧凑排列，无填充）：
┌────────┬────────┬────────────┐
│ i32    │ bool   │ f64        │
│ 4B     │ 1B     │ 8B         │
│ 0..3   │ 4      │ 5..12      │
└────────┴────────┴────────────┘
总大小：可能有填充到 16 字节（取决于对齐）
```

**数组的内存布局：**
```rust
let arr: [i32; 4] = [10, 20, 30, 40];
```
```text
栈上布局（连续存储）：
┌─────┬─────┬─────┬─────┐
│ 10  │ 20  │ 30  │ 40  │
│ 4B  │ 4B  │ 4B  │ 4B  │
└─────┴─────┴─────┴─────┘
总大小：16 字节（4 × 4）
```

### 元组解构

```rust
let t = (1, "hello", 3.14);

// 解构绑定
let (x, y, z) = t;
println!("{} {} {}", x, y, z);  // 1 hello 3.14

// 忽略部分值
let (x, _, z) = t;  // 忽略 y

// 使用 .. 忽略剩余
let (x, ..) = t;  // 只取 x

// 通过 .0 .1 索引访问
println!("{}", t.1);  // hello
```

### 类型转换 `as`

```rust
let a: i32 = 42;
let b: i64 = a as i64; // 安全扩展
let c: i8 = a as i8; // 可能截断（42 → 42，安全）
let d: i8 = 256 as i8; // 截断：256 → 0（超出 i8 范围）
let f: i32 = 3.14 as i32; // 小数截断 → 3
```

> Rust 不做隐式类型转换。跨类型必须通过 `as`。

### 常量

```rust
const MAX: u32 = 1000;
const PI: f64 = 3.14159;
// 类型标注必须出现，值编译期确定
```

| | `let` | `const` |
|--|-------|---------|
| 可变性 | 默认不可变，可加 mut | 永远不可变 |
| 类型标注 | 可选 | 必须 |
| 求值时机 | 运行时 | 编译时 |
| 作用域 | 词法作用域 | 全局或模块级 |
| 内存地址 | 有（栈上） | 无（内联到使用点） |

## 常见陷阱

### 1. `usize` vs `isize` 的选择
数组索引、长度、内存大小始终用 `usize`（与平台指针宽度一致：64位系统上是 64位）。不要用 `i32` 做索引。

### 2. `let` 声明的变量默认不可变
```rust
let x = 5;
// x = 6;  // ❌ 编译错误
let mut y = 5;
y = 6;    // ✅ 合法
```

### 3. `as` 转换可能丢失精度或截断
```rust
let big: i32 = 1_000_000_000;
let small: i8 = big as i8;  // 截断为 0，不报错
```
