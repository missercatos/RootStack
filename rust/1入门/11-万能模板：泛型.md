# 万能模板：泛型

## 原理

### 单态化（Monomorphization）详解

Rust 泛型通过**单态化（Monomorphization）**实现：编译器为每个被使用的具体类型生成独立的代码副本。`fn foo<T>()` 被调用为 `foo::<i32>()` 和 `foo::<f64>()` 时，生成两个独立的函数实例。

```text
你写的代码:
fn add<T: std::ops::Add<Output=T>>(a: T, b: T) -> T { a + b }

fn main() {
    let x = add(1, 2);      // T = i32
    let y = add(1.0, 2.0);  // T = f64
}

编译器生成 (概念性):
fn add_i32(a: i32, b: i32) -> i32 { a + b }
fn add_f64(a: f64, b: f64) -> f64 { a + b }

fn main() {
    let x = add_i32(1, 2);
    let y = add_f64(1.0, 2.0);
}
```

这是零成本抽象（zero-cost abstraction）：运行时性能和手写具体类型版本完全一致，因没有虚函数表查找和 Box 装箱。代价是编译时间增加（更多代码需要 LLVM 优化）和二进制体积变大（代码膨胀）。

### 泛型 vs 动态分发（性能对比）

```text
静态分发 (泛型):
┌─────────────────────────────────────┐
│ 编译时: 为每个 T 生成独立代码         │
│ 运行时: 零开销，直接函数调用           │
│ 编译后: fn process_i32(i32)          │
│         fn process_f64(f64)          │
│ 优点: 可内联，无指针跳转              │
│ 缺点: 二进制体积大 (代码膨胀)          │
└─────────────────────────────────────┘

动态分发 (dyn Trait):
┌─────────────────────────────────────┐
│ 编译时: 生成一份代码 + vtable          │
│ 运行时: 通过 vtable 指针间接调用       │
│ 编译后: fn process(obj: &dyn Trait)   │
│         - obj 指向 [data_ptr, vtable] │
│         - vtable: [drop, fn1, fn2]   │
│ 优点: 二进制体积小，支持异构类型        │
│ 缺点: 指针跳转，阻止内联              │
└─────────────────────────────────────┘
```

对比 C++ 模板：C++ 模板是图灵完备的宏展开，Rust 泛型先做类型检查再单态化，错误信息更清晰。约束通过 trait bound（`T: PartialOrd`）限制可用的操作。

### 与 C++ 模板的对比

| 特性 | Rust 泛型 | C++ 模板 |
|------|-----------|----------|
| 类型检查 | 先检查后单态化 | 实例化时检查 |
| 错误信息 | 清晰（指向约束） | 模糊（指向模板内部） |
| 特化 | 不允许（稳定版） | 允许（特化/偏特化） |
| 约束语法 | `T: Trait` | `enable_if` / concepts |
| SFINAE | 无（用 trait bound） | 有 |
| 图灵完备 | 否 | 是（可做编译期计算） |

## 语法

### 泛型函数

```rust
// T: PartialOrd 是 trait bound，约束 T 必须可比较
fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut max = &list[0];
    for item in list {
        if item > max { max = item; }
    }
    max
}

// 多个泛型参数
fn pair<T, U>(a: T, b: U) -> (T, U) { (a, b) }

// 返回值使用泛型
fn first<T>(list: &[T]) -> Option<&T> {
    list.first()
}
```

### 泛型结构体

```rust
struct Point<T> { x: T, y: T }
// 所有字段必须是同一类型 T

struct Pair<T, U> { first: T, second: U }
// 不同字段可以是不同类型

// 使用
let integer_point = Point { x: 5, y: 10 };
let float_point = Point { x: 1.0, y: 4.0 };
// let mixed = Point { x: 5, y: 4.0 }; // 错误: T 不统一
```

### 泛型方法

```rust
impl<T> Point<T> {
    fn x(&self) -> &T { &self.x }
}

// 针对特定类型实现额外方法
impl Point<f64> {
    fn distance(&self) -> f64 {
        (self.x.powi(2) + self.y.powi(2)).sqrt()
    }
}

// 方法中引入新的泛型参数
impl<T> Point<T> {
    fn mixup<U>(self, other: Point<U>) -> Point<T> {
        Point { x: self.x, y: other.y } // 可能类型不匹配!
    }
}
```

### 泛型枚举（标准库实例）

```rust
enum Option<T> { Some(T), None }
enum Result<T, E> { Ok(T), Err(E) }
// 这些就是泛型枚举的最经典应用
```

### Trait Bound 三种写法

```rust
// 1. impl Trait 语法糖 (参数位置)
fn f(x: &impl Display) { }  // 等价于下面
fn f<T: Display>(x: &T) { } // 语法糖展开

// 2. Turbofish 风格 (调用时指定)
fn f<T: Display>(x: &T) { }
f::<i32>(&42);    // 显式指定 T=i32
42.f::<i32>();    // 方法调用形式

// 3. where 从句（约束多时推荐）
fn f<T>(x: &T) where T: Display + Clone + Debug { }
// where 让签名更清晰，尤其返回值也有约束时
```

### 多重约束

```rust
fn compare<T: PartialOrd + Display>(a: T, b: T) {
    if a > b { println!("{} > {}", a, b); }
}

// 返回值约束
fn create_default<T: Default + Clone>() -> T {
    T::default()
}

// 嵌套约束
fn process<T>(items: &[T])
where
    T: Display + Debug,
    T: PartialOrd,
{
    // ...
}
```

### Const Generics（常量泛型）

```rust
// 编译期常量作为泛型参数
struct Array<T, const N: usize> {
    data: [T; N],
}

impl<T, const N: usize> Array<T, N> {
    fn new() -> Self where T: Default + Copy {
        Array { data: [T::default(); N] }
    }
}

let a: Array<i32, 3> = Array::new();  // [0, 0, 0]
let b: Array<i32, 5> = Array::new();  // [0, 0, 0, 0, 0]

// 编译期约束
fn print_array<T: Debug, const N: usize>(arr: [T; N]) {
    println!("{:?}", arr);
    // N 在编译期已知，运行时无开销
}
```

### 选择

| 命名 | 惯例用法 |
|------|----------|
| `T` | 任意类型 |
| `U, V` | 第二、三类型 |
| `K` | HashMap 键 |
| `V` | HashMap 值 |
| `E` | 错误类型 |
| `R` | 返回类型 |
| `S` | 状态/字符串 |

## 常见陷阱与最佳实践

### 陷阱 1：代码膨胀

```rust
// 两个函数单态化后产生两份机器码
fn process<T: Display>(x: T) { println!("{}", x); }
process::<i32>(&1);
process::<f64>(&1.0);
process::<&str>(&"hello");
// 生成 3 个函数: process_i32, process_f64, process_str
// 如果逻辑复杂，二进制体积显著增长
```

### 陷阱 2：过度约束

```rust
// ❌ 过度约束
fn find_max<T: PartialOrd + Display + Debug + Default + Clone>(list: &[T]) -> &T {
    let mut max = &list[0];
    for item in list { if item > max { max = item; } }
    max
    // 实际只需要 PartialOrd
}

// ✅ 最小约束
fn find_max<T: PartialOrd>(list: &[T]) -> &T {
    let mut max = &list[0];
    for item in list { if item > max { max = item; } }
    max
}
```

### 最佳实践

1. 使用最小约束，不要预设未来需求
2. 优先用 `impl Trait` 简化简单函数签名
3. 复杂约束用 `where` 子句提升可读性
4. 考虑 `dyn Trait` 替代泛型以减小二进制体积（性能敏感时除外）

### 力扣问题

力扣: 力扣排序题 — 泛型排序函数

```rust
fn sort_slice<T: Ord>(slice: &mut [T]) {
    slice.sort();
}

// 泛型栈
struct Stack<T> {
    elements: Vec<T>,
}

impl<T> Stack<T> {
    fn new() -> Self {
        Stack { elements: Vec::new() }
    }
    fn push(&mut self, item: T) {
        self.elements.push(item);
    }
    fn pop(&mut self) -> Option<T> {
        self.elements.pop()
    }
}
```
