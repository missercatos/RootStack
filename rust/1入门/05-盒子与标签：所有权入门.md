# 盒子与标签：所有权入门

## 原理

所有权系统是 Rust 替代 GC 的核心机制，基于三个编译期规则实现静态内存管理：

栈上的值按位复制（`memcpy`）成本低；堆上的值通过指针访问，赋值时仅拷贝指针（Move），不深拷贝堆数据。编译器在函数退出点自动插入 `drop` 调用释放堆内存。

`Copy` trait 标记按位复制安全（stack-only 类型）。非 `Copy` 类型在赋值后原变量被编译器视为"未初始化"，产生 use-after-move 编译错误。这是通过 MIR（Mid-level IR）阶段的 move-checker 实现的 non-lexical lifetime 分析。

根本原因：避免 double-free。两个变量拥有同一块堆内存的所有权，作用域结束时均执行 `drop` → 两次 `free` → 未定义行为。

## 深入理解：所有权系统的运作机制

### 三条核心规则详解

Rust 所有权系统建立在三条看似简单的规则之上，但它们的含义远比表面深入：

```text
规则 1：Rust 中每个值有且仅有一个所有者（owner）
规则 2：在任意时刻，值有且仅有一个所有者
规则 3：当所有者离开作用域时，值被丢弃（drop）
```

**规则 1 和 2 的含义：** 这排除了 C++ 中多个指针指向同一块内存的情况。在 Rust 中，如果你想要多个"视角"查看同一数据，必须使用引用（borrow），而引用不拥有数据。

```rust
let s1 = String::from("hello");
let s2 = s1;
// s1 不再是所有者，s2 是唯一所有者
// 编译器在 MIR 阶段标记 s1 为 "moved"
// 之后任何使用 s1 的代码都会被拒绝
```

**规则 3 的含义：** `drop` 的调用时机是确定性的——在变量离开作用域的最后一刻。这与 C++ 的 RAII（Resource Acquisition Is Initialization）模式一致，但 Rust 通过所有权系统保证恰好 drop 一次。

### Move 语义的内存变化

```rust
let s1 = String::from("hello");
let s2 = s1;
```

```text
执行前 s1：
栈                     堆
┌──────────────────┐   ┌─────────────────┐
│ s1               │   │                 │
│ ptr ───────────────→ │ h │ e │ l │ l │ o │
│ len: 5           │   └─────────────────┘
│ cap: 5           │
└──────────────────┘

执行后 s2（move 之后）：
栈                     堆
┌──────────────────┐   ┌─────────────────┐
│ s1（已失效）      │   │                 │
│ [undefined]      │   │ h │ e │ l │ l │ o │
│                  │   └─────────────────┘
├──────────────────┤         ↑
│ s2               │   s2 的 ptr 指向这里
│ ptr ───────────────→
│ len: 5           │
│ cap: 5           │
└──────────────────┘
```

**关键点：** move 操作只是复制了栈上的 24 字节（ptr + len + cap），堆数据没有被复制。s1 的栈内容被标记为无效，防止误用。

### Clone vs Copy 深入对比

```text
┌─────────────────────────────────────────────┐
│                 Copy trait                    │
│                                               │
│  • 按位复制（memcpy）                         │
│  • 编译器自动执行，无显式调用                   │
│  • 仅适用于栈上数据（大小在编译期已知）          │
│  • 要求类型实现了 Clone（Copy ⊂ Clone）        │
│  • 赋值后原变量仍然有效                        │
│                                               │
│  典型类型：i32, f64, bool, char, &T           │
└─────────────────────────────────────────────┘

┌─────────────────────────────────────────────┐
│                Clone trait                    │
│                                               │
│  • 显式调用 .clone()                          │
│  • 可以深拷贝堆数据（由类型自己决定如何 clone）   │
│  • 运行时开销可能很高（如 Vec clone 需要分配）   │
│  • 赋值后原变量仍然有效                        │
│                                               │
│  典型类型：String, Vec<T>, Box<T>             │
└─────────────────────────────────────────────┘
```

**为什么 `String` 不实现 `Copy`？**

```rust
// String 包含堆指针：
// 栈：ptr (8B) + len (8B) + cap (8B) = 24B
// 堆：实际的字符数据

// 如果 String 是 Copy：
let s1 = String::from("hello");
let s2 = s1;  // 如果是 Copy，s1 和 s2 都指向同一块堆内存
// s1 和 s2 都是所有者 → 都会 drop → double-free！
```

```text
Copy 类型的内存（栈上完整数据）：
┌─────────┐
│ 42      │  ← i32，值就在栈上
└─────────┘
复制：memcpy 4 字节，两个变量各自独立

非 Copy 类型的内存（栈 + 堆）：
栈              堆
┌─────────┐   ┌─────────┐
│ ptr ─────────→ data    │
│ len     │   └─────────┘
│ cap     │
└─────────┘
复制：如果按位复制，两个 ptr 指向同一块堆 → double-free
所以必须 move 或显式 clone
```

### Clone 和 Copy 的实现条件

```rust
// 自动 derive Copy 和 Clone
#[derive(Copy, Clone)]
struct Point {
    x: i32,
    y: i32,
}

// ❌ 不能为包含非 Copy 字段的结构体实现 Copy
// #[derive(Copy)]
// struct Wrapper {
//     name: String,  // String 不是 Copy
// }

// ✅ 可以实现 Clone（深拷贝）
#[derive(Clone)]
struct Wrapper {
    name: String,
}

let w1 = Wrapper { name: String::from("hi") };
let w2 = w1.clone();  // 深拷贝，name 也被 clone
```

### String vs &str 的所有权差异

```text
String（堆分配，拥有数据）：
┌──────────────────────┐
│ 栈：24 字节           │
│ ┌─────┬─────┬─────┐  │
│ │ ptr │ len │ cap │  │
│ └──┬──┴─────┴─────┘  │
│    │                  │
│    ↓                  │
│ 堆：字符数据           │
│ ┌───┬───┬───┬───┬───┐ │
│ │ h │ e │ l │ l │ o │ │
│ └───┴───┴───┴───┴───┘ │
└──────────────────────┘

&str（切片引用，不拥有数据）：
┌──────────────────────┐
│ 栈：16 字节           │
│ ┌─────┬─────┐        │
│ │ ptr │ len │        │
│ └──┬──┴─────┘        │
│    │                  │
│    ↓                  │
│ 堆/静态存储：          │
│ ┌───┬───┬───┬───┬───┐ │
│ │ h │ e │ l │ l │ o │ │
│ └───┴───┴───┴───┴───┘ │
└──────────────────────┘
  没有 cap，因为 &str 不负责释放内存
```

```rust
// String 拥有数据，可以修改
let mut s = String::from("hello");
s.push_str(" world");  // ✅ 可以修改

// &str 只是借用，不能修改
let s: &str = "hello";
// s.push_str(" world");  // ❌ 编译错误：no method named `push_str`
```

### 所有权在函数调用中的行为

```rust
fn take_ownership(s: String) {
    println!("{}", s);
}   // s 离开作用域，String 被 drop

fn borrow_immutably(s: &String) {
    println!("{}", s);
}   // s 离开作用域，但只是引用，不 drop 任何东西

fn main() {
    let s = String::from("hello");

    take_ownership(s);       // s 的所有权转移给函数参数
    // println!("{}", s);    // ❌ 编译错误：s 已被 move

    let s2 = String::from("world");
    borrow_immutably(&s2);  // 借用，不转移所有权
    println!("{}", s2);     // ✅ s2 仍然有效
}
```

**函数返回值也遵循所有权规则：**

```rust
fn create_string() -> String {
    let s = String::from("hello");
    s   // 所有权转移给调用者
}   // s 不会被 drop，因为所有权已转移

fn modify_and_give_back(mut s: String) -> String {
    s.push_str(" world");
    s   // 归还所有权
}

fn main() {
    let s1 = create_string();
    let s2 = modify_and_give_back(s1);
    // s1 已被 move，只有 s2 有效
}
```

### 汇编层面的 move

```rust
let s1 = String::from("hello");
let s2 = s1;
```

对应的汇编（x86-64，简化）：
```asm
; s1 = String::from("hello")
lea     rdi, [rip + .str.0]    ; 加载字符串字面量地址
mov     qword ptr [rbp - 24], rdi  ; ptr
mov     qword ptr [rbp - 16], 5    ; len = 5
mov     qword ptr [rbp - 8], 5     ; cap = 5

; s2 = s1（move）
mov     rax, qword ptr [rbp - 24]  ; 复制 ptr
mov     qword ptr [rbp - 48], rax
mov     rax, qword ptr [rbp - 16]  ; 复制 len
mov     qword ptr [rbp - 40], rax
mov     rax, qword ptr [rbp - 8]   ; 复制 cap
mov     qword ptr [rbp - 32], rax
; s1 的栈位置被标记为无效，但汇编层面只是不使用了
```

**关键观察：** move 就是三个 `mov` 指令，复制 24 字节的栈数据。没有堆内存操作，没有函数调用。这就是零开销。

### C/C++ 中的类似机制

```c
// C 中的浅拷贝（危险）
char* s1 = malloc(6);
strcpy(s1, "hello");
char* s2 = s1;  // 浅拷贝，s2 指向同一块内存
free(s1);
free(s2);  // double-free！未定义行为

// C++ 中的 RAII
std::string s1 = "hello";
std::string s2 = s1;  // 深拷贝（Copy 构造函数）
// 两个独立的字符串，各自释放，安全但有运行时开销

// Rust 中的 move
let s1 = String::from("hello");
let s2 = s1;  // move，s1 失效
// 只有 s2 会 drop，安全且零开销
```

## 语法

### Move 语义

```rust
let s1 = String::from("hello");
let s2 = s1; // s1 所有权转移给 s2
// println!("{}", s1); // 编译错误：use of moved value
```

### Copy 类型（自动复制）

```rust
let x = 5;
let y = x; // x 仍然有效（i32 是 Copy）
println!("{} {}", x, y);
```

实现 `Copy` 的基本类型：

| 类型 |
|------|
| `i8`, `i16`, `i32`, `i64`, `i128`, `isize` |
| `u8`, `u16`, `u32`, `u64`, `u128`, `usize` |
| `f32`, `f64` |
| `bool`, `char` |
| `&T`（不可变引用） |
| `(T1, T2, ...)` 当所有字段都是 Copy |

### Clone — 显式深拷贝

```rust
let s1 = String::from("hello");
let s2 = s1.clone(); // 堆数据深拷贝，s1 仍有效
```

### 函数调用中的所有权

```rust
fn consume(s: String) { } // 接收所有权

fn main() {
 let s = String::from("hi");
 consume(s);
 // println!("{}", s); // 编译错误：s 已移动
}
```

```rust
fn give_back(s: String) -> String { s } // 归还所有权

let s = give_back(String::from("hi")); // 用遮蔽接收
```

### 元组与 Copy

```rust
let t1 = (1, 2, 3); // 全 Copy → 元组可 Copy
let t2 = (1, String::from("h")); // 含非 Copy → 元组不可 Copy
```

## 常见陷阱

### 1. 误以为 move 后还能使用原变量
```rust
let s = String::from("hello");
let s2 = s;
// println!("{}", s);  // ❌ 编译错误：use of moved value `s`
```

### 2. 忘记 `.clone()` 导致意外 move
```rust
let s = String::from("hello");
let s2 = s.clone();  // ✅ 显式深拷贝
// let s2 = s;       // ❌ move 后 s 不可用
```

### 3. 以为 `Copy` 类型赋值是深拷贝
```rust
let x = 5;
let y = x;  // Copy，就是 memcpy，没有"深拷贝"概念
// 两个独立的 i32 值
```

### 4. 结构体中非 Copy 字段导致整个结构体非 Copy
```rust
#[derive(Copy, Clone)]  // ❌ 编译错误：the trait `Copy` may not be implemented
struct User {
    name: String,  // String 不是 Copy
    age: u32,      // u32 是 Copy
}
// 只要有一个字段不是 Copy，整个结构体就不是 Copy
```
