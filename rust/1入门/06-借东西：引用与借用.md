# 借东西：引用与借用

## 原理

引用（Reference）在底层是裸指针（pointer）加编译期约束。`&T` 编译后就是一个 `*const T`，`&mut T` 是 `*mut T`，零运行时开销。但借用检查器（borrow checker）为它们加了严格的别名规则。

核心规则来自编译器 NLL（Non-Lexical Lifetimes）分析：
- 任意时刻，要么一个可变引用（`&mut`），要么多个不可变引用（`&`），不能共存
- 引用的生命周期不能超过被引用数据的生命周期

这条规则的根本目的是防止数据竞争和悬垂指针。LLVM 的 `noalias` 属性由此获得保证，启用大量优化。违反规则导致编译错误，而非运行时崩溃。

`&str` 是宽指针（2*usize: ptr + len），指向 UTF-8 字节序列。`&String` 通过 `Deref` trait 自动转型为 `&str`。两者均不拥有数据。

## 深入理解：引用系统的运作机制

### Shared Reference (&T) vs Mutable Reference (&mut T)

Rust 的引用系统建立在 **别名规则（aliasing rules）** 之上——这是确保内存安全和启用编译器优化的关键：

```text
┌───────────────────────────────────────────────────┐
│          不可变引用 (&T) — 共享借用                  │
│                                                     │
│  • 多个 &T 可以同时存在                              │
│  • 不能修改被引用的数据                              │
│  • 编译后就是一个裸指针 (*const T)，零开销            │
│  • 类似 C 的 const 指针                              │
│                                                     │
│  数据 ──→ &T ──→ &T ──→ &T                         │
│           多个视角，都只读                            │
└───────────────────────────────────────────────────┘

┌───────────────────────────────────────────────────┐
│          可变引用 (&mut T) — 独占借用                │
│                                                     │
│  • 同一时刻只能有一个 &mut T                         │
│  • 可以修改被引用的数据                              │
│  • 编译后是 *mut T，零开销                           │
│  • 不能与任何其他引用共存                             │
│                                                     │
│  数据 ──→ &mut T                                    │
│           独占视角，可读可写                          │
└───────────────────────────────────────────────────┘
```

**为什么不能同时存在 `&T` 和 `&mut T`？** 从 CPU 和编译器优化的角度：

```text
场景：如果允许 & 和 &mut 共存

let mut x = 42;
let r1 = &x;        // 不可变引用，读取 x
let r2 = &mut x;    // 可变引用，修改 x

// 问题 1：缓存一致性
// CPU 可能将 r1 读取的值缓存在 L1 cache
// r2 修改 x 后，r1 的缓存没有更新
// → r1 读取到过时的值

// 问题 2：编译器优化
// 编译器看到 r1 不会修改 x，可以将 x 的值常量折叠
// 但 r2 实际上修改了 x
// → 程序行为不符合预期

// 问题 3：LLVM noalias 优化
// LLVM 假设 &mut 指针是唯一的别名
// 如果存在其他别名，优化结果就是错误的
```

### Borrowing Rules 详解

```rust
let mut s = String::from("hello");

// 规则 1：任意时刻，要么一个 &mut，要么多个 &，不能共存
let r1 = &s;      // ✅ 第一个共享借用
let r2 = &s;      // ✅ 第二个共享借用
// let r3 = &mut s; // ❌ 已有共享借用，不能创建可变借用
println!("{} {}", r1, r2);

// 规则 2：引用的生命周期不能超过数据
let r3 = &s;      // ✅ r3 借用 s
// drop(s);        // ❌ 不能在 r3 还活着时 drop s
println!("{}", r3);
```

**NLL（Non-Lexical Lifetimes）——引用的生命周期是基于使用的，不是基于词法作用域的：**

```rust
let mut s = String::from("hello");

let r1 = &s;
let r2 = &s;
println!("{} {}", r1, r2);  // r1 和 r2 最后一次使用

// r1 和 r2 的生命周期在这里结束（因为不再使用）
let r3 = &mut s;  // ✅ 合法！r1 和 r2 已经不活跃
r3.push_str(" world");
```

```text
词法作用域（旧版 Rust）：
let r1 = &s;         // r1 开始
let r2 = &s;         // r2 开始
println!(...);       // 使用 r1, r2
let r3 = &mut s;     // ❌ r1, r2 仍在作用域内
println!(r3);        // 使用 r3

NLL（现代 Rust）：
let r1 = &s;         // r1 开始
let r2 = &s;         // r2 开始
println!(...);       // r1, r2 最后一次使用 → 生命周期结束
let r3 = &mut s;     // ✅ r1, r2 已结束
println!(r3);        // r3 最后一次使用 → 生命周期结束
```

### Auto-Deref 与 Deref Trait

Rust 的 **自动解引用（auto-deref）** 允许在需要 `&T` 的地方自动使用 `&T`、`&&T`、`&Box<T>` 等：

```rust
let s = String::from("hello");

// String 实现了 Deref<Target = str>
// 所以 &String 可以自动转换为 &str

fn print_str(s: &str) {
    println!("{}", s);
}

print_str(&s);        // ✅ &String → &str（Deref coercion）
print_str(&&s);       // ✅ &&String → &str（两次 deref）
print_str(&**&s);     // ✅ 也可以手动解引用
```

**Deref coercion 的链式转换：**

```text
&String → &str           （String: Deref<Target = str>）
&Vec<T> → &[T]          （Vec<T>: Deref<Target = [T]>）
&Box<T> → &T            （Box<T>: Deref<Target = T>）
&mut T → &T              （&mut T 可以自动转为 &T）

示例链：
&Box<String> → &String → &str
（Box: Deref → String, String: Deref → str）
```

```rust
// 方法查找也使用 Deref
let s = String::from("hello");

// String 没有 len() 方法
// 但 str 有 len() 方法
// 编译器通过 Deref 自动找到 str::len()

s.len()  // 等价于 (*s).len()  // 等价于 <String as Deref>::deref(&s).len()
```

**Deref trait 的定义：**

```rust
// 标准库中的定义
pub trait Deref {
    type Target: ?Sized;
    fn deref(&self) -> &Self::Target;
}

// String 的实现
impl Deref for String {
    type Target = str;
    fn deref(&self) -> &str {
        // 返回内部 str 的切片
    }
}
```

### Reference Lifetime in Loops

在循环中使用引用时，NLL 分析会考虑每次迭代的独立性：

```rust
let mut v = vec![1, 2, 3];

// ✅ 合法：每次迭代中 &v[i] 的生命周期在循环体结束时结束
for i in 0..v.len() {
    let val = &v[i];   // 不可变借用
    println!("{}", val);
    // val 的生命周期在这里结束
}
// 可以在循环外修改 v
v.push(4);

// ❌ 如果将引用保持到循环外：
let first;
for i in 0..v.len() {
    first = &v[i];  // first 借用 v
}
// first 仍然借用 v，不能修改 v
// v.push(5);  // ❌ 编译错误
```

**迭代器中的借用：**

```rust
let mut names = vec!["Alice", "Bob", "Charlie"];

// ✅ 借用迭代：for 中使用 &name
for name in &names {
    println!("{}", name);  // name 是 &&str
}
// 循环结束后可以修改 names
names.push("David");

// ❌ 消耗迭代：for 中使用 name（by value）
for name in names {
    println!("{}", name);  // name 是 &str，但消耗了 Vec
}
// names 被消耗，不能再用
```

### 悬垂引用（Dangling Reference）

Rust 编译器保证引用永远不悬垂：

```rust
// ❌ 编译错误：这个函数不能返回引用
// fn dangle() -> &String {
//     let s = String::from("hello");
//     &s  // s 在函数结束时被 drop，引用悬空
// }

// ✅ 正确做法：返回 String（转移所有权）
fn no_dangle() -> String {
    let s = String::from("hello");
    s  // 所有权转移给调用者
}
```

```text
悬垂引用的内存状态：

dangle() 执行后：
栈                     堆
┌──────────┐          ┌─────────┐
│ s（已释放）│          │ h e l l o│
│ [freed]  │          └─────────┘
└──────────┘               ↑
      │              内存已释放
      └── &s 指向这里      ↓
                    悬垂指针！
                    使用它 = 未定义行为

Rust 在编译期阻止这种情况：
error[E0106]: missing lifetime specifier
 --> src/main.rs:2:16
  |
2 | fn dangle() -> &String {
  |                ^ expected named lifetime parameter
```

### String vs &str 详细对比

| 类型 | 所有权 | 可变 | 大小 | 内存位置 |
|------|--------|------|------|---------|
| `String` | 拥有数据 | 是 | 24B | 栈(24B) + 堆(数据) |
| `&str` | 借用 | 否 | 16B | 栈(16B) → 静态/堆 |
| `&String` | 借用 | 否 | 8B | 栈(8B) → 栈(24B) → 堆 |

```rust
// String: 拥有数据，可修改
let mut s = String::from("hello");
s.push_str(" world");  // ✅ 可以修改

// &str: 只读借用
let s: &str = "hello";
// s.push_str(" world");  // ❌ 没有 push_str 方法

// &String: 借用 String，通过 Deref 转为 &str
let owned = String::from("hello");
let r: &String = &owned;
// r 的类型是 &String，但可以当 &str 用
print_str(r);  // ✅ Deref coercion: &String → &str
```

### C/C++ 中的对比

```c
// C 中的引用（const 指针）
const int* r = &x;  // 类似 Rust 的 &i32
// 没有 &mut 的等价物（C 的指针都可以修改）
// 编译器不阻止别名

// C++ 中的引用
int& r = x;  // 引用，但可以与原始变量共存
// 编译器不阻止别名
// 两个引用可以同时指向同一数据，一个修改后另一个看到变化
```

```rust
// Rust 的严格别名规则
let mut x = 42;
let r1 = &x;
let r2 = &x;   // ✅ 两个共享引用
// let r3 = &mut x;  // ❌ 编译错误：不能在共享引用存在时创建可变引用

// C++ 允许这种危险操作：
// int x = 42;
// int& r1 = x;
// int& r2 = x;  // 两个引用，都指向 x
// r1 = 100;     // 通过 r1 修改 x
// r2 也看到 100  // 看似正常，但编译器可能优化掉 r2 的读取
```

## 语法

### 创建引用

```rust
let s = String::from("hello");
let r = &s; // 不可变引用
let mut m = s;
let rm = &mut m; // 可变引用
```

### 解引用

```rust
let x = 5;
let r = &x;
assert_eq!(5, *r); // * 显式解引用
println!("{}", r); // 打印自动解引用
```

### 借用规则

| 规则 | 含义 |
|------|------|
| 多个 `&T` | 可同时存在（共享借用） |
| 单一 `&mut T` | 唯一可变引用（独占借用） |
| `&T` 和 `&mut T` | 不能共存 |

```rust
let mut s = String::from("hi");
let r1 = &s;
let r2 = &s; // 合法：多个不可变引用
// let r3 = &mut s; // 错误：已有不可变引用存在
println!("{} {}", r1, r2);
let r3 = &mut s; // 合法：r1 和 r2 已不再使用
```

### 函数参数中的引用

```rust
fn len(s: &String) -> usize { s.len() } // 只读借用
fn append(s: &mut String) { s.push_str("!"); } // 可变借用

let mut s = String::from("hello");
len(&s);
append(&mut s);
```

### 悬垂引用（编译器阻止）

```rust
// fn dangle() -> &String {
// let s = String::from("hi");
// &s // 错误：s 被释放后引用悬空
// }
```

## 常见陷阱

### 1. 在不可变引用存在时尝试可变借用
```rust
let mut s = String::from("hello");
let r1 = &s;
// s.push_str(" world");  // ❌ 不能在 &s 存在时修改 s
println!("{}", r1);
s.push_str(" world");  // ✅ r1 不再使用后可以修改
```

### 2. 返回局部变量的引用
```rust
// ❌ 编译错误
// fn bad() -> &String {
//     let s = String::from("hello");
//     &s  // s 即将被 drop，引用悬空
// }

// ✅ 返回所有权
fn good() -> String {
    String::from("hello")
}
```

### 3. 忘记 Deref coercion
```rust
fn print_str(s: &str) { println!("{}", s); }

let s = String::from("hello");
print_str(&s);   // ✅ &String → &str 自动转换
print_str(&&s);  // ✅ 也可以
// 但不要写成：
// print_str(s);  // ❌ 类型不匹配：expected &str, found String
```

### 4. 迭代器中的意外借用
```rust
let mut v = vec![1, 2, 3];
// ❌ 编译错误
// for item in &v {
//     v.push(*item);  // 不可变借用和可变借用冲突
// }
```
