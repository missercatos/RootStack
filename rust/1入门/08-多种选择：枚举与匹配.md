# 多种选择：枚举与匹配

## 原理

Rust 的 `enum` 是带标签的联合体（tagged union / sum type）。编译器在内部存储为：一个 discriminant（标签，通常是一个整数，取最小所需位数）+ 一个变体数据的 union。对于无数据变体，discriminant 本身足够。

### 枚举内存布局详解

```text
enum TrafficLight { Red, Yellow, Green }

内存布局 (简化):
┌──────────────────────────────────────────┐
│ discriminant: u8  (值: 0, 1, 或 2)       │
│ 无额外数据字段                            │
└──────────────────────────────────────────┘
总大小: 1 字节

enum Message {
    Quit,                       // variant 0
    Move { x: i32, y: i32 },   // variant 1 (内联结构体)
    Write(String),              // variant 2 (堆指针)
    ChangeColor(i32, i32, i32), // variant 3 (元组)
}

内存布局:
┌─────────────────────────────────────────────┐
│ discriminant: u8  (0~3)                     │
├─────────────────────────────────────────────┤
│ data: union {                               │
│   (empty),                                  │
│   struct { x: i32, y: i32 },                │
│   String { ptr, len, cap },                 │
│   (i32, i32, i32),                          │
│ }                                           │
│ 大小 = max(0, 8, 24, 12) = 24 字节          │
└─────────────────────────────────────────────┘
```

Rust 编译器会优化 discriminant 的存储。如果某个值空间未被变体使用，discriminant 可以被嵌入到数据中（niche optimization）。

### Niche Optimization（空隙优化）

这是 Rust 枚举设计中最精妙的部分。对于类似 `Option<&T>` 的类型，引用永远不为 null，因此编译器可以用 0 值作为 `None`，完全不需要额外的 discriminant 字节：

```text
Option<&T> 的内存布局 (64 位平台):

Some(&T):
┌──────────────────────┐
│ ptr: 非零地址          │  8 字节
└──────────────────────┘

None:
┌──────────────────────┐
│ ptr: 0x000000000000  │  8 字节
└──────────────────────┘

总大小 = 8 字节 (与裸指针相同!)
```

对比 C++ 的 `std::optional<T>`，它总是额外存储一个 bool discriminant，因此 `std::optional<unique_ptr<int>>` 占用 16 字节，而 Rust 的 `Option<Box<i32>>` 仅占用 8 字节。

`match` 在编译期做穷尽性检查（exhaustiveness checking）。编译器构建决策树（decision tree），为每个模式生成对应的跳转指令。对简单枚举，编译后等价于 `switch` 语句；对复杂模式，生成嵌套的条件分支。

`Option<T>` 是一个大小等于 `max(sizeof(T), 0) + discriminant` 的类型。`None` 没有运行时代价（使用特殊的 discriminant 值或 niche optimization）。例如 `Option<bool>` 占用 1 字节（而非 2 字节），因为 `bool` 只用 0/1，剩余空间可编码 `None`：

```text
Option<bool> 的内存布局:

bool 值: 0x00 = false, 0x01 = true, 0x02~0xFF 未使用
         ↑ niche (空隙)

Option<bool>:
  None = 0x02 (利用未使用的 niche)
  Some(false) = 0x00
  Some(true) = 0x01

总大小: 1 字节 (无额外 discriminant!)
```

`match` 守卫（`if n > 5`）在模式匹配之后执行，不改变穷尽性检查的范围。

### 与 C/C++ 的对比

| 特性 | C enum | C++ std::variant | Rust enum |
|------|--------|-------------------|-----------|
| 类型安全 | 无（隐式转换为 int） | 编译期检查 | 编译期检查 |
| 携带数据 | 不可以（除非 union） | 可以（但需 std::visit） | 可以（原生支持） |
| 穷尽检查 | 无 | 有（但非强制） | 强制 |
| 内存布局 | 只有 int | 可能有填充 | 紧凑优化 |
| 空隙优化 | N/A | N/A | 自动 |

### C/C++ 对比

```c
// C: 枚举只是整数的别名，无类型安全
enum TrafficLight { RED = 0, YELLOW = 1, GREEN = 2 };
enum TrafficLight light = RED;
int x = light;  // 合法：隐式转换为 int
light = 42;     // 合法但语义错误！

// C: 模拟带数据的枚举需要手动标记
struct Message {
    enum { QUIT, MOVE, WRITE } tag;
    union {
        struct { int x, y; } move_data;
        char* write_data;
    };
};
```

```cpp
// C++: std::variant 类型安全但使用繁琐
#include <variant>
#include <string>
struct Quit {};
struct Move { int x, y; };
struct Write { std::string text; };
using Message = std::variant<Quit, Move, Write>;

// 需要 std::visit 访问
std::visit([](auto&& arg) {
    using T = std::decay_t<decltype(arg)>;
    if constexpr (std::is_same_v<T, Move>)
        std::cout << arg.x << "," << arg.y;
}, msg);
```

## 语法

### 定义

```rust
enum TrafficLight {
    Red, // 无数据
    Yellow,
    Green,
}

enum Message {
    Quit,
    Move { x: i32, y: i32 }, // 带命名字段
    Write(String), // 带元组数据
    ChangeColor(i32, i32, i32),
}

// 带递归的枚举（需要 Box 在堆上分配）
enum List {
    Cons(i32, Box<List>),
    Nil,
}
// 内存布局:
// Cons: [i32(4) + Box(8)] = 12 字节
// Nil:  0 字节 → 对齐后 1 字节
```

### match 穷尽匹配

`match` 的穷尽性保证：如果遗漏了某个变体，编译器拒绝编译。这是 Rust 的安全保证之一——不可能产生"未处理的 case"。

```rust
let light = TrafficLight::Red;
match light {
    TrafficLight::Red => "stop",
    TrafficLight::Yellow => "slow",
    TrafficLight::Green => "go",
    // 编译器强制穷尽所有变体
    // 即使添加新变体，所有 match 都会报错
}
```

```rust
match msg {
    Message::Quit => { },
    Message::Move { x, y } => println!("({},{})", x, y),
    Message::Write(text) => println!("{}", text),
    Message::ChangeColor(r, g, b) => println!("{},{},{}", r, g, b),
}
```

穷尽性检查的实现原理：编译器在 MIR（Mid-level IR）阶段构建 decision tree。每个节点是一个测试，叶子是已处理的模式。如果存在未覆盖的叶子，编译报错。

### Option

`Option<T>` 是 Rust 处理"可能缺失"值的核心类型，替代了 C 的 NULL 指针和 C++ 的 nullptr。

```rust
enum Option<T> { Some(T), None }

let x: Option<i32> = Some(5);
// let y = x + 1; // 错误：Option<i32> != i32
// 编译器强制你处理 None 的情况

let y = match x {
    Some(n) => n + 1,
    None => 0,
};

// 快捷方法
x.unwrap(); // panic on None — 仅在确定有值时使用
x.unwrap_or(0); // None 时返回默认值
x.unwrap_or_else(|| compute_default()); // 延迟计算默认值
x.is_some(); // 检查是否有值
x.is_none(); // 检查是否为空
x.map(|v| v * 2); // Some 时变换
x.and_then(|v| if v > 0 { Some(v) } else { None }); // 链式操作
x.as_ref(); // Option<&T> from &Option<T>
```

### if let — 单分支 match 简写

`if let` 是 `match` 的语法糖，当你只关心一个模式时使用。它不会阻止编译器做穷尽检查——因为只有一个分支，编译器认为其他分支被忽略了。

```rust
if let Some(n) = x {
    println!("有值：{}", n);
} else {
    println!("无值");
}

// 等价于
match x {
    Some(n) => println!("有值：{}", n),
    _ => println!("无值"),
}
```

### let-else — 否则分支提前返回

```rust
// let-else: 如果模式不匹配，必须离开当前作用域（break/return/continue/panic）
let Some(n) = x else {
    println!("没有值，提前返回");
    return;
};
// 这里 n 已解构为 i32，可以直接使用
println!("值是 {}", n);
```

### 通配符 `_` 和守卫

```rust
match n {
    1 => "one",
    2..=9 => "small",  // 范围模式
    10..=99 => "medium",
    _ => "other", // 匹配一切（穷尽兜底）
}

match opt {
    Some(n) if n > 0 => "正数",   // 守卫: 匹配后额外检查
    Some(_) => "非正数",
    None => "无",
}

// _ 会绑定但忽略，_x 不绑定
match x {
    Some(_) => println!("有值但不关心"),  // 不绑定
    None => println!("无"),
}
```

### @ 绑定

`@` 模式在匹配范围的同时绑定变量，避免两步操作：

```rust
match age {
    0 => println!("刚出生"),
    n @ 1..=12 => println!("儿童: {}岁", n),   // 匹配范围并绑定
    n @ 13..=17 => println!("青少年: {}岁", n),
    n @ 18.. => println!("成年: {}岁", n),
    _ => unreachable!(), // 穷尽检查：所有 i32 都已覆盖
}

// 没有 @ 绑定需要写成:
match age {
    1..=12 => println!("儿童: {}岁", age),  // 重复使用 age
    13..=17 => println!("青少年: {}岁", age),
    18.. => println!("成年: {}岁", age),
    _ => unreachable!(),
}
```

### 解构模式

```rust
// 元组解构
let (x, y, z) = (1, 2, 3);

// 结构体解构
struct Point { x: i32, y: i32 }
let Point { x, y } = Point { x: 1, y: 2 };

// 嵌套解构
enum Shape {
    Circle(f64),
    Rectangle(f64, f64),
}
let Shape::Circle(radius) = Shape::Circle(3.14);

// 数组解构
let [a, b, ..] = [1, 2, 3, 4, 5]; // a=1, b=2, 其余忽略

// 过滤
let (x, 0, y) = (1, 0, 3); // 匹配: x=1, y=3
// let (x, 1, y) = (1, 0, 3); // 不匹配
```

### 为枚举实现方法

```rust
impl TrafficLight {
    fn duration(&self) -> u32 {
        match self {
            Self::Red => 60,
            Self::Yellow => 5,
            Self::Green => 45,
        }
    }

    // 构造方法
    fn next(&self) -> Self {
        match self {
            Self::Red => Self::Green,
            Self::Green => Self::Yellow,
            Self::Yellow => Self::Red,
        }
    }
}

// 关联函数（类似静态方法）
impl TrafficLight {
    fn all() -> Vec<Self> {
        vec![Self::Red, Self::Yellow, Self::Green]
    }
}
```

### match 与所有权

```rust
let opt: Option<String> = Some(String::from("hello"));

// match 会移动所有权
// match opt {
//     Some(s) => println!("{}", s),  // s 被移动
//     None => println!("none"),
// }
// opt 已被消费

// 用 &opt 保持借用
match &opt {
    Some(s) => println!("{}", s),  // s 是 &String
    None => println!("none"),
}
// opt 仍然可用
```

## 常见陷阱与最佳实践

### 陷阱 1：match 守卫破坏穷尽性

```rust
let x: Option<i32> = Some(5);
// 守卫中的条件不视为模式覆盖
match x {
    Some(n) if n > 0 => println!("正数"),
    Some(_) => println!("非正数"),
    None => println!("无"),
}
// 这是正确的：守卫不影响穷尽性
```

### 陷阱 2：与 C 枚举的互操作

```rust
// C 枚举在 Rust 中用 repr 保证布局
#[repr(C)]
enum CColor { Red = 0, Green = 1, Blue = 2 }

// C 的 int 不会自动映射为 Rust 枚举
// 需要显式转换并处理无效值
let x: i32 = 5;
let color = match x {
    0 => Some(CColor::Red),
    1 => Some(CColor::Green),
    2 => Some(CColor::Blue),
    _ => None,
};
```

### 最佳实践

1. 优先使用 `match` 而非 `if let`，除非只关心一个模式
2. 用 `@` 绑定避免范围匹配时的变量重复
3. 在 enum 上使用 `#[non_exhaustive]` 为库留扩展空间
4. 用 `_` 通配符兜底，除非你想让编译器提醒新变体

### 力扣问题

力扣: 力扣状态机题 — 状态机模式

```rust
#[derive(Debug, PartialEq)]
enum State { Playing, Paused, Over }

impl State {
    fn transition(&self, event: &str) -> Self {
        match (self, event) {
            (State::Playing, "pause") => State::Paused,
            (State::Playing, "stop") => State::Over,
            (State::Paused, "play") => State::Playing,
            (State::Paused, "stop") => State::Over,
            (state, _) => state.clone(),
        }
    }
}
```

力扣: 力扣数组计数题 — match 分支

```rust
fn count_matches(nums: &[i32]) -> (usize, usize, usize) {
    let mut neg = 0;
    let mut zero = 0;
    let mut pos = 0;
    for &n in nums {
        match n.cmp(&0) {
            std::cmp::Ordering::Less => neg += 1,
            std::cmp::Ordering::Equal => zero += 1,
            std::cmp::Ordering::Greater => pos += 1,
        }
    }
    (neg, zero, pos)
}
```
