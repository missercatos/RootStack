# 组织代码：模块与包

## 原理

### 模块系统层次

Rust 的模块系统是纯编译期概念。编译器将多个 `.rs` 文件按 `mod` 声明构建为 crate 树。`src/main.rs` 和 `src/lib.rs` 作为 crate 根（root），编译器以此为起点递归解析模块。

打包层次：Package > Crate > Module

```text
Package (一个项目目录，包含 Cargo.toml):
├── Crate 1: lib crate (src/lib.rs)
├── Crate 2: bin crate (src/main.rs)
├── Crate 3: bin crate (src/bin/tool.rs)
└── ...

Crate (编译单元，生成 .rlib 或可执行文件):
├── Module: src/lib.rs (crate root)
├── Module: src/utils.rs
├── Module: src/net/mod.rs
│   ├── Module: src/net/tcp.rs
│   └── Module: src/net/udp.rs
└── ...

Module (代码组织单元，控制可见性):
├── pub fn public_fn()
├── fn private_fn()
├── pub struct PublicStruct { pub field: Type }
└── struct PrivateStruct { field: Type }
```

### 文件系统映射

```text
src/
├── main.rs           ← crate root (bin crate)
├── lib.rs            ← crate root (lib crate)
├── utils.rs          ← mod utils (在 main.rs 中声明)
├── net/              ← mod net (目录模块)
│   ├── mod.rs        ← mod net 的内容
│   ├── tcp.rs        ← net::tcp
│   └── udp.rs        ← net::udp
└── old/              ← 旧式 (mod.rs 风格)
    ├── mod.rs
    └── stuff.rs
```

### 路径解析

```rust
// 相对路径: 从当前模块开始
fn foo() { self::bar(); }  // 调用当前模块的 bar
fn baz() { super::bar(); } // 调用父模块的 bar

// 绝对路径: 从 crate root 开始
crate::utils::helper();
// 或
my_crate::utils::helper();  // 外部 crate

// self/super/crate 是路径前缀
mod network {
    pub fn connect() {
        super::log("connecting");  // 父模块
        self::handshake();          // 当前模块
        crate::config::get();      // crate root
    }
    fn handshake() { }
}
```

`pub` 修饰符控制可见性。默认 `private`；`pub(crate)` 在本 crate 内可见；`pub(super)` 在父模块可见；`pub(in path)` 在指定路径可见。

```text
可见性层级:
├── pub                  → 任何人可见
├── pub(crate)           → 当前 crate 内可见
├── pub(super)           → 父模块可见
├── pub(in crate::path)  → 指定路径可见
└── (无修饰符)           → 当前模块私有
```

`use` 语句在编译后不会产生任何代码，只是路径别名（相当于 C++ 的 `using`）。模块系统不产生运行时开销。

### 模块路径详解

```rust
// 路径的三种前缀
crate::  // 从 crate root 开始 (绝对路径)
self::   // 从当前模块开始 (相对路径)
super::  // 从父模块开始 (相对路径)

// use 中的路径解析
use crate::net::tcp;    // 绝对路径
use self::config;       // 当前模块的 config
use super::utils;       // 父模块的 utils
```

## 语法

### 内联模块

```rust
mod network {
    pub fn connect() { }

    fn handshake() { } // 私有，外部不可见

    // 嵌套模块
    pub mod http {
        pub fn get() { }
        fn internal() { } // network::http::internal
    }
}

fn main() {
    network::connect();
    network::http::get();
    // network::http::internal(); // 错误: 私有
}
```

### 可见性控制

| 修饰符 | 可见范围 | 示例 |
|--------|----------|------|
| 无 | 当前模块私有 | `fn helper()` |
| `pub` | 公开 | `pub fn connect()` |
| `pub(crate)` | 当前 crate 内 | `pub(crate) fn internal()` |
| `pub(super)` | 父模块 | `pub(super) fn from_parent()` |
| `pub(in path)` | 指定路径 | `pub(in crate::net) fn server_fn()` |

```rust
// 结构体字段的可见性
pub struct User {
    pub name: String,    // 公开: 任何地方可读写
    pub(crate) id: u32,  // crate 内: 可读写
    password: String,     // 私有: 仅当前模块可读写
}

// 构造器模式: 字段私有但提供公开构造方法
impl User {
    pub fn new(name: String, password: String) -> Self {
        User {
            name,
            id: next_id(),
            password,
        }
    }
    pub fn name(&self) -> &str { &self.name }
    // password 没有 getter → 外部无法访问
}
```

### use 语句

```rust
use std::collections::HashMap; // 单路径
use std::io::{self, Read, Write}; // 多路径（self = io 本身）
use std::collections::*; // 通配符（谨慎使用）
use std::fmt::Result as FmtResult; // 别名（解决冲突）

// 嵌套 use
use std::{fs, io};
use std::io::{self, BufRead, BufReader};

// 重导出: 在当前模块重新暴露其他模块的项
pub use crate::net::tcp::Connection;
// 使用者可以直接 use my_crate::Connection
```

### 文档注释

```rust

///
/// # Examples
///
/// ```
/// let result = gcd(14, 21);
/// assert_eq!(result, 7);
/// ```
///
/// # Panics
///
/// 如果 `a` 或 `b` 为 0，则 panic。
pub fn gcd(a: u64, b: u64) -> u64 {
    if b == 0 { a } else { gcd(b, a % b) }
}

### Workspace（工作空间）

```toml
# 根 Cargo.toml
[workspace]
members = [
    "core",
    "cli",
    "web",
]

[workspace.dependencies]
tokio = { version = "1", features = ["full"] }
serde = { version = "1", features = ["derive"] }
```

```toml
# core/Cargo.toml
[package]
name = "my-core"
[dependencies]
tokio.workspace = true  # 共享版本
serde.workspace = true
```

Workspace 的好处：
- 共享 `Cargo.lock`，所有成员依赖版本一致
- 共享 `target/` 目录，减少编译时间
- 统一版本管理
- 一键构建/测试所有成员

## 常见陷阱与最佳实践

### 陷阱 1：`x.rs` 和 `x/mod.rs` 冲突

```text
如果同时存在 src/x.rs 和 src/x/mod.rs:
→ 编译错误!

推荐使用 src/x.rs (新式) 而非 src/x/mod.rs (旧式)
新式路径更清晰: src/x.rs 而非 src/x/mod.rs
```

### 陷阱 2：过度使用 `pub`

```rust
// ❌ 把所有字段都 pub
pub struct Config {
    pub host: String,
    pub port: u16,
    pub password: String,  // 密码暴露!
}

// ✅ 选择性暴露
pub struct Config {
    pub host: String,
    pub port: u16,
    password: String,  // 私有
}

impl Config {
    pub fn new(host: String, port: u16, password: String) -> Self {
        Self { host, port, password }
    }
    pub fn host(&self) -> &str { &self.host }
    pub fn port(&self) -> u16 { self.port }
    // password 无 getter
}
```

### 最佳实践

1. 优先使用 `pub(crate)` 而非 `pub`，限制暴露范围
2. 用 `pub use` 重导出，为外部提供扁平的 API
3. 用 `///` 和 `//!` 写文档，`cargo doc` 生成 HTML
4. 大项目使用 workspace 管理多 crate
5. 优先使用新式 `src/x.rs` 而非 `src/x/mod.rs`

## 实践

### 力扣问题

力扣: 力扣结构化编程题 — 多模块拆分

```rust
// src/lib.rs
pub mod data_structures;
pub mod algorithms;
pub mod utils;

// src/data_structures/mod.rs
pub mod stack;
pub mod queue;
pub mod heap;

// src/data_structures/stack.rs
pub struct Stack<T> {
    elements: Vec<T>,
}

impl<T> Stack<T> {
    pub fn new() -> Self {
        Stack { elements: Vec::new() }
    }
    pub fn push(&mut self, item: T) {
        self.elements.push(item);
    }
    pub fn pop(&mut self) -> Option<T> {
        self.elements.pop()
    }
}
```
