# 出错了怎么办：错误处理

## 原理

Rust 将错误分为两类：

### panic! — 不可恢复

调用 `std::panic!` 宏触发栈展开（unwinding）或直接终止（abort）。展开时沿调用栈逐帧调用 `drop`，由 `panic_handler` 和 `set_hook` 控制。可在 Cargo.toml 中设置 `panic = "abort"` 跳过展开，减小二进制体积。

```text
panic! 执行流程:

fn main() {
    fn a() { fn b() { panic!("boom"); } b(); }  // ← panic 发生
    a();
}

未展开时:
thread 'main' panicked at 'boom', src/main.rs:1:30
note: run with RUST_BACKTRACE=1 env var to display backtrace
进程退出 code 101

展开时 (默认):
1. b() 中 panic! 被调用
2. b() 的栈帧被标记为 "正在展开"
3. b() 中所有局部变量的 drop() 被调用
4. 控制权返回 a()，a() 的 drop 被调用
5. 控制权返回 main()，main() 的 drop 被调用
6. panic handler 打印信息
7. 进程退出
```

### Result\<T, E\> — 可恢复

定义为带两个泛型参数的枚举：

```rust
enum Result<T, E> { Ok(T), Err(E) }
```

### ? 运算符的展开机制

`?` 运算符在编译时展开为 `match` + `return Err`，其中通过 `From` trait 做错误类型自动转换。每个 `?` 相当于一个提前返回（early return），保证错误不丢失。

```rust
// 你写的代码
fn read_file() -> Result<String, io::Error> {
    let mut f = File::open("data.txt")?;
    let mut s = String::new();
    f.read_to_string(&mut s)?;
    Ok(s)
}

// 编译器展开后 (概念性)
fn read_file() -> Result<String, io::Error> {
    let mut f = match File::open("data.txt") {
        Ok(val) => val,
        Err(e) => return Err(From::from(e)),  // From::from 做类型转换
    };
    let mut s = String::new();
    match f.read_to_string(&mut s) {
        Ok(val) => val,
        Err(e) => return Err(From::from(e)),
    };
    Ok(s)
}
```

### 错误类型自动转换 (From trait)

```rust
// 当函数返回 Result<T, E2>，而 ? 产生 E1 时
// 编译器查找 impl From<E1> for E2
// 如果存在，自动调用 E1::into() 转换

fn read_config() -> Result<Config, ConfigError> {
    let content = fs::read_to_string("config.toml")?;  // io::Error
    // 编译器自动: ConfigError::from(io::Error)
    let config: Config = toml::from_str(&content)?;    // toml::de::Error
    // 编译器自动: ConfigError::from(toml::de::Error)
    Ok(config)
}
```

`unwrap` / `expect` 本质是 `match result { Ok(v) => v, Err(e) => panic!(...)}`。

`Option<T>` 与 `Result<T, E>` 的关系：`None` 可视为 `Err(())` 但不携带额外信息。两者均可使用 `?` 传播（需函数返回对应类型）。

### 与 C/C++ 的错误处理对比

| 特性 | C (errno) | C++ (exceptions) | Rust (Result) |
|------|-----------|-------------------|---------------|
| 传播方式 | 手动检查返回值 | 自动栈展开 | `?` 运算符 |
| 忘记处理 | 静默忽略 | 不会忘记（catch） | 编译期强制 |
| 性能开销 | 零（if 判断） | 大（异常表+栈展开） | 零（编译为 match） |
| 类型安全 | 无 | 有（catch by type） | 有（Result 类型） |
| 二进制大小 | 小 | 大（异常处理表） | 小 |
| 不可恢复 | `abort()` | `std::terminate` | `panic!` |

```c
// C: 手动检查每个返回值，容易遗漏
FILE* f = fopen("data.txt", "r");
if (f == NULL) {  // 忘记检查？
    // 使用未初始化的 f → 未定义行为
}
char buf[100];
size_t n = fread(buf, 1, 100, f);
if (n < 100 && ferror(f)) {  // 再次检查
    // 错误处理
}
```

```cpp
// C++: 异常可以跨函数边界传播，但有性能代价
try {
    std::ifstream f("data.txt");
    if (!f) throw std::runtime_error("file not found");
    // ...
} catch (const std::exception& e) {
    std::cerr << e.what() << std::endl;
}
// 异常表增加二进制体积 5-15%
// 即使不抛异常，try 块也有微小开销（某些平台）
```

## 语法

### panic!

```rust
panic!("致命错误");
// 仅用于不可恢复的情况或原型阶段

// 可以在 Cargo.toml 中设置
// [profile.release]
// panic = "abort"  // 跳过展开，减小二进制
```

### Result 基本使用

```rust
use std::fs::File;

let f = match File::open("data.txt") {
    Ok(file) => file,
    Err(e) => {
        eprintln!("打开失败：{}", e);
        return;
    }
};
```

### unwrap / expect

```rust
let f = File::open("data.txt").unwrap(); // Err 时 panic
let f = File::open("data.txt").expect("必须存在"); // 自定义 panic 消息
// expect 比 unwrap 好：panic 消息更清晰
```

### ? 运算符 — 传播错误

```rust
use std::fs;
use std::io::{self, Read};

fn read_file() -> Result<String, io::Error> {
    let mut f = File::open("data.txt")?; // Err 时提前返回
    let mut s = String::new();
    f.read_to_string(&mut s)?;
    Ok(s)
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let content = fs::read_to_string("data.txt")?;
    println!("{}", content);
    Ok(())
    // main 返回 Result 时，Err 会打印 Debug 信息并退出
}
```

### 错误类型匹配

```rust
use std::io::ErrorKind;

match File::open("data.txt") {
    Ok(f) => f,
    Err(e) => match e.kind() {
        ErrorKind::NotFound => File::create("data.txt").unwrap(),
        ErrorKind::PermissionDenied => {
            eprintln!("权限不足");
            return;
        }
        _ => panic!("{}", e),
    },
};
```

### unwrap_or / unwrap_or_else / unwrap_or_default

```rust
let x: Result<i32, &str> = Err("fail");
x.unwrap_or(0); // → 0
x.unwrap_or_else(|e| { println!("错误: {}", e); 0 }); // 延迟计算
x.unwrap_or_default(); // → 0 (i32::default())

File::open("c.toml").unwrap_or_else(|e| {
    if e.kind() == ErrorKind::NotFound {
        File::create("c.toml").unwrap()
    } else { panic!("{}", e); }
});
```

### 自定义错误类型

```rust
use std::fmt;
use std::num::ParseIntError;

#[derive(Debug)]
enum AppError {
    Io(std::io::Error),
    Parse(ParseIntError),
    Custom(String),
}

impl fmt::Display for AppError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            Self::Io(e) => write!(f, "IO 错误: {}", e),
            Self::Parse(e) => write!(f, "解析错误: {}", e),
            Self::Custom(s) => write!(f, "自定义错误: {}", s),
        }
    }
}

impl std::error::Error for AppError {}

// 实现 From 以支持 ? 自动转换
impl From<std::io::Error> for AppError {
    fn from(e: std::io::Error) -> Self { Self::Io(e) }
}

impl From<ParseIntError> for AppError {
    fn from(e: ParseIntError) -> Self { Self::Parse(e) }
}

// 现在可以用 ? 链式调用
fn process() -> Result<i32, AppError> {
    let content = std::fs::read_to_string("data.txt")?;  // io::Error → AppError
    let num: i32 = content.trim().parse()?;  // ParseIntError → AppError
    Ok(num * 2)
}
```

### thiserror vs anyhow

```rust
// thiserror: 减少样板代码，适合库
use thiserror::Error;

#[derive(Error, Debug)]
enum AppError {
    #[error("IO 错误: {0}")]
    Io(#[from] std::io::Error),    // 自动实现 From
    #[error("解析错误: {0}")]
    Parse(#[from] ParseIntError),
    #[error("自定义: {0}")]
    Custom(String),
}

// anyhow: 忽略错误类型，适合应用
use anyhow::{Context, Result};

fn process() -> Result<()> {  // Result<T, anyhow::Error>
    let content = std::fs::read_to_string("data.txt")
        .context("无法读取配置文件")?;  // 添加上下文
    let num: i32 = content.trim().parse()
        .context("无法解析数字")?;
    Ok(())
}
```

### 错误处理策略

| 场景 | 方式 |
|------|------|
| 原型/示例 | `unwrap()` / `expect()` |
| 库代码 | `Result<T, E>` + `?` 传播 |
| 致命错误 | `panic!` |
| 应用层 | main 中用 match 最后处理 |
| 不可能失败 | `unwrap()` + 注释说明原因 |
| 需要上下文 | `anyhow::Context` |

## 常见陷阱

### 陷阱 1：unwrap 在库代码中

```rust
// ❌ 差: 库代码中使用 unwrap
pub fn parse_config(s: &str) -> Config {
    let v: Vec<&str> = s.split('=').collect(); // 可能 panic!
    // ...
}

// ✅ 好: 返回 Result
pub fn parse_config(s: &str) -> Result<Config, ConfigError> {
    let v: Vec<&str> = s.split('=').collect();
    if v.len() != 2 {
        return Err(ConfigError::InvalidFormat);
    }
    // ...
}
```

### 陷阱 2：`?` 的类型转换失败

```rust
// 如果函数返回 Result<T, AppError>
// 而某个 ? 产生的错误类型没有实现 From<E> for AppError
// 编译会失败
fn process() -> Result<(), AppError> {
    let s: Result<i32, _> = "abc".parse(); // ParseIntError
    // 如果没有 impl From<ParseIntError> for AppError，这行报错
    let n = s?;
    Ok(())
}
```

fn get_node_at(head: &Option<Box<ListNode>>, index: usize) -> Result<i32, &'static str> {
    let mut current = head.as_ref().ok_or("空链表")?;
