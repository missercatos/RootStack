# 引用有效期：生命周期入门

## 原理

### 生命周期的本质

生命周期（lifetime）是编译器对引用有效范围的静态标注，本质是 MIR 层的数据流分析结果。每一个引用均有一个隐式生命周期变量，编译器通过 borrow checker 求解生命周期的包含关系，确保所有引用始终指向有效数据。

`'a` 不会延长或缩短任何实际对象的存活时间（代码生成阶段完全消除），它只是一个编译期的"约束关系"。`'static` 生命周期表示数据在整个进程生命周期内有效（存放于只读数据段 `.rodata`），字符串字面量 `"hello"` 即 `&'static str`。

```text
生命周期标注的真正含义:

fn longest<'a>(x: &'a str, y: &'a str) -> &'a str

'a 不是"所有引用的生命周期"，而是:
"返回值的生命周期 <= x 和 y 中较短的那个"

编译器求解:
  lifetime(x) >= lifetime(return_value)
  lifetime(y) >= lifetime(return_value)
  → return_value 的生命周期 = min(lifetime(x), lifetime(y))
```

### NLL（Non-Lexical Lifetimes）

传统的生命周期分析基于词法作用域：引用的生命周期从声明到作用域结束。NLL 改为基于控制流分析：引用的生命周期从最后一次使用到声明。

```text
传统词法生命周期 (Rust 2015):
{
    let r = &x;       // r 的生命周期开始
    // ... 使用 r ...
    let y = 5;        // ← 即使 r 不再使用，生命周期仍继续
}                     // r 的生命周期结束

NLL (Rust 2018+):
{
    let r = &x;
    // ... 使用 r ...
    // ← r 的生命周期在此结束 (最后一次使用)
    let y = 5;        // 现在可以重新借用 x
    // x 可以修改或移动
}
```

```rust
// NLL 允许的代码 (Rust 2015 会拒绝):
let mut data = vec![1, 2, 3];
let first = &data[0];    // 不可变借用开始
println!("{}", first);    // 最后一次使用 first
// ← first 的生命周期结束 (NLL)
data.push(4);             // 可变借用: 现在合法!
```

### Polonius（下一代借用检查器）

Polonius 是 NLL 的进化版本，处理更复杂的借用场景：

```rust
// Polonius 能处理但 NLL 不能的场景:
fn process(condition: bool, data: &mut Vec<i32>) {
    let r = &data[0];        // 不可变借用
    if condition {
        println!("{}", r);    // 在条件分支中使用
    }
    // NLL: r 的生命周期在这里结束
    // Polonius: r 的生命周期在 if 块结束时结束
    // 如果 condition 为 false，r 从未使用，可以更早结束
    data.push(4);
}
```

三条省略规则基于 Rust 团队对常见模式的统计分析设计，覆盖 90%+ 的场景：

1. 每个引用参数获得独立生命周期
2. 单个输入生命周期 → 返回值和它绑定
3. `&self` / `&mut self` → 返回值和 self 绑定

违反规则时编译器在精确的工作点报错（NLL borrowck），而非泛泛的"生命周期错误"。

### 与 C/C++ 的对比

```c
// C: 无生命周期检查，悬垂指针是未定义行为
char* create() {
    char buffer[100];
    sprintf(buffer, "hello");
    return buffer;  // 返回栈上指针 → UB!
}

// 使用者不知道指针已失效
char* s = create();
printf("%s\n", s);  // 未定义行为: 可能打印垃圾数据
```

```cpp
// C++: std::reference_wrapper 或裸指针，无编译期检查
std::string& longest(const std::string& a, const std::string& b) {
    return (a.length() > b.length()) ? a : b;
    // 如果 a 是临时对象，返回引用是危险的
}

// C++ 智能指针提供运行时安全，但有性能代价
auto ptr = std::make_shared<int>(42);
// 如果 shared_ptr 被销毁，ptr 自动置空 (不是悬垂)
```

Rust 的生命周期是**编译期**检查，零运行时开销，彻底消除悬垂指针。

## 语法

### 悬垂引用（编译器阻止）

```rust
// let r;
// {
//     let x = 5;
//     r = &x;  // 编译错误: x does not live long enough
// }
// println!("{}", r);  // r 指向已销毁的 x

// 编译器的思考:
// r 的生命周期需要 >= println! 的使用点
// x 的生命周期在内部块结束
// r 的生命周期 > x 的生命周期 → 违反约束 → 拒绝编译
```

### 函数中的生命周期标注

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
// 语义：返回值生命周期 = min(生命周期(x), 生命周期(y))

// 调用时:
let s1 = String::from("long string");
let result;
{
    let s2 = String::from("xyz");
    result = longest(s1.as_str(), s2.as_str());
    println!("{}", result);  // ✅ s2 还活着
}
// println!("{}", result);  // ❌ s2 已销毁，result 可能悬垂
```

```rust
// 只有返回值引用的参数需要标注
fn first<'a>(x: &'a str, _y: &str) -> &'a str { x }
// _y 可以不标注生命周期
```

### 结构体中的生命周期

```rust
struct Excerpt<'a> {
    part: &'a str, // 字段引用需标注
}

impl<'a> Excerpt<'a> {
    fn get(&self) -> &str { self.part } // 由规则3自动推断
}

// 使用:
let novel = String::from("Call me Ishmael. Some years ago...");
let first_sentence;
{
    let i = novel.as_str().find('.').unwrap_or(novel.len());
    first_sentence = Excerpt { part: &novel[..i] };
}
println!("{}", first_sentence.part);  // ✅ novel 仍然有效
```

### 省略规则速查

| 场景 | 需要标注？ | 规则 |
|------|-----------|------|
| `fn f(s: &str) -> &str` | 否 | 规则1+2 |
| `fn f(&self, s: &str) -> &str` | 否 | 规则1+3 |
| `fn f(x: &str, y: &str) -> &str` | 是 | 多输入，编译器无法确定 |
| `struct S { r: &str }` | 是 | 结构体字段必须标注 |
| `fn f() -> &str` | 通常不合理 | 悬垂风险 |

### 静态生命周期

```rust
let s: &'static str = "hello"; // 字符串字面量
// 整个程序运行期间都有效

// 常量和静态变量也是 'static
const MAX: i32 = 100;           // &'static i32
static GREETING: &str = "hi";  // &'static str

// Box::leak 可以创建 'static 引用
let s = Box::leak(Box::new(String::from("hello")));
// s: &'static mut String
// 注意: 这会造成内存泄漏，除非手动管理
```

### 生命周期 bound

```rust
// 约束泛型参数的生命周期
fn print_ref<'a, T: Display + 'a>(x: &'a T) {
    println!("{}", x);
}
// T: 'a 表示 T 中的任何引用必须至少活 'a 久

// 更复杂的约束
fn merge<'a, 'b, T>(a: &'a T, b: &'b T) -> &'a T
where
    'b: 'a,  // 'b 至少和 'a 一样长
{
    a
}
```

### 常见生命周期模式

```rust
// 模式 1: 同一生命周期 (最常见)
fn first<'a>(x: &'a str, y: &'a str) -> &'a str { x }

// 模式 2: 独立生命周期
fn first_str<'a, 'b>(x: &'a str, _y: &'b str) -> &'a str { x }

// 模式 3: 结构体持有引用
struct Parser<'input> {
    input: &'input str,
    pos: usize,
}

impl<'input> Parser<'input> {
    fn new(input: &'input str) -> Self {
        Parser { input, pos: 0 }
    }
    fn next_token(&mut self) -> Option<&'input str> {
        // 返回的切片生命周期与 input 相同
        let start = self.pos;
        // ... 解析逻辑 ...
        Some(&self.input[start..self.pos])
    }
}

// 模式 4: 生命周期省略
fn get_len(s: &str) -> usize { s.len() }
// 实际签名: fn get_len<'a>(s: &'a str) -> usize
// 返回值是 usize，不涉及生命周期
```

## 常见陷阱与最佳实践

### 陷阱 1：返回局部变量的引用

```rust
// ❌ 编译失败
fn create_ref() -> &str {
    let s = String::from("hello");
    &s  // s 在函数结束时被 drop
    // 返回的引用指向已销毁的数据
}

// ✅ 返回拥有所有权的值
fn create_owned() -> String {
    String::from("hello")  // 所有权转移给调用者
}
```

### 陷阱 2：闭包中的生命周期

```rust
// 闭包捕获引用时，生命周期必须匹配
fn process<F>(data: &str, f: F) -> usize
where
    F: Fn(&str) -> usize,
{
    f(data)
}

// 调用:
let result = process("hello", |s| s.len());
// 闭包的生命周期隐式绑定到 data
```

### 最佳实践

1. 省略规则覆盖 90% 场景，不需要手动标注
2. 编译器的错误信息通常告诉你如何修复
3. 考虑用 `String`/`Vec` 替代引用，让数据拥有所有权
4. `'static` 不意味着"永远存在"，只是"至少整个程序运行期"

    let a: Vec<char> = a.chars().collect();

力扣: 力扣解析器题 — 生命周期与解析

```rust
struct Lexer<'a> {
    input: &'a [u8],
    pos: usize,
}

impl<'a> Lexer<'a> {
    fn new(input: &'a [u8]) -> Self {
        Lexer { input, pos: 0 }
    }

    fn next_token(&mut self) -> Option<&'a [u8]> {
        if self.pos >= self.input.len() {
            return None;
        }
        let start = self.pos;
        while self.pos < self.input.len() && self.input[self.pos] != b' ' {
            self.pos += 1;
        }
        let token = &self.input[start..self.pos];
        self.pos += 1; // skip space
        Some(token)
    }
}
```
