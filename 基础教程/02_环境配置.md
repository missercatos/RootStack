# 第二章: 环境配置 📚(Development Environment Setup)
## ==========================================================================

## 📋 章节概述

在编写 C++ 程序之前，正确配置开发环境是至关重要的第一步。本章将全面介绍如何在
Windows、macOS 和 Linux 三大平台上配置 C++ 编译环境，包括 PATH 环境变量设置、
编译器选项详解、构建系统（Makefile 和 CMake）的使用、第一个程序的编译运行、
调试器的基本操作，以及常见编译错误的排查方法。

## ==========================================================================
### 📖 第一节: PATH 环境变量配置
## ==========================================================================

1.1 什么是 PATH 环境变量
---------------------------------

PATH 是操作系统用来定位可执行文件的环境变量。当你在终端中输入 `g++` 时，系统会
按照 PATH 中列出的目录顺序逐一查找名为 `g++` 的可执行文件。如果找不到，就会报
"command not found" 错误。

1.2 Windows 环境配置
---------------------------------

**安装 MinGW-w64:**

1. 下载 MinGW-w64 安装包或通过 MSYS2 安装
2. 将编译器 bin 目录添加到 PATH

```powershell
# PowerShell 中临时设置
$env:PATH += ";C:\msys64\mingw64\bin"

# 永久设置（需要管理员权限）
[System.Environment]::SetEnvironmentVariable("PATH",
    $env:PATH + ";C:\msys64\mingw64\bin",
    [System.EnvironmentVariableTarget]::Machine)
```

**通过图形界面设置:**

1. 右键「此电脑」→「属性」→「高级系统设置」
2. 点击「环境变量」
3. 在「系统变量」中找到 `Path`，点击「编辑」
4. 添加 `C:\msys64\mingw64\bin`

**验证安装:**

```cmd
g++ --version
```

1.3 macOS 环境配置
---------------------------------

macOS 通过 Xcode Command Line Tools 提供 clang++ 编译器：

```bash
xcode-select --install
```

安装完成后，clang++ 位于 `/usr/bin/clang++`，该路径默认已在 PATH 中。

如果需要 GCC：

```bash
brew install gcc
```

Homebrew 安装的 GCC 通常位于 `/opt/homebrew/bin/`（Apple Silicon）或
`/usr/local/bin/`（Intel）。配置 PATH：

```bash
# 在 ~/.zshrc 中添加
export PATH="/opt/homebrew/bin:$PATH"

# 使配置生效
source ~/.zshrc
```

1.4 Linux 环境配置
---------------------------------

**Ubuntu/Debian:**

```bash
sudo apt update
sudo apt install build-essential
```

`build-essential` 包含 g++、make 等核心工具。

**Fedora/RHEL:**

```bash
sudo dnf groupinstall "Development Tools"
sudo dnf install gcc-c++
```

**Arch Linux:**

```bash
sudo pacman -S base-devel
```

**配置 PATH（适用于自定义安装位置）:**

```bash
# 在 ~/.bashrc 或 ~/.zshrc 中添加
export PATH="/usr/local/gcc-13/bin:$PATH"

# 使配置生效
source ~/.bashrc
```

**验证安装:**

```bash
g++ --version
which g++
echo $PATH
```

### 📖 第二节: 编译器选项详解
## ==========================================================================

2.1 C++ 标准选择
---------------------------------

```bash
g++ -std=c++11 main.cpp    # C++11 标准
g++ -std=c++14 main.cpp    # C++14 标准
g++ -std=c++17 main.cpp    # C++17 标准（推荐）
g++ -std=c++20 main.cpp    # C++20 标准
g++ -std=c++23 main.cpp    # C++23 标准
```

不指定 `-std` 时，GCC 默认使用 `gnu++17`（GCC 11+），较老版本默认 `gnu++14`。

2.2 警告选项
---------------------------------

| 选项 | 说明 |
|------|------|
| `-Wall` | 启用大多数常见警告 |
| `-Wextra` | 启用 `-Wall` 未涵盖的额外警告 |
| `-Wpedantic` | 严格遵循 ISO C++ 标准，报告所有非标准扩展 |
| `-Werror` | 将所有警告视为错误 |
| `-Wshadow` | 变量名遮蔽警告 |
| `-Wconversion` | 隐式类型转换警告 |
| `-Wunused` | 未使用变量/函数警告 |

推荐的开发阶段警告组合：

```bash
g++ -Wall -Wextra -Wpedantic -Wshadow -Wconversion -std=c++17 main.cpp
```

2.3 优化选项
---------------------------------

| 选项 | 说明 |
|------|------|
| `-O0` | 不优化（默认），编译最快，适合调试 |
| `-O1` | 基本优化，减少代码大小和执行时间 |
| `-O2` | 推荐的发布优化级别，不增加代码大小 |
| `-O3` | 激进优化，可能增加代码大小 |
| `-Os` | 优化代码大小 |
| `-Ofast` | `-O3` + 不严格遵循标准的数学优化 |

2.4 调试选项
---------------------------------

| 选项 | 说明 |
|------|------|
| `-g` | 生成调试信息（DWARF 格式） |
| `-g3` | 生成最详细的调试信息，包括宏定义 |
| `-ggdb` | 生成 GDB 专用的调试信息 |
| `-fsanitize=address` | 启用地址消毒器，检测内存错误 |
| `-fsanitize=undefined` | 启用未定义行为检测 |

2.5 链接选项
---------------------------------

| 选项 | 说明 |
|------|------|
| `-o filename` | 指定输出文件名 |
| `-l library` | 链接库（如 `-lm` 链接数学库） |
| `-L path` | 添加库搜索路径 |
| `-I path` | 添加头文件搜索路径 |
| `-c` | 只编译不链接，生成 .o 文件 |
| `-static` | 静态链接 |

2.6 典型编译命令组合
---------------------------------

```bash
# 开发调试版本
g++ -std=c++17 -Wall -Wextra -Wpedantic -g -fsanitize=address -o debug_app main.cpp

# 发布版本
g++ -std=c++17 -O2 -DNDEBUG -o release_app main.cpp

# 多文件编译
g++ -std=c++17 -Wall -Wextra -c foo.cpp -o foo.o
g++ -std=c++17 -Wall -Wextra -c bar.cpp -o bar.o
g++ foo.o bar.o -o app
```

> [!question] 选择题 1
> 以下哪个优化级别最适合用于发布版本？
> - [ ] A. -O0
> - [ ] B. -O1
> - [ ] C. -O2
> - [ ] D. -g
>
> > [!success]- 点击查看答案
> > 正确答案: C
> > 
> > **解析**: `-O2` 是最常用的发布优化级别，它在优化效果和编译时间之间取得了良好平衡，且不会像 `-O3` 那样可能导致代码膨胀。`-O0` 适合调试，`-g` 是调试信息选项而非优化选项。

> [!question] 判断题 1
> `-Wall` 选项会启用编译器支持的所有警告。（ ）
> - [ ] ✅ 正确
> - [ ] ❌ 错误
>
> > [!success]- 点击查看答案
> > 答案: 错误
> > 
> > **解析**: 尽管名字中有 "all"，`-Wall` 实际上只启用了一组常见且有用的警告。还有很多警告需要通过 `-Wextra`、`-Wpedantic`、`-Wshadow` 等选项单独开启。

> [!question] 选择题 2
> 要同时生成调试信息并启用地址消毒器，正确的编译命令是？
> - [ ] A. `g++ -g -fsanitize=address main.cpp`
> - [ ] B. `g++ -O2 -fsanitize=address main.cpp`
> - [ ] C. `g++ -g -DNDEBUG main.cpp`
> - [ ] D. `g++ -static -g main.cpp`
>
> > [!success]- 点击查看答案
> > 正确答案: A
> > 
> > **解析**: `-g` 生成调试信息，`-fsanitize=address` 启用 ASan。选项 B 缺少 `-g`；选项 C 的 `-DNDEBUG` 会禁用 assert；选项 D 与内存检测无关。

3.1 Makefile 基础
---------------------------------

当项目包含多个源文件时，手动编译变得繁琐。Make 是最经典的构建工具。

**Makefile 的基本结构：**

```makefile
target: dependencies
	recipe
```

每条规则由目标（target）、依赖（dependencies）和命令（recipe）组成。
命令行必须以 Tab 字符开头（不能用空格）。

**一个完整的 Makefile 示例：**

```makefile
CXX = g++
CXXFLAGS = -std=c++17 -Wall -Wextra -g
LDFLAGS =

SRCS = main.cpp utils.cpp parser.cpp
OBJS = $(SRCS:.cpp=.o)
TARGET = myapp

all: $(TARGET)

$(TARGET): $(OBJS)
	$(CXX) $(LDFLAGS) -o $@ $^

%.o: %.cpp
	$(CXX) $(CXXFLAGS) -c -o $@ $<

clean:
	rm -f $(OBJS) $(TARGET)

.PHONY: all clean
```

**Makefile 常用自动变量：**

| 变量 | 含义 |
|------|------|
| `$@` | 当前目标名 |
| `$<` | 第一个依赖文件 |
| `$^` | 所有依赖文件（去重） |
| `$?` | 比目标更新的依赖文件 |

**使用方法：**

```bash
make          # 构建默认目标（all）
make clean    # 清理构建产物
make -j4      # 4 线程并行构建
```

3.2 CMake 基础
---------------------------------

CMake 是现代 C++ 项目的标准构建系统生成器。它不直接构建程序，而是生成
Makefile、Ninja 文件或 IDE 项目文件。

**最小 CMakeLists.txt：**

```cmake
cmake_minimum_required(VERSION 3.16)
project(MyApp LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

add_executable(myapp main.cpp utils.cpp parser.cpp)
```

**多目标项目：**

```cmake
cmake_minimum_required(VERSION 3.16)
project(MyProject LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

add_library(mylib STATIC
    src/utils.cpp
    src/parser.cpp
)
target_include_directories(mylib PUBLIC include)

add_executable(myapp src/main.cpp)
target_link_libraries(myapp PRIVATE mylib)
```

**CMake 构建流程：**

```bash
mkdir build && cd build
cmake ..                    # 生成构建文件
cmake --build .             # 编译
cmake --build . --target clean  # 清理
```

**常用 CMake 变量：**

```bash
cmake -DCMAKE_BUILD_TYPE=Debug ..      # 调试版本
cmake -DCMAKE_BUILD_TYPE=Release ..    # 发布版本
cmake -G Ninja ..                      # 使用 Ninja 生成器
```

3.3 CMake vs Makefile 对比
---------------------------------

| 特性 | Makefile | CMake |
|------|----------|-------|
| 跨平台 | 有限 | 优秀 |
| 学习曲线 | 低 | 中等 |
| 依赖管理 | 手动 | find_package 等 |
| IDE 集成 | 弱 | 强 |
| 适用规模 | 小型项目 | 任意规模 |

> [!question] 选择题 1

### 📖 第四节: 第一个程序 — Hello World
## ==========================================================================

4.1 编写源代码
---------------------------------

创建 `hello.cpp`：

```cpp
#include <iostream>

int main() {
    std::cout << "Hello, World!" << std::endl;
    return 0;
}
```

4.2 编译与运行
---------------------------------

**单步编译（编译 + 链接）：**

```bash
g++ -std=c++17 -Wall -o hello hello.cpp
./hello
```

输出：
```
Hello, World!
```

**分步编译：**

```bash
# 步骤 1: 预处理（生成 .i 文件）
g++ -E hello.cpp -o hello.i

# 步骤 2: 编译（生成汇编 .s 文件）
g++ -S hello.i -o hello.s

# 步骤 3: 汇编（生成目标文件 .o）
g++ -c hello.s -o hello.o

# 步骤 4: 链接（生成可执行文件）
g++ hello.o -o hello
```

4.3 理解编译过程
---------------------------------

```
源代码(.cpp) → 预处理(.i) → 编译(.s) → 汇编(.o) → 链接(可执行文件)
     |              |             |            |            |
  hello.cpp    hello.i      hello.s     hello.o       hello
  (文本)      (展开宏/头)   (汇编码)   (机器码)     (可运行)
```

**查看预处理后的文件大小：**

```bash
wc -l hello.i
```

你会发现一个只有几行的源文件，预处理后可能膨胀到数万行——这是因为 `<iostream>`
头文件被完整展开了。

4.4 使用 Clang 编译
---------------------------------

```bash
clang++ -std=c++17 -Wall -o hello hello.cpp
./hello
```

Clang 与 GCC 使用几乎相同的命令行选项，但通常提供更友好的错误信息。

> [!question] 选择题 1
> C++ 编译的正确顺序是？
> - [ ] A. 编译 → 预处理 → 汇编 → 链接
> - [ ] B. 预处理 → 编译 → 汇编 → 链接
> - [ ] C. 预处理 → 汇编 → 编译 → 链接
> - [ ] D. 链接 → 编译 → 预处理 → 汇编
>
> > [!success]- 点击查看答案
> > 正确答案: B
> > 
> > **解析**: 完整编译流程为：预处理（展开宏和头文件）→ 编译（生成汇编代码）→ 汇编（生成目标文件）→ 链接（合并目标文件生成可执行文件）。

> [!question] 判断题 1
> `g++ -c hello.cpp` 会生成可执行文件。（ ）
> - [ ] ✅ 正确
> - [ ] ❌ 错误
>
> > [!success]- 点击查看答案
> > 答案: 错误
> > 
> > **解析**: `-c` 选项告诉编译器只编译不链接，生成目标文件（.o）。要生成可执行文件，需要省略 `-c` 或在后续步骤中将 .o 文件链接起来。

5.1 GDB 基础
---------------------------------

GDB（GNU Debugger）是 Linux 下最常用的 C++ 调试器。

**编译时必须加 `-g` 选项：**

```bash
g++ -std=c++17 -g -o myapp main.cpp
```

**启动 GDB：**

```bash
gdb ./myapp
```

**GDB 常用命令：**

| 命令 | 缩写 | 说明 |
|------|------|------|
| `run` | `r` | 运行程序 |
| `break main` | `b main` | 在 main 函数设断点 |
| `break 15` | `b 15` | 在第 15 行设断点 |
| `next` | `n` | 执行下一行（不进入函数） |
| `step` | `s` | 执行下一行（进入函数） |
| `continue` | `c` | 继续运行到下一个断点 |
| `print x` | `p x` | 打印变量 x 的值 |
| `backtrace` | `bt` | 显示调用栈 |
| `list` | `l` | 显示当前位置的源代码 |
| `info locals` | | 显示所有局部变量 |
| `watch x` | | 监视变量 x，变化时中断 |
| `quit` | `q` | 退出 GDB |

**GDB 调试示例会话：**

```bash
$ gdb ./myapp
(gdb) b main

(gdb) r

(gdb) n
6	    int y = 20;
(gdb) p x
$1 = 10
(gdb) n
7	    int z = x + y;
(gdb) p y
$2 = 20
(gdb) n
8	    std::cout << z << std::endl;
(gdb) p z
$3 = 30
(gdb) c
Continuing.
30
[Inferior 1 (process 12345) exited normally]
(gdb) q
```

5.2 LLDB 基础
---------------------------------

LLDB 是 macOS 默认调试器，也可用于 Linux。它是 LLVM 项目的一部分。

**启动 LLDB：**

```bash
lldb ./myapp
```

**LLDB 常用命令：**

| 命令 | 说明 |
|------|------|
| `run` / `r` | 运行程序 |
| `breakpoint set --name main` | 在 main 函数设断点 |
| `breakpoint set --file main.cpp --line 15` | 在指定行设断点 |
| `b main.cpp:15` | 简写设断点 |
| `thread step-over` / `n` | 执行下一行（不进入函数） |
| `thread step-in` / `s` | 执行下一行（进入函数） |
| `continue` / `c` | 继续运行 |
| `frame variable` | 显示当前帧所有变量 |
| `print x` / `p x` | 打印变量 |
| `bt` | 显示调用栈 |
| `quit` / `q` | 退出 |

**GDB 与 LLDB 命令对照：**

| 功能 | GDB | LLDB |
|------|-----|------|
| 设断点（函数） | `b main` | `b main` |
| 设断点（行号） | `b 15` | `b main.cpp:15` |
| 打印变量 | `p x` | `p x` |
| 查看局部变量 | `info locals` | `frame variable` |
| 查看调用栈 | `bt` | `bt` |
| 条件断点 | `b 15 if x>5` | `b main.cpp:15 -c 'x>5'` |

5.3 调试技巧
---------------------------------

**Core Dump 调试：**

```bash
ulimit -c unlimited
./myapp
gdb ./myapp core
```

**附加到运行中的进程：**

```bash
gdb -p <PID>
```

**使用 AddressSanitizer 辅助调试：**


### 📖 第六节: 常见编译错误及解决方法
## ==========================================================================

6.1 未定义引用 (undefined reference)
---------------------------------

```
/usr/bin/ld: main.o: undefined reference to `foo()'
collect2: error: ld returned 1 exit status
```

**原因:** 链接阶段找不到函数定义。通常是忘记编译/链接包含该函数的源文件。

**解决方法:**

```bash
# 错误：只编译了 main.cpp，忘记了 foo.cpp
g++ main.cpp -o app

# 正确：包含所有源文件
g++ main.cpp foo.cpp -o app
```

6.2 头文件找不到 (No such file or directory)
---------------------------------

```
fatal error: myheader.h: No such file or directory
```

**原因:** 编译器在默认搜索路径中找不到指定的头文件。

**解决方法:**

```bash
# 使用 -I 指定头文件搜索路径
g++ -I./include main.cpp -o app
```

6.3 重复定义 (multiple definition)
---------------------------------

```
/usr/bin/ld: foo.o: multiple definition of `globalVar'
```

**原因:** 全局变量或函数在多个翻译单元中被定义。

**解决方法:**

```cpp
// 在头文件中使用 extern 声明
extern int globalVar;

// 在一个 .cpp 文件中定义
int globalVar = 42;
```

或使用 C++17 的 `inline` 变量：

```cpp
inline int globalVar = 42;
```

6.4 类型不匹配 (type mismatch)
---------------------------------

```
error: cannot convert 'const char*' to 'int'
```

**原因:** 将一种类型的值赋给不兼容类型的变量。

**解决方法:** 检查变量类型，使用正确的类型转换或修改代码逻辑。

6.5 缺少分号
---------------------------------

```
error: expected ';' after expression
```

**原因:** 语句末尾缺少分号。注意：错误可能报在下一行。

**解决方法:** 在报错行的上一行末尾检查是否遗漏了分号。

6.6 模板实例化错误
---------------------------------

```
error: no matching function for call to 'sort(int, int)'
```

**原因:** 向 STL 算法传递了错误类型的参数。

**解决方法:**

```cpp
#include <algorithm>
#include <vector>

std::vector<int> v = {3, 1, 4, 1, 5};
std::sort(v.begin(), v.end());
```

6.7 段错误 (Segmentation Fault)
---------------------------------

虽然这是运行时错误而非编译错误，但极为常见：

```bash
# 用 AddressSanitizer 定位问题
g++ -g -fsanitize=address main.cpp -o app
./app

# 或用 GDB
gdb ./app
(gdb) r
(gdb) bt
```

**常见原因:**
- 空指针解引用
- 数组越界
- 使用已释放的内存
- 栈溢出（无限递归）

> > add_library(math_utils STATIC src/math_utils.cpp)
> > target_include_directories(math_utils PUBLIC include)
> > 
> > add_executable(calculator src/main.cpp)
> > target_link_libraries(calculator PRIVATE math_utils)
> > ```
> > 
> > **构建步骤:**
> > ```bash
> > # Debug 版本
> > mkdir build-debug && cd build-debug
> > cmake -DCMAKE_BUILD_TYPE=Debug ..
> > cmake --build . --verbose
> > ls -la calculator
> > 
> > # Release 版本
> > cd .. && mkdir build-release && cd build-release
> > cmake -DCMAKE_BUILD_TYPE=Release ..
> > cmake --build . --verbose
> > ls -la calculator
> > ```
> > 
> > Release 版本的可执行文件通常比 Debug 版本小得多，因为没有调试信息且代码经过优化。
