## 20.1 安装前准备

### 下载 ISO 镜像

```bash
# 官方下载页面
# https://archlinux.org/download/

# 使用国内镜像加速下载
wget https://mirrors.tuna.tsinghua.edu.cn/archlinux/iso/latest/archlinux-x86_64.iso
wget https://mirrors.tuna.tsinghua.edu.cn/archlinux/iso/latest/archlinux-x86_64.iso.sig
wget https://mirrors.tuna.tsinghua.edu.cn/archlinux/iso/latest/sha256sums.txt
```

### 验证 ISO 完整性

```bash
# SHA256 校验
sha256sum archlinux-x86_64.iso
# 对比 sha256sums.txt 中的值

# GPG 签名验证
gpg --keyserver-options auto-key-retrieve --verify archlinux-x86_64.iso.sig archlinux-x86_64.iso
```

### 制作启动盘

```bash
# Linux 下使用 dd
lsblk # 确认 U 盘设备名（如 /dev/sdb）
sudo dd bs=4M if=archlinux-x86_64.iso of=/dev/sdb conv=fsync oflag=direct status=progress

# 或使用 cp
sudo cp archlinux-x86_64.iso /dev/sdb
sync

# 注意：目标是整个设备（/dev/sdb），不是分区（/dev/sdb1）
# 这会擦除 U 盘上所有数据！

# Windows 下推荐工具：
# - Rufus（DD 模式写入）
# - Ventoy（多 ISO 启动盘）
# - balenaEtcher
```

### 启动到安装环境

```bash
# 1. 进入 BIOS/UEFI 设置（通常按 F2/Del/F12）
# 2. 设置 U 盘为第一启动项
# 3. 如果是 UEFI，确保关闭 Secure Boot（或在安装后再配置）
# 4. 保存并重启
# 5. 选择 "Arch Linux install medium" 启动

# 启动后会进入 root shell
# root@archiso ~ #
```

## 20.2 UEFI vs Legacy BIOS 区别与识别

### 对比表

| 特性 | Legacy BIOS | UEFI |
|------|-------------|------|
| 年代 | 1975年+ | 2005年+ |
| 分区表 | MBR（最大 2TB） | GPT（最大 9.4ZB） |
| 分区数量 | 最多 4 个主分区 | 最多 128 个分区 |
| 启动方式 | 读取 MBR 引导代码 | 从 ESP 加载 .efi 文件 |
| 安全启动 | 不支持 | Secure Boot |
| 启动速度 | 较慢 | 较快 |
| 界面 | 文本 | 图形/文本 |

### 识别当前启动模式

```bash
# 在安装环境中检查
ls /sys/firmware/efi/efivars
# 如果目录存在且有内容 → UEFI 模式
# 如果不存在 → BIOS 模式

# 或者
cat /sys/firmware/efi/fw_platform_size
# 64 → 64位 UEFI
# 32 → 32位 UEFI
# 文件不存在 → BIOS
```

## 20.2-A 引导程序详解

> 引导程序（Bootloader）是系统启动时第一个运行的程序，负责加载内核和 initramfs。选择合适的引导程序对系统稳定性和易用性至关重要。

### 引导程序完整对比

| 特性 | GRUB | systemd-boot | rEFInd | Limine | syslinux |
|------|------|--------------|--------|--------|----------|
| **支持固件** | BIOS/UEFI | 仅UEFI | 仅UEFI | BIOS/UEFI | BIOS/部分UEFI |
| **分区表支持** | MBR/GPT | GPT | GPT | MBR/GPT | MBR/GPT |
| **配置复杂度** | 高 | 低 | 中 | 中 | 中 |
| **启动速度** | 较慢 | 最快 | 快 | 快 | 快 |
| **自动检测OS** | 是 | 部分 | 是 | 否 | 否 |
| **文件系统支持** | 广泛 | 有限 | 有限 | 有限 | 有限 |
| **多内核管理** | 自动 | 手动 | 自动 | 手动 | 手动 |
| **自定义菜单** | 完整 | 简单 | 完整 | 简单 | 简单 |
| **Secure Boot** | 支持 | 支持 | 支持 | 支持 | 有限 |
| **社区支持** | 最广泛 | 广泛 | 中等 | 较小 | 较小 |
| **适用场景** | 通用/双系统 | 纯UEFI系统 | 多系统启动 | 轻量级 | 老旧系统 |

### GRUB（GRand Unified Bootloader）

**特点**：功能最强大，支持最多文件系统和操作系统，是大多数发行版的默认选择。

```bash
# 安装
pacman -S grub efibootmgr

# UEFI 系统安装
grub-install --target=x86_64-efi --efi-directory=/boot --bootloader-id=GRUB

# BIOS 系统安装
grub-install --target=i386-pc /dev/sda

# 生成配置
grub-mkconfig -o /boot/grub/grub.cfg
```

**配置文件**：
- `/etc/default/grub` - 默认配置（可编辑）
- `/boot/grub/grub.cfg` - 生成的配置（勿手动编辑）
- `/etc/grub.d/40_custom` - 自定义条目

**适用场景**：
- 双系统（Windows + Linux）
- 需要自动检测其他操作系统
- 需要复杂的启动菜单定制

### systemd-boot

**特点**：轻量快速，与 systemd 深度集成，配置简单。

```bash
# 安装（无需额外包）
bootctl install

# 创建启动条目
mkdir -p /boot/loader/entries
```

**配置文件**：
- `/boot/loader/loader.conf` - 主配置
- `/boot/loader/entries/*.conf` - 启动条目

**适用场景**：
- 纯 UEFI 系统
- 追求快速启动
- 喜欢简洁配置

### rEFInd

**特点**：自动检测内核和操作系统，图形界面友好。

```bash
# 安装
pacman -S refind
refind-install
```

**配置文件**：
- `/boot/efi/EFI/refind/refind.conf` - 主配置
- `/boot/refind_linux.conf` - Linux 条目

**适用场景**：
- 多系统启动（Linux + Windows + macOS）
- 希望自动检测所有系统
- 喜欢图形化选择界面

### Limine

**特点**：轻量级，支持多种协议，设计简洁。

```bash
# 安装
pacman -S limine
limine-install --fallback
```

**配置文件**：
- `/boot/limine.conf` - 主配置

**适用场景**：
- 轻量级系统
- 需要 BIOS + UEFI 双支持
- 简单的单系统启动

### syslinux

**特点**：简单轻量，主要用于 BIOS 系统。

```bash
# 安装
pacman -S syslinux gptfdisk
syslinux-install_update -i -a -m
```

**配置文件**：
- `/boot/syslinux/syslinux.cfg` - 主配置

**适用场景**：
- 老旧 BIOS 系统
- 简单的单系统启动
- 嵌入式系统

### 引导程序选择指南

```
你的系统是什么固件？
├── BIOS（传统 BIOS）
│   ├── 需要双系统 → GRUB
│   └── 简单单系统 → syslinux 或 GRUB
└── UEFI
    ├── 需要双系统 → GRUB 或 rEFInd
    ├── 纯 Linux → systemd-boot（推荐）
    ├── 多系统（3个以上） → rEFInd
    └── 追求极简 → systemd-boot
```

### 如何判断系统是否支持 EFI

```bash
# 方法1：检查 EFI 变量目录
ls /sys/firmware/efi/efivars
# 存在且有内容 → 支持 EFI

# 方法2：检查 UEFI 固件类型
cat /sys/firmware/efi/fw_platform_size
# 64 → 64位 UEFI
# 32 → 32位 UEFI
# 不存在 → BIOS

# 方法3：检查 BIOS/UEFI 设置
# 重启时按 F2/Del/F12 进入设置界面
# 如果看到图形化设置界面 → UEFI
# 如果只有文本菜单 → 可能是 BIOS

# 方法4：检查磁盘分区表
fdisk -l /dev/sda | grep "Disk label"
# dos → MBR（BIOS）
# gpt → GPT（UEFI）
```

### Secure Boot 处理

```bash
# 检查 Secure Boot 状态
mokutil --sb-state
# 或
cat /sys/firmware/efi/esrt/entries/*/fw_class

# 如果需要禁用 Secure Boot
# 1. 重启进入 BIOS/UEFI 设置
# 2. 找到 Secure Boot 选项（通常在 Security 或 Boot 菜单）
# 3. 设置为 Disabled
# 4. 保存并重启

# Arch Linux 官方内核支持 Secure Boot
# 但需要手动签名或使用 shim
pacman -S shim
```

## 20.4 不同安装场景

### 场景 A: 纯 UEFI + GPT 安装（主流推荐）

适用于 2012 年后的大多数电脑。

#### 分区方案

```
设备 大小 类型 挂载点
/dev/nvme0n1p1 512M EFI System /boot
/dev/nvme0n1p2 所有剩余 Linux filesystem /
（可选）
/dev/nvme0n1p3 适量 Linux swap [SWAP]
```

```bash
# 使用 fdisk 分区
fdisk /dev/nvme0n1

# 输入命令序列：
# g # 创建新的 GPT 分区表
# n # 新建分区 1（EFI）
# <回车> # 分区号默认 1
# <回车> # 起始扇区默认
# +512M # 大小 512MB
# t # 更改分区类型
# 1 # EFI System
# n # 新建分区 2（根分区）
# <回车> # 分区号默认 2
# <回车> # 起始扇区默认
# <回车> # 使用全部剩余空间（或指定大小如 -8G 留出 swap）
# w # 写入分区表

# 如果需要 swap 分区
# n → 3 → 默认 → +8G → t → 3 → 19(Linux swap)
```

### 场景 B: Legacy BIOS + MBR 安装

适用于旧电脑或特殊需求。

#### 分区方案

```
设备 大小 类型 挂载点
/dev/sda1 所有 Linux filesystem /
（可选）
/dev/sda2 适量 Linux swap [SWAP]
```

```bash
fdisk /dev/sda

# 输入命令序列：
# o # 创建新的 MBR (DOS) 分区表
# n # 新建分区
# p # 主分区
# 1 # 分区号 1
# <回车> # 起始扇区默认
# <回车> # 使用全部空间（或留出 swap 空间）
# a # 设置启动标志
# w # 写入

# BIOS + GPT 方案（需要 BIOS Boot Partition）
# 使用 gdisk 创建 GPT 表时，需要一个 1M 的 BIOS Boot 分区：
gdisk /dev/sda
# n → 1 → 默认 → +1M → ef02 (BIOS boot partition)
# n → 2 → 默认 → 默认 → 8300 (Linux filesystem)
```

### 场景 C: 双系统安装（与 Windows 共存）

```bash
# 前提：Windows 已安装在 UEFI + GPT 模式

# 1. 在 Windows 中缩小分区（磁盘管理 → 压缩卷）
# 2. 从 Arch ISO 启动

# 查看现有分区
fdisk -l /dev/nvme0n1
# /dev/nvme0n1p1 EFI System (Windows 已创建，通常 100-500MB)
# /dev/nvme0n1p2 Microsoft reserved (16MB)
# /dev/nvme0n1p3 Microsoft basic data (Windows C:)
# /dev/nvme0n1p4 Windows recovery

# 3. 在空闲空间创建 Linux 分区
fdisk /dev/nvme0n1
# n → 5(或下一个可用编号) → 默认 → 默认（使用空闲空间）
# w

# 4. 不要格式化 Windows 的 EFI 分区！直接复用
# /dev/nvme0n1p1 已经是 FAT32 格式的 ESP，直接挂载到 /boot

# 5. 安装完成后安装 os-prober 检测 Windows
pacman -S os-prober ntfs-3g
# 编辑 /etc/default/grub
# GRUB_DISABLE_OS_PROBER=false
grub-mkconfig -o /boot/grub/grub.cfg
```

## 20.5 分区方案详解

### 使用 cfdisk（TUI 界面，最友好）

```bash
cfdisk /dev/nvme0n1
# 图形化的终端分区工具，支持方向键操作
# 选择 gpt 标签类型
# 用 [ New ] 创建分区
# 用 [ Type ] 更改类型
# 用 [ Write ] 写入
# 用 [ Quit ] 退出
```

### 使用 gdisk（GPT 专用）

```bash
gdisk /dev/nvme0n1
# ? 查看帮助
# p 打印分区表
# n 新建分区
# d 删除分区
# t 更改类型
# w 写入退出

# 常用分区类型代码：
# ef00 EFI System
# 8300 Linux filesystem
# 8200 Linux swap
# 8e00 Linux LVM
# fd00 Linux RAID
```

### 使用 parted（支持脚本化）

```bash
# 交互式
parted /dev/nvme0n1
(parted) mklabel gpt
(parted) mkpart "EFI" fat32 1MiB 513MiB
(parted) set 1 esp on
(parted) mkpart "Root" ext4 513MiB 100%
(parted) print
(parted) quit

# 命令行模式（脚本化）
parted -s /dev/nvme0n1 mklabel gpt
parted -s /dev/nvme0n1 mkpart "EFI" fat32 1MiB 513MiB
parted -s /dev/nvme0n1 set 1 esp on
parted -s /dev/nvme0n1 mkpart "Root" ext4 513MiB 100%
```

### 分区工具详解对比

| 特性 | fdisk | gdisk | cfdisk | parted |
|------|-------|-------|--------|--------|
| **分区表支持** | MBR/GPT | 仅 GPT | MBR/GPT | MBR/GPT |
| **界面** | 文本命令 | 文本命令 | TUI 图形 | 交互式/命令行 |
| **脚本化** | 否 | 否 | 否 | 是 |
| **分区类型代码** | 数字（1=EFI等） | 十六进制（ef00等） | 菜单选择 | 名称（fat32等） |
| **学习曲线** | 中等 | 中等 | 低 | 中等 |
| **适用场景** | 通用 | GPT 专用 | 新手友好 | 自动化脚本 |

**fdisk（最通用）**：

```bash
# MBR 分区表
fdisk /dev/sda
# o → 创建 MBR 分区表
# n → 新建分区
# p → 主分区
# t → 更改类型（1=EFI, 82=swap, 83=Linux）
# w → 写入

# GPT 分区表
fdisk /dev/nvme0n1
# g → 创建 GPT 分区表
# n → 新建分区
# t → 更改类型（1=EFI, 19=swap, 20=Linux）
# w → 写入
```

**gdisk（GPT 专用）**：

```bash
gdisk /dev/nvme0n1
# ? → 查看帮助
# p → 打印分区表
# n → 新建分区
# d → 删除分区
# t → 更改类型
# w → 写入退出

# 常用 GPT 类型代码：
# ef00 → EFI System Partition
# 8200 → Linux swap
# 8300 → Linux filesystem
# 8e00 → Linux LVM
# fd00 → Linux RAID
```

**cfdisk（最友好）**：

```bash
cfdisk /dev/nvme0n1
# 方向键导航
# [ New ] → 创建分区
# [ Type ] → 更改类型
# [ Write ] → 写入分区表
# [ Quit ] → 退出
# 支持 GPT 和 MBR
```

**parted（支持脚本化）**：

```bash
# 交互式
parted /dev/nvme0n1
(parted) mklabel gpt
(parted) mkpart "EFI" fat32 1MiB 513MiB
(parted) set 1 esp on
(parted) mkpart "Root" ext4 513MiB 100%
(parted) print
(parted) quit

# 脚本化（适合自动化安装）
parted -s /dev/nvme0n1 mklabel gpt
parted -s /dev/nvme0n1 mkpart "EFI" fat32 1MiB 513MiB
parted -s /dev/nvme0n1 set 1 esp on
parted -s /dev/nvme0n1 mkpart "Root" ext4 513MiB 100%
```

**工具选择建议**：
- **新手** → cfdisk（图形界面，最易用）
- **GPT 分区** → gdisk 或 fdisk
- **MBR 分区** → fdisk
- **自动化脚本** → parted
- **通用场景** → fdisk

### 方案 1: Btrfs 子卷方案（推荐）

Btrfs 支持子卷、快照、压缩等高级功能。

```bash
# 分区结构
# /dev/nvme0n1p1 512M EFI System
# /dev/nvme0n1p2 剩余 Linux filesystem (Btrfs)

# 格式化
mkfs.fat -F 32 /dev/nvme0n1p1
mkfs.btrfs -f /dev/nvme0n1p2

# 创建子卷
mount /dev/nvme0n1p2 /mnt
btrfs subvolume create /mnt/@
btrfs subvolume create /mnt/@home
btrfs subvolume create /mnt/@log
btrfs subvolume create /mnt/@pkg
btrfs subvolume create /mnt/@snapshots
umount /mnt

# 挂载子卷
mount -o noatime,compress=zstd:3,space_cache=v2,subvol=@ /dev/nvme0n1p2 /mnt

mkdir -p /mnt/{boot,home,var/log,var/cache/pacman/pkg,.snapshots}

mount -o noatime,compress=zstd:3,space_cache=v2,subvol=@home /dev/nvme0n1p2 /mnt/home
mount -o noatime,compress=zstd:3,space_cache=v2,subvol=@log /dev/nvme0n1p2 /mnt/var/log
mount -o noatime,compress=zstd:3,space_cache=v2,subvol=@pkg /dev/nvme0n1p2 /mnt/var/cache/pacman/pkg
mount -o noatime,compress=zstd:3,space_cache=v2,subvol=@snapshots /dev/nvme0n1p2 /mnt/.snapshots

mount /dev/nvme0n1p1 /mnt/boot

# 验证挂载
findmnt -R /mnt
```

子卷设计说明：

| 子卷 | 挂载点 | 理由 |
|------|--------|------|
| `@` | `/` | 根文件系统 |
| `@home` | `/home` | 用户数据独立，方便快照和还原 |
| `@log` | `/var/log` | 日志独立，回滚时保留日志 |
| `@pkg` | `/var/cache/pacman/pkg` | 包缓存独立，不纳入快照 |
| `@snapshots` | `/.snapshots` | 快照存储位置 |

### 方案 2: ext4 传统方案

简单可靠，适合大多数场景。

```bash
# 分区结构
# /dev/nvme0n1p1 512M EFI System /boot
# /dev/nvme0n1p2 剩余 Linux filesystem /
# /dev/nvme0n1p3 8G Linux swap [SWAP]
# （可选独立 /home）

# 格式化
mkfs.fat -F 32 /dev/nvme0n1p1
mkfs.ext4 /dev/nvme0n1p2
mkswap /dev/nvme0n1p3

# 挂载
mount /dev/nvme0n1p2 /mnt
mkdir /mnt/boot
mount /dev/nvme0n1p1 /mnt/boot
swapon /dev/nvme0n1p3
```

### 方案 3: LVM 方案

LVM 提供灵活的逻辑卷管理，支持在线扩容。

```bash
# 分区结构
# /dev/nvme0n1p1 512M EFI System
# /dev/nvme0n1p2 剩余 Linux LVM

# 格式化 EFI 分区
mkfs.fat -F 32 /dev/nvme0n1p1

# 创建 LVM
pvcreate /dev/nvme0n1p2 # 创建物理卷
vgcreate vg0 /dev/nvme0n1p2 # 创建卷组
lvcreate -L 50G vg0 -n root # 创建根逻辑卷
lvcreate -L 8G vg0 -n swap # 创建 swap 逻辑卷
lvcreate -l 100%FREE vg0 -n home # 剩余全部给 home

# 格式化逻辑卷
mkfs.ext4 /dev/vg0/root
mkfs.ext4 /dev/vg0/home
mkswap /dev/vg0/swap

# 挂载
mount /dev/vg0/root /mnt
mkdir /mnt/{boot,home}
mount /dev/nvme0n1p1 /mnt/boot
mount /dev/vg0/home /mnt/home
swapon /dev/vg0/swap

# 注意：使用 LVM 需要在 mkinitcpio.conf 的 HOOKS 中添加 lvm2
# HOOKS=(base udev autodetect microcode modconf kms keyboard keymap consolefont block lvm2 filesystems fsck)
```

### 方案 4: LUKS 加密方案

全盘加密保护数据安全。

```bash
# 分区结构
# /dev/nvme0n1p1 512M EFI System（不加密）
# /dev/nvme0n1p2 剩余 Linux filesystem（LUKS 加密）

# 格式化 EFI
mkfs.fat -F 32 /dev/nvme0n1p1

# 创建 LUKS 加密容器
cryptsetup luksFormat /dev/nvme0n1p2
# 确认 YES
# 输入加密密码（牢记！）

# 打开加密容器
cryptsetup open /dev/nvme0n1p2 cryptroot
# 输入密码

# 现在 /dev/mapper/cryptroot 就是解密后的设备
# 可以在上面创建文件系统或 LVM

# 方案 A: 直接在加密设备上创建 ext4
mkfs.ext4 /dev/mapper/cryptroot
mount /dev/mapper/cryptroot /mnt

# 方案 B: 加密 + LVM
pvcreate /dev/mapper/cryptroot
vgcreate vg0 /dev/mapper/cryptroot
lvcreate -L 50G vg0 -n root
lvcreate -L 8G vg0 -n swap
lvcreate -l 100%FREE vg0 -n home
mkfs.ext4 /dev/vg0/root
mkfs.ext4 /dev/vg0/home
mkswap /dev/vg0/swap
mount /dev/vg0/root /mnt
mkdir /mnt/{boot,home}
mount /dev/vg0/home /mnt/home
mount /dev/nvme0n1p1 /mnt/boot
swapon /dev/vg0/swap

# 方案 C: 加密 + Btrfs
mkfs.btrfs /dev/mapper/cryptroot
mount /dev/mapper/cryptroot /mnt
btrfs subvolume create /mnt/@
btrfs subvolume create /mnt/@home
umount /mnt
mount -o noatime,compress=zstd:3,subvol=@ /dev/mapper/cryptroot /mnt
mkdir -p /mnt/{boot,home}
mount -o noatime,compress=zstd:3,subvol=@home /dev/mapper/cryptroot /mnt/home
mount /dev/nvme0n1p1 /mnt/boot

# mkinitcpio HOOKS 需要添加 encrypt（lvm2 如果用了 LVM）
# HOOKS=(base udev autodetect microcode modconf kms keyboard keymap consolefont block encrypt filesystems fsck)

# 内核参数需要指定加密设备
# cryptdevice=UUID=<LUKS分区UUID>:cryptroot root=/dev/mapper/cryptroot
# 或使用 LVM: cryptdevice=UUID=<LUKS分区UUID>:cryptroot root=/dev/vg0/root
```

## 20.6 格式化与挂载总结

```bash
# 格式化命令速查
mkfs.fat -F 32 /dev/nvme0n1p1 # FAT32 (EFI)
mkfs.ext4 /dev/nvme0n1p2 # ext4
mkfs.btrfs -f /dev/nvme0n1p2 # Btrfs
mkfs.xfs /dev/nvme0n1p2 # XFS
mkswap /dev/nvme0n1p3 # Swap

# 挂载顺序很重要！先挂载根分区，再挂载子目录
mount /dev/nvme0n1p2 /mnt
mkdir -p /mnt/boot
mount /dev/nvme0n1p1 /mnt/boot

# 启用 swap
swapon /dev/nvme0n1p3

# 验证所有挂载
lsblk
findmnt -R /mnt
```

### 文件系统详解

> 选择合适的文件系统对系统性能、数据安全和功能支持至关重要。

| 特性 | ext4 | Btrfs | XFS | F2FS |
|------|------|-------|-----|------|
| **类型** | 日志文件系统 | Copy-on-Write | 日志文件系统 | 日志文件系统 |
| **最大文件大小** | 16 TiB | 16 TiB | 8 TiB | 16 TiB |
| **最大卷大小** | 1 EiB | 16 EiB | 8 EiB | 16 EiB |
| **快照** | 不支持 | 支持 | 不支持 | 不支持 |
| **压缩** | 不支持 | 支持（zstd/lzo/zlib） | 不支持 | 不支持 |
| **子卷** | 不支持 | 支持 | 不支持 | 不支持 |
| **校验和** | 仅元数据 | 元数据+数据 | 仅元数据 | 仅元数据 |
| **在线碎片整理** | 支持 | 支持 | 支持 | 支持 |
| **在线扩容** | 支持 | 支持 | 支持 | 支持 |
| **在线缩容** | 支持 | 不支持 | 不支持 | 不支持 |
| **TRIM 支持** | 支持 | 支持 | 支持 | 支持 |
| **加密** | 支持 | 支持 | 支持 | 支持 |
| **RAID** | 支持 | 内置 | 不支持 | 不支持 |
| **数据恢复** | 较好 | 较好 | 较好 | 较好 |
| **资源占用** | 低 | 中 | 低 | 低 |
| **适用场景** | 通用/桌面 | 高级功能/快照 | 大文件/数据库 | 闪存设备 |

**格式化命令**：

```bash
# ext4（通用推荐）
mkfs.ext4 /dev/nvme0n1p2

# Btrfs（高级功能推荐）
mkfs.btrfs -f /dev/nvme0n1p2

# XFS（大文件推荐）
mkfs.xfs /dev/nvme0n1p2

# F2FS（闪存设备推荐）
mkfs.f2fs /dev/nvme0n1p2

# FAT32（EFI 分区必需）
mkfs.fat -F 32 /dev/nvme0n1p1

```

**挂载选项对比**：

```bash
# ext4 默认挂载
mount -o defaults /dev/nvme0n1p2 /mnt

# ext4 优化挂载（SSD）
mount -o noatime,discard /dev/nvme0n1p2 /mnt

# Btrfs 推荐挂载
mount -o noatime,compress=zstd:3,space_cache=v2,subvol=@ /dev/nvme0n1p2 /mnt

# XFS 默认挂载
mount -o defaults /dev/nvme0n1p2 /mnt

# F2FS 推荐挂载（闪存）
mount -o noatime,discard /dev/nvme0n1p2 /mnt
```

**文件系统选择指南**：

```
你的使用场景？
├── 通用桌面使用
│   ├── 简单稳定 → ext4（推荐）
│   └── 需要快照/压缩 → Btrfs
├── 服务器/数据库
│   ├── 大文件存储 → XFS
│   └── 通用 → ext4
├── 闪存设备（SD卡/U盘）
│   └── F2FS（针对闪存优化）
└── 高级功能需求
    ├── 快照/子卷 → Btrfs

```

**目录结构**：

├── loader/
│   ├── loader.conf          # 主配置文件
│   └── entries/
│       ├── arch.conf        # Arch Linux 启动条目
│       ├── arch-lts.conf    # Arch Linux LTS 条目

**loader.conf 主配置详解**：

```bash
# /boot/loader/loader.conf
```

```ini
# 默认启动条目（支持通配符）
default  arch.conf

# 菜单显示时间（秒）
timeout  3

# 控制台分辨率
# auto → 自动检测
# max → 最大分辨率
# 0 → 80x25 文本模式
console-mode auto

# 启用/禁用编辑器
# yes → 允许在启动时编辑内核参数

# 自动检测其他引导程序（如 Windows）

# 自动检测固件选项（如 UEFI 固件设置）

```

### X11 vs Wayland 完整对比

> X11 和 Wayland 是 Linux 下两种不同的显示服务器协议，决定了图形环境的工作方式。

| 特性 | X11 (X.Org) | Wayland |
|------|-------------|---------|
| **发布年份** | 1984/1987 | 2008 开发，2012 1.0 |
| **架构** | 多程序链：X Server + WM + Compositor 分离 | 单一合成器 (Compositor) 统一处理 |
| **渲染方式** | RAM 多次拷贝 | 零拷贝 GPU |
| **安全模型** | 开放信任 — 任何应用可访问所有输入和屏幕 | 隔离设计 — 应用只能看到自己的窗口 |
| **屏幕撕裂** | 常见 | 已消除 — 合成器控制帧交付 |
| **HiDPI/分数缩放** | 不一致 — 需要逐应用配置 | 按显示器 — 缩放内置于协议 |
| **多显示器 HDR** | 有限 — 事后修补的支持 | 完整支持 — 从头设计 |
| **SSH 远程显示** | 原生支持 (X 转发开箱即用) | 需要外部工具 (XWayland, RDP) |
| **GUI 自动化工具** | 丰富的生态系统 (xdotool, wmctrl) | 有限 — 协议限制跨应用访问 |
| **旧应用支持** | 完整原生支持 | 通过 XWayland 兼容桥 |
| **NVIDIA 驱动支持** | 稳定 — 长期建立 | 良好 — 驱动系列 495+ |
| **电池效率** | 较高开销 | 较低开销 — GPU 缓冲区重用 |
| **开发状态** | 2024 年起仅维护模式 | 积极开发中 |
| **启动方式** | `startx` 或 DM 启动 Xorg | 合成器自身即为显示服务器 |
| **输入延迟** | 较高 | 较低 |

**选择建议**：
- **新系统/新硬件** → Wayland（GNOME/KDE 默认）

### TTY 配置与图形环境区别

> TTY（Teletypewriter）是 Linux 的文本终端界面，图形环境则是基于 X11 或 Wayland 的图形化桌面。

**TTY 与图形环境的区别**：

| 特性 | TTY（文本终端） | 图形环境（X11/Wayland） |
|------|----------------|------------------------|
| **界面** | 纯文本 | 图形化窗口 |
| **资源占用** | 极低 | 较高 |
| **启动方式** | 系统启动后自动可用 | 需要启动显示服务器 |
| **输入设备** | 仅键盘 | 键盘、鼠标、触摸屏等 |
| **多任务** | 单一终端（可用 tmux 多路复用） | 多窗口并行 |
| **适用场景** | 服务器、远程管理、系统维护 | 桌面使用、开发、多媒体 |
| **网络需求** | 无需网络（本地操作） | 通常需要（远程访问需额外配置） |
| **故障恢复** | 更容易 | 可能需要 TTY 恢复 |

## 20.12 常见安装错误与解决方案

### 问题 1: 找不到启动设备 / 无法引导

```bash
# 原因: 引导程序未正确安装
# 解决: 从 LiveUSB 启动，重新安装引导程序

mount /dev/nvme0n1p2 /mnt
mount /dev/nvme0n1p1 /mnt/boot
arch-chroot /mnt

# UEFI + GRUB
grub-install --target=x86_64-efi --efi-directory=/boot --bootloader-id=GRUB
grub-mkconfig -o /boot/grub/grub.cfg

# UEFI + systemd-boot
bootctl install
# 检查 /boot/loader/entries/ 下的配置文件

# 检查 EFI 启动条目
efibootmgr -v
```

### 问题 2: kernel panic - not syncing: VFS: Unable to mount root fs

```bash
# 原因: 内核找不到根分区
# 可能原因:
# 1. 内核参数中的 root=UUID 错误
# 2. initramfs 缺少文件系统驱动或磁盘驱动
# 3. LUKS 加密但未添加 encrypt hook

# 解决:
# 1. 检查 /boot/loader/entries/arch.conf 或 /etc/default/grub 中的 UUID
blkid # 确认正确的 UUID

# 2. 检查 mkinitcpio.conf
# 确保 HOOKS 中包含必要的钩子
# 确保 MODULES 中包含存储驱动（如 nvme、ext4、btrfs）
mkinitcpio -P
```

### 问题 3: 重启后没有网络

```bash
# 原因: NetworkManager 未启用
# 解决（从 chroot 或 rescue 模式）:
systemctl enable NetworkManager
systemctl start NetworkManager

# 或临时使用 dhcpcd
dhcpcd
```

### 问题 4: GRUB 报错 "error: unknown filesystem"

```bash
# 原因: GRUB 无法识别分区的文件系统
# 常见于 Btrfs 或特殊配置

# 解决:
# 1. 确保安装了 grub 的最新版本
pacman -S grub
# 2. 重新安装 GRUB
grub-install ...
grub-mkconfig -o /boot/grub/grub.cfg
```

### 问题 5: 图形界面黑屏/闪烁

```bash
# 原因: 显卡驱动问题
# 临时解决: 在 GRUB 中添加 nomodeset 参数

# 按 'e' 编辑 GRUB 条目
# 在 linux 行末尾添加 nomodeset
# Ctrl+X 启动

# 进入系统后正确安装显卡驱动
```

### 问题 6: 时间不正确（双系统）

```bash
# Windows 使用本地时间，Linux 默认使用 UTC
# 解决方案 A: 让 Linux 使用本地时间
timedatectl set-local-rtc 1

# 解决方案 B: 让 Windows 使用 UTC（推荐）
# 在 Windows 注册表中修改:
# HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\TimeZoneInformation
# 添加 DWORD: RealTimeIsUniversal = 1
```

### 问题 7: pacstrap 报签名错误

```bash
# 更新安装环境中的密钥
pacman-key --init
pacman-key --populate archlinux

# 或更新 archlinux-keyring 包
pacman -Sy archlinux-keyring

# 如果时间不正确也会导致签名验证失败
timedatectl set-ntp true
```

### 问题 8: fstab 错误导致无法启动

```bash
# 系统可能进入 emergency 模式
# 提示: "Give root password for maintenance"

# 输入 root 密码后
mount -o remount,rw / # 重新以读写方式挂载
vim /etc/fstab # 修复错误
reboot
```

## 20.15 快速安装清单

以下是最常见场景（UEFI + ext4 + GRUB）的精简步骤：

```bash
# === 安装环境 ===
iwctl # 连接 WiFi（如果需要）
timedatectl set-ntp true # 同步时间

# === 分区 ===
cfdisk /dev/nvme0n1 # GPT → 512M EFI + 剩余 Linux

# === 格式化 ===
mkfs.fat -F 32 /dev/nvme0n1p1
mkfs.ext4 /dev/nvme0n1p2

# === 挂载 ===
mount /dev/nvme0n1p2 /mnt
mkdir /mnt/boot
mount /dev/nvme0n1p1 /mnt/boot

# === 安装 ===
reflector --country China --sort rate --save /etc/pacman.d/mirrorlist
pacstrap -K /mnt base linux linux-firmware base-devel vim networkmanager grub efibootmgr intel-ucode sudo

# === 配置 ===
genfstab -U /mnt >> /mnt/etc/fstab
arch-chroot /mnt
ln -sf /usr/share/zoneinfo/Asia/Shanghai /etc/localtime
hwclock --systohc
echo "en_US.UTF-8 UTF-8" >> /etc/locale.gen && locale-gen
echo "LANG=en_US.UTF-8" > /etc/locale.conf
echo "myarch" > /etc/hostname
passwd # root 密码
useradd -m -G wheel -s /bin/bash user && passwd user
EDITOR=vim visudo # 取消 %wheel 注释
grub-install --target=x86_64-efi --efi-directory=/boot --bootloader-id=GRUB
grub-mkconfig -o /boot/grub/grub.cfg
systemctl enable NetworkManager
exit

# === 重启 ===
umount -R /mnt
reboot
```
