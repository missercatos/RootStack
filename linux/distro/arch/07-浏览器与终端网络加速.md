# Arch Linux 浏览器与终端网络加速

> 本章聚焦 Arch Linux 客户端网络加速。以 Clash 为核心工具，覆盖终端代理配置、浏览器代理设置、git/yay 加速、开机自启、规则分流和常见问题排查。所有内容均为客户端侧代理，不涉及服务端反向代理。

---

## 1. 什么是代理

Q: 代理是什么？为什么需要它？

A:
- 你的请求先发给代理服务器，代理再转发给目标网站
- 代理 = 中间人，替你转发请求
- 作用：加速访问被限制的网站、隐藏真实 IP
- 类比：你想买东西但店太远，找住在店旁边的朋友帮你买

工作流程：

```
你的软件 → Clash (7890) → 代理节点（日本/美国） → 目标网站
                ↑
          替你转发请求，隐藏你的真实 IP
```

## 2. Clash 三个端口的区别

Q: Clash 有 7890、7891、9090 三个端口，分别是什么？

A:

| 端口 | 类型 | 用途 | 谁在用 |
|------|------|------|--------|
| 7890 | HTTP 代理 | 代理转发 | 浏览器、curl、wget、git、yay |
| 7891 | SOCKS5 代理 | 更底层的代理协议 | Telegram、部分软件 |
| 9090 | API 控制面板 | Clash Dashboard 管理界面 | 浏览器访问 |

- 7890 最常用，大部分软件都走这个
- 7891 是 SOCKS5 协议，部分软件只支持这个
- 9090 是管理面板，用来切换节点、看流量

Q: HTTP 代理和 SOCKS5 代理有什么区别？

A:

| 特性 | HTTP 代理 (7890) | SOCKS5 代理 (7891) |
|------|-----------------|-------------------|
| 协议层级 | 应用层 | 传输层 |
| 支持协议 | 只支持 HTTP/HTTPS | 支持任何协议 |
| 速度 | 稍慢（需要解析 HTTP） | 更快（不解析内容） |
| 兼容性 | 几乎所有软件 | 部分软件 |
| 推荐 | 日常使用 | 需要时使用 |

## 3. 正确启动顺序

Q: 正确的启动顺序是什么？

A:

```
第 1 步：启动 Clash（后台运行）
第 2 步：设置终端代理（让 yay/git/curl 走代理）
第 3 步：启动浏览器（自动走系统代理）
```

为什么这个顺序很重要？
- Clash 不启动，代理端口 7890 不存在
- 终端代理不设置，命令行工具不走代理
- 浏览器在 Clash 启动后才能访问被限制的网站

```bash
# 第 1 步：启动 Clash
cd ~/clash && ./clash -d ~/clash &

# 第 2 步：设置终端代理
export https_proxy=http://127.0.0.1:7890
export http_proxy=http://127.0.0.1:7890

# 第 3 步：启动浏览器
mullvad-browser &
```

## 4. 终端代理设置

Q: 怎么让终端（curl/git/yay）走代理？

A:

### 方法 1：临时设置（当前终端有效）

```bash
export https_proxy=http://127.0.0.1:7890
export http_proxy=http://127.0.0.1:7890
export all_proxy=socks5://127.0.0.1:7891
```

关闭终端后失效，只影响当前终端。

### 方法 2：永久设置（写入 shell 配置）

```bash
# 添加到 ~/.bashrc 或 ~/.zshrc
export https_proxy=http://127.0.0.1:7890
export http_proxy=http://127.0.0.1:7890
export all_proxy=socks5://127.0.0.1:7891
export no_proxy=localhost,127.0.0.1,::1

# 重新加载
source ~/.bashrc
```

每次打开终端自动设置，不需要手动 export。

### 方法 3：单次使用

```bash
curl -x http://127.0.0.1:7890 https://www.google.com -I
git -c http.proxy=http://127.0.0.1:7890 clone https://github.com/...
```

只对这一次命令生效，不影响环境变量。

### 方法 4：临时开关函数

```bash
proxy_on() {
    export https_proxy=http://127.0.0.1:7890
    export http_proxy=http://127.0.0.1:7890
    export all_proxy=socks5://127.0.0.1:7891
    echo "代理已开启"
}

proxy_off() {
    unset https_proxy http_proxy all_proxy
    echo "代理已关闭"
}
```

添加到 `~/.bashrc` 后使用 `proxy_on` / `proxy_off` 切换。

Q: no_proxy 变量有什么用？

A:
- 指定不走代理的地址，如 `localhost,127.0.0.1,::1,192.168.0.0/16`
- 访问本地服务时不走代理，避免不必要的延迟

## 5. 浏览器代理设置

Q: 浏览器怎么走代理？

A:

### Mullvad Browser（推荐）

自动检测系统代理（7890），Clash 启动后直接可用，不需要手动配置。

### Firefox 手动配置

```
设置 → 网络设置 → 手动代理配置
HTTP 代理：127.0.0.1  端口：7890
SOCKS 代理：127.0.0.1  端口：7891
```

### Chrome/Chromium

```bash
chromium --proxy-server=http://127.0.0.1:7890
```

### 系统级代理（GNOME/KDE）

```
GNOME：设置 → 网络 → 网络代理 → 手动
  HTTP 代理：127.0.0.1  端口：7890

KDE：系统设置 → 网络设置 → 代理 → 手动代理配置
  HTTP 代理：127.0.0.1  端口：7890
```

Q: 系统代理和终端代理是同一个东西吗？

A:
- 不是。系统代理影响浏览器和部分 GUI 应用，终端代理影响 curl/git/yay 等命令行工具
- 两者独立配置，互不影响
- Clash 的 7890 端口是底层服务，两者都可以使用它

## 6. 验证代理是否工作

Q: 怎么确认代理在工作？

A:

```bash
# 检查 7890 端口是否在监听
ss -tlnp | grep 7890

# 通过代理访问 Google
curl -x http://127.0.0.1:7890 https://www.google.com -I
# 应该返回 HTTP/2 200

# 查看出口 IP（应该是代理节点的 IP）
curl -x http://127.0.0.1:7890 https://ipinfo.io/ip

# 不通过代理直接访问（应该超时）
curl https://www.google.com -I --connect-timeout 5
```

Q: 输出 "Connection refused" 怎么办？

A:
- Clash 没启动 → 启动 Clash
- 端口号错误 → 检查 config.yaml 中的 port
- 防火墙阻止 → 检查 iptables/nftables

## 7. git 使用代理

Q: git clone 很慢，怎么加速？

A:

### 全局配置

```bash
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890

# 查看配置
git config --global --get http.proxy

# 取消代理
git config --global --unset http.proxy
git config --global --unset https.proxy
```

### 只对 GitHub 配置

```bash
git config --global http.https://github.com.proxy http://127.0.0.1:7890
```

### 单次使用

```bash
git -c http.proxy=http://127.0.0.1:7890 clone https://github.com/user/repo
```

Q: git 配置了代理但还是慢？

A:
- 检查 Clash 是否运行：`ss -tlnp | grep 7890`
- 检查 git 代理配置：`git config --global --get http.proxy`
- 在 Clash Dashboard 切换延迟低的节点
- 大仓库加 depth 参数：`git clone --depth 1 https://github.com/...`

## 9. Clash 开机自启

Q: 怎么让 Clash 开机自动启动？

A:

### 方法 1：systemd user service

```bash
mkdir -p ~/.config/systemd/user

cat > ~/.config/systemd/user/clash.service << 'EOF'
[Unit]
Description=Clash Proxy Service
After=network.target

[Service]
Type=simple
ExecStart=/home/%u/clash/clash -d /home/%u/clash
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target
EOF

systemctl --user enable clash.service
systemctl --user start clash.service

# 开机自启需要启用 lingering
sudo loginctl enable-linger $(whoami)
```

### 方法 2：在 ~/.xinitrc 中启动

```bash
~/clash/clash -d ~/clash &
exec startplasma-x11
```

Q: 什么是 loginctl enable-linger？

A:
- 默认情况下，用户服务只在登录后运行，注销后停止
- `loginctl enable-linger` 让用户服务在系统启动时就开始运行
- 不启用的话，开机后必须先登录才能使用代理

## 11. 代理规则配置

Q: Clash 的 rules 是什么？怎么配置？

A:

```yaml
rules:
  # 国外网站走代理
  - DOMAIN-SUFFIX,google.com,Proxy
  - DOMAIN-SUFFIX,github.com,Proxy
  - DOMAIN-SUFFIX,telegram.org,Proxy

  # 国内网站直连
  - DOMAIN-SUFFIX,baidu.com,DIRECT
  - DOMAIN-SUFFIX,taobao.com,DIRECT
  - DOMAIN-SUFFIX,bilibili.com,DIRECT

  # 局域网直连
  - IP-CIDR,192.168.0.0/16,DIRECT
  - IP-CIDR,10.0.0.0/8,DIRECT

  # 其他走代理
  - MATCH,Proxy
```

Q: 规则的匹配顺序是什么？

A:
- 从上到下依次匹配，第一条匹配的规则生效
- MATCH 是兜底规则，匹配所有未命中前面规则的请求
- 国内网站直连规则放在前面，避免国内流量绕代理

## 12. 如何查询端口

Q: 怎么查看当前哪些端口被占用了？

A:

### 查看所有监听端口
```bash
# 查看所有 TCP 监听端口
ss -tlnp

# 输出示例：
# State   Recv-Q  Send-Q  Local Address:Port  Process
# LISTEN  0       128     127.0.0.1:7890      users:(("clash",pid=1234,fd=6))
# LISTEN  0       128     127.0.0.1:7891      users:(("clash",pid=1234,fd=7))
# LISTEN  0       128     127.0.0.1:9090      users:(("clash",pid=1234,fd=8))
# LISTEN  0       128     0.0.0.0:22          users:(("sshd",pid=567,fd=3))
```

### 查看特定端口
```bash
# 查看 7890 端口
ss -tlnp | grep 7890

# 查看多个端口
ss -tlnp | grep -E '7890|7891|9090'

# 查看所有代理相关端口
ss -tlnp | grep -E '789[0-9]|909[0-9]'
```

### 查看特定进程的端口
```bash
# 查看 clash 进程占用的端口
ss -tlnp | grep clash

# 查看 v2ray 进程占用的端口
ss -tlnp | grep v2ray

# 查看 sing-box 进程占用的端口
ss -tlnp | grep sing-box
```

### 使用 netstat（旧系统）
```bash
# 如果没有 ss，可以用 netstat
sudo pacman -S net-tools
netstat -tlnp | grep 7890
```

Q: 怎么找到代理工具的配置文件？

A:

| 工具 | 默认配置路径 |
|------|-------------|
| Clash | ~/clash/config.yaml |
| Clash Meta | ~/.config/clash-meta/config.yaml |

```bash
sudo updatedb
locate config.yaml | grep -E 'clash|v2ray|sing-box|trojan'
```

Q: 我不知道代理的端口号，怎么找出来？

A:

```bash
# 方法 1：查看配置文件
cat ~/clash/config.yaml | grep -E 'port:|socks-port:|external-controller:'

# 方法 2：查看所有监听端口，找代理相关的
ss -tlnp | grep -v "127.0.0.53" | grep -v "sshd"

# 方法 3：查看环境变量
env | grep -i proxy

# 方法 4：用 lsof 查看
sudo lsof -i -P -n | grep LISTEN | grep -E '789[0-9]|1080|9090'
```

Q: "SSL certificate problem" 怎么办？

A:

```bash
sudo timedatectl set-ntp true
# 或者换个节点
```

Q: Clash 能用但浏览器不能？

A:
- Mullvad Browser：确认 Clash 已启动

A:
- 同一时间只能有一个代理软件监听 7890 端口
- 检查：`ss -tlnp | grep 7890`
- 停止其他代理后再启动 Clash

Q: 代理设置了但 git clone 还是慢？

A:

```bash

git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890
```

## 15. 安全注意事项

Q: 用代理有什么安全风险？

A:
- 信任代理服务商：你的流量经过他们的服务器
- HTTPS 仍然加密：代理只能看到域名，看不到具体内容
- DNS 泄露：确保 DNS 也走代理
- WebRTC 泄露：浏览器可能泄露真实 IP

### 防止 DNS 泄露

```yaml
dns:
  enable: true
  nameserver:
    - 8.8.8.8
    - 1.1.1.1
  fallback:
    - tls://8.8.8.8:853
    - tls://1.1.1.1:853
```

### 防止 WebRTC 泄露

```
Firefox：about:config → media.peerconnection.enabled → false
```
