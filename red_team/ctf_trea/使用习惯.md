## 使用习惯 -- 做题方式的选择

> 前置知识：[[CTF简介|CTF 简介]] -- 先了解 CTF 是什么再来看本题

### 观点先行：做题最重要的是感觉

做题没有标准动作。真正决定解题速度的不是某个工具，而是**感觉**——看到题目后能否顺着自己的习惯一路顺畅地试下去。使用习惯很重要：顺手的方式决定思路是否流畅，硬用不顺手的方式只会卡壳。

> 工具无高下，只有合不合适。圈子里的真实共识是"用什么顺手用什么"，没有谁比谁高级。

### 使用习惯只有两种

做题时怎么操作，归根结底只有两种倾向：

| 习惯 | 特征 | 典型操作 |
|------|------|---------|
| 终端习惯 | 大部分问题终端解决、不离开键盘、能不用鼠标就不用鼠标 | `curl`、`nc`、`grep`、管道、SSH、脚本 |
| 图形化习惯 | 倾向于使用图形界面，看得到、点得到 | DevTools 控制台、Burp、Wireshark、IDA、网页交互操作 |

#### 终端习惯

倾向在终端里完成一切：请求用 `curl`（参数改头、Cookie 用 cookie jar、看原始报文），文件操作和远程用 SSH，逻辑用脚本跑。大部分浏览器管理操作在终端都有替代品：

| 浏览器操作 | 终端替代 |
|-----------|---------|
| 改请求方法/头/体 | `curl -X` / `-H` / `-d` / `-A` / `-e` |
| Cookie 管理 | `curl -c jar.txt`（存）`-b jar.txt`（带） |
| 看响应头/体 | `curl -D -` / `-I` / `-v` |
| JS 动态渲染页面 | 无头浏览器（playwright / puppeteer） |
| DevTools 控制台 | 逻辑复制到 node 里跑，或 `page.evaluate()` |

#### 图形化习惯

倾向用图形界面获得直观反馈：Web 题目用 DevTools 控制台调试，抓包用 Burp，流量分析用 Wireshark，逆向用 IDA/Ghidra，纯网页交互操作直接点在页面上。

### 两种习惯不互斥

不是只会一种。**必要时候会交叉使用**：终端解决不了或太费劲就切图形化，图形化太繁琐就切终端，怎么快怎么来。

### 通用能力：任何习惯都能用

有两类能力不归属任何习惯，无论平时用终端还是图形化，都应该掌握：

#### 脚本自动化

爆破、批量扫描、重复发包这类工作，靠手点或手敲永远做不完，脚本是唯一高效解。它是中立的：既可以在终端跑 python，也可以驱动图形化工具自动化。

#### AI 辅助

AI 是跨时代的工具，在哪里都能参与：生成 payload、写脚本、解释报错、还原逻辑。但**不要过分依赖**——它其实是最耗费时间且不一定出结果的，只能作为重复性工作的辅助，真正的判断和理解还得靠自己。参考本知识库的 [[../AI_come|AI_come]] 了解 AI 辅助渗透的实践。

### 核心观点：照着自己的喜好做

平时喜欢用终端，就不要勉强自己去用控制台；喜欢图形化界面，也不必强迫自己背命令。**照着自己的喜好做**，顺手才是效率。本知识库的教程、命令示例和练习都是终端为主，所以默认你走终端习惯——但最终以你自己舒服为准。

既然本知识库默认终端习惯，第一步就是掌握一些 Linux 终端指令。**在练中记忆，不用背诵**——用多了自然记住，背了不用很快忘光。
