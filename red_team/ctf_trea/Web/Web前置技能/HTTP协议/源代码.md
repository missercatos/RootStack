## 源代码 -- 题目解法

> 前置知识：[[HTTP协议|HTTP 协议基础]] -- 先了解 HTTP 协议基础再来看本题

### 题目描述

页面是一个贪吃蛇小游戏，看起来需要玩游戏才能拿 flag。但实际上 flag 就藏在响应包源码的 HTML 注释里，**根本不用玩**——把源码拉下来看一眼就到手了。

### 解法 1：curl 终端

**步骤：**

1. 直接请求页面，搜 flag 关键字：

```bash
curl -s http://目标/ | grep -o 'ctfhub{[^}]*}'
```

输出直接就是 flag。

2. 或者把响应体全拉下来看，肉眼找注释：

```bash
curl -s http://目标/
```

在输出中间就能看到 `<!-- ctfhub{...} -->`——一条 HTML 注释，浏览器渲染时不显示，但源码里明晃晃躺着。

> 关键点：`grep -o 'ctfhub{[^}]*}'` 用正则匹配 flag 格式，一行提取，不用肉眼扫。如果服务器返回的是 `flag{xxx}` 格式，改成对应的标志头即可。
>
> 陷阱：页面看起来是个正常的小游戏，JS 逻辑完整、Canvas 渲染正常——越像"正常页面"，越容易让人忘了看源码直接开始玩。**小游戏页面，第一步永远是拉源码**。

### 解法 2：浏览器 F12

**步骤：**

1. 打开页面，看到小游戏
2. 按 `Ctrl+U`（或右键"查看网页源代码"），直接搜索 `flag` / `ctfhub` / `{`
3. 找到注释中的 flag

> 也可以用 F12 → Element 面板直接定位。但注意 DevTools 的 Elements 面板是**解析后的 DOM**，某些注入的注释可能被过滤；按 `Ctrl+U` 看的是**原始响应源码**，不会漏。

### 原理精讲 -- 为什么 flag 可以藏在源码里？

#### 服务器响应的本质

浏览器把服务器返回的 HTML 解析成 DOM 树再渲染到屏幕上。但**服务器返回的原始文本**里，有很多东西是不上屏的：

```html
<!-- HTML 注释：浏览器不显示 -->      ← flag 可能藏这里
<script>var key = "abc123"</script>   ← flag 可能在 JS 变量里
<style>/* CSS 注释 */</style>         ← flag 可能在 CSS 里
<input type="hidden" value="xxx">     ← 隐藏表单字段
<meta name="flag" content="xxx">      ← meta 标签
```

浏览器渲染一个"正常页面"给用户看，但这些**上屏之外的文本**，全都在源代码里可读。

#### 为什么是小游戏页面？

不是巧合。小游戏页面：
- 有足够长的 JS 代码和 Canvas 逻辑，让页面看起来"很正经"
- 用可交互的操作（按键、鼠标）吸引注意力
- 你忙着玩游戏的时候，不会想到去看源码

这本质上是一个**注意力引导**——页面把玩家的视线引到游戏上，flag 躺在源码里没人看。源代码题的另一面是"会玩的页面更容易让人忘了看源码"。

#### 服务器逻辑

根本不存在复杂的服务器逻辑。页面就是一个静态 HTML，里面写了 HTML 注释 `<!-- ctfhub{...} -->`。nginx 负责直接返回这个文件，没有任何 PHP 参与。

### 常见藏匿位置

| 藏匿位置 | 终端查找方式 |
|---------|------------|
| HTML 注释 | `curl -s URL \| grep -E '<!--.*flag'` |
| JS 变量 / 字符串 | `curl -s URL \| grep -Eo '(flag\|ctfhub)\{[^}]+\}'` |
| 响应头 | `curl -s -D - URL \| grep -i flag` |
| 隐藏 input | `curl -s URL \| grep -E 'type="hidden"'` |
| meta 标签 | `curl -s URL \| grep -E '<meta.*flag'` |
| CSS 注释 / 伪类 | `curl -s URL \| grep -E '/\*.*flag'` |
| 大段 base64 内容 | base64 解码后搜 flag |
| 路径引用（图片/css/js 文件名） | 看 src/href 里有没有可疑文件名 |

### 核心知识点总结

| 概念 | 说明 |
|------|------|
| 响应包源代码 | 服务器返回的**原始 HTML/JS/CSS 文本**，浏览器不做修改 |
| 渲染 vs 源码 | 浏览器渲染页面时过滤掉注释；源码里注释、JS、style 都在 |
| HTML 注释 | `<!-- 内容 -->`，是源码题最常见的 flag 藏匿位 |
| 查看源码 | `Ctrl+U`（浏览器原始源码）、`curl -s`（终端原始响应） |
| 动态/交互页面 | 越像"正常应用"越容易让人忽略源码检查 |
| `grep -o` | `-o` 只输出匹配部分，适合直接提取 flag |
