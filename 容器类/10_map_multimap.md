STL 容器教程 — map & multimap (有序映射)
## ==========================================================================

## 本章概述

`map` 是基于**红黑树**的键值对容器：每个元素是一个 `pair<const Key, Value>`，按 **key 自动升序排列**，key 唯一。插入、查找、删除都是 O(log n)。它和 `unordered_map` 最核心的差异是：**map 有序**，并因此支持 `lower_bound` / `upper_bound` 范围查询。`multimap` 与 map 几乎相同，但**允许重复 key**。

本章采用手把手渐进式教学，每一步只提示该用哪个函数、要避开哪些陷阱，**代码请自己动手敲**，敲完编译看输出。

> 底层数据结构详解：红黑树的旋转、变色、平衡维护等原理见 [[数据结构/E_红黑树_RedBlackTree]]。本章侧重容器使用。

## --------------------------------------------------------------------------
### 适用场景与优劣分析
## --------------------------------------------------------------------------

| 优点 | 缺点 |
|:------|:------|
| 遍历自动按 key 升序，无需额外排序 | 单次操作 O(log n)，比哈希表的 O(1) 慢 |
| 支持 lower_bound / upper_bound 范围查询 | 内存有红黑树节点指针开销 |
| 最坏复杂度稳定 O(log n)，不会被卡 | key 必须可比较（需 `<` 或比较器） |
| 迭代器在插入/删除后仍有效（除被删者外） | 缓存不友好，常数比哈希表大 |

**适用场景：**

| 场景 | 说明 |
|:------|:------|
| 需要有序遍历的字典 | 按 key 升序输出统计结果 |
| 频率/计数统计 | `map<string,int>` 统计单词出现次数 |
| 离散化 | 大范围坐标映射到小范围下标 |
| 范围查询 | 找"第一个 ≥ k 的 key"等前驱后继问题 |

**map vs unordered_map：**

| | map | unordered_map |
|:----|:-----|:---------------|
| 底层 | 红黑树 | 哈希表 |
| 插入/查找 | O(log n) | O(1) 均摊 |
| 有序 | 是（按 key 升序） | 否 |
| 范围查询 | 支持 lower_bound/upper_bound | 不支持 |
| 内存 | 较小 | 较大 |

**选 map**：需要有序遍历或范围查询，或 O(log n) 足够。
**选 unordered_map**：纯查找不需要顺序，追求 O(1)。

## --------------------------------------------------------------------------
### 第一步：创建容器
## --------------------------------------------------------------------------

> 自己动手 1
> - 包含头文件 `<map>`。
> - 声明一个 key 为 `int`、value 为 `string` 的空 map，例如 `std::map<int, std::string> m;`。
> - 想要降序时可写 `std::map<int, std::string, std::greater<int>> m2;`。
> - 陷阱：自定义类型作 key 时必须能比较——重载 `operator<` 或提供比较器，否则编译失败。

## --------------------------------------------------------------------------
### 第二步：size() 与 empty()
## --------------------------------------------------------------------------

| 函数 | 作用 | 返回值 |
|:------|:------|:------|
| `size()` | 返回键值对数量 | `size_t` |
| `empty()` | 判断是否为空 | `bool` |

> 自己动手 2
> - 对空 map 调用 `m.size()`（应为 0）和 `m.empty()`（应为 true）。

## --------------------------------------------------------------------------
### 第三步：插入元素（多种方式对比）
## --------------------------------------------------------------------------

| 方式 | 写法 | key 已存在时 | 说明 |
|:------|:------|:------|:------|
| `operator[]` | `m[k] = v` | **覆盖**旧 value | key 不存在时会先默认构造再赋值 |
| `insert` | `m.insert({k, v})` | **不覆盖**，插入失败 | 返回 `pair<iterator, bool>` |
| `emplace` | `m.emplace(k, v)` | 不覆盖 | 原位构造，C++11 |
| `insert_or_assign` | `m.insert_or_assign(k, v)` | **覆盖** | 语义明确，C++17 |
| `try_emplace` | `m.try_emplace(k, v)` | 不覆盖、不构造 value | 避免无谓构造，C++17 |

> 自己动手 3
> - 用 `m[1] = "a";` 插入第一对，用 `m.insert({2, "b"});` 插入第二对。
> - 再用 `m.insert({1, "x"});` 试图覆盖 key=1，接住返回值的 `.second`，观察它为 `false`（插入失败，没覆盖）。
> - 改用 `m[1] = "x";` 或 `m.insert_or_assign(1, "x");` 才能真正覆盖。
> - 陷阱：`operator[]` 在 key 不存在时会**自动插入默认值**，这是经典副作用，仅查询时别误用它。

## --------------------------------------------------------------------------
### 第四步：判断 key 是否存在
## --------------------------------------------------------------------------

| 函数 | 作用 | 注意 |
|:------|:------|:------|
| `count(k)` | key 出现次数（map 中 0 或 1） | 不产生副作用 |
| `contains(k)` | C++20 直接返回 `bool` | 最直观 |
| `find(k)` | 返回迭代器 / `end()` | 找到后还能继续操作 |

> 自己动手 4
> - 用 `m.count(1)` 判断 key=1 是否存在。
> - 陷阱：**绝不要**用 `if (m[k])` 判断存在——`operator[]` 会把不存在的 k 插入进去（副作用）。判断存在只用 `count` / `find` / `contains`。

## --------------------------------------------------------------------------
### 第五步：访问/读取 value
## --------------------------------------------------------------------------

| 方式 | 写法 | key 不存在时 | 适用 |
|:------|:------|:------|:------|
| `operator[]` | `m[k]` | 插入默认值再返回 | 确定 key 存在或本就想插入时 |
| `at(k)` | `m.at(k)` | 抛出 `out_of_range` 异常 | 只读且想要"不存在即报错" |
| `find(k)` | `m.find(k)->second` | 返回 `end()`，需先判断 | 安全读取，不产生副作用 |

> 自己动手 5
> - 用 `auto it = m.find(1);`，判断 `it != m.end()` 后用 `it->second` 取出 value。
> - 重点：map 的迭代器解引用得到 `pair`，key 是 `it->first`，value 是 `it->second`。
> - 陷阱：`m.at(不存在的key)` 抛异常；`m[不存在的key]` 偷偷插入默认值。安全只读首选 `find`。

## --------------------------------------------------------------------------
### 第六步：修改 value
## --------------------------------------------------------------------------

value 是可以改的，但 **key 不可改**（元素类型是 `pair<const Key, Value>`，key 带 const）。

> 自己动手 6
> - 用 `m[1] = "new";` 或 `m.insert_or_assign(1, "new");` 修改已有 key 的 value。
> - 也可通过迭代器：`it->second = "new";`。
> - 陷阱：不能写 `it->first = 99;`，key 是 const 改不了。要改 key 只能 erase 旧的再 insert 新的。

## --------------------------------------------------------------------------
### 第七步：删除元素
## --------------------------------------------------------------------------

| 删除方式 | 写法 | 返回 | 说明 |
|:------|:------|:------|:------|
| 按 key 删除 | `m.erase(k)` | 删除个数（0 或 1） | 删不存在的 key 返回 0，安全 |
| 按迭代器删除 | `m.erase(it)` | 下一个迭代器 | 需先 `find` |
| 按区间删除 | `m.erase(first, last)` | 下一个迭代器 | 删除 `[first, last)` |

> 自己动手 7
> - 用 `m.erase(2)` 按 key 删除，接住返回值看是否删成功。
> - 陷阱：`erase(it)` 后 `it` 失效；遍历中删除要用返回的新迭代器（`it = m.erase(it);`）。

## --------------------------------------------------------------------------
### 第八步：遍历（多种方式 + 对比 + 推荐）
## --------------------------------------------------------------------------

map 遍历**保证按 key 升序**——这是与 unordered_map 的核心差异。

| 方式 | 写法 | 性能 | 推荐度 |
|:------|:------|:------|:------|
| 结构化绑定（C++17） | `for (const auto& [k, v] : m)` | 零拷贝 | 最推荐，只读 |
| 结构化绑定可改 value | `for (auto& [k, v] : m)` | 零拷贝 | 需在遍历中改 value 时 |
| `const auto&` | `for (const auto& p : m)` 用 `p.first/p.second` | 零拷贝 | 通用只读 |
| 迭代器 | `for (auto it = m.begin(); it != m.end(); ++it)` 用 `it->first/it->second` | 零拷贝 | 需边遍历边删除时 |
| `auto` 值拷贝 | `for (auto p : m)` | 每次拷贝 pair | 不推荐 |

**推荐**：只读用 `const auto& [k, v]`，改 value 用 `auto& [k, v]`，边遍历边删用迭代器。

> 自己动手 8
> - 插入若干乱序 key（如先插 3 再插 1 再插 2），用 `for (const auto& [k, v] : m)` 遍历打印。
> - 重点：观察输出一定是 key 升序（1,2,3），无论插入顺序如何——这就是 map 有序的体现。

## --------------------------------------------------------------------------
### 第九步：清空容器
## --------------------------------------------------------------------------

> 自己动手 9
> - 用 `m.clear()` 清空，再用 `size()`（0）和 `empty()`（true）验证。

## --------------------------------------------------------------------------
### 特色操作：lower_bound / upper_bound 范围查询
## --------------------------------------------------------------------------

这是 map 相对 unordered_map 的**独有优势**：因为有序，可以做范围查询。

| 函数 | 作用 | 返回 |
|:------|:------|:------|
| `lower_bound(k)` | 第一个 key **≥ k** 的迭代器 | 迭代器 / `end()` |
| `upper_bound(k)` | 第一个 key **> k** 的迭代器 | 迭代器 / `end()` |
| `equal_range(k)` | 返回 `pair<lower_bound, upper_bound>` | pair |

> 自己动手（重要）
> - 在 `map<int,int>` 中插入 key 为 10、20、30，用 `m.lower_bound(15)` 找第一个 ≥ 15 的 key（应指向 20）。
> - 用 `prev(m.lower_bound(k))` 求"前驱"（小于 k 的最大 key），注意先判断不是 `begin()` 以免越界。
> - 陷阱：`lower_bound` 是 ≥（含等于），`upper_bound` 是 >（不含等于），别记反。

## --------------------------------------------------------------------------
### 补充：multimap（允许重复 key）
## --------------------------------------------------------------------------

| | `map` | `multimap` |
|:-----|:-------|:-------|
| key 唯一性 | 唯一 | 允许重复 |
| `operator[]` / `at` | 有 | **无**（一个 key 多个值，无法确定返回哪个） |
| `count(k)` | 0 或 1 | 可大于 1 |
| 取同一 key 的所有值 | 不适用 | `equal_range(k)` 遍历 |

> 自己动手（选做）
> - 创建 `multimap<int,string> mm;`，对 key=1 插入两条不同 value，用 `mm.count(1)` 验证为 2。
> - 陷阱：multimap 没有 `operator[]` 和 `at`，访问只能用迭代器 / `equal_range`。

> [!question] 练习题 1
> **题目**: 输入一段英文文本（一行），统计每个单词出现的次数，按字典序输出单词及其次数。使用 map 实现。
>
> **输入示例**:
> ```
> the cat sat on the mat the cat
> ```
> **输出示例**:

> cat 2
> mat 1
> on 1
> sat 1
> the 3
> ```

> **题目**: 实现一个简单的电话簿系统，支持：1) 添加联系人（姓名→电话）；2) 按姓名查找电话；3) 删除联系人；4) 按姓名字典序列出所有联系人。使用 map 实现。
>
> **输入示例**:

> 6
> 1 Alice 12345
> 1 Bob 67890
> 2 Alice
> 3 Bob
> 4
> 2 Bob
> ```

> ```

> [!question] 练习题 3

> ```
