# 02 对象存储

> **对象存储（Object Storage）** 是面向"海量非结构化数据"的云存储：用 **HTTP API** 存取，天然可扩展、易用、便宜（按量）。代表是 **AWS S3** 及其兼容服务（阿里 OSS、腾讯 COS、MinIO 等）。

## 一、核心概念

| 概念 | 含义 |
|------|------|
| **Bucket** | 桶，存放对象的容器 |
| **Object** | 对象，即"文件 + 元数据 + 键" |
| **Key** | 对象的唯一名字（类似路径） |
| **Endpoint** | 服务访问地址 |
| **Access Key / Secret** | 访问凭证 |

- 没有真正的目录树，**用 `/` 前缀模拟层级**。
- 对象**不可部分修改**（要改就整个重传，或分片上传新版本）。

---

## 二、对比传统文件系统

| | 对象存储 | 文件系统 |
|--|:--------:|:--------:|
| 接口 | HTTP/S3 API | POSIX 文件操作 |
| 结构 | 扁平 bucket | 目录树 |
| 修改 | 整体替换 | 随机改 |
| 扩展 | 近乎无限 | 有限 |
| 场景 | 图片/视频/备份/网站 | 通用文件 |

---

## 三、典型用途

- 网站/App 的**静态资源**（图片、视频、附件）。
- **备份与归档**（配合生命周期转冷）。
- **大数据**输入输出。
- **K8s 持久化**（MinIO/Ceph RGW）。
- 跨地域内容分发（配合 CDN）。

---

## 四、成本模型（重要）

对象存储费用 = **存储费 + 流量费 + 请求费**：

| 项 | 说明 |
|----|------|
| 存储 | 按 GB/月，越冷越便宜 |
| **流量（下行/外网）** | **常是最大开销**，注意计费 |
| 请求 | 按次数（PUT/GET） |
| 生命周期 | 自动转冷/删除，省钱 |

> 上传通常免费，**下载/外网流出很贵**——用前先算清。

## 其他问题（Q&A）

**Q1：对象存储能像网盘一样用吗？**
A：能（很多网盘底层就是对象存储），但**没有原生文件浏览体验**，需客户端/S3 浏览器。

**Q2：MinIO 和 S3 什么关系？**
A：MinIO 是**兼容 S3 API** 的开源对象存储，可自建，接口与 S3 一致。

**Q3：对象存储适合放数据库吗？**
A：不适合（延迟/无随机改）；它适合**大文件、海量小文件、备份**。

**Q4：为什么很多人"被对象存储账单"吓到？**
A：**外网流量费 + 请求费**。用 CDN、生命周期策略、内网访问可大幅降本。

**Q5：如何保证对象存储里的数据安全？**
A：**版本控制 + 生命周期 + 加密 + 权限策略**；并遵守"多副本"原则。
