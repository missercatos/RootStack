# 策略与实践

> 一个好的备份体系要回答四个问题：**备什么？备到哪？多久备一次？怎么验证能恢复？** 本篇给出可落地的策略与工具。

---

## 一、设计备份策略

| 问题 | 建议 |
|------|------|
| 备什么 | 重要数据/配置/密钥；操作系统可重装则不必全备 |
| 备到哪 | 本地(快) + 异地云(容灾)，至少 2 份 |
| 频率 | 关键数据每日；冷数据每周/每月 |
| 保留 | 保留多代（如 7 天/4 周/12 月），防"悄悄损坏" |
| 验证 | **定期恢复演练** + 校验和 |

---

## 二、备份类型

| 类型 | 说明 |
|------|------|
| 全量 | 每次全备，费空间 |
| 增量 | 备变化，快但依赖链 |
| 差异 | 备自上次全量以来的变化 |
| 镜像/克隆 | 整盘可引导克隆 |
| **快照** | 时间点副本（本地/存储层） |

---

## 三、常用工具

| 工具 | 特点 |
|------|------|
| **restic** | 去重、加密、多后端（本地/S3/SFTP） |
| **borg** | 去重、压缩、加密 |
| Duplicati | 图形化、多后端 |
| rclone | 云盘/对象存储同步与挂载 |
| 云厂商备份服务 | 与云平台集成 |
| Clonezilla | 整盘镜像 |

---

## 四、冷归档与生命周期

- 对象存储可设**生命周期规则**：如"30 天后转低频、90 天后转归档、3 年后删除"。
- 归档层**取回慢、可能收费**，适合"几乎不读、但要留着"的数据。
- 归档也要**多副本 + 定期抽检**。

---

## 五、成本与恢复演练

- 费用 = 存储 + 流量（尤其外网下行）+ 请求 + 取回。
- **上传便宜、下载贵**；用 CDN/内网可降本。
- **每季度做一次恢复演练**：从备份还原一个文件/整机，验证可用。

---

## 其他问题（Q&A）

**Q1：只做本地备份行不行？**
A：不够。火灾/被盗/勒索会团灭。要有**异地/离线**副本。

**Q2：备份多久做一次合适？**
A：按"你能接受丢多少数据（RPO）"定。关键数据每日甚至实时。

**Q3：怎么防备份本身坏了？**
A：**多代保留 + 校验和 + 抽检恢复**；别只留最新一份。

**Q4：能不能只靠 RAID 当备份？**
A：不能。RAID 防盘坏，不防误删/病毒。

**Q5：备份和快照什么关系？**
A：快照是"某一刻的只读视图"，恢复快；但它常在同一存储上，**仍需异地备份**。
