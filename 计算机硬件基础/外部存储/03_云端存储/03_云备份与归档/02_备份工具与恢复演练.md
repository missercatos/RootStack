# 备份工具与恢复演练

> 云备份落地的关键是**工具选型**与**真的能恢复**。本篇给出常用工具与脚本化实践，并强调恢复演练。

---

## 一、工具选型

| 工具 | 适合 | 特点 |
|------|------|------|
| **restic** | 个人/团队 | 去重、加密、多后端(S3/SFTP/本地) |
| **borg** | 单机/服务器 | 去重、压缩、快 |
| **rclone** | 上云 | 多云同步/挂载 |
| **Duplicati** | 图形化 | 多后端、易用 |
| **rsync** | 简单增量 | 脚本化、通用 |
| ZFS/Btrfs 快照 | 存储层 | 时间点副本 |
| Clonezilla | 整机 | 裸机镜像 |

---

## 二、restic 最小示例

```bash
export RESTIC_PASSWORD='强密码'
restic -r s3:s3.example.com/bucket init        # 初始化仓库
restic -r s3:... backup /home /etc             # 备份
restic -r s3:... snapshots                     # 看快照
restic -r s3:... restore latest --target /restore   # 恢复
restic -r s3:... check --read-data             # 校验数据完整性
```

> restic 支持去重+加密，适合把"一份异地副本"放到对象存储。

---

## 三、脚本化与自动化

```bash
#!/usr/bin/env bash
set -e
export RESTIC_REPOSITORY=s3:...
export RESTIC_PASSWORD_FILE=/root/.restic_pass
restic backup /data /home --exclude-caches
restic forget --keep-daily 7 --keep-weekly 4 --keep-monthly 12 --prune
restic check
```

- 用 **systemd timer / cron** 定时执行。
- 备份完发通知（邮件/webhook）便于发现失败。
- **保留策略**用 `forget --keep-*`。

## 四、恢复演练（必做）

```text
每月: 还原一个文件, 校验内容
每季: 还原一个目录/数据库, 启动验证
每年: 从零重建一台机器
```

> 记录**恢复步骤文档**，并让第二个人也能照做。

## 其他问题（Q&A）

**Q1：备份要加密吗？**
A：异地/云备份**务必加密**（restic/borg 默认支持）。

**Q2：备份失败怎么及时发现？**
A：让脚本**失败即通知**，并监控"最近一次成功时间"。

**Q3：备份频率与保留怎么定？**
A：按 RPO 定频率；保留用 GFS（日/周/月）。

**Q4：备份会不会很占带宽？**
A：用增量/去重，只传变化；可限速（`--limit-upload`）。

**Q5：对象存储 + restic 是常见组合吗？**
A：非常常见，成本低且异地，推荐。
