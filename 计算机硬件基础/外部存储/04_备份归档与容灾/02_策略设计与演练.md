# 策略设计与演练

> 备份方案的价值在"**恢复成功**"那一刻才兑现。本篇给可落地的策略模板、工具选择与演练方法。

---

## 一、设计四步

```text
1. 盘点资产: 哪些数据/配置/密钥重要, 优先级
2. 定目标:   RPO(能丢多少) / RTO(能停多久)
3. 选方案:   本地+异地+离线, 保留多代
4. 定验证:   定期恢复演练 + 校验和
```

---

## 二、常用工具

| 工具 | 特点 |
|------|------|
| restic / borg | 去重、加密、多后端、快照式 |
| rclone | 云盘/对象存储同步、挂载 |
| rsync | 简单增量、脚本化 |
| Duplicati | 图形化、多后端 |
| ZFS/Btrfs 快照 | 存储级时间点副本 |
| Clonezilla | 整盘镜像 |
| 云备份服务 | 与云平台集成 |

---

## 三、保留策略（轮转）

- 常见 **GFS**：日备保留 7 份、周备 4 份、月备 12 份。
- 或"祖父-父-子"轮转，控制空间同时保留历史。
- **保留多代**是防"悄悄损坏/迟发现"的关键。

---

## 四、恢复演练（最重要）

| 演练 | 频率 |
|------|------|
| 还原单个文件 | 每月 |
| 还原整个目录/数据库 | 每季度 |
| 整机/系统重建 | 每半年/年 |

> 没演练过的备份 = **薛定谔的备份**。

---

## 五、成本与优化

- 费用 = 存储 + 流量（下行贵）+ 请求 + 取回（归档）。
- 优化：CDN、内网、生命周期降冷、去重压缩。
- **别为省小钱牺牲"能恢复"**。

---

## 其他问题（Q&A）

**Q1：备份要保留多久？**
A：取决于价值与合规；至少多代（如 7 日 + 4 周 + 12 月）。

**Q2：备份文件要校验吗？**
A：要。用哈希/校验和，定期抽检，防"备份本身损坏"。

**Q3：备份占空间太大怎么办？**
A：用去重/增量/压缩（restic/borg），并做生命周期管理。

**Q4：怎么防止"备份被一起加密"？**
A：离线/不可变备份 + 备份账号最小权限 + 多副本。

**Q5：同一份数据要备几处？**
A：遵循 3-2-1；关键数据 3-2-1-1-0。
