# 多路径与高可用

> SAN 的价值之一是**高可用**：通过多路径、多控制器、集群文件系统，让"存储/链路坏一条"也不影响业务。本篇讲这些机制。

---

## 一、为什么要多路径（MPIO）

```text
主机HBA1 ──交换机1── 存储控制器A
主机HBA2 ──交换机2── 存储控制器B
        (同一 LUN 的两条路)
```

- 任一链路/控制器故障，仍有另一条可用。
- 还能**负载均衡**，提高吞吐。

| 模式 | 说明 |
|------|------|
| 主备（Active/Passive） | 一条用、一条待命 |
| 主主（Active/Active） | 两条都用、负载均衡 |

---

## 二、iSCSI 多路径实践（Linux）

```bash
# 装 multipath-tools 后配置 /etc/multipath.conf
systemctl enable --now multipathd
multipath -ll          # 查看聚合后的多路径设备
# 使用 /dev/mapper/mpathX 而不是 /dev/sdX
```

---

## 三、集群共享文件系统

多台主机同时读写同一块 SAN 存储，需要**集群文件系统**：

| 系统 | 平台 |
|------|------|
| GFS2 / OCFS2 | Linux |
| VMFS | VMware |
| NTFS Cluster | Windows |

> 普通文件系统（ext4）**不能**被多主机同时挂载写，否则损坏。

---

## 四、高可用要点

| 要点 | 说明 |
|------|------|
| 双控制器 | 存储阵列冗余 |
| 双交换机 | FC 双 Fabric |
| 双 HBA | 主机冗余 |
| 多路径 | 链路冗余/均衡 |
| 快照/复制 | 数据级保护 |

## 其他问题（Q&A）

**Q1：多路径和 RAID 有什么区别？**
A：RAID 是**盘级冗余**；多路径是**链路/控制器冗余**。互补。

**Q2：为什么不能两台机器同时挂 ext4？**
A：ext4 无集群锁，同时写会**损坏数据**。用集群文件系统或只让一台写。

**Q3：iSCSI 断网后会自动恢复吗？**
A：多路径 + 自动重连通常能恢复；应用要能容忍短暂 I/O 等待。

**Q4：SAN 高可用成本高吗？**
A：高（双份交换机/HBA/控制器），所以多用于关键业务。
