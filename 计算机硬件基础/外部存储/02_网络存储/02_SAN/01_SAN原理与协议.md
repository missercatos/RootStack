# SAN 原理与协议

> 理解 SAN 只需抓住一句话：**它给主机一块"网络上的裸磁盘"**。主机在上面自建文件系统，性能与灵活性接近本地盘，但可集中管理、远距离扩展。

---

## 一、工作流程

```text
服务器(HBA) ──FC/iSCSI──> SAN 交换机 ──> 存储阵列 ──> 磁盘
                                ↑
                          通过 LUN 映射给主机
```

1. 存储阵列划分 LUN；
2. 通过 **LUN Masking/Zoning** 把 LUN 映射给指定主机；
3. 主机把自己那块 LUN 当成 `/dev/sdX` 一样使用。

---

## 二、关键技术

| 技术 | 作用 |
|------|------|
| **Zoning** | FC 中隔离端口，控制谁能看到谁 |
| **LUN Masking** | 把 LUN 只暴露给授权主机 |
| **多路径（MPIO）** | 多链路冗余与负载均衡 |
| **Snapshot/Clone** | 存储级快照与克隆 |
| **Thin Provisioning** | 按需分配，节省空间 |

---

## 三、iSCSI 快速上手（Linux）

```bash
# 客户端发现并登录 iSCSI 目标
iscsiadm -m discovery -t sendtargets -p <nas-ip>:3260
iscsiadm -m node -T <target-iqn> -p <nas-ip>:3260 --login
lsblk                 # 会多出一块"本地磁盘"
# 之后按普通磁盘分区格式化即可
```

## 其他问题（Q&A）

**Q1：iSCSI 盘和本地盘一样用吗？**
A：基本一样（可分区/格式化/挂载）；但**依赖网络**，断网会掉盘。

**Q2：为什么 SAN 更贵更难？**
A：专用硬件/交换网络、多路径、运维复杂度都高，但换来高性能与集中管理。

**Q3：SAN 的"块"和文件的区别？**
A：**块**是无结构的扇区集合，主机自己建文件系统；**文件**是已组织好的目录结构。前者灵活、性能高，后者方便共享。

**Q4：虚拟化为什么爱用 SAN？**
A：虚拟机磁盘就是"块"，集中存放便于迁移、快照、高可用。
