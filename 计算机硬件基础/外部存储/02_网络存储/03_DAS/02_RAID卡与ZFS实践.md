# RAID 卡与 ZFS 实践

> DAS 本身不提供冗余，冗余来自**主机的 RAID 卡**或**ZFS/mdadm**。本篇比较这两种做法，给出选择建议。

---

## 一、两条路线

| | 硬件 RAID 卡 | 软件 RAID / ZFS |
|--|:------------:|:---------------:|
| 性能 | 有缓存/电池，强 | 耗 CPU/内存 |
| 迁移 | 换卡可能丢阵列 | 盘可换机读 |
| 功能 | 硬件加速、BBU | 快照/校验/压缩/去重 |
| 成本 | 卡贵 | 免费 |
| 推荐 | 传统企业 | 自建/新方案 |

---

## 二、硬件 RAID 要点

| 要点 | 说明 |
|------|------|
| **BBU/缓存** | 断电保护写缓存，防丢失 |
| 写策略 | Write-Back 快、Write-Through 稳 |
| 阵列迁移 | 尽量同型号卡 |
| 监控 | 硬盘/电池健康告警 |

---

## 三、ZFS 要点

```bash
# 创建镜像池（RAID1）
zpool create tank mirror /dev/sda /dev/sdb
zfs create tank/data
zfs set compression=lz4 tank/data
zfs snapshot tank/data@2026-09-30
zpool status                  # 查看健康
zpool scrub tank              # 校验/修复
```

| 能力 | 说明 |
|------|------|
| 校验和 | 检测并修复静默损坏 |
| 快照 | 便宜、即时 |
| 压缩/去重 | 省空间（去重吃内存） |
| RAIDZ | 类 RAID5/6，但更可靠 |

---

## 四、选择建议

| 场景 | 建议 |
|------|------|
| 家用/自建 | **ZFS**（RAIDZ/镜像） |
| 企业传统 | 硬件 RAID + BBU |
| 既要又要 | 硬件 RAID 管盘 + 文件系统快照 |

---

## 其他问题（Q&A）

**Q1：ZFS 要多少内存？**
A：越大越好（ARC 缓存）；开启去重要谨慎（内存开销大）。

**Q2：RAID 卡电池坏了要紧吗？**
A：要紧——写缓存失去保护，掉电可能丢数据；及时更换。

**Q3：能不能混用硬件卡和 ZFS？**
A：可以（卡直通盘给 ZFS），但更推荐 **HBA 直通 + ZFS**。

**Q4：DAS 扩容要注意什么？**
A：RAID 扩容耗时且有风险，先备份；ZFS 加 vdev 更灵活。
