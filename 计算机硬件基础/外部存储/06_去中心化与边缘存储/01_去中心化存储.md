# 去中心化存储

> **去中心化存储**把数据切分/加密后分散到大量节点，用**内容寻址 + 激励**保证可用。代表：IPFS（内容寻址）、Filecoin（激励层）、Swarm、Storj、Arweave（永久存储）。

---

## 一、核心思想

```text
文件 → 分片/加密 → 分散到众多节点
读取 → 内容哈希(CID)定位 → 从持有者取回并校验
```

| 概念 | 含义 |
|------|------|
| **内容寻址** | 用内容哈希（如 CID）标识，而非 IP/路径 |
| **分片** | 数据切块分散存放 |
| **冗余/纠删码** | 丢失部分节点仍可恢复 |
| **pin** | 把数据固定在本地/某节点以免被回收 |
| **激励层** | 代币激励节点提供存储/带宽 |

---

## 二、代表项目

| 项目 | 定位 |
|------|------|
| IPFS | 内容寻址分发协议 |
| Filecoin | 建立在 IPFS 上的存储市场 |
| Arweave | 一次性付费的永久存储 |
| Swarm | 以太坊生态去中心化存储 |
| Storj/Chia 等 | 分布式存储网络 |

---

## 三、优点与代价

| 优点 | 代价 |
|------|------|
| 抗单点/抗审查 | 延迟与可用性参差 |
| 数据可校验 | 需 pin/付费才长期保存 |
| 无中心信任 | 隐私/合规复杂 |
| 潜在低成本 | 生态与工具不成熟 |

---

## 其他问题（Q&A）

**Q1：IPFS 和 BT 有什么区别？**
A：IPFS 是**内容寻址**的通用分发层（可用 CID 持久引用），BT 更偏临时 swarm 下载。

**Q2：上传到 IPFS 就一定永久保存吗？**
A：不。没人 **pin** 就可能被回收；要长期保存需 pinning 服务或激励网络。

**Q3：敏感数据能放去中心化存储吗？**
A：务必**客户端加密**；内容寻址的哈希本身可能泄露信息（已知明文攻击）。

**Q4：适合什么场景？**
A：抗审查发布、NFT/链上元数据、众筹存储；不适合低延迟强一致的业务。
