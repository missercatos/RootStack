# 边缘存储与 CDN

> **边缘存储**把数据/缓存放到"离用户或设备最近"的地方，降低延迟、节省回源带宽。**CDN**（内容分发网络）是最成熟的形态；**边缘计算**则把计算也下沉到边缘。

---

## 一、为什么要边缘

| 问题 | 边缘的价值 |
|------|-----------|
| 距离远 → 延迟高 | 就近取数 |
| 回源流量贵 | 就近缓存 |
| 源站压力大 | 分流 |
| 设备离线/弱网 | 边缘暂存 |

---

## 二、CDN 工作原理

```text
用户 → 就近边缘节点(有缓存?) 
         ├─ 命中 → 直接返回(快)
         └─ 未命中 → 回源站取 → 缓存 → 返回
```

| 概念 | 说明 |
|------|------|
| 边缘节点 | 分布各地的缓存服务器 |
| 回源 | 缓存没有时回源站取 |
| 缓存失效 | TTL、主动刷新 |
| 动态加速 | 优化回源链路 |

---

## 三、边缘存储/计算

- **边缘缓存**：把对象存储 + CDN 组合，既便宜又近。
- **边缘计算**：在边缘节点跑函数（如 Cloudflare Workers），减少往返。
- **IoT 边缘**：设备侧/网关暂存与预处理。

---

## 四、注意

- CDN 面向**可公开分发**的内容；**敏感/私有数据不要走 CDN 缓存**。
- 缓存刷新有延迟，更新内容要注意 TTL。
- 回源流量与请求计费要算清。

---

## 其他问题（Q&A）

**Q1：CDN 能加速所有内容吗？**
A：主要加速**静态/可缓存**内容；动态内容靠优化回源链路。

**Q2：CDN 和对象存储什么关系？**
A：对象存储做**源站**，CDN 做**边缘缓存**，是经典组合。

**Q3：边缘存储会丢数据吗？**
A：边缘通常是**缓存/临时层**，权威数据仍在中心/对象存储。

**Q4：怎么防止 CDN 缓存泄露私有数据？**
A：设置私有缓存策略、鉴权 URL、不缓存敏感响应。
