# 分区、文件系统与格式化

> 一块 U 盘要能用，需要**分区表**（描述"这块盘怎么划分"）和**文件系统**（描述"分区里怎么放文件"）。选错了，会出现"放不下大文件""别的系统读不出""启动不了"等问题。本篇讲清它们的原理与选择。

---

## 一、为什么需要分区

裸设备只是一堆可寻址的扇区。要装文件，必须先：

1. **建分区表**：告诉系统"这块盘分成几个区、每个区从哪到哪"；
2. **建文件系统**：在每个分区里建立目录、文件、空闲空间等结构；
3. **挂载**：把分区挂到目录树，才能访问文件。

---

## 二、分区表：MBR vs GPT

| 维度 | **MBR**（主引导记录） | **GPT**（GUID 分区表） |
|------|----------------------|------------------------|
| 位置 | 磁盘第 0 扇区 | 磁盘头 + **尾部备份** |
| 分区数 | 主分区最多 **4**（可扩逻辑分区） | 最多 **128** |
| 容量上限 | **2 TiB**（512B 扇区） | 极大（EB 级） |
| 冗余 | 无 | 有**备份 GPT** |
| 引导 | 内含 MBR 引导代码 | 依赖 **ESP** |
| 适用 | 老设备/兼容性 | 现代 UEFI 默认 |

> ⚠️ **对虚标盘/坏盘：优先 MBR**。因为 GPT 的**备份在磁盘末尾**，写入末尾会失败。

### MBR 结构要点
- 第 0 扇区：引导代码 + **4 个 16 字节分区项** + `0x55AA` 标志。
- 分区项含：起始 LBA、扇区数、**类型 ID**、bootable 标志。

---

## 三、分区类型 ID（常见）

| ID | 类型 | 用途 |
|----|------|------|
| `0xEF` | **EFI System Partition（ESP）** | UEFI 引导分区 |
| `0x0C` | FAT32 (LBA) | 常见 U 盘、启动盘数据区 |
| `0x0B` | FAT32 | 同上（CHS） |
| `0x07` | NTFS / exFAT | Windows |
| `0x83` | Linux | Linux 数据 |
| `0x82` | Linux swap | 交换分区 |
| `0xEE` | GPT 保护分区 | GPT 磁盘的保护性 MBR |

---

## 四、扇区与对齐

| 概念 | 含义 | 影响 |
|------|------|------|
| 512e | 物理 4K、逻辑 512B | 主流 |
| 4Kn | 物理/逻辑都 4K | 新盘 |
| **分区对齐** | 分区起始落在 1MiB 边界 | 不对齐会降低 SSD/U 盘性能 |

> 建分区时让起始扇区 = **2048**（即 1MiB 对齐）是通行做法。

---

## 五、文件系统对比

| 文件系统 | 单文件上限 | 跨平台 | 特点与场景 |
|----------|:----------:|:------:|-----------|
| **FAT16** | 2 GiB | 极好 | 老设备、小容量 |
| **FAT32** | **4 GiB** | 极好 | 兼容性最强；放不下 >4G 单文件 |
| **exFAT** | 极大 | 好 | U 盘主流；无 4G 限制；Windows/macOS/Linux 通吃 |
| **NTFS** | 极大 | Windows 原生（Linux 用 ntfs-3g） | 权限、日志、压缩 |
| **ext4** | 极大 | Linux 原生 | Linux 默认 |
| **btrfs** | 极大 | Linux | 快照、子卷、校验和 |
| **XFS** | 极大 | Linux | 大文件、高并发 |
| **UDF** | 极大 | 好 | 光盘格式；Windows ISO 用它 |
| **ISO9660** | 4 GiB(level3) | 好 | 光盘标准；Joliet/Rock Ridge 扩展 |
| **APFS** | 极大 | macOS 原生 | 苹果 |
| **ReFS** | 极大 | Windows | 服务器/弹性 |

### 簇（Cluster）
文件系统按"簇"分配空间。簇越大，小文件越浪费空间；簇越小，元数据越多。**exFAT/FAT32 的簇大小可在格式化时选**。

---

## 六、"格式化"到底是什么

| 类型 | 做什么 | 数据 |
|------|--------|------|
| **快速格式化** | 只重建文件系统元数据（FAT/MFT/superblock） | **不擦除**，可恢复 |
| **完整格式化** | 快速 + 扫描坏道 | 大多可恢复 |
| **低级格式化** | 重建扇区/擦除（极少用，且伤盘） | 不可恢复 |

**关键结论**：格式化只"重写目录"，不等于销毁数据。**安全擦除**需要覆盖写或加密擦除。

---

## 七、怎么选文件系统

| 用途 | 推荐 | 理由 |
|------|------|------|
| 普通 U 盘拷文件 | **exFAT** | 跨平台、无 4G 限制 |
| Windows 安装盘 | **FAT32** 或 NTFS | UEFI 只认 FAT；大文件用 NTFS/拆 WIM |
| Linux 安装盘 | ext4 / ISO 内建 | 由镜像决定 |
| macOS 专用 | APFS/HFS+ | 苹果生态 |
| 移动硬盘跨平台 | exFAT | 兼顾大文件与三平台 |
| 需要权限/日志 | NTFS / ext4 | 安全性与可靠性 |

## 八、常用命令（Linux）

```bash
lsblk -o NAME,SIZE,RM,FSTYPE,LABEL,MODEL   # 看设备与分区
blkid                                       # 看文件系统与 UUID
sfdisk -l /dev/sdX                          # 看分区表
# 建 MBR + 一个 FAT32 分区（起始 2048，类型 c，活动）
printf 'label: dos\n2048,,c,*\n' | sudo sfdisk /dev/sdX
sudo mkfs.vfat -F32 -n MYUSB /dev/sdX1       # 格式化 FAT32
sudo mkfs.exfat -n MYUSB /dev/sdX1           # 格式化 exFAT
sudo mkfs.ntfs -f -L MYUSB /dev/sdX1         # 格式化 NTFS
sudo fsck.vfat /dev/sdX1                      # 检查/修复
```

## 其他问题（Q&A）

**Q1：为什么 FAT32 U 盘放不下 5G 的电影？**
A：FAT32 单文件上限 **4 GiB**。改用 **exFAT** 或 NTFS 即可。

**Q2：格式化了，数据还能恢复吗？**
A：快速格式化只重写目录，**数据仍在**，可用恢复软件抢救。要真正销毁需覆盖擦除或加密擦除。

**Q3：能不能"无损转换"文件系统？**
A：部分工具支持 FAT32↔NTFS 之类转换，但**不保证安全**。稳妥做法是备份后重新格式化。

**Q4：分区表损坏，盘显示"RAW"或容量异常？**
A：先备份/镜像整个设备，再用 `testdisk` 尝试恢复分区表；不要急着格式化（会覆盖元数据）。

**Q5：U 盘插到电视/车机/相机不认？**
A：多为文件系统或分区表不兼容。老设备常只认 **FAT32 + MBR**。可单独分一个小 FAT32 分区给它。

**Q6：簇大小选多少？**
A：通用场景用默认即可；大量小文件可选小簇省空间，大文件多可选大簇提性能。

**Q7：MBR 和 GPT 该选哪个？**
A：新机器 + UEFI → GPT；老设备/兼容性优先、或**虚标/坏盘** → MBR。
